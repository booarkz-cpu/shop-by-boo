## Локальный интеграционный прогон

Из рабочей копии запустите `bash scripts/integration-test.sh`. Скрипт переносит зафиксированное дерево и локальные изменения отслеживаемых файлов во временную копию. Новый исходный файл сначала добавьте через `git add`, чтобы включить его в прогон. Скрипт создаёт тестовые настройки, собственный Compose-проект и тома, ожидает готовности API и воркера, сверяет ревизию Alembic и запускает pytest в отдельном тестовом образе. Для проверок, меняющих схему, выделяются база `integration_pytest` и отдельный индекс Redis. Временная копия, доступная процессу тестов, монтируется только для чтения. Порт API назначается на loopback. После прогона удаляются ресурсы созданного проекта. Для ручного запуска интеграционный overlay по умолчанию публикует API на `127.0.0.1:18000`.

Для выборочного запуска передайте пути pytest следующим аргументом, например `bash scripts/integration-test.sh tests/test_schema_matches_migrations.py`. Для автоматического прогона Docker выделяет свободные подсети, поэтому несколько тестовых проектов могут работать рядом с основным стеком. Этот путь и сценарии взаимодействия оплаты с выдачей VPN проверяет задание Docker Compose на данных стенда.

# Заморозка подписки и повторные попытки автопродления (v28.50)

## Заморозка подписки

Код: `backend/app/subscription_freeze.py`, таблица `subscription_freezes` (миграция `0084_subscription_freeze`). Админка: «Тарифы → Заморозка подписки», в мобильных админках — карточка «Заморозка подписки». Клиенту заморозка доступна в кабинете (раздел «Подписка»), в боте (`/freeze`) и через API.

Как это работает:
1. Клиент выбирает срок заморозки. Магазин сразу сдвигает конец подписки на этот срок — и в базе, и в панели (`expireAt`). Затем пользователь в панели выключается.
2. Пока подписка заморожена (статус `frozen`), VPN не работает. Автопродление не списывает деньги, напоминания и проверка окончания видят уже новую дату.
3. Когда срок заморозки выходит, подписка размораживается сама (проверка раз в 5 минут). VPN включается, клиент получает сообщение.
4. При досрочной разморозке неиспользованные дни вычитаются из срока, и VPN включается сразу.
5. Покупка, подарок или бонусные дни на замороженную подписку сначала её размораживают. Иначе дни заморозки сложились бы с оплаченным доступом.

Отменить замороженную подписку нельзя: сначала её нужно разморозить.

| Правило | По умолчанию |
| --- | --- |
| Заморозка включена | нет |
| Срок одной заморозки | от 3 до 30 дней |
| Всего дней за 365 дней | 30 |
| Заморозок за 365 дней | 2 |
| Должно оставаться дней подписки | от 1 |
| Только оплаченные подписки | да (пробный период заморозить нельзя) |

Семейную подписку замораживает только владелец семьи. Дни при досрочной разморозке считаются по факту: два дня из семи — это два дня из годового лимита.

API клиента: `GET /api/me/freeze`, `POST /api/me/freeze` (`days`, `subscription_id`), `POST /api/me/freeze/thaw`.
API админки: `GET`/`PUT /api/admin/freeze`, `POST /api/admin/freeze/{subscription_id}/thaw`.

## Повторные попытки автопродления

Код: `backend/app/dunning.py`, используется планировщиком автопродления (`schedulers.py`). Админка: «Тарифы → Повторные попытки автопродления», в мобильных админках — карточка с тем же названием.

Пока правила выключены, работает прежняя схема: повтор через 2, 4 … 72 часа, 72 часа льготного доступа, после третьего отказа автопродление выключается, клиенту ничего не приходит.

Если правила включены:
- **Расписание повторов.** Повторы идут через заданное число часов (по умолчанию 24, 72, 120). Если отказов больше, чем интервалов, повторяется последний интервал.
- **Число отказов.** После него автопродление выключается (по умолчанию 3).
- **Льготный доступ.** Сколько часов VPN работает после неудачного списания (по умолчанию 72). Задавайте его не короче расписания повторов, иначе VPN выключится раньше последней попытки.
- **Сообщения клиенту.** После каждого отказа приходит сообщение в Telegram и в приложении: номер попытки, время следующей и что сделать. Последнее сообщение говорит, что автопродление выключено. На одну попытку — одно сообщение.
- **Продление с баланса.** Раз в 15 минут магазин находит подписки, у которых не прошло списание и истекает льготный доступ. Если на балансе клиента хватает денег на тариф, подписка продлевается с баланса как обычная покупка, а счётчик отказов сбрасывается.

API админки: `GET`/`PUT /api/admin/dunning`. Ответ `GET` содержит, сколько клиентов ждут повтора, у скольких автопродление выключено, сколько подписок в льготном режиме и сколько продлено с баланса за 30 дней.

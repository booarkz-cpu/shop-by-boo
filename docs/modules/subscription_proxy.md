# Прослойка подписки и функции remnawave-subscription-middleware

С v28.38.0 магазин сам выполняет работу прослойки перед подпиской Remnawave. Идеи взяты из проекта [remnawave-subscription-middleware](https://github.com/Mrvibecodic/remnawave-subscription-middleware); реализация своя, на Python, внутри магазина, код не копировался: в репозитории проекта нет файла лицензии. Сверка по функциям — в [docs/ru/MIDDLEWARE_RECONCILIATION.md](../ru/MIDDLEWARE_RECONCILIATION.md).

Все функции выключены по умолчанию. Вызовы панели проверяются на самой новой Remnawave в CI (`tests/live/test_remnawave_live.py`).

## Зеркало подписки (`sub_proxy.py`) — «Серверы → Прослойка подписки»

Панель Remnawave обычно стоит за границей, и её домен подписки из России открывается нестабильно. Клиенты перестают получать обновления.

С прослойкой клиент получает ссылку `https://<домен зеркала>/<shortUuid>` (с префиксом — `/<prefix>/<shortUuid>`). Магазин забирает подписку у панели: по умолчанию по внутреннему адресу `<REMNAWAVE_URL>/api/sub/<shortUuid>`, суффиксы форматов (`/json`, `/clash`, `/singbox`, `/mihomo`) сохраняются.

| Возможность | Как работает |
| --- | --- |
| Ссылки клиентам | При «выдавать ссылку зеркала» кабинет, Mini App, бот, приложения, синхронизация и реселлеры показывают адрес зеркала (`client_url`). Ссылка панели продолжает работать |
| Заголовки панели | Передаются клиенту без `set-cookie`, `server` и служебных заголовков. `profile-web-page-url` указывает на зеркало |
| Блокировка устройства | HWID в списке — заглушка вместо конфигов: один нерабочий сервер с текстом владельца и `announce`. Запрос до панели не доходит |
| HWID из User-Agent | `x-hwid=…`, `x-device-os=…`, `x-device-model=…` внутри User-Agent (v2rayNG, Clash) передаются панели как заголовки. Её собственный лимит устройств видит и эти устройства |
| Правила по приложению | Первое подходящее по User-Agent (регулярное выражение) и ОС правило меняет заголовки: `profile-title`, `announce`, `profile-update-interval`… Пустое значение удаляет заголовок, кириллица отправляется как `base64:…` |
| Доп. ключи по скваду | Ссылки (VLESS, WireGuard, Hysteria…) добавляются клиентам сквада |
| Вторая подписка | Серверы второй подписки (`merge_url` с `{short_uuid}`) добавляются в ту же ссылку |
| Маскировка | На всё, что не похоже на подписку, и на неизвестный shortUuid отвечает нейтральная страница входа |

Доп. ключи и вторая подписка добавляются, только если одновременно:
- подписка активна в магазине;
- ответ — список ссылок (base64 или текст): JSON и YAML не меняются;
- панель не сообщила о лимите устройств (`x-hwid-*`).

**Домен зеркала:**
- `SUB_PROXY_DOMAINS` в `.env`: Caddy переписывает `https://<домен>/<x>` в `/sub/<x>`;
- без своего домена зеркало работает по адресу `https://<API_DOMAIN>/sub/<shortUuid>`;
- лимит — 240 запросов в минуту с одного IP.

**Журнал запросов** — «Мониторинг → Журнал подписки», таблица `sub_requests`, хранится 14 дней. В каждой записи:
- время и клиент;
- приложение и версия из User-Agent;
- ОС, модель и HWID;
- IP;
- решение (`proxied`, `extended`, `blocked`, `not_found`, `error`), код, размер и время ответа.

**Версии клиентов** (`client_versions.py`):
- каталог приложений с репозиторием GitHub и последней версией;
- последняя версия проверяется фоновой задачей не чаще раза в сутки на приложение, только пока прослойка включена;
- можно задать версию вручную;
- запрос старой версии помечается «устарел». Это подсказка: версию сообщает сам клиент.

API:
- `GET/PUT /api/admin/sub-proxy`;
- `POST /api/admin/sub-proxy/blocked`, `DELETE /api/admin/sub-proxy/blocked/{hwid}`;
- `GET /api/admin/sub-proxy/log`, `GET /api/admin/sub-proxy/apps`;
- `GET/PUT /api/admin/sub-proxy/clients`, `POST /api/admin/sub-proxy/clients/refresh`;
- `GET /sub/{path}`.

## Вебхуки: пересылка и журнал изменений (`webhook_tee.py`)

**Пересылка** — «Интеграции → Вебхуки панели»:
- каждое событие панели уходит ещё на несколько адресов (только HTTPS);
- исходное тело переподписывается секретом получателя (`X-Remnawave-Signature`, HMAC-SHA256 hex), три попытки;
- есть тестовое событие для проверки получателей.

**Журнал «Кто менял пользователя»:**
- по каждому событию с пользователем сохраняется снимок полей: статус, срок, лимит и стратегия трафика, лимит устройств, сквады, внешний сквад, тег, описание, Telegram ID, email;
- пишутся поля, изменившиеся с прошлого события;
- метка **магазин** — если сам магазин менял эти поля через API за последние 5 минут (`panel_api_stats`), иначе **извне**;
- лишних запросов к панели нет;
- хранится 90 дней; CSV-выгрузка с обезличиванием подменяет имена, email и UUID на `id1`, `id2`…

**Лента «События подписок»** на дашборде собирает по свежести оплаты, события панели и правки извне.

API:
- `GET/PUT /api/admin/webhooks/tee`, `POST /api/admin/webhooks/tee/test`;
- `GET /api/admin/panel-changes`, `GET /api/admin/panel-changes.csv`;
- `GET /api/admin/subscription-feed`.

## Запросы к панели (`panel_api_stats.py`) — «Мониторинг → Запросы к панели»

- Каждый вызов API Remnawave и каждая подписка через прослойку считаются в памяти.
- Источники: клиенты, админка, прослойка, вебхуки, фоновые задачи.
- Пути обобщаются до шаблонов (`/api/users/{x}`).
- Раз в минуту суммы пишутся почасово в `panel_api_stats`.
- Видно: запросы, ошибки, среднее время, пиковый час — за сутки, 3 дня и неделю.
- Хранится 30 дней. API: `GET /api/admin/panel-api-stats?hours=24`.

## Срок с первого подключения (`first_connect.py`) — «Тарифы»

Для отмеченных тарифов новая подписка создаётся активной со сроком «оплата + ожидание + срок тарифа». Ожидание — меньшее из срока тарифа и `max_wait_days`, не больше 30 дней.

По вебхуку `user.first_connected` неиспользованная часть ожидания вычитается: в панели (`expireAt`) и в магазине. Продления во время ожидания сохраняются. Если клиент так и не подключится, срок начнётся сам. API: `GET/PUT /api/admin/first-connect`.

## Грейс через ограниченный сквад (`grace_access.py`)

Режим «перевести в ограниченный сквад»: на время льготного доступа клиент переводится в указанный Internal Squad, например медленный сервер. Сквад тарифа возвращается сам при оплате; вручную — `POST /api/admin/grace/{subscription_id}/restore-squads`.

## Сессии и аномалии (`vpn_sessions.py`) — «Клиенты → Сессии и аномалии»

**Сбор сессий:**
- раз в 2–60 минут магазин опрашивает подключённые ноды: `POST /api/connections/by-node/{node}` → задача → `GET /api/connections/by-node/{job}` (Remnawave 3.4; старого `/api/ip-control` больше нет);
- снимки склеиваются в сессии: клиент, нода, IP, провайдер (ASN) и страна через кэш RIPEstat;
- хранится 30 дней.

**Аномалии:**
- правила по текущему снимку: больше N адресов, провайдеров или стран, при желании «× лимит устройств»;
- уровень правила — жёлтый или красный;
- совпадение — отметка в списке и событие в ленте клиента; закрытие тоже пишется.

**Карточка клиента:** история по провайдерам, сводка за неделю, «Сейчас онлайн» (`POST/GET /api/connections/by-user`) и сброс соединений (`POST /api/connections/drop`). Если подключённых нод нет, панель отвечает ошибкой A219, и магазин показывает «нигде не подключён».

**«География клиентов»** — векторная карта стран (v28.42.0, `admin/src/worldMap.tsx`, Natural Earth 1:110m) и список стран и провайдеров по сессиям, без IP.

API:
- `GET/PUT /api/admin/sessions/config`, `GET /api/admin/sessions/anomalies`;
- `GET /api/admin/users/{id}/sessions`, `GET /api/admin/users/{id}/online`, `POST /api/admin/users/{id}/drop-connections`;
- `GET /api/admin/sessions/geo`.

## Трафик по дням и серверам (`panel_usage.py`)

- Живой запрос `GET /api/bandwidth-stats/users/{id}?start&end&topNodesLimit=100`, в магазине ничего не хранится.
- Показывает столбики по дням, сумму, среднее, пик и долю каждого сервера.
- Где видно: карточка клиента в админке (7, 30 или 90 дней), «Трафик по дням» в кабинете и Mini App (`GET /api/me/traffic`), строка «Трафик за 30 дней» в «Моей статистике» приложений.

## Пул WireGuard / AmneziaWG и ключи подключения (`wg_pool.py`)

**Пул:**
- владелец загружает готовые `.conf`, хранятся зашифрованными;
- клиент с активной подпиской получает свой конфиг: один на устройство, не больше лимита устройств тарифа;
- можно ограничить сквадами;
- освобождённый конфиг другому клиенту не выдаётся.

**Ключи подключения** — кабинет, Mini App и команда бота `/keys`:
- каждый сервер подписки отдельной ссылкой (`GET /api/subscriptions/by-short-uuid/{short}`) плюс доп. ключи сквада;
- копирование и QR, который приходит как data URL и потому работает и в Mini App.

API:
- `GET /api/me/wg-config`, `GET /api/me/wg-config/qr`, `GET/DELETE /api/me/wg-configs`;
- `GET /api/me/subscription/keys`, `GET /api/me/subscription/keys/{i}/qr`;
- `GET/PUT /api/admin/wg-pool`, `POST /api/admin/wg-pool/upload`, `DELETE /api/admin/wg-pool/free`.

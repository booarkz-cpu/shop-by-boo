# Синхронизация состояния между ботом, Mini App, кабинетом и приложениями

После оплаты подписка выдаётся автоматически: webhook → задание → Remnawave → уведомления в бот, push и центр
уведомлений. Чтобы **уже открытые** клиенты сразу показали новое состояние, все они читают одно и то же:

`GET /api/me/sync` → `{"version", "subscriptions", "active", "wallet", "pending_payments", "servers"}`

* `version` — SHA-256 от самих данных, а не счётчик. Ни один путь изменения (оплата, автопродление, правка
  администратором, бонусные дни, отзыв) не может «забыть» уведомить клиентов.
* `?since=<version>` (или `If-None-Match`) — ответ `304` без тела, если ничего не изменилось.
* `&wait=1..25` — запрос ждёт изменения до 25 секунд (проверка раз в 3 с, соединение с базой между проверками
  возвращается в пул).
* В `servers` нет счётчика онлайна: он меняется каждую минуту и вызывал бы ложные «изменения».

| Клиент | Как читает |
| --- | --- |
| Кабинет и Telegram Mini App | `cabinet/src/account-sync.ts`: длинный опрос, пока вкладка видима; при смене версии — перечитать данные |
| Android | `LaunchedEffect` в `MainActivity.kt`: `wait=10`, только пока приложение на экране |
| iOS | `.task(id:)` в `ContentView.swift`: так же, только в активной сцене |
| Бот | Читает базу на каждое действие — всегда актуален |

Тесты: `tests/test_account_sync.py`, `cabinet/src/account-sync.test.tsx`, сквозной сценарий в
`tests/test_e2e_journeys.py`.

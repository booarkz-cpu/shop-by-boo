# Карточки модулей в мобильных админках

Чтобы каждый новый модуль сразу был в Android и iOS админках без выпуска новой версии приложений, магазин сам описывает
карточки: `GET /api/admin/mobile/panels` (`backend/app/mobile_panels.py`).

```json
{"panels": [{"id": "payment_methods", "title": "Способы оплаты",
  "rows": [{"label": "СБП", "value": "ЮKassa → RollyPay", "tone": "ok"}],
  "actions": [{"label": "Выключить выбор способа", "method": "PUT", "path": "/api/admin/payments/methods",
               "body": {"enabled": false, "routes": {}}, "confirm": ""}]}]}
```

Приложения (3.2.0 и новее, раздел «Операции») показывают строки и превращают каждое действие в кнопку, которая
отправляет ровно этот запрос с сессией администратора. Разрешены только пути `/api/admin/` и методы POST/PUT/DELETE;
права проверяет сервер, как для веб-админки. Действие с `confirm` сначала спрашивает подтверждение. Ошибка одного
модуля показывается в его карточке и не скрывает остальные.

Сейчас карточки: способы оплаты, горячий резерв, автомасштабирование нод, монитор блокировок и модули v28.37
(качество связи, прогноз оттока, автоответы, P&L, реселлеры). Новый модуль добавляет функцию в `BUILDERS`.
Тесты: `tests/test_payment_methods.py::test_mobile_panels_describe_modules`.

# Здоровье касс (v28.45)

Код: `backend/app/gateways/` — по модулю на кассу и таблица `GATEWAYS`; `backend/app/gateway_ops.py` — проба, отчёт и порядок касс. Раздел админки: «Платёжные агенты → Здоровье касс». В мобильных админках — карточка «Здоровье касс».

## Таблица касс

`GATEWAYS` (`gateways/__init__.py`) — единое место, где описана каждая дополнительная касса:
- класс и ключи;
- адрес уведомлений;
- способ проверки подписи;
- запрос, которым платёж перечитывается перед выдачей;
- есть ли возвраты и автоплатежи через API.

Из таблицы собираются очередь касс, сверка и восстановление платежей, возвраты (`refunders()`), фоновые задачи и проверка ключей для оповещений. С v28.46 у CloudPayments есть возвраты через API и автопродление по токену карты. Новая касса — это один модуль и одна строка в таблице. Тест `tests/test_gateway_ops.py` сверяет таблицу со списками `payment_policy` и `payment_methods`, с настройками и с маршрутами уведомлений.

`payments_extra.py` оставлен как совместимый модуль: прежние импорты работают.

## Проба касс

Каждые `probe_hours` часов (по умолчанию 6) магазин делает в каждой настроенной кассе одну проверочную операцию. Это авторизованный запрос статуса выдуманного заказа или баланса, деньги не двигаются. Ответ «заказ не найден» считается успехом: ключи приняты.

| Результат | Что это значит |
| --- | --- |
| HTTP 401/403 | ключи не приняты |
| HTTP 5xx | касса отвечает ошибкой |
| нет ответа | нет связи |

После `fail_threshold` неудач подряд (по умолчанию 2) касса выводится из очереди на `cooldown_hours` часов, и оператору приходит карточка в Telegram. Пока проба не проходит, касса остаётся вне очереди. Когда проба проходит, касса возвращается в очередь сама, и приходит сообщение. Касса, которую вывел из очереди оператор, пробой не возвращается.

## Уведомления, которые не пришли

`GET /api/admin/gateways/notifications?days=7` показывает по каждой кассе:
- сколько заказов оплачено;
- сколько оплат найдено сверкой, без уведомления от кассы;
- сколько заказов висят в ожидании дольше `notify_minutes` минут.

Если доля оплат без уведомления за сутки не меньше `missing_alert_share` % и оплат не меньше 5, оператор получает карточку — не чаще раза в сутки на кассу. Обычно причина в неверном адресе уведомлений или ключе подписи в кабинете кассы.

## Лучшая касса первой

Если включено `auto_priority`, раз в сутки кассы, у которых за `auto_days` дней набралось не меньше `auto_min_orders` заказов, выстраиваются по конверсии. Остальные кассы сохраняют свой порядок после них. Каждое изменение пишется в журнал действий. Кнопка «Показать новый порядок» в админке ничего не меняет, а только показывает расчёт (`POST /api/admin/gateways/auto-priority?dry_run=true`).

## Боевая приёмка

Workflow «Payments acceptance» (`.github/workflows/payments-acceptance.yml`) проверяет каждую кассу, ключи которой добавлены в секреты репозитория под теми же именами, что в `.env`. Где у кассы есть тестовый режим, лучше дать тестовые ключи. Для каждой такой кассы:
1. проба проходит;
2. страница оплаты создаётся на маленькую сумму (по умолчанию 10);
3. платёж читается обратно со статусом «не оплачен».

Никто не платит, деньги не двигаются. Workflow запускается каждый понедельник и вручную. Кассы без ключей пропускаются.

Путь денег «оплата → уведомление → выдача» проверяет человек с тестовой картой: [PAYMENTS_LIVE_CHECKLIST.md](../ru/PAYMENTS_LIVE_CHECKLIST.md).

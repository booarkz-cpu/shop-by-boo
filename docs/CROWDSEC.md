# CrowdSec — защита от перебора паролей и сканеров

Карточка **CrowdSec — защита от брутфорса** в разделе «Установка → Обслуживание и защита». Ставится на любой
сервер установки: панель или ноду.

Код: скрипт `CROWDSEC` в `backend/app/rw_netmods.py`, шаг в `backend/app/rw_steps.py`.
Проверка: `scripts/ci/crowdsec-check.sh` (настоящая установка в CI) и `tests/test_rw_netmods.py`.

## Что делает

1. Подключает официальный репозиторий CrowdSec с его ключом подписи и ставит два пакета: движок `crowdsec`
   и блокировщик `crowdsec-firewall-bouncer-nftables`.
2. Включает сценарии `crowdsecurity/linux` и `crowdsecurity/sshd`: перебор паролей SSH и сканирование.
3. Вносит в белый список адрес, с которого вы подключаетесь, адрес магазина, адрес панели и адреса,
   которые вы указали сами. Эти адреса не блокируются.
4. Запускает движок и блокировщик. Блокировки исполняет nftables в собственных таблицах CrowdSec;
   таблицы «Защиты ноды», ufw и fail2ban не затрагиваются.

## Общий список блокировок

Переключатель «Общий список блокировок CrowdSec», по умолчанию выключен.

| | Выключен | Включён |
| --- | --- | --- |
| Откуда блокировки | Только журналы этого сервера | Журналы сервера и общий список CrowdSec |
| Что сервер отправляет в CrowdSec | Ничего | Адреса тех, кто его атакует |
| Как устроено | Движок запущен с `-no-capi`, учётные данные Central API стёрты | Сервер зарегистрирован в Central API |

Пакет CrowdSec при установке один раз регистрирует сервер в Central API. При выключенном списке учётные
данные сразу после этого стираются.

## Удаление

«Выключить» удаляет оба пакета, репозиторий, ключ, настройки, данные и таблицы nftables CrowdSec.
Повторное удаление безопасно.

## Ошибки

| Сообщение | Что значит |
| --- | --- |
| CrowdSec ставится только на Debian и Ubuntu с systemd | Другая система |
| CrowdSec не установился или не запустился | Причина — в журнале шага: туда попадает конец журнала службы |
| Ключ репозитория CrowdSec не скачался | У сервера нет выхода в интернет к packagecloud.io |

## Что проверено

В каждом прогоне CI скрипт выполняется на настоящей машине Ubuntu:

- обе службы запущены, блокировщик зарегистрирован;
- белый список содержит переданные адреса;
- без общего списка Central API недоступен;
- решение о блокировке адреса доходит до nftables;
- «показать блокировки» выводит её, «снять блокировку» убирает её из nftables;
- повторный запуск даёт то же состояние;
- удаление не оставляет пакетов, файлов и таблиц.

## Блокировки: посмотреть и снять

В той же карточке в поле «Что сделать»:

| Действие | Что делает |
| --- | --- |
| Установить или обновить настройки | Установка, белый список, общий список блокировок |
| Показать действующие блокировки | В журнал шага выводятся до 30 последних блокировок: адрес, причина, источник, срок — и их общее число |
| Снять блокировку с адреса | Удаляет блокировку адреса; адрес уходит из nftables за несколько секунд |

Просмотр и снятие блокировки установку не меняют, и откатывать после них нечего.
Чтобы адрес не блокировался впредь, добавьте его в «Адреса без ограничений» и запустите установку ещё раз.

# Целостность журнала действий

Раздел панели администратора: **Журнал действий**, блок «Целостность журнала».

Код: `backend/app/audit_seal.py`, блок `apps/lucy-admin/web/src/audit-seal.tsx`,
тесты `tests/test_audit_seal.py` и `apps/lucy-admin/web/e2e/audit-seal.spec.ts`.

## Зачем

Журнал действий отвечает на вопрос «кто, когда и что сделал». Он лежит в базе данных, и запись в нём можно
изменить или удалить напрямую, в обход магазина. Печати делают такое изменение заметным.

## Как это работает

1. Каждые десять минут фоновый процесс берёт записи журнала, появившиеся после предыдущей печати.
2. По ним считается контрольная подпись HMAC-SHA256. В подпись входят все поля каждой записи и предыдущая печать.
   Ключ подписи — секрет сервера `APP_SECRET` из файла `.env`. В базе данных его нет.
3. Печать — диапазон номеров записей, их число и подпись — сохраняется в настройках магазина.

Проверка пересчитывает подписи по записям, как они есть сейчас. Если запись изменили или удалили,
подпись её диапазона не сойдётся.

## Что показывает блок

| Поле | Значение |
| --- | --- |
| «Журнал цел» | Все печати сошлись при последней проверке |
| «Нарушено диапазонов: N» | Таблица: номера записей, сколько было запечатано, сколько найдено сейчас, когда запечатано |
| «Запечатано записей» | Сколько записей уже под печатью и до какого номера |
| «Ещё не запечатано» | Записи, сделанные после последней печати |
| «Последняя проверка» | Когда журнал проверяли в последний раз |

Проверка запускается кнопкой «Проверить журнал». Сама по расписанию она не запускается.

## Что делать при нарушении

Проверка называет диапазон записей, а не одну запись. Сравните записи этого диапазона с резервной копией базы:
`scripts/backup.sh` делает копии, в них журнал сохранён таким, каким был на момент копии.

## Пределы защиты

| Что | Почему |
| --- | --- |
| Записи моложе последней печати (до десяти минут) | Они ещё не запечатаны; их изменение незаметно |
| Тот, у кого есть секрет сервера | Он может поставить печати заново. Печати защищают от того, кто может писать в базу, но не читает `.env` |
| Удаление всех печатей вместе с записями в конце журнала | Проверка увидит пропавшую печать в середине цепочки, но не увидит аккуратно отрезанный конец |
| Точность | Находится диапазон (до 5000 записей), а не отдельная запись |

После смены `APP_SECRET` печати, поставленные со старым секретом, проверяются по `APP_SECRET_PREVIOUS`, пока он задан.

## Хранение

Печати лежат в таблице настроек (`audit.seals`); схема базы не менялась.
Когда печатей становится больше тысячи, самые старые объединяются в одну — только если они на этот момент сходятся.

## Что проверено и что нет

Проверено тестами, в том числе на настоящей таблице: печать, проверка, изменённая запись, удалённая запись,
удалённая печать, печать с чужим секретом, объединение старых печатей.

Не проверено на работающем сервере под нагрузкой.

# VPN Shop — v28.18.0 (runtime 21.5.1)

Current stable core: API, admin, cabinet/Mini App, bot, Support Pro and mobile sources. Shop migration: `0072_traffic_analysis`; Support Pro: `0008`. v28.18.0 rewrites the guides (a Russian launch guide from server to first sale and 30 per-module guides checked against the code) and adds a plan editor with Remnawave Internal Squad selection, a combined referrals and partners section, a fix that lets switching incident mode off lift maintenance, and optional client-to-IP observations from the Xray log for abuse checks. v28.17.0 added a receive-only MX for service addresses (DMARC reports into the mail domain section, support mail into Support Pro) with SPF, DKIM and DMARC checks, greylisting, limits, ClamAV and STARTTLS; it never relays and never sends bounces. v28.16.0 added deep traffic analysis on nodes: nDPI when installed, otherwise a built-in classifier of the first packets of each flow (BitTorrent handshake, DHT, uTP, trackers, and a heuristic for encrypted BitTorrent that never affects abuse scoring), attributed to clients via the Xray log in node memory. v28.15.0 added BitTorrent detection on nodes from the Xray access log: the agent sends only per-client counts (no destinations), the shop keeps hourly counters for 30 days, marks the client in abuse scoring for 24 hours and notifies them once a day; encrypted BitTorrent is not detected. v28.14.0 added a node terminal: a full shell on a VPN node through its agent (no SSH, no open ports on the node), enabled on both the shop server and the node, admin-only with 2FA and a password-and-code confirmation per session, time and idle limits, and an encrypted transcript that leaves out secrets typed with echo off. v28.13.0 added a mail domain section (MX, SPF with the 10-lookup limit, DKIM against the panel key, DMARC policy and report addresses) and DMARC aggregate reports from a read-only mailbox or upload, deduplicated, limited against archive bombs and XXE, accepted only for the shop's domain, with retention and erasure. v28.12.0 added a Zendesk and Freshdesk bridge to Support Pro 3.8 (ticket and history import without duplicates, requester matched by email, operator replies posted once, pause on HTTP 429, erasure that blocks re-import). v28.11.0 added passkeys to the Android and iOS apps (Credential Manager, AuthenticationServices, app association files on the cabinet domain, PKCE-bound sign-in code). v28.10.0 redesigned the admin panel: an "All sections" start page lists all 58 features in 8 groups with a one-sentence description and task search, every section has a breadcrumb, title and description, and every form field has a visible label. v28.9.0 added node network intelligence: ASN, network holder and RIR country (RIPEstat) and IP reputation (AbuseIPDB, optional) with a freshness cache and source rate limits. v28.8.0 added a plugin runtime: signed manifest packages from trusted publishers, explicit capability approval, scoped plugin API, HMAC-signed events, upgrade and rollback without restart. v28.7.0 added an email support channel to Support Pro 3.7 (IMAP intake without duplicates, threaded SMTP replies, loop and bounce protection, erasure and retention). v28.6.0 added an opt-in Android home-screen subscription widget and multiple shop profiles in the Android and iOS admin apps. v28.5.0 added opt-in native push notifications for the Android and iOS apps (FCM HTTP v1 and APNs, token bound to the signed-in session and revoked on sign-out). v28.4.0 moved the admin panel, customer cabinet and Telegram Mini App to Next.js with the Remna dark design (collapsible sidebar, mobile drawer, metric dashboard, Telegram WebApp SDK integration) and added a reconciled historical import of subscriptions and payments with rollback and a customer profile API. v28.3.0 added 96 typed live settings with encrypted secrets, staged apply, audit, process convergence and rollback; all restart-bound fields and 2 workflow-owned fields are classified explicitly.

Production payments remain closed until application E2E v2 is completed. Full roadmap transfer and owner-signed APK/IPA are not complete. Stable is the release channel of the current core.

To test locally: clone tag `v28.18.0` and run `bash scripts/test-up.sh`. Loopback ports: API 18080, admin 18081, cabinet 18082, Mini App 18083. The sandbox subscription does not provide a VPN tunnel.

New server installation from a root SSH/Termius terminal:

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28.18.0/install.sh -o /root/shop-install.sh && BRANCH=v28.18.0 bash /root/shop-install.sh
```

Use the update procedure for an existing shop; preserve secrets and verify a consistent backup first.

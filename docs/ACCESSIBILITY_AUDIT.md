# Аудит доступности интерфейсов

Дата: 16 ноября 2026. Проверенный исходный снимок: `92363652b1b74e7b8f84711a5808bc300bc776e4`
(ветка документации PR #360). Этот документ фиксирует статическую проверку веб-панели,
кабинета и общего кода Mini App. Он не подтверждает соответствие всего продукта WCAG
и не заменяет работу с экранным диктором. Функциональное требование REQ-UI-0007 остаётся PARTIAL.

## Результат и границы

Найдены два существенных дефекта исходного кода и два дополнительных пробела семантики.
В первую очередь нужны исправления контраста основных кнопок тёмной темы и управления
фокусом быстрого поиска. Исправления runtime в этот документальный коммит не входят.
Целостность базовой системы есть: общие компоненты, токены двух тем, текстовые статусы,
нативные кнопки, подписи полей и правила уменьшения движения. Полнота их применения ко
всем разделам не доказана.

| Область | Что проверено здесь | Статус доказательства |
| --- | --- | --- |
| Lucy Admin Web | Каркас, быстрый поиск, общие кнопки/состояния, темы, существующие E2E | Статический аудит; новый браузерный прогон не выполнялся |
| Кабинет | Вход/регистрация, навигация, Meter/Segmented, CSS | Статический аудит и расчёт контраста |
| Telegram Mini App | Общий код кабинета и отдельная сборка поверхности | WebView, Telegram и экранный диктор NOT_RUN |
| Android-клиент | Область следующей проверки: Compose, темы, текстовый масштаб | TalkBack, touch targets и крупный шрифт NOT_RUN |
| Android/iOS магазина и админки | Область следующей проверки: нативные экраны/встроенный веб-контент | Accessibility Scanner, VoiceOver, Dynamic Type NOT_RUN |

Производительность, все responsive-состояния, визуальная целостность всех экранов и полный
каскад тем здесь не измерялись. Общий балл из 20 не присваивается: он скрывал бы непроверенные
измерения. Наличие зелёного общего CI не означает успешный аудит доступности.

Ориентиры: [WCAG 2.2, перечень критериев W3C](https://www.w3.org/WAI/WCAG22/quickref/),
[модальный диалог WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/),
[вкладки WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/).
Привязки к критериям ниже обозначают предмет проверки; отсутствие атрибута само по себе
не доказывает отказ всех вспомогательных технологий.

## Находки по приоритету

### A11Y-01, P1 — контраст белого текста основной кнопки в тёмной теме

Источники: [CSS кабинета](../apps/user-cabinet/src/style.css) (`--primary-rgb`,
`--primary-hover`, `--on-primary`, `.btn-primary`), [тема админки](../apps/lucy-admin/web/src/theme.css)
(те же токены, `.primary`, `.auth-submit`). В кабинете основной текст кнопки имеет размер
14.5px/600, в форме админки 15px: это обычный, а не крупный текст.

| Тема/состояние | Текст | Фон | Расчётный контраст |
| --- | --- | --- | ---: |
| Тёмная, основное | #FFFFFF | #3B82F6 | 3.678:1 |
| Тёмная, hover | #FFFFFF | #60A5FA | 2.542:1 |
| Светлая, основное | #FFFFFF | #2563EB | 5.169:1 |
| Светлая, hover | #FFFFFF | #1D4ED8 | 6.702:1 |
| Тёмная, основной текст карточки | #E2E8F0 | #0F172A | 14.482:1 |
| Тёмная, вторичный текст карточки | #94A3B8 | #0F172A | 6.963:1 |

Это расчёт непрозрачных пар из CSS, а не замер всех отрисованных пикселей/градиентов.
Для обычного текста первые две пары ниже 4.5:1 (WCAG 1.4.3); особенно плохо читается
наведение. Нельзя исправлять только основной фон, оставляя hover без проверки.
Следующий шаг: согласовать фон/текст обеих пар с действующими токенами, затем проверить
computed styles и контраст реальных кнопок входа/оплаты в обеих темах. Disabled-состояния
оценивать отдельно; полученные числа не относятся к ним.

Воспроизведение расчёта без сторонних зависимостей, из корня репозитория:

```bash
python3 - <<'PY'
def luminance(rgb):
    channels = [int(rgb[i:i+2], 16) / 255 for i in (0, 2, 4)]
    linear = [v / 12.92 if v <= .04045 else ((v + .055) / 1.055) ** 2.4 for v in channels]
    return sum(w * v for w, v in zip((.2126, .7152, .0722), linear))
for fg, bg in [('ffffff','3b82f6'), ('ffffff','60a5fa'), ('ffffff','2563eb'),
               ('ffffff','1d4ed8'), ('e2e8f0','0f172a'), ('94a3b8','0f172a')]:
    low, high = sorted((luminance(fg), luminance(bg)))
    print(fg, bg, f'{(high + .05) / (low + .05):.3f}:1')
PY
```

### A11Y-02, P1 — быстрый поиск объявлен модальным без полного управления фокусом

Источник: [AdminShell](../apps/lucy-admin/web/src/admin-shell.tsx), блок `command`.
Есть `role="dialog"`, `aria-modal="true"`, autofocus поля и Escape. Однако обработчик
клавиатуры не удерживает Tab/Shift+Tab внутри окна, фон не делается inert, ссылка на
инициатор поиска и возврат фокуса при его закрытии отсутствуют. Единственный явный
`menuButton.current?.focus()` относится к мобильному drawer, не к поиску.

Пользователь клавиатуры может перейти к перекрытому интерфейсу; экранный диктор получает
обещание модального поведения, которое код не обеспечивает. Предметы проверки: WCAG
2.4.3/4.1.2 и шаблон modal dialog APG. Существующая обработка стрелок/Enter в результатах
не заменяет удержание Tab. Следующий шаг: модальный primitive с initial focus, изоляцией
фона, удержанием и возвратом фокуса; отдельно определить фокус после перехода в раздел.
Регрессия: открыть кнопкой и Ctrl/Meta+K, обойти всё окно Tab/Shift+Tab, закрыть Escape
и щелчком снаружи, проверить фокус и повторное открытие. Браузерный сценарий пока NOT_RUN.

### A11Y-03, P2 — вкладки входа/регистрации имеют неполную семантику

Источник: [main.tsx кабинета](../apps/user-cabinet/src/main.tsx), `.auth-switch`.
Есть `tablist`, `tab`, `aria-selected` и обычные кнопки. Нет обработки стрелок для вкладок,
связи `aria-controls`/`tabpanel` и управления tabIndex выбранного элемента. Tab и Enter
позволяют нажать каждую кнопку, поэтому это не объявляется полной недоступностью входа.
Пользователь слышит роль вкладок, но получает неполное ожидаемое поведение (WCAG
1.3.1/4.1.2, шаблон tabs APG). Следующий шаг: реализовать цельный tabs-pattern либо
использовать обычный переключатель кнопками без ложного обещания вкладок. Проверить
ArrowLeft/Right, Home/End, порядок Tab и сохранение введённых данных.

### A11Y-04, P2 — неизвестное значение Meter объявляется измерением без значения

Источник: [ui.tsx кабинета](../apps/user-cabinet/src/ui.tsx), `Meter`.
При `value === null` остаются `role="meter"`, min/max и имя, но `aria-valuenow` отсутствует;
неопределённость представлена только штриховкой и прозрачностью. Точное объявление
конкретным диктором здесь не воспроизводилось. Следующий шаг: представить отсутствие
данных явно текстом/доступным именем, отделить неопределённое состояние от числового
измерения и проверить ноль, null, границы и восстановление значения (WCAG 4.1.2).

## Что уже есть и что существующие тесты действительно проверяют

| Механизм | Источник | Предел доказательства |
| --- | --- | --- |
| Фокус клавиатуры | CSS кабинета `:focus-visible`, theme.css админки | Правило есть; реальная видимость/перекрытие всех контролов не проверены |
| Уменьшение движения | `prefers-reduced-motion` в CSS обеих поверхностей | Отключение анимации/переходов есть; сохранение всех индикаторов состояния не проверено |
| Подписи/состояния | [Button](../apps/lucy-admin/web/src/components/ui/button.tsx), [LoadState/SuccessNote](../apps/lucy-admin/web/src/components/ui/state.tsx) | Есть disabled/aria-busy, alert/status; это не доказательство покрытия всех форм |
| Текст вместе с цветом | `StatusBadge` в ui.tsx кабинета; статусные компоненты админки | Декоративные точки скрыты; не все места вызова просмотрены |
| Переключатель радио | `Segmented` в ui.tsx кабинета | Есть roving tabIndex и стрелки; вызовы с пустыми/невалидными options отдельно не проверены |
| Язык документа | i18n.tsx обеих поверхностей | При смене языка обновляется `document.documentElement.lang`; статический lang=ru не записан как ложный дефект |
| Контекстные подсказки и навигация | [remna-design.spec.ts](../apps/lucy-admin/web/e2e/remna-design.spec.ts) | Проверяет aria-description, мобильное меню, Escape/возврат фокуса drawer, радио стрелками; не focus trap поиска |
| Кабинет/Mini App | [cabinet-design.spec.ts](../apps/lucy-admin/web/e2e/cabinet-design.spec.ts) | Проверяет части навигации/темы/ширины; не полный аудит screen reader |

CSS `.skip-link` в старом style.css сам по себе не доказывает наличие ссылки обхода
меню в DOM. Наличие landmarks тоже нужно учитывать: отсутствие именно skip-link
не объявляется автоматически нарушением. Размер `.icon-btn` 40px не записан как
автоматический отказ AA: критерий WCAG 2.5.8 имеет порог 24 CSS px и исключения;
проектная цель 44px/нативные рекомендации требуют отдельной оценки.

## План полной проверки и критерии закрытия

1. Веб: начать с входа, навигации, поиска, тарифа/оплаты, восстановления учётной записи,
   поддержки и опасной административной операции. Для каждой поверхности сохранить SHA,
   сборку, браузер/ОС, язык, тему, viewport и применённую вспомогательную технологию.
2. Выполнить существующие Playwright E2E через команду из [CI](../.github/workflows/ci.yml),
   затем добавить профильные проверки focus trap/restore, семантики вкладок, доступных
   имён, live regions и вычисленного контраста. axe-скан — дополнение, не замена ручного обхода.
3. Проверить клавиатуру без мыши: Tab/Shift+Tab, Enter/Space, стрелки, Escape; доступность
   закрытых drawer, логичный фокус после маршрута/ошибки, отсутствие перекрытого фокуса.
4. Проверить 320/390/768/1440 CSS px, zoom 200% и reflow 400%, длинные RU/EN/UK строки,
   обе темы, reduced motion, режим повышенной контрастности, пустые/ошибочные/disabled-состояния.
   Для touch targets измерить итоговые области и расстояния, а не только иконку.
5. Screen reader: NVDA с поддерживаемым браузером и VoiceOver/Safari; отдельно Telegram
   WebView. Проверить имена, роли, заголовки, порядок чтения, валидацию и объявления результата.
6. Android: TalkBack, Accessibility Scanner, максимальный системный размер текста и
   масштаб клиента; подключение/ошибка VPN, импорт, PIN/биометрия и возврат после блокировки.
   iOS: VoiceOver, Dynamic Type, безопасные области, клавиатура. Нужны реальные устройства;
   успешная сборка/эмуляторный функциональный тест не заменяют эти проверки.
7. Для каждой A11Y-находки записать исправляющий commit и свежую регрессию. Закрыть
   REQ-UI-0007 только после проверки всех перечисленных в нём направлений во всех продуктах;
   выпуск этого отчёта закрывает только документальный REQ-DOC-0034.

Результаты axe, ручного screen-reader прохода, мобильных замеров и новых E2E здесь
отсутствуют и должны оставаться NOT_RUN. Приоритет следующего изменения: A11Y-01,
затем A11Y-02, затем A11Y-03/04; после исправлений выполнить общий визуальный проход.

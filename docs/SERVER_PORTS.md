# Порты серверов

Задача владельца от 2026-11-13: «Все необходимые порты открываются автоматически при установке, и порты можно открыть
через панель администратора».

## Что делает магазин сам

При установке и при включении модулей магазин открывает нужные порты **во всех брандмауэрах сервера**, какие найдёт:

| Брандмауэр | Как открывается | Переживает перезагрузку |
|---|---|---|
| ufw | `ufw allow 443/tcp` | да, сам ufw |
| firewalld | `firewall-cmd --permanent --add-port` | да, сам firewalld |
| iptables с закрывающей цепочкой INPUT | правило ACCEPT с пометкой `corgi-ports` | да: служба `corgi-ports` возвращает правила при загрузке |
| nftables с цепочкой input «policy drop» | правило accept с пометкой `corgi-ports` | да: та же служба |

Если брандмауэра на сервере нет, порты и так открыты на самом сервере.

Магазин **никогда не включает брандмауэр** сам и **никогда не закрывает порт SSH**.

### Какие порты нужны

| Что стоит на сервере | Порты |
|---|---|
| Панель Remnawave, страница подписки (Caddy) | TCP 80, TCP 443 |
| Нода (VLESS + REALITY) | TCP 443 |
| Сайт SelfSteal на ноде | TCP 80 |
| Транспорт xHTTP | TCP 4443 |
| Транспорт gRPC | TCP 8443 |
| Hysteria2 | UDP 443 |
| VLESS + TCP + TLS | TCP 2053 |
| VLESS через Cloudflare CDN | TCP 2083 |
| MTProto, Psiphon, MASQUE | порт, выбранный при включении |
| Порт ноды для панели | только для адреса панели — у него своё правило, всем он не открывается |

Шаг «открыть порты» виден в плане установки. Если установка откатывается, магазин закрывает только те порты, которые
открыл в этой установке.

## Порты вручную

Панель администратора → «Установка» → блок «Порты сервера».

1. Выберите сервер и нажмите «Проверить порты». Видно, какой брандмауэр стоит, какие порты нужны установкам магазина,
   открыты ли они, и какая программа слушает каждый порт.
2. «Открыть все нужные» — открывает всё, что нужно установкам магазина на этом сервере.
3. «Открыть другой порт» — любой порт TCP или UDP.
4. «Закрыть» есть только у портов, которые открыл магазин. Порт SSH закрыть нельзя.
5. «Проверить снаружи» — магазин пробует подключиться к каждому TCP-порту со своего сервера.

## Брандмауэр хостинга

У многих хостингов есть свой брандмауэр в панели хостинга — например, группа безопасности. Он стоит вне сервера,
и магазин его не видит и не меняет.

Признак: в таблице «брандмауэр: открыт», а «снаружи: не доходит». Тогда откройте порт в панели хостинга.

UDP-порты (Hysteria2) снаружи так не проверить.

## Чем проверено

- `scripts/ci/ports-check.sh` в каждом запуске CI: настоящие iptables и nftables в сетевых пространствах с веб-сервером
  за брандмауэром. Порт открывается и становится доступен; после «перезагрузки» правила возвращаются; порт закрывается;
  порт SSH закрыть нельзя; чужие правила сервера не трогаются.
- `tests/test_rw_ports.py` — какие порты нужны, разбор проверки, шаг установки и его откат.
- `apps/lucy-admin/web/e2e/server-ports.spec.ts` — блок в панели.

ufw и firewalld в CI не проверяются: их нельзя включить на машине CI без риска оборвать её сеть. Команды для них —
стандартные команды этих программ.

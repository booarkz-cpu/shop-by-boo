# Автообновление: безопасность

Дистрибутив `v28.56.0`, runtime/API `21.5.1`. Описание механизма: [AUTO_UPDATE.md](AUTO_UPDATE.md).

Автообновление — это удалённое выполнение кода от root на production-сервере. Здесь зафиксировано,
какие именно меры реализованы в коде, а какие остаются ответственностью оператора.

## 1. Модель угроз

| Угроза | Что делает механизм | Остаточный риск |
| --- | --- | --- |
| Подмена артефакта в релизе | SHA-256 из `.sha256` и из манифеста, сверка с фактическим хешем | Компрометация GitHub-аккаунта владельца репозитория |
| Подмена тега/версии | Строгий `^v\d+\.\d+\.\d+$`, `draft`/`prerelease` отклоняются | — |
| Подмена коммита | `manifest.commit == tag_commit(tag)` | — |
| Загрузка с чужого URL | `browser_download_url` обязан начинаться с `https://github.com/<repo>/releases/download/<tag>/` | — |
| Панель как канал RCE | Панель пишет только `enabled`, `time`, `check_now`; формат валидируется на обеих сторонах | Компрометация админской сессии |
| Подделка запроса на обновление | Требуется право `settings.runtime.write` + запись в аудит `auto_update.run_requested` | — |
| Повторный/параллельный запуск | `409` при `running` или `pending_run`; `flock` в `scripts/backup.sh` | — |
| Утечка секретов в снимок | `tar` исключает `.env`, `.env.*`, `*/.env`, `*/node_modules`, `.git`, `.rollback`, `.control` | — |
| Утечка секретов в лог | Журнал ограничен `LOG_LINES = 40`; значения `.env` не печатаются | Сторонние скрипты внутри сборки |
| Откат при сбое | `trap rollback ERR`, `rollback.sh` требует архив **и** дамп БД | Потеря изменений между снимком и сбоем |
| Опасная миграция | Миграции выполняются после снимка и дампа; при ошибке — откат | Необратимые миграции не блокируются автоматически (см. §5) |

## 2. Разделение полномочий

- **Панель (backend, непривилегированный процесс)** не может выполнить команду на сервере. Она
  пишет JSON-файл в `.control`. Это ключевое архитектурное ограничение: даже полный захват
  админской сессии не даёт прямого RCE — атакующий может лишь запросить обновление на
  официальный, проверенный по SHA-256 релиз.
- **Агент (root, systemd)** читает только три поля и проверяет формат. Метка `check_now`
  генерируется сервером и проверяется на `^[A-Za-z0-9:._-]{1,64}$`, поэтому подстановка в шелл
  невозможна — агент не интерполирует её в команды.
- **GitHub** не имеет доступа к серверу. Workflow не выполняют `docker compose` на хосте.

## 3. Права и аудит

| Действие | Право | Запись в аудит |
| --- | --- | --- |
| `GET /api/admin/auto-update` | `ops.releases` | нет (чтение) |
| `PUT /api/admin/auto-update` | `settings.runtime.write` | `auto_update.settings` |
| `POST /api/admin/auto-update/run` | `settings.runtime.write` | `auto_update.run_requested` |

В аудит попадают `enabled`, `time` и метка запроса — не секреты.

## 4. Требования к хосту

- Юниты пишутся в `/etc/systemd/system` только от root: `[[ $EUID -eq 0 ]]` в `scripts/auto-update.sh`.
- Каталог `.control` должен быть доступен backend-контейнеру на запись. В контейнере это
  `/data/control`; UID backend — `10001` (`backend/Dockerfile`, константа `BACKEND_UID`).
- Файлы состояния пишутся атомарно: временный файл + `os.replace`, режим `0o640`.
- Рекомендуется отдельный непривилегированный пользователь для чтения журналов; обновление
  запускается только от root.

## 5. Что механизм НЕ делает сам — зона ответственности оператора

Честный список ограничений:

1. **Необратимые миграции не блокируются автоматически.** Проверка «опасная миграция» выполняется
   человеком при подготовке релиза. Автоматического анализа `downgrade`/`DROP COLUMN` нет.
2. **Нет автоматической проверки CVE в зависимостях** перед установкой. Dependabot и
   `scripts/security-scan.sh` работают отдельно, вне цикла обновления.
3. **Компрометация аккаунта владельца репозитория** не обнаруживается: подписанный релиз от
   захваченного аккаунта пройдёт все проверки. Защита — 2FA, branch protection, ограничение
   числа администраторов.
4. **Автоустановка включена по умолчанию** (`DEFAULT = {"enabled": true, "time": "03:00"}`).
   Если политика требует ручного подтверждения, отключите её:
   `sudo bash scripts/auto-update.sh disable` или переключателем в панели.
5. **Секреты GitHub не ротируются** этим механизмом. Для ротации — `scripts/rotate-secrets.sh`.

## 6. Требования к секретам в CI

Значения секретов не должны попадать в логи, артефакты и релизы. В workflow уже используются
(имена приведены без значений): `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH`,
`DEPLOY_PORT`, `HETZNER_API_TOKEN`, `WEBHOOK_BASE_URL`, `LOAD_TARGET_URL`, а также ключи
платёжных провайдеров и мобильной подписи. Полный перечень и порядок проверки:
[TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md](TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md).

Правила:

- не выводить `env` целиком в лог шага;
- не передавать секреты в `run:` через `echo`;
- для артефактов проверять, что в них нет `.env` (снимки уже это исключают);
- `secrets.GITHUB_TOKEN` использовать только с минимальными `permissions:`.

## 7. Защита от повторного запуска

- `POST /run`: `409`, если `status.running` или `pending_run`.
- Агент фиксирует `handled_check_now`, поэтому одна метка обрабатывается один раз.
- При неудачном релизе версия попадает в `/etc/vpn-shop/auto-update.failed` и **ночью повторно не
  ставится**; повтор возможен только ручным «Обновить сейчас».
- После сбоя включается `recovery_mode` — автообновление остановлено до ручной проверки.

## 8. Проверка перед включением на production

```bash
# 1. Убедиться, что релиз на GitHub — стабильный и с полным набором ассетов
curl -s https://api.github.com/repos/booarkz-cpu/shop-by-boo/releases/latest | jq '.tag_name,.draft,.prerelease'

# 2. Убедиться, что .control доступен backend-у
sudo -u '#10001' test -w /opt/vpn-shop/.control && echo writable

# 3. Сделать резервную копию до первого обновления
sudo BACKUP_BUNDLE_PASSWORD='<пароль>' bash scripts/backup.sh

# 4. Проверить состояние
sudo bash scripts/auto-update.sh status
```

Не включайте автообновление на сервере, для которого не проверено восстановление из
`scripts/backup.sh` — см. [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).

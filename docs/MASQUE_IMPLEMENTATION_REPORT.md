# MASQUE: отчёт о реализации

Дата проверки: 2026-11-12. Раздел мастер-промпта: REQ-MASQUE-0001…0012.

**Итог одной строкой.** MASQUE в Xray-core существует и документирован. Панель Remnawave его не знает, поэтому
с v28.129.0 магазин ведёт протокол сам: ставит на ноду за сайтом SelfSteal, выдаёт доступ по подпискам и отдаёт
свою подписку. Как этим пользоваться — [MASQUE_PANEL.md](MASQUE_PANEL.md). Что проверено и что нет — ниже.

## 2. Как MASQUE устроен в Xray

- Это CONNECT-IP по RFC 9484: IP-пакеты идут внутри HTTP/3 (QUIC, UDP) или HTTP/2 (Extended CONNECT, TCP).
- Версию HTTP задаёт `alpn` в `tlsSettings`. Если на сервере указаны и `h3`, и `h2`, обе слушают один номер порта:
  HTTP/3 на UDP, HTTP/2 на TCP.
- Работает только с обычным TLS. **REALITY не поддерживается.** Mux на клиенте не поддерживается.
- Вход по HTTP Basic: логин (`email`) и пароль (`pass`). Без пользователей сервер отклоняет все туннели.
- Сервер выдаёт каждому туннелю адрес из `address`: не больше одного префикса IPv4 (до /30) и одного IPv6 (до /126).
  Когда адреса кончаются, сервер отвечает 503.
- MTU от 1280 до 65535, по умолчанию 1280. Начальный пакет QUIC — 1350 байт: при меньшем MTU пути HTTP/3 не соединится.
- В отличие от Hysteria и XHTTP H3, отпечаток QUIC браузера Chrome не имитируется.

## 3. Порты и соседство с другими протоколами (REQ-MASQUE-0005)

Нода магазина уже занимает: TCP 443 (VLESS + REALITY), UDP 443 (Hysteria2), TCP 4443 (XHTTP), TCP 8443 (gRPC),
TCP 2053 (VLESS + TLS), TCP 2083 (CDN), TCP 80 (сайт SelfSteal).

| Вариант | Можно ли | Почему |
|---|---|---|
| MASQUE HTTP/3 на UDP 443 | нет, если стоит Hysteria2 | один UDP-порт — один слушатель |
| MASQUE HTTP/2 на TCP 443 | нет | порт занят REALITY, а MASQUE с REALITY не работает |
| MASQUE на отдельном порту | да | по умолчанию выбран **2087** — свободен и на TCP, и на UDP |
| Общий 443 через обратный прокси по SNI | только для HTTP/2 | прокси должен разбирать TLS по SNI; для REALITY это ломает маскировку. Не делаем |

Сертификат — тот же, что у Hysteria2 и VLESS + TLS: его выпускает Caddy ноды для домена SelfSteal, таймер копирует
в `/opt/remnanode/hysteria`. Новый ACME-клиент не нужен.

Проверка конфликтов — `masque.port_conflicts`: она знает, какие протоколы занимают TCP, какие UDP, какие оба.

## 4. Управление через API Xray (REQ-MASQUE-0006)

Проверено по исходникам v26.11.9:

- `HandlerService`: `AddInbound`, `RemoveInbound`, `AlterInbound`, `ListInbounds`, `GetInboundUsers`,
  `GetInboundUsersCount` — есть.
- Сервер MASQUE реализует `AddUser` и `RemoveUser`. При удалении пользователя его туннели закрываются сразу
  (это прямо сказано в документации и покрыто тестом ядра `TestServerRemoveUserClosesTunnels`).
- `StatsService`: `GetStats`, `QueryStats`, `GetStatsOnline`, `GetUsersStats` — есть. Учёт трафика пользователя
  включается уровнем (`level`) в локальной политике.

То есть добавлять и убирать пользователей без перезапуска ядра можно. С v28.129.0 магазин так и делает: для MASQUE
на ноде стоит отдельный Xray, и магазин управляет его пользователями по SSH командами `xray api adu` и `rmu`
(§9). API наружу не открыт: он слушает только loopback ноды.

## 5. Подписка и клиенты (REQ-MASQUE-0007)

- Подписку Remnawave собирает сама, и в её генераторах (Xray JSON, sing-box, Mihomo, Clash) MASQUE нет.
  Поэтому у MASQUE своя подписка магазина (§9).
- Общего формата ссылки для сервера с логином и паролем нет. В v2rayNG `masque://` несёт ключи устройства WARP.
- Передать такой сервер клиенту можно только целым JSON-конфигом. `masque.outbound` собирает проверенный outbound.
- MASQUE не ломает остальные конфигурации: в профили и подписки Remnawave он не добавляется вовсе.
- Собственное приложение «Корги Люси» собирается на Xray (коммит ядра закреплён в `scripts/mobile/build-xray-aar.sh`).
  Поддержка MASQUE в нём на устройстве не проверялась.

## 6. Защита от зондирования (REQ-MASQUE-0009)

- Запрос без верного логина и пароля получает 401. Запрос на другой путь получает 404.
- У самого inbound MASQUE сайта-прикрытия нет: кто откроет его порт напрямую, увидит сервер, который отвечает 404
  на всё, кроме одного пути. Поэтому магазин не выставляет inbound наружу, а ставит перед ним сайт SelfSteal (§9).
- Маски FinalMask применяются: UDP-маски к HTTP/3, TCP-маски к HTTP/2.
- **Защита от DPI не гарантируется.** MASQUE выглядит как обычный HTTP/3, но сам факт длинного соединения с
  датаграммами к одному серверу заметен.

## 7. Другие движки (REQ-MASQUE-0010)

sing-box 1.15.0 добавляет `masque-server` и `masque-client` (HTTP/1.1, 2 и 3). На дату проверки это alpha-версия.
Менять движок ради MASQUE смысла нет: Xray его поддерживает, а панель и подписку магазин ведёт сам.

### Проверка на настоящем Xray

`bash scripts/masque-selfcheck.sh` скачивает официальный выпуск Xray, поднимает сервер и клиент MASQUE на одной
машине и забирает страницу через туннель. Запуск 2026-11-12 на runner GitHub (Ubuntu 24.04), Xray 26.11.9:

| Проверка | Результат |
|---|---|
| Xray принимает inbound сервера и outbound клиента (`xray run -test`) | да |
| Туннель по HTTP/3: адрес выдан, страница получена | да |
| Туннель по HTTP/2: адрес выдан, страница получена | да |
| Неверный пароль | отклонён: `invalid credentials` |

Что выяснилось по ходу и важно для настоящей ноды:

- Клиент Xray проверяет сертификат по встроенному списку центров, а не по системному. Самоподписанный сертификат
  он не примет; у ноды должен быть публичный сертификат — у нод магазина он есть.
- Outbound `freedom` на сервере по умолчанию не пускает к частным адресам. Пользователь туннеля не доберётся до
  внутренней сети ноды. Это защита ядра; отключать её не нужно.

Скрипт — для одноразовой машины: он добавляет строку в `/etc/hosts`. В общий CI он не включён, чтобы сборка не
зависела от скачивания Xray.

## 9. MASQUE за сайтом SelfSteal (v28.129.0)

Задача владельца от 2026-11-12: маскировка под собственный сайт SelfSteal, установка на ноды, своя подписка.

### Почему так

У inbound MASQUE в Xray нет fallback: любой другой путь получает голый 404, сайта нет. Чтобы посетитель порта
видел сайт, перед Xray нужен прокси, который отдаёт сайт и пропускает только туннель. Проверено на runner GitHub:

| Прокси перед Xray | Сайт на порту | Туннель HTTP/2 | Вывод |
|---|---|---|---|
| Caddy 2.11.9 | да | нет: «the server did not enable extended CONNECT» | не подходит |
| HAProxy 2.8 и 3.2 | да | да | выбран |

HTTP/3 спрятать нельзя: датаграммы QUIC через такой прокси не проходят. Поэтому за сайтом MASQUE работает
по HTTP/2 поверх TCP.

### Что стоит на ноде

Каталог `/opt/corgi-masque`, два контейнера в сети хоста, образы закреплены по хешу:

- `corgi-masque-xray` — официальный образ Xray 26.11.9. Inbound MASQUE слушает только `127.0.0.1:12087`.
  API — unix-сокет `/opt/corgi-masque/run/api.sock` (с v28.131.0): порт на loopback был бы доступен через VPN самой
  ноды при старом ядре панели, а пароля у API нет. Inbound перевести на сокет нельзя: транспорт MASQUE этого не умеет.
- `corgi-masque-haproxy` — HAProxy 3.2 на внешнем TCP-порту (по умолчанию 2087) с сертификатом домена SelfSteal.
  Запрос, путь которого начинается с секретного сегмента ноды, уходит в Xray. Всё остальное — на тот же unix-сокет
  сайта SelfSteal, куда REALITY отдаёт чужие соединения, с PROXY protocol: сайт видит адрес посетителя.

Сертификат копируется из Caddy ноды раз в сутки (`corgi-masque-cert.timer`). Порт открывается в ufw, если он включён.

### Что видит посторонний

Проверено в CI: главная страница сайта; его же страница 404 на неизвестном адресе и на неверном «секретном» пути;
заголовки сайта (HSTS, без `Server`); HTTP/2. Обычный GET на верный секретный путь без туннеля тоже получает 404.
Секретный сегмент пути свой у каждой ноды и получается из секрета магазина.

Ограничения маскировки, о которых нужно знать:

- Порт не 443: 443 занят REALITY. Сайт на нестандартном порту сам по себе необычен.
- Если сайт SelfSteal остановлен, HAProxy отвечает собственной страницей 503.
- Неверный логин на верном пути получает 401 от Xray — но путь знает только тот, у кого есть подписка.
- Длинное соединение HTTP/2 с большим объёмом данных заметно при анализе трафика. **Защита от DPI не гарантируется.**

### Защиты от обнаружения (v28.130.0)

Что видит и что может сделать тот, кто ищет прокси, и чем это закрыто. Всё проверяется в `scripts/ci/masque-check.sh`.

| Приём обнаружения | Защита | Включение |
|---|---|---|
| Открыть порт браузером или сканером | Сайт SelfSteal, его 404 и заголовки | всегда |
| Запросить известный путь MASQUE (`/.well-known/masque/…`) | Пути там нет: у каждой ноды свой секретный сегмент | всегда |
| Подтвердить найденный путь обычным запросом | Обычный запрос на секретный путь получает 404 сайта; в Xray уходит только extended CONNECT | всегда |
| Отправить непонятный запрос и узнать прокси по странице ошибки | Ответы 400 как у сервера сайта; остальные служебные ответы — закрытие соединения | всегда |
| Обойти адреса без имени домена и собрать сертификаты | Строгий SNI: сертификат без имени не выдаётся | по выбору |
| Сравнить версии TLS и шифры с портом 443 | Те же версии, наборы шифров и кривые, что у Caddy сайта | по выбору |
| Подбирать пароли или пути | После порога отказов адрес получает только сайт, даже с верным паролем; блокировку снаружи не видно | по выбору |

Как устроена блокировка. HAProxy считает на адрес два события: ответ 401 от Xray и туннельный запрос на чужой путь.
Когда счётчик достигает порога, запросы этого адреса перестают попадать в Xray. Запись живёт срок блокировки после
последнего запроса адреса.

Оговорки, которые нужно знать:

- Счётчик считает отказы, а клиент повторяет попытку сам: одна неудачная попытка даёт несколько отказов.
- Адрес может быть общим у многих абонентов мобильного оператора. Клиент с истёкшей подпиской способен на время
  закрыть MASQUE соседям по адресу. Поэтому порог по умолчанию 30, срок 10 минут, и защиту можно выключить.
- Отпечаток TLS полностью совпасть не может: порт MASQUE обслуживает HAProxy (OpenSSL), сайт — Caddy (Go).
  Совпадают версии, шифры и кривые; порядок расширений и поведение сессий — нет.
- Маски FinalMask за прокси неприменимы: TLS завершается на HAProxy.

«Проверить маскировку» в панели сравнивает ответы порта MASQUE и порта 443 снаружи — с сервера магазина.

### Пользователи и подписка

- Доступ есть у подписки, которая оплачена, не приостановлена и не заморожена, если её тариф выбран в настройках
  (ни один не выбран — у всех).
- Логин и пароль нигде не хранятся: они вычисляются из секрета магазина и номера подписки.
- Раз в минуту магазин сверяет список. На ноду он идёт по SSH, только когда список изменился, и не реже раза в
  30 минут. Пользователи добавляются и убираются через API Xray (`xray api adu`, `rmu`) без перезапуска; туннели
  убранного пользователя закрываются сразу.
- Подписка — `GET /api/masque/sub/<токен>`: массив готовых конфигураций Xray, по одной на ноду. Токен подписан
  секретом магазина; токен одной подписки не открывает другую.
- Ссылку можно перевыпустить (покупатель — в кабинете, администратор — в панели). Счётчик перевыпусков входит
  в то, из чего вычисляются логин, пароль и токен, поэтому старые перестают действовать сразу.

### Трафик и лимиты (v28.131.0)

- Скрипт ноды `traffic` читает счётчики Xray по логинам и обнуляет их. Магазин вызывает его раз в 5 минут и копит
  трафик по подпискам в настройке `masque.traffic`.
- При включённой настройке «засчитывать в лимит» для подписок с лимитом магазин спрашивает у панели, сколько она
  насчитала, и складывает. Сумма достигла лимита — подписка выпадает из списка MASQUE при следующей сверке.
  Новый период панели (`lastTrafficResetAt`) обнуляет счётчик; без данных панели — начало календарного месяца.
- Число туннелей: HAProxy ведёт таблицу открытых туннелей по логину (`http_auth_user`) и сверяет с картой лимитов.
  Карта меняется через управляющий сокет HAProxy (`add map`, `set map`, `del map`), без перезагрузки: перезагрузка
  оставляла бы старый процесс жить, пока живы его туннели, и обнуляла бы счётчики.

### Чем проверено

`scripts/ci/masque-check.sh` идёт в каждом запуске CI на runner GitHub: настоящий Caddy SelfSteal ноды (как в
установщике, с внутренним сертификатом), закреплённые образы Xray и HAProxy, настоящий клиент Xray 26.11.9.
Проверяются: сайт на порту, туннель, отказ при неверном пароле и неизвестном пользователе, закрытый доступ к частным
адресам ноды, добавление и удаление пользователя без перезапуска, трафик в `status`, повторная установка, удаление.

## 10. Что не сделано и почему

| Что | Причина |
|---|---|
| Мгновенное отключение по лимиту | Трафик читается раз в 5 минут, панель опрашивается не чаще раза в 15 минут на подписку |
| Общий на все ноды лимит туннелей | HAProxy считает открытые туннели на своей ноде |
| Ссылка `masque://` | Общего формата для сервера с логином и паролем нет |
| HTTP/3 | Нельзя спрятать за сайтом |
| IPv6 внутри туннеля | У многих нод нет маршрута IPv6; клиенту выдаётся только IPv4 |
| Проверка на VPS с настоящим доменом и на телефоне | Нет VPS и устройства; проверено на одной машине CI |
| Проверка MASQUE в клиентах на телефоне | Клиент «Корги Люси» с 1.9.4 понимает ссылку `masque` (ядро Xray 26.11.9); Happ и INCY — по таблице в `MASQUE_PANEL.md`; на устройстве не проверялось |

Сделано после первой версии отчёта: ссылка в боте и в приложениях Android/iOS (v28.131.0, приложения 3.8.0), порт MASQUE
открывается и закрывается в брандмауэре ноды сам (v28.135.0), сверка нод MASQUE в «Сверке с панелью» (v28.137.0): раз в
6 часов магазин спрашивает каждую ноду, работает ли стек, какой порт и сколько пользователей, и пишет о новых расхождениях.

## 11. Если MASQUE появится в Remnawave

Проверять поиском слова `masque` в коде `remnawave/backend`. Тогда можно будет добавить транспорт `masque` в
`rw_plan.TRANSPORTS`, а учёт трафика и устройств отдать панели.

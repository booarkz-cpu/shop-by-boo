# MASQUE: отчёт о реализации

Дата проверки: 2026-11-12. Раздел мастер-промпта: REQ-MASQUE-0001…0012.

**Итог одной строкой.** MASQUE в Xray-core существует и документирован, но включить его в магазине сейчас нельзя:
панель Remnawave не умеет выдавать пользователей и подписку для этого протокола. Сделано то, что можно проверить
без неё: сверка версий ядра на нодах, проверенный inbound по официальной схеме, проверка конфликтов портов и
страница готовности в админ-панели. Переключателя «включить MASQUE» нет — он был бы фиктивным.

## 1. Что подтверждено по официальным источникам

Источники читались напрямую из репозиториев (git clone на дату проверки), а не из пересказов.

| Что | Источник | Результат |
|---|---|---|
| Версия Xray-core v26.10.10 | теги `XTLS/Xray-core` | **Такого тега нет.** Соседние: v26.9.30 и v26.10.21 |
| Первый тег с MASQUE | `proxy/masque`, `transport/internet/masque` в тегах | **v26.9.30** (коммит `b26a91d`); в v26.9.9 каталога нет |
| Версия, которую требует магазин | первый тег не старше «v26.10.10+» | **v26.10.21** (коммит `1b1647c`) |
| Последний тег на дату проверки | теги `XTLS/Xray-core` | v26.11.9 (коммит `676eaf6`) |
| Документация inbound, outbound, транспорта | `XTLS/Xray-docs-next`, коммит `44ed2e8` | есть на трёх языках |

## 2. Как MASQUE устроен в Xray

- Это CONNECT-IP по RFC 9484: IP-пакеты идут внутри HTTP/3 (QUIC, UDP) или HTTP/2 (Extended CONNECT, TCP).
- Версию HTTP задаёт `alpn` в `tlsSettings`. Если на сервере указаны и `h3`, и `h2`, обе слушают один номер порта:
  HTTP/3 на UDP, HTTP/2 на TCP.
- Работает только с обычным TLS. **REALITY не поддерживается.** Mux на клиенте не поддерживается.
- Вход по HTTP Basic: логин (`email`) и пароль (`pass`). Без пользователей сервер отклоняет все туннели.
- Сервер выдаёт каждому туннелю адрес из `address`: не больше одного префикса IPv4 (до /30) и одного IPv6 (до /126).
  Когда адреса кончаются, сервер отвечает 503.
- MTU от 1280 до 65535, по умолчанию 1280. Начальный пакет QUIC — 1350 байт: при меньшем MTU пути HTTP/3 не соединится.
- В отличие от Hysteria и XHTTP H3, отпечаток QUIC браузера Chrome не имитируется.

## 3. Порты и соседство с другими протоколами (REQ-MASQUE-0005)

Нода магазина уже занимает: TCP 443 (VLESS + REALITY), UDP 443 (Hysteria2), TCP 4443 (XHTTP), TCP 8443 (gRPC),
TCP 2053 (VLESS + TLS), TCP 2083 (CDN), TCP 80 (сайт SelfSteal).

| Вариант | Можно ли | Почему |
|---|---|---|
| MASQUE HTTP/3 на UDP 443 | нет, если стоит Hysteria2 | один UDP-порт — один слушатель |
| MASQUE HTTP/2 на TCP 443 | нет | порт занят REALITY, а MASQUE с REALITY не работает |
| MASQUE на отдельном порту | да | по умолчанию выбран **2087** — свободен и на TCP, и на UDP |
| Общий 443 через обратный прокси по SNI | только для HTTP/2 | прокси должен разбирать TLS по SNI; для REALITY это ломает маскировку. Не делаем |

Сертификат — тот же, что у Hysteria2 и VLESS + TLS: его выпускает Caddy ноды для домена SelfSteal, таймер копирует
в `/opt/remnanode/hysteria`. Новый ACME-клиент не нужен.

Проверка конфликтов — `masque.port_conflicts`: она знает, какие протоколы занимают TCP, какие UDP, какие оба.

## 4. Управление через API Xray (REQ-MASQUE-0006)

Проверено по исходникам v26.11.9:

- `HandlerService`: `AddInbound`, `RemoveInbound`, `AlterInbound`, `ListInbounds`, `GetInboundUsers`,
  `GetInboundUsersCount` — есть.
- Сервер MASQUE реализует `AddUser` и `RemoveUser`. При удалении пользователя его туннели закрываются сразу
  (это прямо сказано в документации и покрыто тестом ядра `TestServerRemoveUserClosesTunnels`).
- `StatsService`: `GetStats`, `QueryStats`, `GetStatsOnline`, `GetUsersStats` — есть. Учёт трафика пользователя
  включается уровнем (`level`) в локальной политике.

То есть добавлять и убирать пользователей без перезапуска ядра можно. **Не реализовано:** магазин не ходит в API
Xray напрямую — нодами управляет панель Remnawave, а она MASQUE не знает. Своя прямая связка «магазин → gRPC Xray
на ноде» означала бы второй, параллельный панели, канал управления пользователями и лимитами.

## 5. Подписка и клиенты (REQ-MASQUE-0007)

- Подписку собирает Remnawave. В её генераторах (Xray JSON, sing-box, Mihomo, Clash) MASQUE нет.
- Общего формата ссылки для сервера с логином и паролем нет. В v2rayNG `masque://` несёт ключи устройства WARP.
- Передать такой сервер клиенту можно только целым JSON-конфигом. `masque.outbound` собирает проверенный outbound.
- Неподдерживаемый MASQUE не ломает остальные конфигурации: в профили и подписки он не добавляется вовсе.
- Собственное приложение «Корги Люси» собирается на Xray (коммит ядра закреплён в `scripts/mobile/build-xray-aar.sh`).
  Поддержка MASQUE в нём на устройстве не проверялась.

## 6. Защита от зондирования (REQ-MASQUE-0009)

- Запрос без верного логина и пароля получает 401. Запрос на другой путь получает 404.
- Настоящего сайта-прикрытия у inbound MASQUE нет: любой, кто откроет порт, увидит сервер HTTP/3 или HTTP/2,
  который отвечает 404 на всё, кроме одного пути. Это отличается от REALITY, где посторонний видит чужой сайт.
- Маски FinalMask применяются: UDP-маски к HTTP/3, TCP-маски к HTTP/2.
- **Защита от DPI не гарантируется.** MASQUE выглядит как обычный HTTP/3, но сам факт длинного соединения с
  датаграммами к одному серверу заметен.

## 7. Другие движки (REQ-MASQUE-0010)

sing-box 1.15.0 добавляет `masque-server` и `masque-client` (HTTP/1.1, 2 и 3). На дату проверки это alpha-версия.
Менять движок нод ради MASQUE смысла нет: препятствие не в ядре, а в панели и формате подписки.

## 8. Что сделано в коде

| Файл | Что делает |
|---|---|
| `backend/app/masque.py` | версия ядра ноды против требуемой; inbound и outbound по официальной схеме с проверкой полей; конфликты портов; `GET /api/admin/masque` — только чтение |
| `admin/src/masque.tsx` | блок «MASQUE (CONNECT-IP)» на вкладке «Смена протокола»: ноды, причины, проверка порта, пример inbound |
| `scripts/masque-selfcheck.sh` | проверка на настоящем Xray (см. ниже) |
| `tests/test_masque.py` | версии, схема, отказы, порты рядом со всеми транспортами магазина |
| `admin/e2e/masque.spec.ts` | страница в браузере; отдельно проверено, что кнопки «включить» нет |

### Проверка на настоящем Xray

`bash scripts/masque-selfcheck.sh` скачивает официальный выпуск Xray, поднимает сервер и клиент MASQUE на одной
машине и забирает страницу через туннель. Запуск 2026-11-12 на runner GitHub (Ubuntu 24.04), Xray 26.11.9:

| Проверка | Результат |
|---|---|
| Xray принимает inbound сервера и outbound клиента (`xray run -test`) | да |
| Туннель по HTTP/3: адрес выдан, страница получена | да |
| Туннель по HTTP/2: адрес выдан, страница получена | да |
| Неверный пароль | отклонён: `invalid credentials` |

Что выяснилось по ходу и важно для настоящей ноды:

- Клиент Xray проверяет сертификат по встроенному списку центров, а не по системному. Самоподписанный сертификат
  он не примет; у ноды должен быть публичный сертификат — у нод магазина он есть.
- Outbound `freedom` на сервере по умолчанию не пускает к частным адресам. Пользователь туннеля не доберётся до
  внутренней сети ноды. Это защита ядра; отключать её не нужно.

Скрипт — для одноразовой машины: он добавляет строку в `/etc/hosts`. В общий CI он не включён, чтобы сборка не
зависела от скачивания Xray.

## 9. Что не сделано и почему

| Требование | Состояние | Причина |
|---|---|---|
| Zero-Touch установка MASQUE на ноду | нет | ставить inbound без пользователей бессмысленно: ядро отклонит все туннели |
| Выдача пользователей и лимитов | нет | панель Remnawave не поддерживает протокол |
| MASQUE в подписке | нет | нет в генераторах панели и нет общего формата ссылки |
| Переключатели MASQUE в панели | нет | переключатель без работающей выдачи был бы фиктивным |
| Проверка на VPS с настоящим доменом и на телефоне | нет | нет VPS и устройства; проверено только на одной машине |

## 10. Когда вернуться

1. В `remnawave/backend` появляется MASQUE (пользователи в inbound и подписка) — тогда добавить транспорт `masque`
   в `rw_plan.TRANSPORTS`, а inbound брать из `masque.inbound`.
2. Либо владелец решает вести MASQUE мимо панели, напрямую через API Xray. Это отдельный проект: учёт трафика,
   лимиты и отключение по сроку придётся дублировать.

Страница готовности покажет, на скольких нодах ядро уже подходит.

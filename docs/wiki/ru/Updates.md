# Обновление магазина

## Ручное обновление

Запланируйте окно обслуживания. В стандартной установке выполните команды из `/opt/vpn-shop` с правами root. Если в вашей установке другой каталог, укажите его в `APP_DIR` и используйте его вместо пути ниже.

Перед обновлением создайте зашифрованную копию. Скрипт запросит пароль и на время копирования приостановит работающие сервисы, которые записывают данные. Сохраните файл `.vpb`, контрольную сумму и пароль для восстановления. По умолчанию копии находятся в `/var/backups/vpn-shop`.

```bash
cd /opt/vpn-shop &&
  bash scripts/backup.sh &&
  RELEASE_TAG=v28.161.0 bash scripts/update-from-github.sh
```

Эта команда выбирает опубликованный `v28.161.0`. Для более нового стабильного выпуска укажите его точный тег. Без `RELEASE_TAG` скрипт ищет последний стабильный выпуск. Если установленная версия такая же или новее, обновление завершится без замены файлов.

## Что проверяет обновление

Загрузчик проверяет тег и SHA-256 архива, распаковывает его во временный каталог и сверяет версию. Если дистрибутив задаёт минимальную исходную версию, проверяется и она. Для `v28.161.0` версия дистрибутива отличается от версии API, поэтому загрузчик также сверяет манифест с архивом и коммитом тега.

После проверки архива `update.sh` создаёт снимок файлов и SQL-дамп базы магазина в `.rollback`, затем применяет обновление и запускает `doctor.sh`.

## Ночные обновления

Таймер systemd работает на сервере магазина. Время по умолчанию — 03:00 по Москве, со случайной задержкой до 15 минут. Параметр `Persistent=true` позволяет выполнить пропущенный запуск после включения сервера. Посмотреть расписание и результат последней попытки можно командой ниже.

```bash
cd /opt/vpn-shop && sudo bash scripts/auto-update.sh status
```

Чтобы включить или отключить таймер, используйте `install` или `disable` вместо `status`. Команда `run` проверяет наличие обновления и может сразу установить его.

## Если обновление прервалось

После начала замены файлов ошибка может привести к автоматическому откату. Проверьте журнал, состояние сервисов и наличие `.rollback/RECOVERY_MODE`. Ручной `scripts/rollback.sh` по умолчанию восстанавливает файлы из `.rollback/latest.tar.gz` и базу магазина из `.rollback/latest.sql`. Записи после создания дампа могут быть утрачены. Для восстановления обеих баз и секретов используйте полную зашифрованную копию.

Команды сверены с исходниками v28.161.0. Установку и восстановление на конкретном VPS следует подтверждать результатом проверки этого сервера.

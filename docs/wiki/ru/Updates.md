# Обновления

Магазин обновляется до опубликованных GitHub Releases. Есть ручной запуск и ночная автоматическая проверка.

## Архитектура

Отдельного сервера-планировщика нет. Планировщик — это **systemd на том же хосте**, где работает магазин.
GitHub служит только источником проверенных релизов и не имеет доступа к файловой системе сервера.

| Где | Что | Файл |
| --- | --- | --- |
| Хост (root, systemd) | ночной таймер и агент | `scripts/auto_update.py`, `scripts/auto-update.sh` |
| Хост | загрузка и проверка релиза (SHA-256, манифест) | `scripts/update-from-github.sh` |
| Backend | только пишет запрос и читает состояние | `backend/app/auto_update_api.py` |
| Панель | кнопки и статус | раздел «Обновления» |

Обмен идёт через два JSON-файла в `.control`: панель пишет запрос, агент пишет состояние. Агент принимает
ровно три поля (`enabled`, `time`, `check_now`) и проверяет их формат — панель не может выполнить на сервере
ничего другого.

## Расписание

По умолчанию **03:00 Europe/Moscow**, случайная задержка до 15 минут (`RandomizedDelaySec=900`),
`Persistent=true` — пропущенный запуск выполнится после включения хоста.

Изменить время можно в разделе «Обновления»: агент перепишет unit-файл таймера.

```bash
sudo bash scripts/auto-update.sh status     # состояние и расписание
sudo bash scripts/auto-update.sh install    # включить ночную проверку
sudo bash scripts/auto-update.sh disable    # выключить
```

## Что происходит при обновлении

1. Проверка источника — только стабильные релизы GitHub.
2. Получение метаданных версии и манифеста.
3. Проверка версии и канала.
4. Проверка совместимости и обязательной конфигурации.
5. Проверка миграций: необратимая миграция останавливает автоустановку.
6. Резервная копия базы и снимок файлов.
7. Загрузка артефакта и сверка SHA-256.
8. Распаковка, миграции, сборка.
9. Перезапуск сервисов.
10. Проверка `/health`, ключевых API, панели и базы.
11. Запись результата и уведомление администратору.

При провале любой критической проверки артефакт **не устанавливается**.

## Откат

При сбое после установки запускается проверенный откат к снимку, сделанному перед обновлением:

```bash
bash scripts/rollback.sh
```

Если безопасный откат невозможен, обновление останавливается, диагностика сохраняется, администратор
получает уведомление.

## Ручное обновление

```bash
bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.57.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

## Что видно в разделе «Обновления»

Текущая и доступная версия, источник и канал, дата последней проверки и последнего обновления, расписание,
состояние автообновления, история операций, результат проверки совместимости, статус резервной копии, статус
миграций, health checks и ссылка на GitHub Release.

Кнопки: «Проверить обновления», «Обновить сейчас», «Включить автообновление», «Отключить автообновление»,
«Посмотреть журнал», «Проверить состояние системы», «Восстановить предыдущую версию».

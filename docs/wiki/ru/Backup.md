# Резервные копии

## Что копировать

| Что | Почему |
| --- | --- |
| база магазина | клиенты, подписки, платежи, заказы |
| база Support Pro | обращения и переписка |
| `.env` | секреты и настройки, без него установка не восстановится |
| загруженные файлы (`MEDIA_DIR`) | аватары, баннеры, вложения |

## Создать полную копию

В стандартной установке запустите команду в окно обслуживания. Введите пароль длиной от 12 до 1024 символов и сохраните его отдельно.

```bash
cd /opt/vpn-shop && sudo bash scripts/backup.sh
```

Скрипт приостанавливает работающие сервисы, которые записывают данные, пока делает дампы и копирует файлы. По умолчанию в `/var/backups/vpn-shop` появятся `shop-*.vpb` и его `.sha256`. Для другого каталога задайте `BACKUP_DEST`. Храните оба файла вне сервера и сохраняйте предыдущую проверенную копию до проверки следующей. Копии `.enc` из админ-панели восстанавливаются в самой панели.

## Восстановить на отдельном сервере

1. Подготовьте изолированный сервер с той же версией магазина и пустыми томами. Оставьте сервисы, которые пишут данные, остановленными. Сохраните исходные базы и рабочие тома. Проводите такие учения ежемесячно.
2. Сверьте контрольную сумму архива. Полностью расшифруйте его в файл с доступом только для владельца. При ошибке удалите незавершённый файл. После успешной расшифровки сверьте содержимое по `backup-manifest.json`.
3. Восстановите файлы окружения перед запуском баз. Проверьте `shop.dump` и, если в копии есть Support Pro, `support.dump` командой `pg_restore --list`. Восстановите каждый дамп через `pg_restore --exit-on-error` в соответствующую базу. Распакуйте медиа, пакеты приложений и вложения поддержки в их тома.
4. Сравните записи подписок и платежей с состоянием на момент копии. Проверьте вход администратора, вложения и `bash scripts/doctor.sh` перед переключением клиентов.

[Команды проверки и восстановления](https://github.com/booarkz-cpu/shop-by-boo/blob/main/docs/ru/BACKUP_CURRENT.md) · [Порядок действий при потере сервера](https://github.com/booarkz-cpu/shop-by-boo/blob/main/docs/ru/DISASTER_RECOVERY.md).

## Откат обновления

`scripts/rollback.sh` возвращает сохранённые перед обновлением файлы и основную базу магазина. Для согласованного восстановления Support Pro и файлов используйте полную копию. [Обновление и откат](Updates.md).

## Секреты в копиях

`.env` содержит пароли и токены. Не кладите копию `.env` в git, в публичное хранилище и в открытые вложения.
Если копия уехала наружу — считайте секреты скомпрометированными и смените их:

```bash
bash scripts/rotate-secrets.sh
```

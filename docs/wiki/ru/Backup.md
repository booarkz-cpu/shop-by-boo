# Резервные копии

## Что копировать

| Что | Почему |
| --- | --- |
| база магазина | клиенты, подписки, платежи, заказы |
| база Support Pro | обращения и переписка |
| `.env` | секреты и настройки, без него установка не восстановится |
| загруженные файлы (`MEDIA_DIR`) | аватары, баннеры, вложения |

## Создать копию

```bash
bash scripts/backup.sh
```

Команда делает дамп базы и складывает его в `BACKUP_DIR`. В админ-панели раздел «Резервное копирование»
показывает список копий, размер, дату и результат проверки целостности. Проверка запускается и по расписанию.

## Почему одной копии мало

Копия на том же сервере исчезнет вместе с сервером. Держите хотя бы одну копию вне хоста — в объектном
хранилище (поддерживается S3-совместимое) или на другом сервере.

Правило: **не удаляйте единственную копию** ни до успешного обновления, ни после — пока не истёк срок
хранения и не появилась следующая.

## Проверить копию

Копия без проверки восстановления — это надежда, а не копия. Раз в месяц:

```bash
# разверните копию на тестовом хосте и выполните
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" -c "select count(*) from users;"
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" -c "select count(*) from payments;"
```

Числа должны совпадать с рабочим магазином на момент копии.

## Восстановить

```bash
bash scripts/backup.sh                                        # 1. сначала копия текущего состояния
docker compose stop backend worker bot                        # 2. остановить запись
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" < backup.sql
docker compose start backend worker bot                       # 3. поднять
bash scripts/doctor.sh                                        # 4. проверить
```

Версия схемы в дампе должна совпадать с версией магазина. Если дамп от другой версии — сначала восстановите
её, затем обновляйтесь штатно.

## Откат версии

```bash
bash scripts/rollback.sh
```

Скрипт возвращает предыдущий выпуск из снимка, сделанного перед обновлением. Поэтому копия создаётся
автоматически перед каждым обновлением.

## Секреты в копиях

`.env` содержит пароли и токены. Не кладите копию `.env` в git, в публичное хранилище и в открытые вложения.
Если копия уехала наружу — считайте секреты скомпрометированными и смените их:

```bash
bash scripts/rotate-secrets.sh
```

# Диагностика

Симптом → причина → как проверить → как исправить.

## Интерфейс

### `Cannot read properties of undefined (reading 'trim')`

**Причина:** в ответе API поле, которое редактор считает объектом метки `{ru, en, uk}`, пришло строкой или
`undefined`.

**Проверка:** откройте консоль браузера (F12 → Console), найдите упавший запрос, посмотрите форму поля в
ответе.

**Исправление:** в v28.57.0 форма закреплена тестом на сервере. На более старой сборке — обновитесь:

```bash
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.57.0 bash scripts/update-from-github.sh
```

### `(s || []).map is not a function`

**Причина:** API вернул объект вместо списка.

**Проверка:** посмотрите ответ эндпоинта в Network.

**Исправление:** панель нормализует `items`, `results` и `data`. Если ошибка осталась — запрос идёт не к
своему backend: проверьте `NEXT_PUBLIC_API_URL` и `PUBLIC_BASE_URL`.

### Чёрная страница админки или кабинета

**Причина:** сбой отрисовки React без границы ошибок размонтировал всё дерево.

**Проверка:** консоль браузера покажет сообщение до падения.

**Исправление:** в v28.57.0 добавлены `app/error.tsx` и корневые boundary — вместо пустой страницы виден
экран с причиной и кнопкой повтора.

### Раздел не загружается

| Код ответа | Значение | Что делать |
| --- | --- | --- |
| 401 | сессия истекла | войти заново |
| 403 | нет права у роли | выдать право в «Безопасность» |
| 404 | нет маршрута на сервере | проверить версию backend |
| 422 | неверные данные формы | прочитать поле в тексте ошибки |
| 500 | исключение на сервере | `docker compose logs backend` |
| 503 | зависимость недоступна | проверить Remnawave, БД, Redis |

## Сервисы

### Docker Compose не запускается

```bash
docker compose config          # покажет синтаксическую ошибку и незаполненные переменные
ls -la .env                    # файл должен существовать
```

### Контейнер перезапускается

```bash
docker compose ps                       # STATUS покажет Restarting
docker compose logs --tail=100 backend  # причина падения
free -h                                 # хватило ли памяти
```

### API недоступен

```bash
curl -s localhost:8000/health
docker compose logs backend | tail -50
```

Ожидаемый ответ: `{"ok":true,"version":"21.5.1","redis":true,"database":true}`.

### Нет HTTPS-сертификата

```bash
dig +short admin.ваш-домен.ru     # должен вернуть IP сервера
docker compose logs caddy | tail -30
```

Частая причина — домен ещё не указывает на сервер или закрыт порт 80.

## Данные

### Ошибка миграции

```bash
docker compose exec -T backend alembic current
docker compose exec -T backend alembic heads
```

Если `current` впереди `heads` — база от более новой версии. Восстановите копию и обновитесь штатно.

### Подписка не создаётся

```bash
docker compose logs backend | grep -i remnawave | tail -20
```

Проверьте `REMNAWAVE_URL`, `REMNAWAVE_TOKEN` и что у тарифа указан Internal Squad.

## Деньги

### Webhook не приходит

1. В панели кассы проверьте адрес: `https://ваш-домен/api/webhooks/<провайдер>`.
2. Проверьте, что домен доступен снаружи: `curl -I https://ваш-домен/health`.
3. Посмотрите журнал входящих в разделе «Платежи».

### Платёж не подтверждается

Сумма, валюта и номер заказа должны совпасть. Смотрите `docker compose logs backend` — там будет причина
отказа: подпись, сумма или недоступность проверки у провайдера.

## Обновления

### Обновление не проходит

```bash
sudo bash scripts/auto-update.sh status     # этап, результат, журнал
df -h                                       # свободное место
```

Причины: нет прав root, мало места, не сошлась контрольная сумма, несовместимая миграция.

## Копии

### Резервная копия не создаётся

```bash
df -h
ls -la "$BACKUP_DIR" 2>/dev/null || grep BACKUP_DIR .env
```

## Быстрая проверка всего

```bash
bash scripts/doctor.sh
```

Проверяет конфигурацию Compose, состояние контейнеров и `/health`. Это первая команда при любой проблеме.

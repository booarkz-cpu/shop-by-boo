# Установка магазина

## Подготовка сервера и DNS

Подключитесь к серверу Ubuntu или Debian по SSH с правами root. Подготовьте имена, которые будете вводить при установке. Для каждого имени создайте запись A с IPv4-адресом сервера. При использовании IPv6 проверьте также запись AAAA.

По умолчанию установщик предлагает `api`, `admin`, `app`, `cabinet` и `support` на вашем базовом домене. Проверьте DNS для каждого выбранного имени, включая дополнительные имена бота, Mini App и панели, если вы ими пользуетесь.

```bash
dig +short api.example.com
```

## Установка опубликованной версии

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28.161.0/install.sh -o /root/shop-install.sh &&
  BRANCH=v28.161.0 bash /root/shop-install.sh
```

Выполните команды в SSH-сеансе. Установщик запросит домены и реквизиты, создаст `.env` и запустит сервисы. По умолчанию рабочий каталог — `/opt/vpn-shop`. При настройке UFW скрипт учитывает порт SSH и добавляет правила для TCP 80/443 и UDP 443.

## Настройки и первый вход

Установщик генерирует `APP_SECRET` и `DB_PASSWORD`. Сохраните созданный `.env` вместе с резервной копией. Для входа используйте адрес админ-панели, выведенный в конце установки, и заданные `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Если пароль оставлен пустым, установщик его сгенерирует.

`PUBLIC_BASE_URL` указывает на публичный HTTPS-адрес API. Домен кабинета задаётся отдельно. Для выдачи доступа через Remnawave нужны адрес панели и токен. Для Telegram-бота нужен `BOT_TOKEN`. Перейдите в «Безопасность» для настройки 2FA и в «Тарифы» для выбора Internal Squad.

## Проверка установки

Из рабочего каталога запустите штатную диагностику. Она проверяет конфигурацию Compose, готовность backend по `/health/ready` внутри контейнера и HTTP-ответы админ-панели, Mini App и кабинета.

```bash
cd /opt/vpn-shop && bash scripts/doctor.sh
```

При успехе вывод содержит `API health: OK`, `admin HTTP: OK`, `miniapp HTTP: OK` и `cabinet HTTP: OK`. Для внешней проверки подставьте свой домен API вместо `api.example.com`.

```bash
curl -fsS https://api.example.com/health/ready
```

Если внутренняя проверка проходит, а публичный адрес недоступен, проверьте DNS и журнал Caddy. При ошибке backend начните с `docker compose logs --tail=100 backend` в рабочем каталоге.

# Встановлення магазину

## Підготовка сервера та DNS

Підключіться до сервера Ubuntu або Debian через SSH як root. Для кожного імені, яке вводитимете під час встановлення, створіть запис A з IPv4-адресою сервера. Якщо використовуєте IPv6, перевірте також запис AAAA.

За замовчуванням інсталятор пропонує `api`, `admin`, `app`, `cabinet` і `support` на вашому базовому домені. Перевірте DNS для всіх вибраних імен, включно з додатковими іменами бота, Mini App і панелі, якщо ви їх використовуєте.

```bash
dig +short api.example.com
```

## Встановлення опублікованої версії

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28.161.0/install.sh -o /root/shop-install.sh &&
  BRANCH=v28.161.0 bash /root/shop-install.sh
```

Виконайте команди в сеансі SSH. Інсталятор запитає домени та реквізити, створить `.env` і запустить сервіси. Типовий каталог встановлення — `/opt/vpn-shop`. Під час налаштування UFW інсталятор враховує порт SSH і додає правила для TCP 80/443 та UDP 443.

## Налаштування та перший вхід

Інсталятор генерує `APP_SECRET` і `DB_PASSWORD`. Збережіть створений `.env` разом із резервною копією. Відкрийте адресу панелі адміністратора, яку інсталятор виведе наприкінці, і ввійдіть за допомогою `ADMIN_EMAIL` та `ADMIN_PASSWORD`. Якщо залишити поле пароля порожнім, інсталятор його згенерує.

`PUBLIC_BASE_URL` містить публічну HTTPS-адресу API. Для кабінету використовується окремий домен. Для надання доступу через Remnawave потрібні адреса панелі й токен. Для Telegram-бота потрібен `BOT_TOKEN`. У розділі безпеки налаштуйте двофакторну автентифікацію, а в розділі тарифів виберіть Internal Squad.

## Перевірка встановлення

Запустіть діагностику з каталогу встановлення. Скрипт перевіряє конфігурацію Compose, звертається до `/health/ready` всередині контейнера backend і перевіряє HTTP-відповіді панелі адміністратора, Mini App і кабінету.

```bash
cd /opt/vpn-shop && bash scripts/doctor.sh
```

У разі успіху ви побачите `API health: OK`, `admin HTTP: OK`, `miniapp HTTP: OK` і `cabinet HTTP: OK`. Для зовнішньої перевірки вкажіть домен свого API замість `api.example.com`.

```bash
curl -fsS https://api.example.com/health/ready
```

Якщо внутрішня перевірка успішна, а публічна адреса недоступна, перевірте DNS і журнал Caddy. У разі помилки backend почніть з `docker compose logs --tail=100 backend` у каталозі встановлення.

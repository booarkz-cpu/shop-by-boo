# Оновлення

Магазин оновлюється до опублікованих GitHub Releases. Є ручний запуск і нічна автоматична перевірка.

## Архітектура

Окремого сервера-планувальника немає. Планувальник — це **systemd на тому ж хості**, де працює магазин. GitHub
слугує лише джерелом перевірених релізів і не має доступу до файлової системи сервера.

| Де | Що | Файл |
| --- | --- | --- |
| Хост (root, systemd) | нічний таймер і агент | `scripts/auto_update.py`, `scripts/auto-update.sh` |
| Хост | завантаження й перевірка релізу (SHA-256, маніфест) | `scripts/update-from-github.sh` |
| Backend | лише пише запит і читає стан | `backend/app/auto_update_api.py` |
| Панель | кнопки та статус | розділ «Оновлення» |

Обмін іде через два JSON-файли в `.control`: панель пише запит, агент пише стан. Агент приймає рівно три поля
(`enabled`, `time`, `check_now`) і перевіряє їх формат — панель не може виконати на сервері нічого іншого.

## Розклад

Типово **03:00 Europe/Moscow**, випадкова затримка до 15 хвилин (`RandomizedDelaySec=900`),
`Persistent=true` — пропущений запуск виконається після ввімкнення хоста.

Час змінюється в розділі «Оновлення»: агент переписує unit-файл таймера.

```bash
sudo bash scripts/auto-update.sh status     # стан і розклад
sudo bash scripts/auto-update.sh install    # увімкнути нічну перевірку
sudo bash scripts/auto-update.sh disable    # вимкнути
```

## Що відбувається під час оновлення

1. Перевірка джерела — лише стабільні релізи GitHub.
2. Отримання метаданих версії та маніфесту.
3. Перевірка версії й каналу.
4. Перевірка сумісності та обов'язкової конфігурації.
5. Перевірка міграцій: незворотна міграція зупиняє автоустановку.
6. Резервна копія бази та знімок файлів.
7. Завантаження артефакту й звірка SHA-256.
8. Розпакування, міграції, збирання.
9. Перезапуск сервісів.
10. Перевірка `/health`, ключових API, панелі та бази.
11. Запис результату й сповіщення адміністратора.

Якщо критична перевірка не пройдена, артефакт **не встановлюється**.

## Відкат

При збої після встановлення запускається перевірений відкат до знімка, зробленого перед оновленням:

```bash
bash scripts/rollback.sh
```

Якщо безпечний відкат неможливий, оновлення зупиняється, діагностика зберігається, адміністратор отримує
сповіщення.

## Ручне оновлення

```bash
bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.57.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

## Що видно в розділі «Оновлення»

Поточна й доступна версія, джерело та канал, дата останньої перевірки й останнього оновлення, розклад, стан
автооновлення, історія операцій, результат перевірки сумісності, стан резервної копії, стан міграцій, health
checks і посилання на GitHub Release.

Кнопки: «Перевірити оновлення», «Оновити зараз», «Увімкнути автооновлення», «Вимкнути автооновлення»,
«Подивитися журнал», «Перевірити стан системи», «Відновити попередню версію».

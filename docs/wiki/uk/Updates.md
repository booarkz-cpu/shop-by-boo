# Оновлення магазину

## Оновлення вручну

Заплануйте час для обслуговування. Для типової інсталяції виконайте команди з `/opt/vpn-shop` як root. Якщо магазин встановлено в іншому каталозі, вкажіть його в `APP_DIR` і використовуйте замість шляху нижче.

Перед оновленням створіть зашифровану резервну копію. Скрипт запитає пароль і на час копіювання призупинить запущені сервіси, що записують дані. Збережіть файл `.vpb`, контрольну суму й пароль відновлення. Типовий каталог копій — `/var/backups/vpn-shop`.

```bash
cd /opt/vpn-shop &&
  bash scripts/backup.sh &&
  RELEASE_TAG=v28.161.0 bash scripts/update-from-github.sh
```

Ця команда вибирає опублікований `v28.161.0`. Для новішого стабільного випуску вкажіть його точний тег. Без `RELEASE_TAG` скрипт шукає останній стабільний випуск. Якщо встановлено таку саму чи новішу версію, скрипт завершить роботу без заміни файлів.

## Що перевіряє оновлення

Завантажувач перевіряє тег і SHA-256 архіву, розпаковує архів у тимчасовий каталог і звіряє версію. Якщо вказано мінімальну вихідну версію, перевіряє також її. Для `v28.161.0` версія дистрибутива відрізняється від версії API, тому завантажувач також звіряє маніфест з архівом і комітом тега.

Після перевірки архіву `update.sh` створює знімок файлів і SQL-дамп бази магазину в `.rollback`, застосовує оновлення та запускає `doctor.sh`.

## Нічні оновлення

Таймер systemd працює на сервері магазину. Типовий час запуску — 03:00 за московським часом, із випадковою затримкою до 15 хвилин. `Persistent=true` дозволяє виконати пропущений запуск після ввімкнення сервера. Команда нижче показує розклад і результат останньої спроби.

```bash
cd /opt/vpn-shop && sudo bash scripts/auto-update.sh status
```

Щоб увімкнути або вимкнути таймер, укажіть `install` або `disable` замість `status`. Команда `run` перевіряє наявність оновлення й може відразу його встановити.

## Якщо оновлення перервалося

Помилка після початку заміни файлів може запустити автоматичне відновлення. Перевірте журнал, стан сервісів і наявність `.rollback/RECOVERY_MODE`. Під час ручного запуску `scripts/rollback.sh` типово відновлює файли з `.rollback/latest.tar.gz` і базу магазину з `.rollback/latest.sql`. Записи, створені після дампа, можуть бути втрачені. Для відновлення обох баз і секретів використовуйте повну зашифровану резервну копію.

Команди звірено з початковим кодом v28.161.0. Встановлення та відновлення на конкретному VPS слід підтвердити результатами перевірки цього сервера.

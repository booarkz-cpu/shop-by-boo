# Діагностика

Симптом → причина → як перевірити → як виправити.

## Інтерфейс

### `Cannot read properties of undefined (reading 'trim')`

**Причина:** у відповіді API поле, яке редактор вважає об'єктом мітки `{ru, en, uk}`, прийшло рядком або
`undefined`.

**Перевірка:** відкрийте консоль браузера (F12 → Console), знайдіть запит, що впав, подивіться форму поля.

**Виправлення:** у v28.57.0 форма закріплена тестом на сервері. На старішому збиранні — оновіться:

```bash
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.57.0 bash scripts/update-from-github.sh
```

### `(s || []).map is not a function`

**Причина:** API повернув об'єкт замість списку.

**Перевірка:** подивіться відповідь ендпоінта в Network.

**Виправлення:** панель нормалізує `items`, `results` і `data`. Якщо помилка лишилася — запит іде не до свого
backend: перевірте `NEXT_PUBLIC_API_URL` і `PUBLIC_BASE_URL`.

### Порожня (чорна) сторінка адмінки або кабінету

**Причина:** збій відображення React без межі помилок розмонтував усе дерево.

**Перевірка:** консоль браузера покаже повідомлення до падіння.

**Виправлення:** у v28.57.0 додано `app/error.tsx` і кореневі boundary — замість порожньої сторінки видно екран
із причиною й кнопкою повтору.

### Розділ не завантажується

| Код | Значення | Що робити |
| --- | --- | --- |
| 401 | сесія спливла | увійти знову |
| 403 | у ролі немає права | видати право в «Безпека» |
| 404 | немає маршруту на сервері | перевірити версію backend |
| 422 | невірні дані форми | прочитати поле в тексті помилки |
| 500 | виняток на сервері | `docker compose logs backend` |
| 503 | залежність недоступна | перевірити Remnawave, БД, Redis |

## Сервіси

### Docker Compose не запускається

```bash
docker compose config          # покаже синтаксичну помилку та незаповнені змінні
ls -la .env                    # файл має існувати
```

### Контейнер перезапускається

```bash
docker compose ps                       # STATUS покаже Restarting
docker compose logs --tail=100 backend  # причина падіння
free -h                                 # чи вистачило пам'яті
```

### API недоступний

```bash
curl -s localhost:8000/health
docker compose logs backend | tail -50
```

Очікувана відповідь: `{"ok":true,"version":"21.5.1","redis":true,"database":true}`.

### Немає HTTPS-сертифіката

```bash
dig +short admin.ваш-домен.com     # має повернути IP сервера
docker compose logs caddy | tail -30
```

Часта причина — домен ще не вказує на сервер або закритий порт 80.

## Дані

### Помилка міграції

```bash
docker compose exec -T backend alembic current
docker compose exec -T backend alembic heads
```

Якщо `current` попереду `heads` — база від новішої версії. Відновіть копію й оновіться штатно.

### Підписка не створюється

```bash
docker compose logs backend | grep -i remnawave | tail -20
```

Перевірте `REMNAWAVE_URL`, `REMNAWAVE_TOKEN` і що в тарифу вказано Internal Squad.

## Гроші

### Webhook не приходить

1. У панелі каси перевірте адресу: `https://ваш-домен/api/webhooks/<провайдер>`.
2. Перевірте, що домен доступний ззовні: `curl -I https://ваш-домен/health`.
3. Подивіться журнал вхідних у розділі «Платежі».

### Платіж не підтверджується

Сума, валюта й номер замовлення мають збігатися. Дивіться `docker compose logs backend` — там буде причина
відмови: підпис, сума або недоступність перевірки у провайдера.

## Оновлення

### Оновлення не проходить

```bash
sudo bash scripts/auto-update.sh status     # етап, результат, журнал
df -h                                       # вільне місце
```

Причини: немає прав root, мало місця, не зійшлася контрольна сума, несумісна міграція.

## Копії

### Резервна копія не створюється

```bash
df -h
ls -la "$BACKUP_DIR" 2>/dev/null || grep BACKUP_DIR .env
```

## Швидка перевірка всього

```bash
bash scripts/doctor.sh
```

Перевіряє конфігурацію Compose, стан контейнерів і `/health`. Це перша команда за будь-якої проблеми.

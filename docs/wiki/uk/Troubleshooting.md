# Діагностика

Симптом → причина → як перевірити → як виправити.

## Інтерфейс

### `Cannot read properties of undefined (reading 'trim')`

**Причина:** у відповіді API поле, яке редактор вважає об’єктом мітки `{ru, en, uk}`, прийшло рядком або
`undefined`.

**Перевірка:** відкрийте консоль браузера (F12 → Console), знайдіть запит, що впав, подивіться форму поля.

**Виправлення:** у v28.159.0 форма закріплена тестом на сервері. Для старішої версії дотримуйтеся [інструкції з резервного копіювання й оновлення](Updates.md).

### `(s || []).map is not a function`

**Причина:** API повернув об’єкт замість списку.

**Перевірка:** подивіться відповідь ендпоінта в Network.

**Виправлення:** панель нормалізує `items`, `results` і `data`. Якщо помилка лишилася — запит іде не до того
backend: перевірте `NEXT_PUBLIC_API_URL` і `PUBLIC_BASE_URL`.

### Порожня (чорна) сторінка адмінки або кабінету

**Причина:** збій відображення React без межі помилок розмонтував усе дерево.

**Перевірка:** консоль браузера покаже повідомлення до падіння.

**Виправлення:** у v28.159.0 додано `app/error.tsx` і кореневі межі помилок — замість порожньої сторінки видно екран
із причиною й кнопкою повтору.

### Розділ не завантажується

| Код | Значення | Що робити |
| --- | --- | --- |
| 401 | сесія спливла | увійти знову |
| 403 | у ролі немає права | видати право в «Безпека» |
| 404 | немає маршруту на сервері | перевірити версію backend |
| 422 | неправильні дані форми | прочитати поле в тексті помилки |
| 500 | виняток на сервері | `docker compose logs backend` |
| 503 | залежність недоступна | перевірити Remnawave, БД, Redis |

## Сервіси

Виконуйте команди Docker Compose з каталогу встановлення магазину. Типовий шлях — `/opt/vpn-shop`. Якщо магазин встановлено в іншому каталозі, передайте скриптам його шлях через `APP_DIR`.

### Docker Compose не запускається

```bash
docker compose config --quiet
ls -la .env                    # файл має існувати
```

### Контейнер перезапускається

```bash
docker compose ps                       # STATUS покаже Restarting
docker compose logs --tail=100 backend  # причина падіння
free -h                                 # чи вистачило пам’яті
```

### API недоступний

Спочатку виконайте перевірку на сервері магазину. Рядок `API health: OK` означає, що API відповів на запит до `/health/ready` усередині контейнера backend.

```bash
bash scripts/doctor.sh
```

Потім перевірте публічну адресу з іншого комп’ютера. Замініть `api.example.com` на свій домен API. Якщо внутрішня перевірка успішна, а публічний запит завершився помилкою, перевірте DNS, сертифікат і журнал Caddy.

```bash
curl -fsS https://api.example.com/health/ready
```

### Немає HTTPS-сертифіката

Підставте свій домен адмінпанелі.

```bash
dig +short admin.example.com     # має повернути IP сервера
docker compose logs caddy | tail -30
```

Часта причина — домен ще не вказує на сервер або закритий порт 80.

## Дані

### Помилка міграції

```bash
docker compose exec -T backend alembic current
docker compose exec -T backend alembic heads
```

Якщо `current` попереду `heads` — база від новішої версії. Відновіть копію й оновіться штатно.

### Підписка не створюється

```bash
docker compose logs backend | grep -i remnawave | tail -20
```

Перевірте `REMNAWAVE_URL`, `REMNAWAVE_TOKEN` і що в тарифі вказано Internal Squad.

## Гроші

### Webhook не приходить

1. Звірте домен і шлях сповіщень з налаштуваннями свого платіжного провайдера. Наприклад, ЮKassa використовує `/api/webhooks/yookassa`. [Підключення провайдера](Payments.md).
2. Перевірте доступність домену API ззовні командою з розділу «API недоступний». Успішна відповідь підтверджує доступність API. Доставку самого сповіщення перевірте в журналі провайдера.
3. Подивіться журнал вхідних у розділі «Платежі».

### Платіж не підтверджується

Сума, валюта й номер замовлення мають збігатися. Дивіться `docker compose logs backend` — там буде причина
відмови: підпис, сума або недоступність перевірки у провайдера.

## Оновлення

### Оновлення не проходить

```bash
sudo bash scripts/auto-update.sh status     # етап, результат, журнал
df -h                                       # вільне місце
```

Причини: немає прав root, мало місця, контрольна сума не збігається, несумісна міграція.

## Копії

### Резервна копія не створюється

Скрипт `scripts/backup.sh` зберігає зашифровані файли `.vpb` і контрольні суми `.vpb.sha256` у `/var/backups/vpn-shop`. Якщо під час запуску задано `BACKUP_DEST`, перевірте той каталог.

```bash
df -h
ls -ld -- "${BACKUP_DEST:-/var/backups/vpn-shop}"
```

## Швидка перевірка всього

```bash
bash scripts/doctor.sh
```

Скрипт перевіряє конфігурацію Compose, виводить стан контейнерів і перевіряє `/health/ready` усередині backend, а також HTTP-відповіді адмінпанелі, Mini App та кабінету.

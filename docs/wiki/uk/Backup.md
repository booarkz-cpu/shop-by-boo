# Резервні копії

## Що копіювати

| Що | Навіщо |
| --- | --- |
| база магазину | клієнти, підписки, платежі, замовлення |
| база Support Pro | звернення та листування |
| `.env` | секрети й налаштування; без нього встановлення не відновити |
| завантажені файли (`MEDIA_DIR`) | аватари, банери, вкладення |

## Створити копію

```bash
bash scripts/backup.sh
```

Команда робить дамп бази й складає його в `BACKUP_DIR`. У розділі «Резервне копіювання» адмін-панелі видно
список копій, розмір, дату й результат перевірки цілісності. Перевірка запускається і за розкладом.

## Чому однієї копії мало

Копія на тому ж сервері зникне разом із сервером. Тримайте хоча б одну копію поза хостом — в об'єктному
сховищі (підтримується S3-сумісне) або на іншому сервері.

Правило: **не видаляйте єдину копію** ні до успішного оновлення, ні після — доки не минув строк зберігання і не
з'явилася наступна.

## Перевірити копію

Копія без перевірки відновлення — це надія, а не копія. Раз на місяць:

```bash
# розгорніть копію на тестовому хості й виконайте
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" -c "select count(*) from users;"
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" -c "select count(*) from payments;"
```

Числа мають збігатися з робочим магазином на момент копії.

## Відновити

```bash
bash scripts/backup.sh                                        # 1. спершу копія поточного стану
docker compose stop backend worker bot                        # 2. зупинити запис
docker compose exec -T db psql -U "$DB_USER" -d "$DB_NAME" < backup.sql
docker compose start backend worker bot                       # 3. підняти
bash scripts/doctor.sh                                        # 4. перевірити
```

Версія схеми в дампі має збігатися з версією магазину. Якщо дамп від іншої версії — спершу відновіть її, потім
оновлюйтеся штатно.

## Відкат версії

```bash
bash scripts/rollback.sh
```

Скрипт повертає попередній випуск зі знімка, зробленого перед оновленням. Тому копія створюється автоматично
перед кожним оновленням.

## Секрети в копіях

`.env` містить паролі й токени. Не кладіть копію `.env` у git, публічне сховище чи відкриті вкладення. Якщо
копія пішла назовні — вважайте секрети скомпрометованими й змініть їх:

```bash
bash scripts/rotate-secrets.sh
```

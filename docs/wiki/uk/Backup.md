# Резервні копії

## Що копіювати

| Що | Навіщо |
| --- | --- |
| база магазину | клієнти, підписки, платежі, замовлення |
| база Support Pro | звернення та листування |
| `.env` | секрети й налаштування; без нього встановлення не відновити |
| завантажені файли (`MEDIA_DIR`) | аватари, банери, вкладення |

## Створити повну копію

Для стандартної інсталяції виконайте команду під час технічного обслуговування. Введіть пароль завдовжки від 12 до 1024 символів і збережіть його окремо.

```bash
cd /opt/vpn-shop && sudo bash scripts/backup.sh
```

Разом із копією збережіть тег дистрибутива та повний SHA коміту Git або SHA-256 інсталяційного архіву. Поле `source_version` у маніфесті вказує версію runtime/API.

Скрипт тимчасово зупиняє активні сервіси, які записують дані, поки копіює бази та файли. За замовчуванням у `/var/backups/vpn-shop` з’являться `shop-*.vpb` та його файл `.sha256`. Інший каталог задає `BACKUP_DEST`. Зберігайте обидва файли поза сервером і тримайте попередню перевірену копію до перевірки наступної. Копії `.enc` з адмінпанелі відновлюйте в самій панелі.

## Відновити на окремому сервері

1. Підготуйте ізольований сервер із тією самою версією магазину й порожніми томами. Сервіси, які записують дані, мають залишатися зупиненими. Збережіть вихідні бази та робочі томи. Проводьте такі навчання щомісяця.
2. Звірте контрольну суму архіву. Повністю розшифруйте його у файл із доступом лише для власника. У разі помилки видаліть неповний файл. Після успішного розшифрування звірте вміст із `backup-manifest.json`.
3. Відновіть файли середовища перед запуском баз. Перевірте `shop.dump` і, якщо копія містить Support Pro, `support.dump` командою `pg_restore --list`. Відновіть кожен дамп у відповідну базу через `pg_restore --exit-on-error`. Розпакуйте медіафайли, пакети застосунків і вкладення підтримки у відповідні томи.
4. Порівняйте записи підписок і платежів зі станом на момент копіювання. Перевірте вхід адміністратора, вкладення та результат `bash scripts/doctor.sh`, перш ніж перемикати трафік.

[Команди перевірки та відновлення російською](https://github.com/booarkz-cpu/shop-by-boo/blob/main/docs/ru/BACKUP_CURRENT.md) · [Порядок дій у разі втрати сервера](https://github.com/booarkz-cpu/shop-by-boo/blob/main/docs/ru/DISASTER_RECOVERY.md).

## Відкат оновлення

`scripts/rollback.sh` повертає файли та основну базу магазину зі знімка перед оновленням. Для узгодженого відновлення Support Pro і файлів скористайтеся повною копією. [Оновлення та відкат](Updates.md).

## Секрети в копіях

`.env` містить паролі й токени. Не кладіть копію `.env` у git, публічне сховище чи відкриті вкладення. Якщо
копія пішла назовні — вважайте секрети скомпрометованими й змініть їх:

```bash
bash scripts/rotate-secrets.sh
```

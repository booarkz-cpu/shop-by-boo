# Адмін-панель

Кожен розділ читає та змінює реальні дані. Кожна дія перевіряє право на сервері — приховати кнопку в браузері
недостатньо.

## Як влаштований доступ

Ролі: `admin`, `operator`, `support`, `viewer`. Право перевіряється залежністю `require_permission(...)` на
кожному адміністративному маршруті. Наприклад, повернення потребує `payments.refund`, перегляд клієнта —
`users.read`, відповідь у підтримці — `support.write`.

Якщо кнопка не спрацьовує — спершу подивіться відповідь сервера: `403` означає «немає права», а не «зламаний
інтерфейс».

## Що робить панель при збої

* Помилка завантаження розділу показує причину й кнопку повтору — дані не змінюються;
* збій відображення показує екран помилки замість порожньої сторінки;
* небезпечні операції (повернення, видалення, вимкнення підписки) потребують підтвердження.

## Робота з клієнтом

1. Відкрийте «Користувачі», знайдіть клієнта за поштою, Telegram або ID.
2. У картці: підписки, платежі, пристрої, трафік по днях, сесії.
3. Дії: продовжити, змінити тариф, вимкнути, повернути гроші, надіслати повідомлення.

Трафік по днях береться зі статистики Remnawave. Якщо панель її не віддає, розділ покаже порожній графік, а не
помилку.

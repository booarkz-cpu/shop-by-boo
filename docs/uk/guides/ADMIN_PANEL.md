# Посібник з адмінпанелі

Адмінпанель — єдине місце керування магазином. Кожен розділ працює через типізований API backend. Браузер не виконує команд на сервері й не передає серверу довільних команд, шляхів чи адрес для виконання.

Російський оригінал: [ADMIN_PANEL_GUIDE](../../ru/new/ADMIN_PANEL_GUIDE.md). Пов'язане: [ADMIN_MODULES](../../ru/new/ADMIN_MODULES.md) (модулі й розділи), [ADMIN_CONTROL_MATRIX](../../ru/new/ADMIN_CONTROL_MATRIX.md) (операції кожного модуля), [RBAC](../../ru/new/RBAC.md) (ролі та права). Інші посібники: [зміст](README.md).

## Вхід

Адреса панелі — `https://<ADMIN_DOMAIN>`. Способи входу:
- e-mail і пароль;
- ключ доступу (passkey);
- Telegram Mini App, якщо до адміністратора прив'язано Telegram ID і не ввімкнено двофакторний захист;
- одноразовий квиток із застосунку адміністратора (дійсний 60 секунд).

З двофакторним захистом після пароля потрібен код із застосунку-автентифікатора або резервний код. Небезпечні дії (відновлення копії, запуск плану на серверах, видалення копій тощо) ще раз питають код; він діє 10 хвилин у цій сесії.

Першого адміністратора створює установник. Інших додають у «Безпека → Ролі та адміністратори»: e-mail, пароль, Telegram ID і роль; там само обліковий запис можна вимкнути або видалити.

## Будова панелі

- **Меню** ліворуч, вісім груп: Аналітика, Користувачі, Тарифи й оплата, Маркетинг, Бот і кабінет, Сервери, Система, Безпека. На телефоні меню висувається кнопкою.
- **Пошук розділу:** `⌘K` / `Ctrl+K` або поле на сторінці «Усі розділи».
- **Адмін-центр** («Система → Адмін-центр: 30 модулів»): 30 модулів завдання — які розділи ними керують, які операції є, яких прав потребують. Кнопка в рядку відкриває розділ.
- **Стан розділу.** Кожен розділ показує завантаження, помилку з причиною та кнопкою «Повторити» або порожній стан з підказкою. Без права сервер відповідає 403, і розділ показує причину.

## Стан системи

«Аналітика → Стан системи» (`GET /api/admin/health/summary`, право `ops.diagnostics`) — одна сторінка зі станом усіх частин установки. Кожен рядок має статус («у нормі», «увага», «помилка» або «не налаштовано»), одне речення про знайдене, час відповіді мережевих перевірок і кнопку розділу, що керує цією частиною.

| Частина | Що перевіряється | Розділ |
| --- | --- | --- |
| Backend (API) | Відповідає; номер випуску і версія API | Оновлення |
| Frontend | Адмінпанель, кабінет і Mini App віддають сторінку | Розгортання |
| PostgreSQL | `SELECT 1`, час відповіді | Діагностика |
| Міграції бази | Позначка в базі збігається з останньою міграцією випуску | Оновлення |
| Redis | `PING`, час відповіді | Діагностика |
| Remnawave | Панель відповідає і приймає токен; без адреси — «не налаштовано» | Remnawave: панель |
| Вузли | Скільки ввімкнених вузлів на зв'язку | Сервери |
| Caddy (зворотний проксі) | Приймає HTTPS для доменів магазину | Діагностика |
| Сертифікати TLS | Ланцюжок сертифіката кожного домену дійсний; попередження за 14 днів до кінця строку | Діагностика |
| Платежі | Які агенти налаштовані, які тимчасово виведені з черги після помилок, чи не призупинено приймання | Платіжні агенти |
| Фонові завдання | Живий обробник (позначка за 90 с), завдання в черзі довше 15 хв, невиконані за добу | Черга завдань |
| Резервні копії | Вік останньої вдалої копії; попередження після 26 год | Резервні копії |
| Telegram-бот | Зв'язок бота з Telegram, як його повідомляє процес бота | Telegram-бот |
| Оновлення | Встановлений випуск і останній випуск на GitHub (відповідь зберігається годину) | Оновлення |

Кожна перевірка має власну межу часу (5 секунд для мережевих); повільна чи зламана частина не приховує інших; відповіді зовнішніх сервісів, токени й паролі на сторінку не потрапляють — причина пишеться в журнал сервера. «Перевірити знову» повторює всі перевірки. Вільне місце і пам'ять показують «Моніторинг» і «Діагностика».

## Типові завдання

| Завдання | Де |
| --- | --- |
| Знайти клієнта, продовжити, змінити тариф, повернути гроші | Користувачі → Клієнти магазину → картка клієнта |
| Створити або змінити тариф | Тарифи й оплата → Тарифи, Конструктор тарифів |
| Увімкнути вхід через Google, Яндекс ID, VK ID | Система → Налаштування без перезапуску, група OAuth |
| Підключити платіжного агента | Система → Налаштування без перезапуску (ключі), далі Тарифи й оплата → Платіжні агенти (увімкнення, черга кас, перевірка) |
| Підключити Remnawave | Система → Налаштування без перезапуску: `REMNAWAVE_URL`, `REMNAWAVE_TOKEN`; далі Сервери → Remnawave: панель — або встановити її з панелі ([посібник з Remnawave](REMNAWAVE.md)) |
| Додати або перезапустити вузол | Сервери → Сервери |
| Тексти бота, кнопки, банери, документи; тексти застосунків | Бот і кабінет; Android та iOS |
| Показати чи сховати блок «Застосунки» в кабінеті | Android та iOS → блок «Застосунки» в кабінеті |
| Резервна копія і відновлення | Безпека → Резервні копії, Відновлення |
| Оновити магазин | Система → Оновлення: перевірка випуску, автооновлення за розкладом або кнопкою |
| Хто що змінив | Безпека → Журнал дій: пошук за адміністратором, дією, об'єктом і періодом |

## Що досі потребує сервера

| Що | Чому |
| --- | --- |
| Перше встановлення магазину | Контейнерів ще немає. Саму Remnawave ставлять з панелі: «Сервери → Встановлення Remnawave» |
| Одноразове встановлення агента автооновлення (`scripts/auto-update.sh install`) на магазинах, встановлених до v28.74.0 | Агент працює на хості; контейнер не може поставити службу systemd, і це навмисно. Новіші установники вмикають його самі |
| Власні домени магазину (`ADMIN_DOMAIN`, `API_DOMAIN`…), підключення до бази й Redis | Читаються з `.env` під час старту контейнерів. Ключі кас, Remnawave, Cloudflare, пошти і `BOT_TOKEN` змінюються без перезапуску в «Налаштуваннях без перезапуску»; домени порталу підписки — у «Сервери → Домени та сертифікати» |

Усі 30 модулів керуються з панелі. Макетів без функції в ній немає.

## Безпека

- Права сервер перевіряє на кожному запиті ([RBAC](../../ru/new/RBAC.md)).
- Зміни пишуться в журнал дій.
- Системні операції — копія, перевірка відновлення, оновлення, перезапуск вузла — йдуть окремими маршрутами з перевіркою вхідних даних; команди на хості виконує агент, який приймає лише запити відомого формату.
- Термінал вузлів потребує права `nodes.terminal` і працює лише на вузлах, де власник сам його ввімкнув (`AGENT_TERMINAL=1`).

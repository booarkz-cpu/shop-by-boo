# Встановлення магазину

Термінал потрібен один раз — для першого розгортання контейнерів магазину. Усе інше робиться в адмінпанелі: налаштування без перезапуску, оновлення, Remnawave, резервні копії.

Російський оригінал: [INSTALLATION_GUIDE](../../ru/new/INSTALLATION_GUIDE.md). Інші посібники: [зміст](README.md).

## Вимоги

| Що | Мінімум |
| --- | --- |
| ОС | Ubuntu 22.04 / 24.04 / 26.04 або Debian 12 / 13 (інші — з попередженням) |
| Ресурси | 2 CPU, 4 ГБ RAM, 30 ГБ диска |
| Доступ | root через SSH; домени магазину вказують на сервер (A/AAAA) |
| Порти | 80 і 443 (Caddy); 25 — лише якщо ввімкнено приймання пошти |

## Встановлення однією командою

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28/install.sh | sudo bash
```

`install.sh` ставить `git`, `curl` і Docker (`deploy/install-docker.sh`), клонує випуск у `/opt/vpn-shop-src` і передає роботу `deploy/install-vps.sh`, який:

1. **Перевіряє систему:** ОС, root, вільні порти, наявність термінала для запитань. Без термінала задайте `INSTALL_NONINTERACTIVE=1` і змінні оточення.
2. **Налаштовує:** питає домени, e-mail для Let's Encrypt, токен бота і порт SSH; генерує секрети (`APP_SECRET`, паролі баз); пише `.env` з правами 600 (`scripts/harden-env.py`).
3. **Фаєрвол:** відкриває порт SSH, 80 і 443. PostgreSQL, Redis, API і панелі назовні не відкриваються.
4. **Образи:** закріплює базові образи за digest (`scripts/pin-images.sh`, файл `.env.images`).
5. **Збирає і запускає:** `deploy/build-production.sh`, далі чекає на API і міграції (`alembic upgrade head` під час старту backend).
6. **Support Pro:** створює першого оператора і показує TOTP.
7. **Автооновлення:** вмикає агент `scripts/auto-update.sh install` ([AUTO_UPDATE](../../ru/new/AUTO_UPDATE.md)).

Повторний запуск установника на встановленому магазині нічого не ламає: `install.sh` відмовиться замінювати каталог з іншим випуском і запропонує оновлення.

## Діагностика

| Команда | Що перевіряє |
| --- | --- |
| `bash scripts/preflight.sh` | синтаксис скриптів, збірку Python, закріплені digest, `docker compose config` |
| `bash scripts/doctor.sh` | контейнери, `/health/ready` API, відповідь адмінпанелі, кабінету і Mini App |
| Адмінпанель → «Стан системи» | кожну частину магазину окремо ([посібник з панелі](ADMIN_PANEL.md#стан-системи)) |
| Адмінпанель → «Automation Center» | усю автоматику ([AUTOMATION_CENTER](../../ru/new/AUTOMATION_CENTER.md)) |

## Оновлення, резервні копії та відновлення

| Що | З адмінпанелі | Із сервера (якщо панель недоступна) |
| --- | --- | --- |
| Оновити магазин | «Оновлення → Перевірити й оновити зараз» | `sudo bash scripts/auto-update.sh run` |
| Відкат | автоматично, якщо оновлення не вдалося | `sudo bash scripts/rollback.sh` (останній знімок) |
| Резервна копія | «Резервні копії»: розклад, «Створити», перевірка, вивантаження в Telegram | `bash scripts/backup.sh` (обидві бази, файли й `.env`, зашифровано) |
| Відновлення | «Резервні копії → Відновити» (з підтвердженням) | кроки в [BACKUP_CURRENT](../../ru/BACKUP_CURRENT.md) |
| Remnawave | «Оновлення → Автооновлення Remnawave» | — |

Знімки оновлень лежать у `.rollback/` і не містять секретів (`.env`). `.env` і каталог `.control` агента автооновлення зберігаються і під час оновлення, і під час відкату.

Кожен PR проходить у CI **навчання з відновлення**: дані в працюючому магазині → зашифрована копія `scripts/backup.sh` → втрата всіх томів і обох `.env` → відновлення лише з копії → кожна таблиця, підписка, платіж і адміністратор на місці, адміністратор входить.

Докладно про Docker: [DOCKER_GUIDE](../../ru/new/DOCKER_GUIDE.md).

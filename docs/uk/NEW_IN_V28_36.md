# Що нового у v28.36.0

Короткі нотатки для власника магазину про модулі v28.36.0. Докладні сторінки (російською) — за посиланнями в розділах.

## Черга кас
«Тарифи й оплата → Платіжні агенти → Черга кас» задає порядок резервного ланцюжка (типово ЮKassa → RollyPay → Platega →
CryptoBot → Freekassa): вище/нижче, вимкнути, «повернути в роботу» після спрацювання запобіжника. Замовлення, яке каса
не прийняла, саме переходить до наступної налаштованої. Та сама черга є в адмін-застосунках Android та iOS (вкладка
«Платежі»). Готовність до запуску попереджає, поки ключі є лише в однієї каси.
Звіт по касах (`GET /api/admin/payments/providers-report`) показує конверсію, середній чек, збої й повернення та
називає найкращу касу від 10 замовлень. Докладніше: [оплата](../modules/billing_and_taxes.md).

## Автоматизація повернення грошей
Нові події автоматизації: **кинутий кошик** (через N хвилин після неоплаченого замовлення, 5–4320) і **невдале
автопродовження** (0–14 днів після), з готовими шаблонами: нагадування, промокод для кинутого кошика, серія «сьогодні /
день 1 / день 3» після невдалого продовження та сповіщення про обмеження трафіку.

## Синхронізація, яку будять коміти
`/api/me/sync` відповідає одразу після коміту платежу, підписки чи користувача цього клієнта (Redis `sync:user:<id>`
між процесами, перевірка кожні 15 с як запобіжник). Докладніше: [account_sync](../modules/account_sync.md).

## Монітор блокувань
Проби (`scripts/block-probe.py` на недорогому VPS у регіоні клієнтів) кожні 5 хвилин перевіряють домени API, резервні
домени й вузли. Якщо всі проби регіону не дістаються до адреси, яку магазин бачить робочою, — це блокування: сповіщення
в Telegram, заблокована адреса API переходить у кінець підписаного списку для застосунків, а за бажанням усім клієнтам
додається резервний Internal Squad (Reality, XHTTP). «Сервери → Монітор блокувань». Масові виклики сквадів Remnawave не
перевірялися на живій панелі, тому автоматичний резервний сквад типово вимкнено.
Докладніше: [anti_blocking](../modules/anti_blocking.md).

## Юніт-економіка за джерелами
Джерело першого дотику (`?start=src_vk_ads`, `?startapp=src_…`, `?utm_source=…` у кабінеті) зберігається один раз
(міграція `0079_acquisition`). «Аналітика → Юніт-економіка» показує нових і платних клієнтів, виторг, витрати на рекламу
за місяць, CAC і ROMI. Докладніше: [unit_economics](../modules/unit_economics.md).

## Діагностика «Не працює VPN» у застосунках
У застосунках Android та iOS 3.2.0 кнопка «Повідомити про проблему» (за наявності підписки) перевіряє DNS, API магазину,
завантаження підписки й TCP до кожного сервера, надсилає це разом зі словами клієнта в `POST /api/me/diagnostics` і
одразу показує ймовірну причину. Підтримка отримує повний звіт у зверненні.
Докладніше: [in_app_diagnostics](../modules/in_app_diagnostics.md).

## Гарячий резерв бази
`scripts/hot-standby.sh` налаштовує потокову реплікацію PostgreSQL на другий сервер: TLS, роль лише для реплікації,
порт відкритий тільки для IP резерву (правило DOCKER-USER — порти Docker обходять ufw). Агент резерву
(`scripts/standby-agent.py`, щохвилини) звітує про відставання і пише в Telegram, коли основний мовчить на всіх шляхах
(потік реплікації, `/health/live`, TCP 443 і 22). Підвищення — одна команда (`hot-standby.sh promote`) або автоматично
з `AUTO_PROMOTE=1`, за бажанням з перемиканням DNS у Cloudflare. Автопідвищення типово вимкнене через ризик двох основних
баз; старий основний після повернення спершу виконує `hot-standby.sh demote`. На двох справжніх серверах ще не
перевірялося — проведіть навчальне перемикання. Докладніше: [hot_standby](../modules/hot_standby.md).

## Автомасштабування вузлів
«Сервери → Автомасштабування» стежить за кількістю користувачів онлайн на один робочий вузол. Вище верхнього порогу —
рекомендація в Telegram або, в режимі «Авто», створення сервера в Hetzner Cloud з Remnawave Node і додавання його в
панель; нижче нижнього — видалення вузла, який створило саме автомасштабування (ручні — ніколи). Для «Авто» потрібні
`HETZNER_API_TOKEN` і `REMNANODE_SECRET_KEY` у `.env`. Створення/видалення вузла в Remnawave не перевірялося на живій
панелі — простежте перший запуск. Докладніше: [node_autoscale](../modules/node_autoscale.md).

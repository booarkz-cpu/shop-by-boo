# Перевірка магазину без платіжних систем

Цей контур піднімає API, адмінку, кабінет і Mini App на вашому комп’ютері. YooKassa, Platega, RollyPay, Stripe, PayPal, крипто-шлюз, Telegram і Remnawave не потрібні.

Пісочниця не вдає бойовий VPN. Посилання підписки буде `sandbox://local/...`. Клієнт Happ його не імпортує. Так перевіряються реєстрація, вітрина, оплата і запис підписки в базі.

`bash scripts/test-up.sh` передає `.env.test` до Compose і прив’язує тестові порти до `127.0.0.1`. Для віддаленого доступу використайте SSH-тунель: `ssh -L 18081:127.0.0.1:18081 user@server`. `COOKIE_SECURE=false` стосується лише локального тесту. Бойове встановлення описано в [DEPLOYMENT.md](DEPLOYMENT.md).

## Що потрібно

- Docker Engine і плагін Compose.
- Вільні порти 18080, 18081, 18082, 18083.
- Каталог цього репозиторію.

## 1. Запустити

З кореня репозиторію:

```bash
bash scripts/test-up.sh
```

Скрипт:

1. Якщо файлу `.env.test` немає, копіює `.env.test.example` і підставляє випадкові `APP_SECRET`, пароль бази і пароль адміністратора.
2. Передає `.env.test` до Compose і запускає `docker-compose.test.yml`.
3. Чекає `http://127.0.0.1:18080/health`.
4. Проганяє `scripts/sandbox-e2e.sh`: реєстрація, покупка тарифу «Тестовий місяць» через провайдер `sandbox`, завершення видачі.

Наприкінці скрипт друкує `ADMIN_EMAIL` і, під час першої генерації, `ADMIN_PASSWORD`. Пароль також лежить у `.env.test`. Файл не комітьте.

| Поверхня | Адреса |
| --- | --- |
| API | http://127.0.0.1:18080 |
| Адмінка | http://127.0.0.1:18081 |
| Кабінет | http://127.0.0.1:18082 |
| Mini App | http://127.0.0.1:18083 |

Зупинити:

```bash
docker compose --env-file .env.test -f docker-compose.test.yml down
```

Дані бази лишаються в томах Compose. Щоб почати з порожньої бази, додайте `-v`.

## 2. Перевірити здоров’я

```bash
curl -fsS http://127.0.0.1:18080/health
curl -fsS http://127.0.0.1:18080/api/public/config
```

У другій відповіді `payments_sandbox` дорівнює `true`, а в `payment_providers` є `sandbox`.

## 3. Увійти в адмінку

1. Відкрийте http://127.0.0.1:18081
2. Введіть `admin@example.test` і пароль з `.env.test`.
3. Відкрийте список тарифів. На порожній базі вже є «Тестовий місяць»: 100 у валюті за замовчуванням, 30 днів, 100 ГБ, 3 пристрої.
4. Створіть другий тариф і вимкніть його. Вимкнений тариф не має з’явитися в кабінеті.

## 4. Купити тариф у кабінеті

1. Відкрийте http://127.0.0.1:18082
2. Зареєструйте новий email і пароль.
3. Відкрийте тарифи і оплатіть «Тестовий місяць». Якщо кнопка не передає провайдера, запит без імені провайдера все одно йде в пісочницю: інших кас у `.env.test` немає.
4. Кабінет повертається з параметром `sandbox_payment`. Завершення викликає `POST /api/payments/sandbox/complete`.
5. У розділі підключення посилання починається з `sandbox://local/`.

Той самий шлях уже виконав `scripts/sandbox-e2e.sh`. Повторна покупка іншим email перевіряє, що вітрина жива.

## 5. Поповнити баланс

У кабінеті, якщо є поповнення гаманця, сума від 50 до 100000. Пісочниця позначає платіж оплаченим і зараховує суму на `wallet_balance`. Повтор із тим самим `Idempotency-Key` не зараховує суму вдруге.

## 6. Чого чекати не варто

- Контейнер бота в тестовому файлі не запускається. Порожній `BOT_TOKEN` у production і далі зупиняє бота, а поза production процес бота просто чекає, якщо його все ж запустили.
- Вузли в `/api/public/servers` можуть бути порожніми. Це нормально без агента і без Remnawave.
- Живий провайдер у цьому контурі відповідає помилкою: ключів кас немає.
- Запит `provider=yookassa` не переписується в пісочницю. Пісочниця обирається сама лише коли провайдера не вказано і жодна жива каса не налаштована, або коли явно передано `sandbox`.

## 7. Якщо запуск не вдався

```bash
docker compose --env-file .env.test -f docker-compose.test.yml logs --tail 80 backend
```

Якщо API не стає готовим, майже завжди видно текст Alembic або `APP_SECRET must be at least 32 characters`. Не ставте в `.env.test` значення `APP_ENV=production`.

# Ограничения релиза

Дистрибутив `v28.56.0`, runtime/API `21.5.1`, миграция магазина `0088_filter_and_regions`.

Документ существует, чтобы продукт не считался полностью проверенным там, где проверки не было.
Каждое ограничение имеет статус и указание, что нужно для его снятия.

## 1. Общее состояние

Код в репозитории проходит все автоматические проверки, доступные без внешних сервисов:
lint, shell-синтаксис, компиляция, 2507 backend-тестов, typecheck и build двух фронтендов,
контракты документации, карта проекта, 88 миграций с единым head.

Внешние интеграции (Remnawave, платёжные провайдеры, Telegram, OAuth, push, Docker, установщик,
ночное автообновление, сборка мобильных приложений, публикация в магазины) **не проверены в живом
режиме** в этом релизе. Причина — отсутствие секретов и доступа к серверу. Это ограничение
проверки, а не заявление о неработоспособности: логика покрыта тестами, но живой цикл не прогонялся.

## 3а. Состояние публикации `v28.56.0`

Раздел переписан по фактическому состоянию GitHub на 2026-10-31: предыдущая редакция описывала
публикацию `v28.55.0` и после смены версии стала неверной.

| Что проверено | Результат |
| --- | --- |
| Тег `v28.56.0` существует | **НЕТ** — `GET /git/ref/tags/v28.56.0` → `404`. Последний тег — `v28.55.0` (`b87d20ac`) |
| Релиз опубликован | **НЕТ** — страница релизов заканчивается на `v28.55.0` (`2026-10-31T18:51:22Z`) |
| `install.sh` по адресу тега `v28.56.0` | **404** — до публикации установка с тега невозможна; используйте `v28.55.0` или `main` |
| Прогон `publish-release.yml` | Gate вернул `ready=false`: на коммите релиза не было успешного `ci.yml`. Упаковка и публикация были **skipped**, workflow при этом отчитался `success` |
| Причина | Группа `concurrency` в `ci.yml`/`docker.yml` была привязана к `github.ref`, поэтому перезапуск CI старого коммита отменял прогон нового. Исправлено: группа `ci-${ref}-${sha}` |

Публикация выполняется автоматически: после зелёных `ci.yml` **и** `docker.yml` на текущем `main`
`publish-release.yml` создаёт тег, упаковывает дистрибутив и публикует релиз. Проверка результата —
`GET /releases/tags/v28.56.0`, а не статус workflow.

Ссылка на релиз после публикации: https://github.com/booarkz-cpu/shop-by-boo/releases/tag/v28.56.0

## 6. Как снять ограничения

1. Выдайте секреты по [TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md](TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md).
2. Пройдите группы по порядку из §15 того же документа.
3. Для серверных ограничений — [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) и
   [AUTO_UPDATE_TESTING.md](AUTO_UPDATE_TESTING.md).
4. Обновите таблицу §2, заменив статус на `PASS` или `FAIL` с датой.

Пока ограничения не сняты, формулировка «продукт полностью проверен» неприменима.

# Версии и журналы изменений

Что в проекте выпускается отдельно, как нумеруется и где записываются изменения.
Документ описывает действующий порядок; каждое правило ниже проверяется тестом или скриптом, который назван рядом.

## Что имеет собственную версию

| Что | Вид версии | Где записана | Где журнал изменений |
| --- | --- | --- | --- |
| Дистрибутив магазина (всё целиком) | `vMAJOR.MINOR.PATCH`, тег и выпуск на GitHub | `backend/app/release_identity.py` (`DISTRIBUTION_TAG`), `release-manifest.template.json` | `CHANGELOG.md`, `docs/ru/RELEASE_V…md` на каждый выпуск |
| Runtime/API магазина | `MAJOR.MINOR.PATCH` | `backend/app/release_identity.py` (`RUNTIME_VERSION`), `backend/app/main.py` (`APP_VERSION`) | Заметки выпуска, в котором версия менялась |
| База магазина | Имя последней миграции | `backend/alembic/versions/` | Заметки выпуска: строка «Head магазина» |
| Support Pro | Номер и имя последней миграции | `support-pro/VERSION`, `support-pro/alembic/` | Заметки выпуска: строка «Support Pro» |
| Приложения магазина и администратора, Android и iOS | Одна версия на всё семейство, `MAJOR.MINOR.PATCH` | `mobile/android-*/app/build.gradle.kts`, проекты Xcode | `MOBILE.md`, раздел «Что нового» |
| «Корги Люси: клиент» для Android | `MAJOR.MINOR.PATCH`, свой выпуск `client-vX.Y.Z` | `apps/vpn-client/android/app/build.gradle.kts` | `docs/ru/new/ANDROID_CLIENT_APP.md` |

## Правила

1. **Версия дистрибутива растёт с каждым изменением, которое должно дойти до установленных магазинов.**
   Выпуск публикуется автоматически после слияния в `main` и зелёного CI.
   Версия дистрибутива и версия runtime независимы: runtime меняется только при изменении API или схемы данных.
2. **Каждый выпуск имеет заметки** `docs/ru/RELEASE_V<версия>.md` с версиями всех частей, списком изменений,
   тем, чем проверено, и тем, чего пока нет. Наличие и согласованность проверяет `scripts/check-current-docs.py`.
3. **Номера версий в документах сверяются с кодом** тем же скриптом: README, заметки, манифест выпуска.
4. **Семейство мобильных приложений меняет версию целиком**: Android и iOS, магазин и администратор —
   `tests/test_mobile_family_status.py`. `versionCode` = версия без точек, умноженная до четырёх знаков (`3.7.0` → `3700`).
5. **Клиент выпускается под своим тегом** `client-vX.Y.Z`; первая сборка версии остаётся неизменной — `tests/mobile-client-release.test.cjs`.
   `versionCode` клиента = версия без точек (`1.9.3` → `193`).
6. **Опубликованный файл выпуска не подменяется** другим содержимым: сборка откажется — `.github/workflows/mobile-release.yml`.
7. **Исторические записи не переписываются**: в журналах и заметках прошлых выпусков остаются прежние номера.

## Как поднять версию дистрибутива

1. Изменить версию во всех местах, где она текущая (README, манифест выпуска, `release_identity.py`, чек-лист).
2. Добавить `docs/ru/RELEASE_V<версия>.md`, запись в начало `CHANGELOG.md`, блок «Новое в» в `README.md`.
3. Перегенерировать `docs/PROJECT_FILE_MAP.md`: `python3 scripts/generate-project-map.py`.
4. Проверить: `python3 scripts/check-current-docs.py` и `python3 scripts/check-doc-links.py`.

## Чего в порядке нет

- Отдельной отметки «ломающие изменения» в заметках выпуска. Такие изменения описываются в общем списке.
- Подписи архива дистрибутива ключом владельца. Есть контрольные суммы SHA-256 и, начиная с v28.122.0,
  аттестация происхождения GitHub (`gh attestation verify`).

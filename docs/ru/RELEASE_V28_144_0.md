# Релиз v28.144.0 — установка по этапам, совместимость версий, последняя проверенная копия не удаляется

Дистрибутив: `v28.144.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-14. Раздел реестра «Инфраструктура, установщик, копии», продолжение.

## Установка по этапам (REQ-INFRA-0008)

Установщик (`deploy/install-vps.sh`) записывает в `/var/log/vpn-shop-install.json` (путь меняется переменной
`INSTALL_STATUS`), где он сейчас: проверка сервера → ответы на вопросы → системные пакеты и Docker → файлы выпуска →
`.env` и секреты → порты и firewall → сборка образов → запуск служб → API и миграции → первый оператор → итог.
У каждого этапа — состояние (`pending`, `running`, `done`, `failed`) и время; при сбое — этап и понятная причина
(сообщение установщика или строка, на которой он упал). В конце установщик печатает путь к этому файлу.

Остаток: повтор установки с середины не поддержан — запуск поверх частичной установки останавливается и предлагает
`deploy/build-production.sh`. Поэтому требование отмечено как PARTIAL.

## Совместимость версий при обновлении (REQ-INFRA-0009)

В манифесте выпуска появилось поле `min_upgrade_from` — самая старая установленная версия, с которой на этот выпуск
можно перейти за один шаг. Если установка старше, обновление отказывает до любых изменений и пишет, до какой версии
обновиться сначала (`RELEASE_TAG=v…`). Сейчас это `28.0.0`: все установки серии 28 обновляются напрямую.

## Последняя проверенная копия не удаляется (REQ-INFRA-0037)

Найдена ошибка: срок хранения копий в панели оставлял N самых новых и удалял остальные подряд. Если после копии,
прошедшей проверку восстановления, делались непроверенные, проверенная могла удалиться. Теперь последняя проверенная
копия остаётся всегда, даже если она старше срока.

# Выпуск v28.43.0 — кассы Cashera и ParityPay

Дистрибутив: `v28.43.0`. Runtime/API: `21.5.1`. Head магазина: `0081_subscription_proxy` (новых миграций нет). Support Pro: `0008` / 3.8. Мобильные приложения: 3.4.0. Дата и commit фиксируются тегом выпуска.

## Что изменилось

**Кассы Cashera и ParityPay** — «Платёжные агенты»

- Карта и СБП через Cashera и ParityPay, только разовые платежи. Касса встаёт в очередь касс и в выбор способа оплаты, как только заданы ключи: в «Система → Настройки без перезапуска» (секреты хранятся зашифрованно) или в `.env`.
- Как магазин проверяет подлинность уведомлений:
  - Cashera — заголовки `X-Api-Key` и `X-Secret`, сверка в постоянном времени, при неверных ответ 401;
  - ParityPay — подпись HMAC-SHA256 ключом №2 по значениям полей.
- Подписка выдаётся только после повторной проверки платежа в API кассы: статус, заказ, сумма. У Cashera сумма сверяется в копейках, валюта тоже.
- Реестр настроек: 224 поля, из них 132 live (+5 ключей касс).

**Исправление AuraPay**

- Подпись уведомления считается по значениям ровно в том виде, в каком их прислала касса. Раньше целая сумма `1200` превращалась при разборе в `1200.0`, и такая подпись не сходилась.

Подробно — [billing_and_taxes.md](../modules/billing_and_taxes.md#cashera-и-paritypay-v2843), что сделать владельцу — [OWNER_ACTIONS.md](OWNER_ACTIONS.md).

## Проверки

- `tests/test_payments_cashera_paritypay.py`: страница оплаты, сумма в копейках, статические учётные данные Cashera, подпись ParityPay и AuraPay по исходным значениям, повторная проверка платежа, отказ при неверных данных — на моках.

## Не вошло

# Выпуск v28.19.0 — допуск реальных платежей (staging E2E v2)

Дистрибутив: `v28.19.0`. Runtime/API: `21.5.1`. Head магазина: `0073_e2e_v2`. Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

## Что завершено

Реализован контракт сквозной проверки оплаты, без которого реальные платежи открыть было нельзя. [Инструкция](STAGING_E2E_V2_IMPLEMENTATION.md).

### Стенд (`APP_ENV=staging`)

Для каждой выбранной платёжной системы магазин сам проводит настоящий заказ и проверяет его по своим записям:

1. заказ через обычный `POST /api/payments/create` служебным покупателем стенда;
2. повтор с тем же `Idempotency-Key` не создаёт второй заказ;
3. администратор оплачивает заказ на странице песочницы провайдера;
4. подписанный webhook этого заказа получен и обработан во время проверки. Опрос провайдера или ручная отметка «оплачено» этот этап не проходят;
5. независимая сверка с провайдером: сумма, валюта, номер заказа;
6. выдача: одна операция, подписка, пользователь Remnawave найден по ID, срок совпадает;
7. тот же подписанный webhook повторяется дважды одновременно, состояние не меняется;
8. поддельные webhook отклоняются: чужой адрес отправителя (YooKassa) или неверная подпись (Platega, RollyPay) дают HTTP 4xx, изменённые ID или сумма ничего не меняют;
9. возврат обычным кодом возвратов магазина (`request → approve → execute → reconcile`), одна запись возврата в журнале;
10. повторный возврат не создаёт вторую операцию у провайдера;
11. доступ в Remnawave отключён, подписка магазина закрыта;
12. повтор старого webhook об успехе после возврата ничего не возвращает.

Повтор webhook идёт через приложение магазина с исходными заголовками и адресом отправителя, поэтому проходит ту же проверку подписи и IP, что и настоящий. Тело и заголовки хранятся зашифрованными только до конца проверки.

Итог вычисляет сервер и подписывает Ed25519-ключом стенда. Одновременно идёт одна проверка. Прерванная перезапуском проверка помечается неудачной, ничего не публикует и не может стать «пройдена».

### Рабочий сервер

- Ключ стенда и платёжные системы сохраняются отдельно от проверки v1. Новая ревизия закрывает платежи.
- «Получить код запуска» выдаёт одноразовый код для текущей ревизии.
- Результат принимается, только если:
  - подпись сделана ключом стенда;
  - в результате этот код;
  - стенд работает на той же версии дистрибутива;
  - все выбранные системы прошли все 11 этапов;
  - результату не больше 24 часов, и он не из будущего.
- Ключ шлюза сменён на `payments.production_gate.v2`: флаг, сохранённый прежними версиями, платежи не открывает.
- Каждый новый платёж, пополнение кошелька и автопродление перепроверяют результат. Через 24 часа платежи закрываются до свежей проверки.

### Антифрод

- Решения по сигналам в панели: «Ложная тревога», «Мошенничество», «Открыть снова», заметка пишется в журнал действий, фильтр по статусу.
- Повторное сканирование не создаёт дубль, пока у клиента есть открытый сигнал того же типа.

## API

- Стенд: `GET /api/admin/e2e-v2/overview`, `POST /api/admin/e2e-v2/runs`, `POST /api/admin/e2e-v2/runs/{id}/cancel`.
- Рабочий сервер: `PUT /api/admin/e2e-v2/admission/config`, `POST /api/admin/e2e-v2/admission/nonce`, `POST /api/admin/e2e-v2/admission/attestation`; `POST /api/admin/payments/production-gate` проверяет результат v2.
- `GET /api/admin/fraud` отдаёт `resolved_at`.

## Обновление

Миграция `0073_e2e_v2` добавляет таблицы `e2e_runs`, `e2e_cases`, `e2e_webhook_captures`. Используйте [проверяемый регламент обновления](DISTRIBUTION_UPGRADE_CURRENT.md):

```bash
cd /opt/vpn-shop && bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.19.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

После обновления реальные платежи закрыты, даже если раньше ворота были открыты. Чтобы открыть их, поднимите стенд той же версии и пройдите [допуск](STAGING_E2E_V2_IMPLEMENTATION.md).

Ожидаемые head: магазин `0073_e2e_v2`, Support Pro `0008`.

## Границы выпуска

- Оплату в песочнице провайдера выполняет человек.
- Пополнение кошелька и автопродление своих сквозных сценариев не имеют: они проходят через тот же шлюз, но перед первым днём продаж сделайте настоящую покупку своей картой и возврат.
- Недоступность Remnawave и очередь повторов выдачи проверяются автотестами, а не на стенде.
- Проверку с вашими кассами проходит каждая установка; манифест выпуска сохраняет `production_e2e_verified=false`.

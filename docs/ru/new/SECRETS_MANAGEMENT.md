# Управление секретами

## Где что хранится

| Секрет | Где | Как защищён | Как меняется |
| --- | --- | --- | --- |
| `APP_SECRET` (подпись сессий, ключ шифрования секретов в БД) | `.env` на сервере | файл 600, вне Git | `bash scripts/rotate-secrets.sh`: новый ключ, прежний — в `APP_SECRET_PREVIOUS`, токены и шифр читаются обоими до перешифровки |
| Пароли PostgreSQL, Redis | `.env` | файл 600; базы наружу не открыты | вручную в `.env` и в базе, затем `docker compose up -d` |
| Ключи касс, Remnawave, почта, Cloudflare, `BOT_TOKEN`, S3 | «Настройки без перезапуска» (или `.env`) | в БД — AES-256-GCM ключом `APP_SECRET`; в ответах API не показываются | там же; применение требует [подтверждения](RBAC.md#подтверждение-опасных-действий-step-up) |
| SSH-доступ к серверам мастера | `remnawave_servers.ssh_secret` | AES-256-GCM; в API не возвращается | «Установка Remnawave → Сменить ключ» (ниже) |
| Секреты панели Remnawave (пароль администратора, токен API, пароль БД) | `remnawave_installations.secrets` | AES-256-GCM; пароль показывается только по запросу с подтверждением | переустановка |
| TOTP администраторов, коды восстановления | `admin_users` | AES-256-GCM | «Защита и 2FA» |
| Резервные копии магазина | том `backup_data` | `openssl aes-256-cbc -pbkdf2` паролем из настроек (по умолчанию включено) | «Резервные копии» |
| Копии базы панели Remnawave в магазине | `backup_data/remnawave/` | AES-256-GCM ключом `APP_SECRET`; скачивание — с подтверждением | автоматически при обновлении панели |
| Журналы контейнеров в браузере | `.control/logs/` | значения секретов из `.env` заменены на `***` агентом до записи | — |
| `METRICS_TOKEN` | `.env` | сравнение `compare_digest`; без него `/metrics` отвечает 503 | `.env` |

Секреты никогда не пишутся в журнал действий, журналы шагов мастера (маскируются) и ответы API.

## SSH-ключи серверов мастера

Каждый сервер получает свой ключ Ed25519, созданный магазином. Как сменить ключ:

1. «Серверы → Установка Remnawave» → строка сервера → **Сменить ключ** (право `provision_nodes` и подтверждение кодом 2FA или паролем).
2. Магазин дописывает новый открытый ключ в `~/.ssh/authorized_keys` пользователя SSH с пометкой `corgi-shop-<сервер>-<время>-<хвост>`.
3. Магазин входит новым ключом и проверяет `sudo`. Если войти не удалось, новая строка убирается, доступ остаётся прежним.
4. Строка прежнего ключа магазина удаляется по своей пометке. **Ключи владельца не трогаются.**
5. Новый закрытый ключ сохраняется зашифрованным. Если магазин входил по паролю, пароль больше не хранится. Вход по паролю на сервере можно отключить: `PasswordAuthentication no`.

В строке сервера видны отпечаток ключа магазина и его возраст. После 180 дней строка подсвечивается. Серверы, где магазин входит ключом или паролем владельца или ключом старше 180 дней, считает метрика `vpnshop_rw_ssh_key_rotation_due` (правило `VpnShopSshKeyRotationDue`). Каждая смена записывается в «Историю безопасности».

Отпечаток ключа **самого сервера** (host key) обязателен при добавлении в реестр: без совпадения магазин к серверу не подключится.

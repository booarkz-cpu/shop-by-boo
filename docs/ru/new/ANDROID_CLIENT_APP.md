## Отдельность от существующих приложений

| | Клиент магазина | Админка | **Корги Люси: клиент** |
| --- | --- | --- | --- |
| Каталог | `mobile/android-user` | `mobile/android-admin` | `mobile/android-client` |
| `applicationId` | `shop.remnawave.user` | `shop.remnawave.admin` | `shop.corgi.client` (отладочная сборка — `.preview`) |
| Сборка в CI | `ci.yml`, `android-vpn-e2e.yml` | `ci.yml` | `android-client.yml` (своя) |
| Вход в магазин | да | да | нет: подписка, ссылки или JSON |

Код существующих приложений, их ключи, выпуски и имена файлов не меняются. Движок общий только как файл: `libv2ray.aar` собирается тем же `scripts/mobile/build-xray-aar.sh` (кэш общий) и копируется в `mobile/android-client/app/libs`. Код движка (`engine/Xray.kt`) и разбора ссылок написан для клиента отдельно — так изменения в нём не могут сломать сборку клиента магазина.

## Почему не форк INCY

Репозиторий `INCY-DEV/incy-platforms` (проверен 2026-11-05, коммит `6d2d0c3`) содержит только ссылки на сборки, манифест версий и настройки Obtainium; исходного кода приложения и лицензии там нет, само приложение закрытое. Поэтому код, значки и название не берутся: приложение написано с нуля на нашем движке, по функциям, которые INCY описывает публично.

## Версия 1.7.2 — доверенные Wi-Fi (N12, фаза 2)

- **«Подключение» → «Доверенные Wi-Fi»**: имена сетей (SSID, до 20), в которых туннель встаёт на паузу — например, домашний Wi-Fi. В мобильной сети и любом другом Wi-Fi туннель сразу включается снова, но только если паузу поставила эта функция: выключенный вручную VPN сам не включится.
- Срабатывает по системному сигналу смены сети (`NetworkReceiver`, тот же, что «Подключаться при смене сети»), даже когда приложение закрыто.
- Имя Wi-Fi Android отдаёт только с доступом к геолокации, в фоне — с «Разрешить всегда» (`ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`). «Добавить текущую сеть» спрашивает разрешение; имя можно вписать и вручную.
- Проверки: `TrustedNetworksTest` — пауза в доверенной сети, возврат только после своей паузы, без списка — ничего, имя сети как его отдаёт Android, сохранение и ограничения списка.

## Версия 1.7.1 — Smart Failover (N12, фаза 2)

- **«Подключение» → «Авто-переключение»**: раз в 10 секунд «URL проверки» открывается через туннель (служебный SOCKS-вход Xray с паролем этого подключения). Если выбранный сервер не отвечает дольше заданного — 15, 30, 60 или 120 с, — клиент записывает это в журнал, выбирает самый быстрый другой сервер провайдера по последним замерам пинга (без замеров — следующий в списке) и поднимает туннель заново, без участия пользователя. По умолчанию выключено.
- Для «Автовыбора» не нужен: там уже работает балансировщик Xray. Для полного JSON-конфига и подписок с готовыми конфигами переключение не выполняется.
- Проверки: `FailoverTest` — переключение только после тайм-аута без ответов, ответ сбрасывает счёт, выбор самого быстрого другого сервера, без замеров — следующий, «Автовыбор» и один сервер — без переключения, сохранение настроек.

## Версия 1.7.0 — DNS и порядок правил (N12, фаза 1)

- **«Подключение» → «DNS · MTU»**: «Локальный DNS для сайтов напрямую» — домены, которые идут мимо VPN («РФ напрямую», свои правила «direct»), спрашиваются у него (например `77.88.8.8` или `https+local://dns.yandex/dns-query`), остальные — у удалённых DNS через туннель. Принимаются адреса, которые понимает Xray: IP, `localhost`, `https://`, `https+local://`, `tcp://`, `tcp+local://`, `quic+local://`.
- **FakeDNS**: приложения сразу получают адрес из `198.18.0.0/15`, сниффинг возвращает по нему домен, настоящий запрос делает сервер — быстрее первые загрузки и нет утечек DNS. Запросы устройства на порт 53 при этом отвечает DNS Xray (`dns-out`); собственные запросы Xray к DNS-серверам в петлю не попадают.
- **Стратегия доменов**: «Авто» (как раньше: IPIfNonMatch с geo-файлами, AsIs без них), AsIs, IPIfNonMatch, IPOnDemand.
- **«Маршрутизация» → «Порядок: блок → прокси → напрямую»** — свои правила применяются в этом порядке, иначе — как записаны.
- Проверки: `DnsSettingsTest` (по умолчанию ничего не меняется; FakeDNS — пул, сниффинг, `dns-out` только для входов устройства; локальный DNS только для доменов «напрямую»; стратегия; порядок правил; проверка адресов и сохранение настроек).

## Скачать и обновлять

- APK: [corgi-lusi-client.apk](https://github.com/booarkz-cpu/shop-by-boo/releases/latest/download/corgi-lusi-client.apk) — в каждом выпуске магазина, подписан ключом `corgi`; рядом `corgi-lusi-client.apk.sha256` и манифест `corgi-lusi-client.json`.
- [Obtainium](https://github.com/ImranR98/Obtainium): «Добавить приложение» → адрес `https://github.com/booarkz-cpu/shop-by-boo` → «Фильтр APK по регулярному выражению»: `^corgi-lusi-client\.apk$` → сохранить. Obtainium сам проверит новые выпуски.
- **Свой выпуск клиента** (с v28.89.0): на каждую новую версию клиента «Mobile packages» создаёт выпуск `client-v<версия>` (например, `client-v1.4.0`) с тем же APK, `.sha256` и манифестом, ссылка которого ведёт на этот выпуск. Он никогда не становится «последним выпуском» — ссылки `releases/latest/download/…` магазина не меняются. Чтобы Obtainium следил только за клиентом, добавьте ещё «Фильтр названий выпусков»: `^client-v`.

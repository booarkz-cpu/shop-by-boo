# Установка магазина

Терминал нужен один раз: для первого развёртывания контейнеров магазина. Остальное делается в админке: настройки без перезапуска, обновления, Remnawave, резервные копии.

## Требования

| Что | Минимум |
| --- | --- |
| ОС | Ubuntu 22.04 / 24.04 / 26.04 или Debian 12 / 13 (другие — с предупреждением) |
| Ресурсы | 2 CPU, 4 ГБ RAM, 30 ГБ диска |
| Доступ | root по SSH; домены магазина, указывающие на сервер (A/AAAA) |
| Порты | 80 и 443 (Caddy), 25 — только если включён приём почты |

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28/install.sh | sudo bash
```

`install.sh` ставит `git`, `curl` и Docker (`deploy/install-docker.sh`), клонирует выпуск в `/opt/vpn-shop-src` и передаёт работу `deploy/install-vps.sh`. Тот выполняет такие шаги:

1. **Проверка системы:** ОС, root, свободные порты, наличие терминала для вопросов. Без терминала нужно задать `INSTALL_NONINTERACTIVE=1` и переменные окружения.
2. **Конфигурация:** спрашивает домены, e-mail для Let's Encrypt, токен бота и порт SSH. Генерирует секреты (`APP_SECRET`, пароли баз). Пишет `.env` с правами 600 (`scripts/harden-env.py`).
3. **Фаервол:** открывает порт SSH, 80 и 443. PostgreSQL, Redis, API и панели наружу не открываются.
4. **Образы:** закрепляет базовые образы по digest (`scripts/pin-images.sh`, файл `.env.images`).
5. **Сборка и запуск:** `deploy/build-production.sh`, ожидание API и миграций (`alembic upgrade head` при старте backend).
6. **Support Pro:** создаёт первого оператора и показывает TOTP.
7. **Автообновление:** включает агент `scripts/auto-update.sh install` ([AUTO_UPDATE.md](AUTO_UPDATE.md)).

Повторный запуск установщика на установленном магазине ничего не ломает: `install.sh` откажется заменять каталог с другим выпуском и предложит обновление.

## Диагностика

| Команда | Что проверяет |
| --- | --- |
| `bash scripts/preflight.sh` | синтаксис скриптов, сборку Python, закреплённые digest, `docker compose config` |
| `bash scripts/doctor.sh` | контейнеры, `/health/ready` API, ответ админки, кабинета и Mini App |
| Админка → «Состояние системы» | все части магазина по отдельности ([руководство по панели](ADMIN_PANEL_GUIDE.md#состояние-системы-system-control-center)) |
| Админка → «Automation Center» | вся автоматика ([AUTOMATION_CENTER.md](AUTOMATION_CENTER.md)) |

## Обновление, резервные копии и восстановление

| Что | Из админки | С сервера (если админка недоступна) |
| --- | --- | --- |
| Обновить магазин | «Обновления → Проверить и обновить сейчас» | `sudo bash scripts/auto-update.sh run` |
| Откат | автоматически при сбое обновления | `sudo bash scripts/rollback.sh` (последний снимок) |
| Резервная копия | «Резервные копии»: расписание, «Создать», проверка, загрузка в Telegram | `bash scripts/backup.sh` |
| Восстановление | «Резервные копии → Восстановить» (с подтверждением) | — |
| Remnawave | «Обновления → Автообновление Remnawave» | — |

Снимки обновлений лежат в `.rollback/`. Секретов (`.env`) в них нет. `.env` и каталог `.control` агента автообновления сохраняются и при обновлении, и при откате.

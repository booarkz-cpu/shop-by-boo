# Правила подписки панели Remnawave

С v28.69.0 (этап 12). «Серверы → Расширения Remnawave → Правила подписки». Это настройки подписки самой панели (`/api/subscription-settings`); правила прослойки и портала магазина описаны в [SUBSCRIPTION_SECURITY](SUBSCRIPTION_SECURITY.md) и [SUBSCRIPTION_PORTAL](SUBSCRIPTION_PORTAL.md).

## 1. Правила ответа (SRR)

Правила ответа подписки (`responseRules`) решают, что получит клиент. Правило — условия по заголовкам запроса (User-Agent и другие), оператор и тип ответа:

| Тип ответа | Что получает клиент |
| --- | --- |
| `XRAY_JSON`, `XRAY_BASE64`, `MIHOMO`, `STASH`, `CLASH`, `SINGBOX` | Подписку в формате, по шаблону подписки этого типа |
| `BROWSER` | Страницу подписки для браузера |
| `BLOCK`, `STATUS_CODE_404`, `STATUS_CODE_451` | Отказ с кодом 403, 404 или 451 |
| `SOCKET_DROP` | Обрыв соединения |

Операторы условий: `EQUALS`, `NOT_EQUALS`, `CONTAINS`, `NOT_CONTAINS`, `STARTS_WITH`, `NOT_STARTS_WITH`, `ENDS_WITH`, `NOT_ENDS_WITH`, `REGEX`, `NOT_REGEX`.

Правила правятся как JSON (версия конфигурации `1`). Схему проверяет панель.

**Проверка правил.** Введите User-Agent и нажмите «Проверить правило»: панель (`POST /api/system/testers/srr-matcher`) показывает, сработало ли правило, какое и какой будет ответ. Ничего не сохраняется.

Пример — старые клиенты получают отказ. Это пример панели «Block Legacy Clients»; вставьте его в JSON и поправьте User-Agent.

## 2. Лимит устройств (HWID)

`hwidSettings` — включён ли лимит устройств и запасной лимит для пользователей без своего. Лимиты тарифов Lucy (`hwidDeviceLimit` пользователя) работают, только когда лимит здесь включён.

## 3. Заголовки и хосты

- `customResponseHeaders` — свои заголовки ответа подписки для всех клиентов. Имя — латиница, цифры, `_`, `-`; значение — одна строка до 500 символов.
- «Перемешивать хосты» — `randomizeHosts`: порядок серверов в подписке случайный.

## 4. Где правила работают

- Ссылка панели — правила SRR.
- Ссылка через прослойку магазина — прослойка запрашивает подписку у панели с заголовками клиента, поэтому SRR тоже работают. Браузер прослойка обслуживает сама (портал), до панели он не доходит.

## 5. Проверено

- `tests/test_rw_extensions.py` — тело запроса, заголовки тестера.
- `tests/live/test_remnawave_live.py::test_extensions_plugins_srr_pages_and_templates` — настоящая панель: заголовок сохраняется, тестер отвечает на правила панели.

# Тестирование платежей

Тестирование добровольное: установщик и выпуск не делают тестовых списаний. Реальные деньги списываются только с разрешения владельца. Sandbox и рабочие ключи не смешиваются: у касс с тестовым режимом это отдельные ключи или отдельная настройка, а sandbox магазина в production не включается (`runtime_security.py` останавливает запуск).

## Что проверяется в CI без ключей

| Набор | Что проверяет |
| --- | --- |
| `tests/test_payment_contract.py` | каждая касса реестра: другая касса и другая сумма отклоняются, неподтверждённая оплата не выдаётся (503), подтверждённая выдаётся один раз, повтор — `duplicate`, неудачная выдача уходит на повтор; журнал уведомлений |
| `tests/test_payments_*.py`, `test_cryptobot.py`, `test_tribute.py` | подписи уведомлений каждой кассы, разбор статусов, отказ на неверную подпись |
| `tests/test_behaviour_payments*.py`, `test_money_review.py` | создание заказа, идемпотентность, сверка, возвраты |
| `tests/test_sandbox_*.py` | sandbox магазина: оплата, отмена, возврат, автоплатёж |
| `tests/test_cloudpayments_refund_recurring.py`, `test_external_refund.py` | возвраты через API и из кабинета кассы |
| `tests/test_payment_fraud.py` | антифрод |

## Живая проверка кассы (когда есть sandbox-ключи)

1. **Ключи.** Введите тестовые ключи кассы в «Настройках без перезапуска», адрес уведомлений в кабинете кассы — `https://<домен API>/api/webhooks/<код кассы>`.
2. **Проверка ключей.** «Кассы → Здоровье касс → Проверить кассы сейчас» — в строке кассы должно быть «✅».
3. **Сценарии.** Пройдите их по очереди, после каждого смотрите «Кассы → Журнал уведомлений» и «Платежи».

| Сценарий | Как | Ожидаемый результат |
| --- | --- | --- |
| Успешная оплата | купить тариф тестовой картой кассы | событие «обработано», подписка выдана, чек записан |
| Неуспешная оплата | тестовая карта с отказом | заказ `failed`, подписки нет |
| Отмена | закрыть страницу оплаты или отменить в кассе | заказ не оплачен, подписки нет |
| Истечение сессии | не платить до истечения срока счёта | заказ закрыт сверкой |
| Повторное уведомление | «отправить повторно» в кабинете кассы | событие то же, второй выдачи нет |
| Неверная подпись | отправить уведомление с изменённым телом (`curl`) | «Отклонённые»: HTTP 403 |
| Задержка подтверждения | касса шлёт уведомление раньше, чем статус «оплачен» | 503, касса повторяет; выдача — после подтверждения |
| Выдача подписки | после оплаты | пользователь в Remnawave, срок и устройства по тарифу |
| Повторная синхронизация | «Платежи → Повторить выдачу» | выдача не удваивается |
| Возврат | «Возвраты» (касса с API) или кабинет кассы | доступ отозван, запись в финансовом журнале |

4. **Отметка.** Запишите результат в [PAYMENT_INTEGRATION.md](PAYMENT_INTEGRATION.md): поменяйте `BLOCKED_SECRETS` на `PASS` или `FAIL` с датой.

Полная инструкция по всем внешним проверкам — [TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md](../../TESTING_GUIDE_EXTERNAL_DEPENDENCIES.md).

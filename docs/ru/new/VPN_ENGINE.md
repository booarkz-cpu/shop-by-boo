# VPN Engine: сравнение и выбор

Задача этапа 17: выбрать движок по сравнению, не писать свой протокол и не выдавать макет за приложение. Сравнивались **Xray-core** и **sing-box** — два движка, которые умеют VLESS с REALITY и собираются для Android и iOS.

## Сравнение

| Критерий | Xray-core | sing-box |
| --- | --- | --- |
| Лицензия | MPL-2.0 (копилефт на уровне файлов: код приложения может оставаться закрытым, изменения самих файлов движка публикуются) | GPL-3.0 (приложение, связанное с движком, распространяется под GPL-3.0) |
| Совместимость с Remnawave | панель и ноды Remnawave работают на Xray: те же протоколы, транспорты и параметры, что выдаёт подписка | поддерживает основные протоколы, но формат конфигурации свой: подписку нужно переводить, часть новых транспортов Xray появляется с задержкой |
| VLESS, REALITY | да | да |
| Android (VpnService) | `libv2ray.aar` (AndroidLibXrayLite, LGPL-3.0, отдельная `.so` — заменяема), туннель tun2socks | `libbox.aar`, встроенный TUN-стек |
| iOS (Network Extension) | Xray-core + hev-socks5-tunnel (MIT) в расширении `CorgiTunnel` | `Libbox.xcframework`, встроенный TUN-стек |
| Ограничение памяти расширения iOS | оба на Go; уложиться помогают ограничение памяти Go и отказ от тяжёлых правил маршрутизации | то же |
| Состояние в проекте | интегрирован (Android — `CorgiVpnService`, iOS — `CorgiTunnel`), сборка в CI из закреплённых коммитов | не интегрирован |

## Решение

**Xray-core.** Причины:
1. Сервер — Xray (Remnawave): клиент на том же движке понимает подписку без перевода.
2. MPL-2.0 не требует открывать код приложения магазина. GPL-3.0 у sing-box потребовал бы распространять приложение под GPL-3.0.
3. Движок уже встроен и собирается в CI. Переход на sing-box — переписать туннель на обеих платформах без выигрыша для пользователя.

Свой протокол не пишется. Без встроенного движка (сборка без `libv2ray.aar` или без расширения iOS) приложение честно передаёт подписку в совместимый клиент: Happ, v2rayNG, Hiddify, v2RayTun, Streisand.

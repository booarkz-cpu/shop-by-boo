# Интерфейс: правила и компоненты

Правила для админ-панели (`apps/lucy-admin/web/`), личного кабинета и Mini App (`apps/user-cabinet/`). Дизайн-система называется «Remna Dark»: тёмная тема по умолчанию и светлая по выбору; стиль — современный SaaS в духе Material Design. Соблюдение правил проверяют тесты, перечисленные в конце.

## Цвета и шрифты

| Роль | Тёмная тема | Где задано |
| --- | --- | --- |
| Фон страницы | `#090D16` (`--bg`) | `apps/lucy-admin/web/src/theme.css`, `apps/user-cabinet/src/style.css` |
| Карточки, панели | `#0F172A` (`--surface`, `--panel`) | там же |
| Вложенные поверхности | `#131C31` (`--surface-2`), `#1A2540` (`--surface-3`) | там же |
| Линии | `#1E293B` (`--line`) | там же |
| Текст / вторичный текст | `#E2E8F0` (`--text`) / `#94A3B8` (`--muted`) | там же |
| Акцент | синий `rgb(59 130 246)` (`--primary`), наведение `#60A5FA` | там же |
| Статусы | `--success`, `--warning`, `--danger` с фонами `*-bg` | там же |
| Текст интерфейса | Inter (`--font-sans`) | шрифт в пакете приложения, `@fontsource-variable/inter` |
| ID, ключи, хэши, код | JetBrains Mono (`--font-mono`, класс `.mono`, `<code>`) | `@fontsource-variable/jetbrains-mono` |

Цвет в компонентах берётся только из переменных: так светлая тема (`:root[data-theme="light"]`) меняет всё сразу. Шрифты лежат в пакетах приложений и не загружаются с внешних CDN.

## Каркас

- **Админ-панель** (`apps/lucy-admin/web/src/admin-shell.tsx`):
  - слева меню из групп разделов (`apps/lucy-admin/web/src/sections.ts`), на компьютере его можно свернуть до значков;
  - на телефоне меню становится выдвижной панелью;
  - быстрый поиск раздела — `⌘K`.
  - Все разделы с описаниями собраны на странице «Все разделы»; 30 модулей задания — в «Система → Админ-центр».
- **Кабинет и Mini App**: на телефоне одна колонка и нижняя панель вкладок, от 960 px — боковое меню.
- **Ширины экрана:**
  - 380 и 430 px — узкие телефоны;
  - 720–760 px — телефоны и маленькие планшеты;
  - 900–1280 px — планшеты и ноутбуки;
  - 960 px — переход кабинета на боковое меню.
  - Ни один раздел не прокручивается по горизонтали на ширине 390 px; широкие таблицы прокручиваются внутри `.table-wrap`.

## Компоненты

| Компонент | Где | Правило |
| --- | --- | --- |
| Карточка | `.card` | Один блок — одна задача; заголовок `h3`, пояснение `.muted` |
| Таблица | `Table` в `apps/lucy-admin/web/src/main.tsx`, `.table-card` + `.table-wrap` | Поиск по строкам, страницы по 20, пустое состояние «Здесь пока нет записей» |
| Поле формы | `<label className="field">` | У каждого поля подсказка по клавиатуре и касанию (`components/field-hints.tsx`) |
| Выбор из списка | `components/select-field.tsx`, `components/ui/select.tsx` | Работает с клавиатуры |
| Фильтры | `.filters` | Сетка полей, кнопка «Найти»; поиск запускается и по Enter |
| Статус | `components/ui/status.tsx` (`StatusBadge`, `StatusDot`) | Тона `ok`, `warn`, `danger`, `idle`, `info`; цвет дублируется текстом |
| Уведомление | `toast(...)` в разделах | Коротко о результате действия |
| Окно поверх страницы | `role="dialog"` + `aria-modal="true"` (быстрый поиск) | Закрывается по Esc и щелчку вне окна |
| Состояния блока | `components/ui/state.tsx` | См. ниже |

## Состояния

У каждой страницы и каждого блока с данными есть все состояния. Пустого чёрного экрана и бесконечной загрузки после ошибки быть не должно.

| Состояние | Как выглядит | Реализация |
| --- | --- | --- |
| Loading | скелет раздела или «Загрузка…» в карточке | `SectionSkeleton`, `LoadState` |
| Empty | что пусто и что сделать дальше | строка таблицы «Здесь пока нет записей», `EmptyState` |
| Error | причина от сервера и кнопка «Повторить» | раздел: «Не удалось загрузить раздел» + «Ответ сервера» + «Повторить загрузку»; блок: `LoadState error onRetry` |
| Success | зелёная строка или уведомление | `SuccessNote`, `toast` |
| Disabled | кнопка или поле приглушены, курсор «нельзя», рядом объяснение причины | `button:disabled`, текст причины рядом |
| Retry | повтор без перезагрузки и без потери введённых данных | `onRetry`, `load()` раздела |

Ошибка отрисовки не гасит всю панель:
- у каждого раздела есть своя граница ошибок (`AdminErrorBoundary`);
- у приложений целиком — `app/error.tsx`.

Ответы сервера тоже понятны интерфейсу (`docs/ru/new/API.md`):
- непредвиденная ошибка приходит в JSON с кодом запроса;
- если Remnawave не настроен, сервер отвечает 503 с объяснением, что указать;
- если панель Remnawave не ответила — 502.

## Как добавить раздел админки

1. Описать раздел в `apps/lucy-admin/web/src/sections.ts`: группа, `tab`, название и одно предложение описания.
2. Добавить `tab` в тип `Tab`, значок в `NavIcon` и адрес первоначальной загрузки в `load()` (`apps/lucy-admin/web/src/main.tsx`).
3. Написать компонент в отдельном файле и подключить его в переключатель разделов. Состояния — через `components/ui/state.tsx`.
4. Если раздел относится к одному из 30 модулей задания, добавить его в `MODULES` (`backend/app/admin_center.py`) и пересоздать `ADMIN_CONTROL_MATRIX.md`.

## Разделы Remnawave, портала подписки и установки (v28.61.0)

Раньше раздел «Серверы» вмещал 11 разных блоков. Теперь он разделён:

| Раздел | Что в нём |
| --- | --- |
| Серверы | Узлы, автомасштабирование, прогноз нагрузки, пул WireGuard, фильтр рекламы |
| Remnawave: панель | Профили конфигурации, хосты, внутренние сквады, статистика вызовов API панели |
| Портал подписки | Прослойка подписок на своём домене, правила для приложений, блокировка устройств, каталог клиентов, журнал выдачи |
| Доступность и качество | Проверки доступности, RIPE Atlas, качество подключений, скорость у клиентов |
| Мониторинг | Только проверки доступности сервисов и версии компонентов |

Мастера установки Remnawave (этап 10) и менеджера доменов (этап 11) в интерфейсе пока нет: их нет и в backend. Макет без работающей функции в панель не добавляется. Их место и этапы показаны в «Админ-центре».

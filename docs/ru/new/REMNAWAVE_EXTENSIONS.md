# Менеджер расширений Remnawave

Этап 12. Раздел «Серверы → Расширения Remnawave» (`admin/src/rw-extensions.tsx`), backend — `backend/app/rw_extensions.py`, маршруты `/api/admin/rw/extensions/...`. Всё управляется из админки, без SSH и терминала.

Функции, которые есть в API панели Remnawave, вызываются через API панели: состояние хранит сама панель, магазин её не дублирует. Функции на сервере ноды (SelfSteal, IPv6, ядро Xray, WARP, NetBird, Xray Checker) выполняет мастер установки по SSH закрытым списком шагов ([DEPLOYMENT_AGENT](DEPLOYMENT_AGENT.md)).

Источник списка функций — `eGamesAPI/remnawave-reverse-proxy` (MIT, Copyright (c) 2025 eGames): меню «Расширения ноды», «Подписки: правила и страница», WARP, IPv6, Xray Checker, NetBird. Код скрипта не переносился: реализация своя, по API панели и шагам мастера.

## 2. Профили конфигурации

- **Список:** каждый профиль, его inbound (тег, протокол, порт) и ноды, которые его используют. Профиль, занятый нодами, не удаляется.
- **Конфигурация:** «Конфигурация» показывает JSON профиля. Сохранение отправляет его в панель (`PATCH /api/config-profiles`); панель проверяет конфигурацию и перезапускает ноды профиля.
- **Назначить нодам:** для каждой ноды выбирается inbound профиля (`PATCH /api/nodes`, `configProfile`).
- **Хост:** `POST /api/admin/rw/extensions/profiles/{uuid}/host` создаёт хост панели для inbound — адрес и SNI, которые получат клиенты. Остальные хосты правятся в «Remnawave: панель».

### Конструктор VLESS + REALITY

| Поле | Значение |
| --- | --- |
| Название | 2–30 символов: латиница, цифры, пробел, `_`, `-` (требование панели) |
| Домены SNI | `serverNames`, до 10 доменов |
| Маскировка | **SelfSteal** — `dest` = `/dev/shm/selfsteal.sock`, `xver: 1` (сайт-шаблон самой ноды); **чужой сайт** — `dest` = `домен:порт`, `xver: 0` |
| Порт | 443 по умолчанию |
| shortIds | 1–8 случайных по 16 шестнадцатеричных символов |
| Минимальная версия клиента | `minClientVer`, вида `25.1.1` |
| Блокировки | `geoip:private` и BitTorrent → `BLOCK` |
| DNS | DoH `https://dns.google/dns-query`, только IPv4 |

Ключи x25519 выдаёт панель (`GET /api/system/tools/x25519/generate`). Закрытый ключ попадает в профиль, открытый показывается после создания: панель сама подставляет его в подписки.

## 3. Модули на серверах (мастер установки)

SelfSteal ставится вместе с нодой: в мастере установки для одной ноды укажите «Домен ноды» и сайт-шаблон. Остальные модули — «Установка Remnawave → задача установки → Журнал → Модули серверов». Каждое изменение — план из закрытого списка шагов (`node_module`, `write_files`, `compose_up`, `verify`), который администратор просматривает и подтверждает. Ошибка шага откатывает сделанное.

### SelfSteal

- Caddy ноды (`/opt/remnawave-selfsteal`, образ закреплён по SHA-256) слушает `:80` (ACME и переадресация) и сокет `/dev/shm/selfsteal.sock` с `proxy_protocol` и TLS. Сертификат — Let's Encrypt для домена ноды или внутренний CA Caddy для проверки.
- Нода монтирует `/dev/shm`. Профиль VLESS + REALITY на 443: `dest` — сокет, `xver: 1`, `serverNames` — домен ноды; ключи x25519 выдаёт панель. Хост — `домен:443` с SNI домена.
- Проверка: сайт отвечает на сокете (`curl --haproxy-protocol --unix-socket`), нода на связи с панелью.
- Тот, у кого нет ключей REALITY, видит на порту 443 обычный сайт с сертификатом домена ноды.

Ограничения: одна нода — один домен; SelfSteal не ставится на сервер панели или страницы подписки (их Caddy занимает 443).

### IPv6

`/etc/sysctl.d/99-remnawave-ipv6.conf`, ключи `disable_ipv6` для `all`, `default`, `lo` и интерфейса маршрута по умолчанию (пока сам интерфейс выключен, IPv6 не работает и при `all = 0`). Прежний файл сохраняется (`.rw-prev`) и возвращается откатом.

С v28.73.0 при выключении IPv6 Linux сбрасывает адреса интерфейса, и при включении статический или DHCPv6-адрес сам не возвращается. Поэтому шаг «включить» запоминает, был ли у сервера глобальный IPv6-адрес, и перечитывает сеть так, как её настраивает дистрибутив: `netplan apply`, `ifdown`/`ifup` или перезапуск `systemd-networkd`. Затем он ждёт адрес до 15 секунд и окончания проверки дубликатов адресов (до 10 секунд). Если адрес не вернулся, шаг завершается ошибкой, и мастер откатывает изменение.

Если IPv6 выключен в ядре (`ipv6.disable=1`), шаг сообщает об этом и ничего не меняет.

### Ядро Xray

1. Магазин берёт из GitHub релиз XTLS/Xray-core (последний или указанный) и SHA-256 файла для каждой архитектуры (`x86_64`, `aarch64`). Сумма попадает в план, план подтверждается по своему SHA-256.
2. Сервер скачивает архив только с `github.com/XTLS/Xray-core/releases/download/…` и сверяет SHA-256. Если опубликован `.dgst`, сверяет и его. Затем проверяет, что внутри ELF, и ставит `/opt/remnanode/xray-core/xray`, сохранив прежний файл.
3. Файл ноды получает том `./xray-core/xray:/usr/local/bin/xray:ro`, нода перезапускается, проверка читает версию ядра в контейнере.

«Вернуть ядро из образа» убирает том. Выбранная версия хранится в установке, поэтому «Обновить» сохраняет её. Если профиль панели переключил `rw-core` на другое ядро, работает ядро профиля.

## 4. Права и журнал

| Действие | Право | Журнал |
| --- | --- | --- |
| Смотреть | `read` | — |
| Профили, ключи, назначение нодам, хост, плагины, WARP в профиле, серверный роутинг | `provision_nodes` | `rw.profile.*`, `rw.node.profile`, `rw.plugin.*`, `rw.node.plugin`, `rw.routing.*` |
| Модули серверов (план и запуск) | `provision_nodes` | `rw.installation.planned`, `rw.installation.approved` |
| Правила подписки, страница, шаблоны | `settings.runtime.write` | `rw.subscription_settings.updated`, `rw.subpage_config.*`, `rw.template.*` |

Если панель отклонила запрос (например, неверная конфигурация), её сообщение показывается администратору. Без подключения к панели раздел отвечает 503 и объясняет почему.

# Менеджер расширений Remnawave

Этап 12. Раздел «Серверы → Расширения Remnawave» (`apps/lucy-admin/web/src/rw-extensions.tsx`), backend — `backend/app/rw_extensions.py`, маршруты `/api/admin/rw/extensions/...`. Всё управляется из админки, без SSH и терминала.

Функции, которые есть в API панели Remnawave, вызываются через API панели: состояние хранит сама панель, магазин её не дублирует. Функции на сервере ноды (SelfSteal, IPv6, ядро Xray, WARP, NetBird, Xray Checker) выполняет мастер установки по SSH закрытым списком шагов ([DEPLOYMENT_AGENT](DEPLOYMENT_AGENT.md)).

Источник списка функций — `eGamesAPI/remnawave-reverse-proxy` (MIT, Copyright (c) 2025 eGames): меню «Расширения ноды», «Подписки: правила и страница», WARP, IPv6, Xray Checker, NetBird. Код скрипта не переносился: реализация своя, по API панели и шагам мастера.

## 2. Профили конфигурации

- **Список:** каждый профиль, его inbound (тег, протокол, порт) и ноды, которые его используют. Профиль, занятый нодами, не удаляется.
- **Конфигурация:** «Конфигурация» показывает JSON профиля. Сохранение отправляет его в панель (`PATCH /api/config-profiles`); панель проверяет конфигурацию и перезапускает ноды профиля.
- **Назначить нодам:** для каждой ноды выбирается inbound профиля (`PATCH /api/nodes`, `configProfile`).
- **Хост:** `POST /api/admin/rw/extensions/profiles/{uuid}/host` создаёт хост панели для inbound — адрес и SNI, которые получат клиенты. Остальные хосты правятся в «Remnawave: панель».

### Конструктор VLESS + REALITY

| Поле | Значение |
| --- | --- |
| Название | 2–30 символов: латиница, цифры, пробел, `_`, `-` (требование панели) |
| Домены SNI | `serverNames`, до 10 доменов |
| Маскировка | **SelfSteal** — `dest` = `/dev/shm/selfsteal.sock`, `xver: 1` (сайт-шаблон самой ноды); **чужой сайт** — `dest` = `домен:порт`, `xver: 0` |
| Порт | 443 по умолчанию |
| shortIds | 1–8 случайных по 16 шестнадцатеричных символов |
| Минимальная версия клиента | `minClientVer`, вида `25.1.1` |
| Блокировки | `geoip:private` и BitTorrent → `BLOCK` |
| DNS | DoH `https://dns.google/dns-query`, только IPv4 |

Ключи x25519 выдаёт панель (`GET /api/system/tools/x25519/generate`). Закрытый ключ попадает в профиль, открытый показывается после создания: панель сама подставляет его в подписки.

## 3. Модули на серверах (мастер установки)

SelfSteal ставится вместе с нодой: в мастере установки для одной ноды укажите «Домен ноды» и сайт-шаблон. Сменить сайт-шаблон позже — модуль «Сайт SelfSteal» (с v28.88.0): переписываются только файлы Caddy на ноде и Caddy перезапускается; нода, ключи REALITY и подписки не меняются, при ошибке возвращается прежний сайт. Остальные модули — «Установка Remnawave → задача установки → Журнал → Модули серверов». Каждое изменение — план из закрытого списка шагов (`node_module`, `write_files`, `compose_up`, `verify`), который администратор просматривает и подтверждает. Ошибка шага откатывает сделанное.

### SelfSteal

- Caddy ноды (`/opt/remnawave-selfsteal`, образ закреплён по SHA-256) слушает `:80` (ACME и переадресация) и сокет `/dev/shm/selfsteal.sock` с `proxy_protocol` и TLS. Сертификат — Let's Encrypt для домена ноды или внутренний CA Caddy для проверки.
- Нода монтирует `/dev/shm`. Профиль VLESS + REALITY на 443: `dest` — сокет, `xver: 1`, `serverNames` — домен ноды; ключи x25519 выдаёт панель. Хост — `домен:443` с SNI домена.
- Проверка: сайт отвечает на сокете (`curl --haproxy-protocol --unix-socket`), нода на связи с панелью.
- Тот, у кого нет ключей REALITY, видит на порту 443 обычный сайт с сертификатом домена ноды.

Ограничения: одна нода — один домен; SelfSteal не ставится на сервер панели или страницы подписки (их Caddy занимает 443).

### Транспорты ноды (v28.82.0)

Рядом с VLESS + TCP + REALITY на 443 нода SelfSteal может принимать клиентов ещё тремя способами. Выбор — галочками при установке («SelfSteal → дополнительно») или действием «Модули серверов → Транспорты ноды»; выбранный набор заменяет текущий, без галочек остаётся только TCP + REALITY.

| Транспорт | Порт | Настройки |
| --- | --- | --- |
| VLESS + xHTTP + REALITY | TCP 4443 | путь `/xhttp`, режим `auto`; ключи и сайт REALITY — те же |
| VLESS + gRPC + REALITY | TCP 8443 | serviceName `grpc`, multiMode; ключи и сайт REALITY — те же |
| Hysteria2 | UDP 443 | TLS с сертификатом домена SelfSteal, ALPN `h3`; пароль клиента — его UUID (подставляет панель) |

Что делает план:
1. На ноде (`node_module transports`): открывает порты в ufw, если он включён; для Hysteria2 копирует сертификат домена из Caddy SelfSteal (любой издатель, включая внутренний CA) в `/opt/remnanode/hysteria` и ставит таймер systemd `corgi-hysteria-cert.timer` (раз в сутки). Xray перечитывает сертификат сам (`ocspStapling`, раз в час).
2. Файл ноды монтирует `/opt/remnanode/hysteria` в `/var/lib/corgi-hysteria` только для чтения; нода перезапускается.
3. В панели (`node_transports`): inbound'ы профиля SelfSteal, по хосту на каждый транспорт, транспорты добавляются во все сквады, где есть inbound REALITY (снятые — убираются оттуда), ноде назначаются все inbound'ы профиля, нода перезапускается. Откат возвращает прежний набор.

Клиенты «Корги Люси» (с v28.81.0) понимают ссылки `hysteria2://` и JSON-подписки Remnawave с этими транспортами.

### Протоколы и маскировка, порт ноды (v28.90.0)

Модуль называется «Протоколы и маскировка». К трём транспортам добавлен четвёртый — **VLESS + TCP + TLS** (TCP 2053, сертификат домена SelfSteal, тот же, что у Hysteria2). Кнопка «Все протоколы на этой ноде» ставит все сразу.

- **Отпечаток браузера (uTLS)** — Firefox по умолчанию; Chrome, Safari, iOS, Android, Edge, QQ, случайный из популярных, полностью случайный. Ставится в поле `fingerprint` всех хостов профиля SelfSteal, в том числе созданных раньше; у Hysteria2 (QUIC) отпечатка нет. Откат возвращает прежние значения.
- **TLS 1.2 / 1.3** — `minVersion` и `maxVersion` у VLESS + TCP + TLS. REALITY и Hysteria2 работают только по TLS 1.3.

**Порт ноды для панели** (модуль и галочка мастера): своя таблица nftables `inet corgi_node_port` (приоритет −10, раньше остальных правил) пропускает к порту ноды только адрес панели и указанные дополнительные адреса; остальные соединения сбрасываются. Таблица загружается при старте системы (`corgi-node-port.service`). Если ufw включён, в нём то же правило. Сразу на всех нодах установки; при переезде панели сначала добавьте новый адрес. После правила шаг «Проверка» ждёт, что панель видит ноду; если нет — правило снимается и проверка сообщает об этом. В CI скрипт проверяется настоящими соединениями в network namespaces (`scripts/ci/node-port-guard.sh`).

### Защита сервера (v28.84.0)

Из remnawave-manager. «Модули серверов → Защита сервера», серверы на выбор:

| Что | Как |
| --- | --- |
| fail2ban для SSH | Свой файл `/etc/fail2ban/jail.d/corgi.local`: порты SSH из `sshd -T`, 3 ошибки за 10 минут — бан на 2 часа; журнал — `auth.log` или systemd |
| Автообновления безопасности | Свои `apt.conf.d/21corgi-auto-upgrades` и `52corgi-unattended`: только источники `-security`, без автоматической перезагрузки |
| BBR | `sysctl.d/99-corgi-bbr.conf` (`fq` + `bbr`); если ядро не умеет BBR — шаг останавливается с ошибкой |
| SSH только с адресов администратора | Через ufw: разрешение с указанных адресов (до 10, не шире /16) и с адреса магазина — его видит sshd этого сервера, так магазин не потеряет доступ. Если ufw выключен или адрес магазина не определился — шаг останавливается, ничего не меняя |

Файлы дистрибутива не трогаются. Что было до шага (файлы и правила ufw), запоминается в `/var/lib/corgi-harden/run`; ошибка или откат возвращают прежнее. Ротация журналов Docker у контейнеров мастера уже задана в их файлах (`max-size 10m`, 3 файла).

### Самовосстановление (v28.84.0)

Таймер systemd `corgi-watchdog.timer` на самом сервере, каждые 2 минуты: контейнеры каталогов мастера, которые не работают, запускаются снова; если панель трижды подряд не ответила на `/health`, контейнер `remnawave` перезапускается. Записи — в журнале (`journalctl -t corgi-watchdog`). Работает и тогда, когда магазин не может достучаться до сервера. Выключение убирает таймер и скрипт.

### Управление нодами (v28.84.0)

«Мониторинг нод» в админке: у каждой ноды — «Перезапустить», «Выключить» / «Включить» и «Изменить» (имя, адрес). Запросы идут в панель (`POST /api/nodes/{uuid}/actions/enable|disable`, `PATCH /api/nodes`), каждое действие — в журнале (`nodes.enable`, `nodes.disable`, `nodes.update`), право `provision_nodes`.

### IPv6

`/etc/sysctl.d/99-remnawave-ipv6.conf`, ключи `disable_ipv6` для `all`, `default`, `lo` и интерфейса маршрута по умолчанию (пока сам интерфейс выключен, IPv6 не работает и при `all = 0`). Прежний файл сохраняется (`.rw-prev`) и возвращается откатом.

С v28.75.0 при выключении IPv6 Linux сбрасывает адреса интерфейса, и при включении статический или DHCPv6-адрес сам не возвращается. Поэтому шаг «включить» запоминает, был ли у сервера глобальный IPv6-адрес, и перечитывает сеть так, как её настраивает дистрибутив: `netplan apply`, `ifdown`/`ifup` или перезапуск `systemd-networkd`. Затем он ждёт адрес до 15 секунд и окончания проверки дубликатов адресов (до 10 секунд). Если адрес не вернулся, шаг завершается ошибкой, и мастер откатывает изменение.

Если IPv6 выключен в ядре (`ipv6.disable=1`), шаг сообщает об этом и ничего не меняет.

### Ядро Xray

1. Магазин берёт из GitHub релиз XTLS/Xray-core (последний или указанный) и SHA-256 файла для каждой архитектуры (`x86_64`, `aarch64`). Сумма попадает в план, план подтверждается по своему SHA-256.
2. Сервер скачивает архив только с `github.com/XTLS/Xray-core/releases/download/…` и сверяет SHA-256. Если опубликован `.dgst`, сверяет и его. Затем проверяет, что внутри ELF, и ставит `/opt/remnanode/xray-core/xray`, сохранив прежний файл.
3. Файл ноды получает том `./xray-core/xray:/usr/local/bin/xray:ro`, нода перезапускается, проверка читает версию ядра в контейнере.

«Вернуть ядро из образа» убирает том. Выбранная версия хранится в установке, поэтому «Обновить» сохраняет её. Если профиль панели переключил `rw-core` на другое ядро, работает ядро профиля.

### Раздел «SelfSteal» (v28.91.0)

«Серверы → SelfSteal»: сводка нод («известно про N из M»: ноды мастера и ноды подключённой панели), проверка снаружи по 11 пунктам (`backend/app/selfsteal_check.py`: только адрес ноды из реестра, только публичный адрес), свой сайт из архива (`backend/app/selfsteal_sites.py`: zip / tar.gz до 20 МБ, проверка каждого файла), каталог из 22 шаблонов с отдельной сборкой для каждой ноды. Сайт выкладывается на ноду целиком (`rw_steps.SITE`: SHA-256, `sites/site-<sha>`, ссылка `current`, откат). Caddy ноды: своя страница 404, HSTS, без заголовка Server, без перенаправления всех адресов на главную. Подробности — [RELEASE_V28_91_0](../RELEASE_V28_91_0.md).

### Раздел «Установка» и модули серверов (v28.92.0)

«Серверы → Установка» собирает все операции с серверами (`backend/app/install_catalogue.py`). Новые модули (`backend/app/rw_netmods.py`): «Защита ноды» (таблица `inet corgi_guard`: лимит новых соединений с адреса, бан на 10 минут, белый список — адреса магазина и панели, CGNAT), «MSS clamp» (`inet corgi_mss`, по измеренному MTU пути), «Файл подкачки», «Подбор сайта для REALITY» (только чтение). Действия установки «snapshot» (копия базы панели и файлы компонентов в зашифрованном хранилище магазина) и «remove_component»; ежедневные снапшоты — `backend/app/rw_snapshots.py`. ### Экстренное восстановление и «Анти-РКН» (v28.93.0)

Действие `restore_files` (`rw_steps.PUT_CONFIGS`) возвращает файлы компонентов из снапшота: архив проверяется по SHA-256, пути только `/opt/remnawave*` и `/opt/remnanode`, текущие файлы упаковываются в `/root/corgi-before-restore-<время>.tar.gz` и возвращаются шагом отката. `GET /api/admin/install/anti-censorship` — девять пунктов по каждой ноде из данных магазина (без сетевых проверок), у каждого пункта — карточка каталога, которая его исправляет.

### MTProto-прокси для Telegram (v28.94.0)

Модуль `mtproto` (`rw_netmods.MTPROTO`): контейнер `corgi-mtproto` из образа `nineseconds/mtg:2` (9seconds/mtg, MIT, закреплён по digest) в режиме `simple-run` с FakeTLS-секретом под выбранный сайт; `--network host`, `--read-only`, `--cap-drop ALL`, порт 1024–65535 не из портов ноды. Секрет — `/etc/corgi/mtproto.secret` (0600), создаётся один раз; в журнал шага не пишется, ссылка — в состоянии установки и в `GET /api/admin/install/mtproto`. Проверка настоящим контейнером — `scripts/ci/mtproto-check.sh`.

### Российские списки блокировок (v28.95.0)

Модуль `geo_files`: `rw_releases.geo_lists()` берёт последний выпуск `runetfreedom/russia-v2ray-rules-dat` (тег ГГГГММДДЧЧММ) с SHA-256, опубликованным GitHub, и фиксирует его в плане; `rw_steps.GEO` скачивает `geoip.dat` / `geosite.dat` только с адреса этого выпуска, сверяет сумму и кладёт в `/opt/remnanode/geo/ru-*.dat` (прежние — в `.rw-prev`); `node_compose(geo=True)` монтирует их в `/usr/local/share/xray/ru-*.dat` (встроенные файлы образа не заменяются); нода перезапускается. В правилах — `ext:ru-geosite.dat:<категория>`, `ext:ru-geoip.dat:<категория>`. Настоящая проверка — `scripts/ci/geo-check.sh`.

### Смена домена панели (v28.97.0)

Действие `change_domain` (`ActionIn.new_panel_domain`, `keep_old_domain`): `PlanIn.panel_domain` меняется, прежний попадает в `panel_domain_aliases` (до трёх). План — `preflight` (DNS нового домена), `backup_panel`, `write_files` панели и Caddy, `compose_up`, `wait_panel`, `verify`. `rw_plan.caddyfile(moved=…)` пишет для прежнего домена блок: `/api/sub/*` и `/api/*` с Bearer — в панель (Host нового домена), остальное — `redir 308`. После успеха `rw_jobs._move_subscription_links` переписывает `Subscription.subscription_url` с префиксом прежнего домена (только без отдельной страницы подписки).

### Cloudflare CDN (v28.98.0)

Модуль `cdn` (`ModuleIn.cdn_nodes`, `cdn_subscription`, `cdn_domain`, `cloudflare_token`): токен проверяется (`/user/tokens/verify`) и хранится в секретах установки. ### Свой сервер Psiphon (v28.99.0)

Модуль `psiphon` (`psiphon_port`, `psiphon_protocol` OSSH / TLS-OSSH): `rw_netmods.PSIPHON` собирает psiphond на ноде (`PSIPHON_COMMIT`, `PSIPHON_BUILDER` по digest, `CGO_ENABLED=0`), создаёт ключи (`psiphond generate`) один раз, служба `corgi-psiphon` с `ProtectSystem=strict` и без capabilities. `rw_netmods.psiphon_client` — конфиг ConsoleClient только с `TargetServerEntry` этого сервера; `GET /api/admin/install/psiphon`.

# Админ-панель: руководство

Админ-панель — единое место управления магазином. Каждый раздел работает через типизированный API backend. Браузер не выполняет команд на сервере и не передаёт серверу произвольные команды, пути или адреса для исполнения.

Связанные документы:
- [ADMIN_MODULES](ADMIN_MODULES.md) — модули и разделы;
- [ADMIN_CONTROL_MATRIX](ADMIN_CONTROL_MATRIX.md) — какие операции есть у каждого модуля;
- [RBAC](RBAC.md) — роли и права;
- [UI_UX_GUIDE](UI_UX_GUIDE.md) — правила интерфейса.

## Вход

Адрес панели — `https://<ADMIN_DOMAIN>`. Способы входа:
- email и пароль;
- ключ доступа (passkey);
- Telegram Mini App, если к администратору привязан Telegram ID и у него не включена двухфакторная защита;
- одноразовый билет из приложения администратора (живёт 60 секунд).

Если у администратора включена двухфакторная защита, после пароля нужен код из приложения-аутентификатора или резервный код.

Первого администратора создаёт установщик. Остальных добавляют в разделе «Безопасность → Роли и администраторы»: там задаются email, пароль, Telegram ID и роль, и там же учётную запись можно отключить или удалить.

## Устройство панели

- **Меню** слева, восемь групп: Аналитика, Пользователи, Тарифы и оплата, Маркетинг, Бот и кабинет, Серверы, Система, Безопасность. На телефоне меню выдвигается кнопкой.
- **Поиск раздела** — `⌘K` / `Ctrl+K` или поле на странице «Все разделы».
- **Админ-центр** («Система → Админ-центр: 30 модулей») — таблица 30 модулей задания: какие разделы ими управляют, какие операции доступны, каких прав они требуют и каких модулей пока нет. Кнопка в строке открывает раздел.
- **Состояние раздела.** Каждый раздел показывает загрузку, ошибку с причиной и кнопкой «Повторить» или пустое состояние с подсказкой. Если у роли нет права, сервер отвечает 403, и раздел показывает причину.

## Состояние системы (System Control Center)

«Аналитика → Состояние системы» (`GET /api/admin/health/summary`, право `ops.diagnostics`) — одна страница с состоянием всех частей установки. Код: `backend/app/system_status.py`.

У каждой строки:
- статус: «в норме», «внимание», «ошибка» или «не настроено»;
- одно предложение о том, что найдено;
- время ответа для сетевых проверок;
- кнопка раздела, где эта часть управляется.

| Часть | Что проверяется | Раздел |
| --- | --- | --- |
| Backend (API) | Отвечает; номер выпуска и версии API | Обновления |
| Frontend | Админка, кабинет и Mini App отдают страницу (`http://admin/`, `http://cabinet/`, `http://miniapp/` внутри сети docker compose) | Развёртывания |
| PostgreSQL | Запрос `SELECT 1`, время ответа | Диагностика |
| Миграции базы | Отметка в базе совпадает с последней миграцией выпуска | Обновления |
| Redis | `PING`, время ответа | Диагностика |
| Remnawave | Панель отвечает и принимает токен; если адрес не задан — «не настроено» | Remnawave: панель |
| Узлы | Сколько включённых узлов на связи | Серверы |
| Caddy (обратный прокси) | Принимает HTTPS на `caddy:443` для доменов магазина | Диагностика |
| Сертификаты TLS | Сертификат каждого домена проходит проверку цепочки; предупреждение за 14 дней до конца срока | Диагностика |
| Платежи | Какие агенты настроены, какие временно выведены из очереди после ошибок, не приостановлен ли приём | Платёжные агенты |
| Фоновые задачи | Живой обработчик задач (отметка за 90 с), задачи в очереди дольше 15 мин, невыполненные за сутки | Очередь задач / Фоновые процессы |
| Резервные копии | Возраст последней успешной копии; предупреждение после 26 ч | Резервные копии |
| Telegram-бот | Заданы токен и имя бота (связь с Telegram не проверяется) | Меню бота и Mini App |
| Обновления | Установленный выпуск и последний выпуск на GitHub (ответ хранится час) | Обновления |

Как работает проверка:
- у каждой проверки свой предел времени — 5 секунд для сетевых;
- медленная или сломанная часть не скрывает остальные;
- ответы внешних сервисов, токены и пароли в ответ не попадают — причина пишется в журнал сервера;
- общий статус страницы: «Все системы работают», «Работает, но есть что проверить» или «Есть неработающие части»;
- кнопка «Проверить снова» повторяет все проверки.

Чего эта страница не проверяет:
- **Связь бота с Telegram.** Страница проверяет только, заданы ли токен и имя бота. Бот работает в отдельном контейнере; его здоровье проверяет healthcheck Docker. Отдельного сигнала от бота в панели пока нет.
- **Установки без docker compose.** Имена `caddy`, `admin`, `cabinet`, `miniapp` — это сервисы из `docker-compose.yml`. При другой схеме развёртывания строки Frontend и Caddy покажут ошибку.
- **Свободное место и память.** Это показывают «Мониторинг» и «Диагностика».

## Типичные задачи

| Задача | Где |
| --- | --- |
| Найти клиента, продлить, сменить тариф, вернуть деньги | Пользователи → Клиенты магазина → карточка клиента |
| Создать или изменить тариф | Тарифы и оплата → Тарифы, Конструктор тарифов |
| Включить тарифы Lucy Mini/Max/Ultra | Тарифы и оплата → Тарифы → «Тарифы Lucy» ([кабинет](USER_CABINET_GUIDE.md#тарифы-lucy)) |

| Подключить платёжного агента | Система → Настройки без перезапуска (ключи), затем Тарифы и оплата → Платёжные агенты (включение, очередь касс, проверка) |
| Подключить Remnawave | Система → Настройки без перезапуска: `REMNAWAVE_URL`, `REMNAWAVE_TOKEN`; затем Серверы → Remnawave: панель |
| Добавить или перезапустить узел | Серверы → Серверы |
| Тексты бота, кнопки, баннеры, документы | Бот и кабинет |
| Резервная копия и восстановление | Безопасность → Резервные копии, Восстановление |
| Обновление магазина | Система → Обновления: проверка выпуска и автообновление по расписанию или по кнопке |
| Кто что изменил | Безопасность → Журнал действий: поиск по администратору, действию, объекту и периоду |

## Что пока требует сервера

Задание требует, чтобы терминал нужен был только для первого развёртывания. Сейчас без консоли сервера не обойтись в таких случаях:

| Что | Почему | Когда уйдёт |
| --- | --- | --- |
| Первая установка магазина | Контейнеров ещё нет | Мастер установки — этап 10; запуск контейнера панели останется в терминале по заданию |
| Однократная установка агента автообновления (`scripts/auto-update.sh install`) | Агент работает на хосте, а backend в контейнере не выполняет команд на сервере. После установки агента расписание и запуск обновлений управляются из раздела «Обновления» | Этап 10 — вместе с мастером установки |
| Домены, `BOT_TOKEN`, подключение к базе и Redis | Эти значения читаются при запуске контейнеров (`.env`). Ключи платёжных агентов, Remnawave и почты меняются без перезапуска в разделе «Настройки без перезапуска» | Домены и сертификаты — этап 11 |

Модулей Installation, Domains, Certificates, Reverse Proxy и Node Extensions в панели нет. Их разделы появятся вместе с работающим backend на этапах 10–12. Макетов без функции в панели нет.

## Безопасность

- Права проверяет сервер на каждый запрос ([RBAC](RBAC.md)).
- Изменения пишутся в журнал действий.
- Системные операции — копия, проверка восстановления, обновление, перезапуск узла — запускаются через отдельные маршруты с проверкой входных данных.
  - Команды на хосте выполняет агент. Он принимает от backend только запрос заранее известного формата.
- Терминал узлов доступен только с правом `nodes.terminal` и только на узлах, где владелец включил его сам (`AGENT_TERMINAL=1`).

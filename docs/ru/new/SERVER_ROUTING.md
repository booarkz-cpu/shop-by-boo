# Серверный роутинг (мост между нодами)

С v28.70.0 (этап 12). «Серверы → Расширения Remnawave → Серверный роутинг». Идея — `server_routing` из `eGamesAPI/remnawave-reverse-proxy` (MIT, Copyright (c) 2025 eGames). Всё делается через API панели Remnawave, без SSH.

## 1. Что получается

Клиент подключается к **ноде входа** (например, в России). Часть трафика нода входа отправляет дальше, на **ноду выхода** (например, в Финляндии), через мост Shadowsocks.

| Режим | Российские адреса (`geoip:ru`, `geosite:category-ru`) | Остальное |
| --- | --- | --- |
| Прямо (`direct`) | с ноды входа (`DIRECT`) | через ноду выхода |
| Через мост (`bridge`) | через ноду выхода | как было в профиле |

В обоих режимах частные адреса (`geoip:private`, `geosite:private`) и BitTorrent блокируются (`BLOCK`), если в профиле ещё нет таких правил.

## 2. Что меняется в панели

1. **Профиль ноды выхода:** inbound `SR_BRIDGE_SS_IN` (Shadowsocks, `chacha20-ietf-poly1305`, TCP и UDP, выбранный порт). Нода выхода получает его к своим inbound и продолжает обслуживать клиентов.
2. **Внутренний сквад** `SR Bridge <id>` с этим inbound и **служебный пользователь** `srbridge<id>`. Его пароль Shadowsocks (`ssPassword`) — пароль моста. Пользователь бессрочный, без лимита трафика.
3. **Профиль ноды входа:** исходящий `SR_BRIDGE_SS` на адрес ноды выхода и правила выбранного режима. Правила администратора остаются. Правила той же формы (`geoip:ru`, `geosite:category-ru`) заменяются, иначе мост не сработает.

Повторный запуск (другая нода выхода, другой режим) заменяет исходящий и правила. Служебный пользователь и его пароль используются повторно.

**Порт.** Если на сервере выхода включён файрвол, откройте выбранный порт (TCP и UDP) для адреса ноды входа. Магазин напоминает об этом после создания моста.

## 3. Удаление

«Удалить мост» убирает из профиля входа исходящий `SR_BRIDGE_SS` и правила моста, удаляет служебного пользователя и сквад. Inbound `SR_BRIDGE_SS_IN` на профиле выхода остаётся: им могут пользоваться другие мосты. Ненужный inbound удаляется в JSON профиля выхода.

## 4. API

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/api/admin/rw/extensions/routing` | `read` |
| POST | `/api/admin/rw/extensions/routing` — `entry_profile_uuid`, `exit_node_uuid`, `port`, `mode` | `provision_nodes` |
| DELETE | `/api/admin/rw/extensions/routing/{profile_uuid}` | `provision_nodes` |

Журнал: `rw.routing.created`, `rw.routing.deleted`.

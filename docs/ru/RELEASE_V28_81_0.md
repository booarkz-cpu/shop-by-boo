# Выпуск v28.81.0 — исправление: Android-приложения видят серверы подписок Remnawave в формате Xray JSON

Дистрибутив: `v28.81.0`. Runtime/API: `21.5.1`. Head магазина: `0093_ssh_key_rotation` (миграций нет). Support Pro: `0008` / 3.8.

## Что было не так

Подписка Remnawave вида `https://домен/shortUuid` не импортировалась: приложения не видели серверов. Причина проверена на живой подписке владельца 2026-11-05: на запрос клиента v2rayNG / Happ панель по своим правилам ответа отдаёт не ссылки `vless://…` в base64, а **Xray JSON** — массив полных конфигураций с названиями (`remarks`). Первая — «самый быстрый» с собственным балансировщиком, дальше по одной на сервер. Оба приложения понимали только ссылки.

## Что сделано

- **Оба Android-приложения** (клиент магазина и «Корги Люси: клиент» 1.2.0) понимают оба ответа подписки: ссылки и Xray JSON. Серверы называются так, как в панели. Выбранный сервер подключается конфигурацией панели как есть, только вход заменяется туннелем. «Самый быстрый» — это конфигурация с балансировщиком панели.
- В приложениях нет файлов geoip/geosite, а панель ссылается на них в правилах. Поэтому `geoip:private` заменяется самими частными диапазонами, остальные geo-списки убираются. Иначе Xray отказался бы запускать всю конфигурацию. В «Корги Люси: клиенте» после загрузки geo-файлов правила остаются как есть.
- **Ссылки `hysteria2://`** теперь подключаются: в Xray-core 26 есть Hysteria2. Ссылки с обфускацией salamander пропускаются, их не собирают наполовину.
- Диагностика в приложении считает серверы и проверяет их адреса для обоих форматов.

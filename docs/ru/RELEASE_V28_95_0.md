# Выпуск v28.95.0 — российские списки блокировок на нодах

Дистрибутив: `v28.95.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Задача владельца N7 этапа 20 («geo-файлы и списки zapret»). Всё — в **«Серверы → Установка» → «Российские списки блокировок»**.

## Что нового

- **Российские geo-списки на нодах** — файлы [runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat) (данные под GPL-3.0; скачиваются на сервер владельца, в магазин не копируются): заблокированные в России домены и адреса (antifilter, re:filter, списки сообщества), домены, доступные только из России, реклама и другие категории.
  - Встроенные `geoip.dat` / `geosite.dat` образа ноды не трогаются: списки кладутся рядом под своими именами `ru-geoip.dat` и `ru-geosite.dat` (`/usr/local/share/xray/` в контейнере, `/opt/remnanode/geo/` на сервере).
  - Версия списков фиксируется при составлении плана вместе с SHA-256, который опубликовал GitHub; на ноде файл ставится только при совпадении суммы и только с адреса выпуска этого репозитория. Прежние файлы возвращаются при ошибке.
  - Нода перезапускается с новыми файлами (как при смене ядра Xray); «Выключить» убирает их из ноды.
  - В правилах маршрутизации панели: `ext:ru-geosite.dat:ru-blocked`, `ext:ru-geoip.dat:ru-blocked`, `ext:ru-geosite.dat:ru-available-only-inside` и др.
  - Источник обновляет списки каждые 6 часов: повторное «Включить» ставит последнюю сборку.

## Что пока не сделано из N7 и почему

| Операция | Причина |
| --- | --- |
| Автообновление списков по расписанию | Каждое обновление перезапускает ноду — нужно согласовать окно с владельцем (можно включить через «Автообновление Remnawave») |
| Psiphon | Сторонний клиент с закрытыми частями — нужен аудит лицензии и бинарников |
| CDN (Cloudflare) | Нужен аккаунт и токен Cloudflare владельца |
| Смена домена панели | Меняет ссылки подписок всех клиентов — нужна согласованная миграция со страницей подписки |

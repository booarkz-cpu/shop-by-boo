# Релиз v28.118.0 — вся экосистема: автообновление с GitHub одной таблицей

Дистрибутив: `v28.118.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-11. Задача владельца: автоматическое обновление с GitHub всей экосистемы (этап 22, часть 1).

## Что изменилось

- Раздел «Обновления» начинается с таблицы **«Вся экосистема: автообновление с GitHub»**.
  - Строки: магазин (бот, Mini App, кабинет, панель администратора, Support Pro), панель Remnawave, ноды, страница подписки, гео-списки, три приложения для Android, два для iOS.
  - Колонки: установлено, на GitHub, состояние, автообновление, как обновляется.
  - Сверху — итог: сколько частей обновляются сами, сколько выключено, у скольких автообновления нет.
- Таблица ничего не меняет. Настройки остаются в блоках «Автообновление с GitHub» и «Автообновление Remnawave».

Подробно: [AUTO_UPDATE.md](../AUTO_UPDATE.md#10-вся-экосистема).

## Что показала сверка

| Часть | Автообновление |
| --- | --- |
| Магазин | Есть: ночной агент на сервере |
| Remnawave и гео-списки | Есть, по умолчанию выключено |
| «Корги Люси: клиент» для Android | Есть: проверка в приложении |
| Приложения магазина и администратора для Android | Нет |
| Приложения для iOS | Нет: нужен Apple Developer |

## Чем проверено

- `tests/test_ecosystem_updates.py` — строки таблицы для включённого, выключенного и неустановленного агента, для частичного выбора установок Remnawave, для недоступного GitHub.
- `admin/e2e/ecosystem-updates.spec.ts` — таблица в браузере.

## Чего пока нет

- Проверки обновлений в приложениях магазина и администратора для Android — следующая часть этапа.
- Ночной прогон на настоящем сервере не проверен: нужен VPS (пункт O1 в [BACKLOG.md](new/BACKLOG.md)).

## Что нужно от владельца

Ничего для установки. Чтобы Remnawave обновлялась сама, включите «Автообновление Remnawave» в разделе «Обновления».

# Email-канал поддержки (Support Pro 3.7)

Support Pro читает почтовый ящик поддержки по IMAP и превращает письма клиентов в обращения. Ответ оператора уходит клиенту письмом по SMTP в той же цепочке, поэтому в почтовой программе клиента переписка выглядит как обычный диалог. Канал работает рядом с Telegram, веб-порталом и мостом магазина и ничего в них не меняет.

## Как это работает

1. Worker Support Pro раз в `EMAIL_POLL_SECONDS` (по умолчанию 30 с) читает новые письма из папки `EMAIL_IMAP_FOLDER`. Ящик открывается только для чтения: письма не удаляются и не помечаются прочитанными.
2. Для каждого отправителя создаётся клиент с email-адресом. Первое письмо открывает обращение с темой письма, следующие письма того же клиента присоединяются к нему.
3. Оператор отвечает в карточке обращения как обычно. Ответ уходит письмом с темой `Re: <тема> [#номер]` и подписью «Ответьте на это письмо, чтобы продолжить обращение».
4. Клиент отвечает из своей почты — письмо попадает в то же обращение. Закрытое обращение при ответе открывается снова. Цитата предыдущего письма отрезается.

### Защита

- **Повтор письма не создаёт дубль.** Письмо узнаётся по заголовку Message-ID, курсор ящика сдвигается в той же транзакции, что и сохранение. Если почтовый сервер перенумерует письма (смена UIDVALIDITY), ящик перечитывается, но уже принятые письма не дублируются.
- **Чужой адрес не попадает в чужое обращение.** Письмо присоединяется к обращению только через Message-ID наших писем или метку `[#номер]` в теме и только от того же адреса. Письмо с чужого адреса с той же меткой открывает отдельное обращение.
- **Отправителя email можно подделать.** В карточке обращения показывается проверка DMARC, которую выполнил принимающий почтовый сервер (заголовок Authentication-Results): «пройдена», «частично», «не пройдена — возможна подделка» или «нет данных». Не меняйте по письму email, пароль, подписку или выплаты без дополнительной проверки клиента.
- **Без почтовых петель.** Автоответы (`Auto-Submitted`), рассылки (`Precedence: bulk/list`, `List-Id`) и письма с собственного адреса поддержки пропускаются. Возврат (bounce) не открывает обращение, а отмечает исходный ответ как недоставленный с понятной причиной.
- **Вложения** до `EMAIL_MAX_MB` (по умолчанию 10 МБ на письмо) сохраняются и проверяются антивирусом, если он настроен. Более крупные файлы не принимаются, их имена указываются в сообщении.
- Исходное письмо целиком не хранится — только текст, вложения и Message-ID для цепочки.

### Отправка ответов

| Ситуация | Статус ответа | Что делать |
| --- | --- | --- |
| Почтовый сервер принял письмо | «Отправлено письмом (принято почтовым сервером)» | — |
| SMTP недоступен или временно отказал (4xx) | «В очереди», повтор через 30 с, 1, 2, 4… мин, до 5 попыток | Проверьте сервер SMTP |
| Адрес отклонён или постоянный отказ (5xx) | «Ошибка» с причиной | Уточните адрес клиента |
| Соединение оборвалось во время отправки | «Результат неизвестен» | Проверьте папку «Отправленные», затем «Повторить» с подтверждением |
| Письмо вернулось позже (bounce) | «Ошибка: письмо вернулось» | Уточните адрес клиента |

Если SMTP не настроен, ответы получают статус «Ошибка» с подсказкой, какие переменные задать.

## Настройка

Переменные задаются в `support-pro/.env` (для встроенного Support Pro — тот же файл в каталоге установки). Пароли почты хранятся только там и в интерфейсе не показываются.

```dotenv
EMAIL_ADDRESS=support@example.com
EMAIL_FROM_NAME=Служба поддержки
# Приём
EMAIL_IMAP_HOST=imap.example.com
EMAIL_IMAP_PORT=993
EMAIL_IMAP_SECURITY=ssl          # ssl (993) или starttls (143)
EMAIL_IMAP_USER=support@example.com
EMAIL_IMAP_PASSWORD=пароль-приложения
EMAIL_IMAP_FOLDER=INBOX
EMAIL_POLL_SECONDS=30
# Отправка
EMAIL_SMTP_HOST=smtp.example.com
EMAIL_SMTP_PORT=587
EMAIL_SMTP_SECURITY=starttls     # starttls (587), ssl (465) или plain (только доверенный локальный relay)
EMAIL_SMTP_USER=support@example.com
EMAIL_SMTP_PASSWORD=пароль-приложения
# Данные
EMAIL_MAX_MB=10
EMAIL_RETENTION_DAYS=0           # 0 — хранить; N — очищать закрытые email-обращения старше N дней
EMAIL_PRIVACY_NOTICE=Мы обрабатываем переписку по политике https://example.com/privacy
```

Порядок:

1. Создайте отдельный ящик поддержки и пароль приложения (у Яндекс, Mail.ru и Gmail обычный пароль для IMAP/SMTP не подходит). Включите доступ по IMAP.
2. Для доставляемости настройте у домена SPF, DKIM и DMARC (проверка — раздел магазина «Почтовый домен», [инструкция](MAIL_DOMAIN_CURRENT.md)) для сервера SMTP.
3. Сделайте согласованный backup базы Support Pro и выполните миграцию до `0007` (`docker compose run --rm support_migrate` или `python -m app.migrate`).
4. Перезапустите `support_worker` (и `support_pro`): `docker compose up -d support_pro support_worker`.
5. Откройте в Support Pro раздел **Система → Email-канал**: приём и отправка должны быть «Включены», ошибок нет.
6. Отправьте письмо с личного адреса на адрес поддержки, ответьте из карточки и ответьте ещё раз из почты — все сообщения должны оказаться в одном обращении.

Если ящик недоступен, раздел показывает ошибку, а курсор не сдвигается: после восстановления письма будут прочитаны. Письмо, которое не удаётся обработать три цикла подряд, пропускается с записью в состоянии канала и остаётся в ящике для ручной проверки.

## Данные клиента

Карточка клиента показывает его каналы связи. Администратору доступны два действия.

- **Объединить с клиентом.** Если тот же человек уже писал в Telegram или через магазин, укажите ID этого клиента. Email-адрес и все обращения переносятся к нему, новые письма с этого адреса тоже попадают к нему.
- **Удалить email-данные клиента** (с подтверждением). Удаляются тексты писем и ответов, вложения, Message-ID, адрес и имя клиента; обращения закрываются, неотправленные ответы отменяются. Внутренние заметки команды сохраняются. Действие записывается в журнал. Восстановить данные нельзя.

`EMAIL_RETENTION_DAYS` автоматически очищает текст и вложения закрытых email-обращений старше заданного срока (раз в час). Сами обращения и сроки SLA остаются для отчётов. `EMAIL_PRIVACY_NOTICE` добавляет строку о политике обработки данных в каждый ответ.

## Обновление и откат

Миграция `0007` добавляет таблицы `email_channel_state`, `email_links` и уникальность email-адреса клиента. Без переменных `EMAIL_*` поведение Support Pro не меняется. Откат миграции заблокирован, если есть email-обращения: иначе ответы потеряют цепочку.

## Проверка

`support-pro/tests/test_email_channel.py` (SQLite и PostgreSQL) проверяет:

- создание обращения и отсутствие дублей при повторе и смене UIDVALIDITY;
- цепочку по Message-ID и повторное открытие закрытого обращения;
- отказ письму с чужого адреса с меткой обращения в теме;
- пропуск автоответов, рассылок и собственного адреса; разбор возвратов;
- отказ ящика и пропуск «ядовитого» письма;
- заголовки ответа и исходы SMTP: принято, временный и постоянный отказ, неизвестный результат;
- вложения и лимит размера, разбор HTML и отрезание цитат;
- удаление данных, перенос истории, срок хранения;
- страницу состояния канала.

`tests/test_migrations.py` проверяет roundtrip миграции и защиту отката. Проверка на реальном почтовом ящике и сервере SMTP остаётся за оператором.

# Сквозная проверка платежей на стенде: staging E2E v2

**Проверка добровольная.** Начиная с v28.20.0 реальные платежи открыты с момента установки и по таймеру не закрываются, а результат этой проверки на приём платежей не влияет. Аварийная остановка приёма — кнопка «Остановить приём платежей» в **Безопасность → Защита и 2FA** или **Тарифы и оплата → Проверка платежей**.

Проверка нужна, если вы хотите полностью убедиться в платёжном контуре на отдельном сервере: она проводит настоящий заказ и проверяет всё, от webhook до отзыва доступа после возврата.

## Что доказывает проверка

Для каждой выбранной платёжной системы стенд делает настоящий заказ и проверяет его по собственным записям магазина. Ни один этап не берётся из отчёта скрипта или браузера.

| Этап | Что проверяется |
| --- | --- |
| Заказ через обычный checkout | `POST /api/payments/create` тестовым покупателем: один заказ, HTTPS-страница оплаты провайдера |
| Повтор с тем же ключом | Тот же `Idempotency-Key` не создаёт второй заказ |
| Подписанный webhook | Провайдер сам прислал уведомление об этом заказе во время проверки, и обработчик его принял. Ручная отметка «оплачено» или опрос провайдера этот этап не проходят |
| Сверка с провайдером | Отдельный запрос к провайдеру подтверждает оплату с той же суммой, валютой и номером заказа |
| Выдача | Одна операция выдачи, подписка, пользователь Remnawave найден по его ID, срок совпадает |
| Повтор webhook | Тот же подписанный webhook дважды одновременно: заказ, подписка, финансовый журнал, срок не изменились |
| Подделки | Webhook с чужого адреса или с неверной подписью отклоняется (HTTP 4xx); webhook с изменённым ID или суммой ничего не меняет |
| Возврат | Обычный код возвратов магазина, провайдер подтвердил, в финансовом журнале одна запись возврата |
| Повторный возврат | Не создаёт вторую операцию у провайдера |
| Отзыв доступа | Пользователь Remnawave отключён, подписка магазина закрыта |
| Успех после возврата | Повтор старого webhook об оплате не возвращает оплату и доступ |

Любая ошибка, тайм-аут, остановка или перезапуск сервера во время проверки дают «не пройдена».

Результат подписывается ключом Ed25519 стенда. Рабочий сервер записывает его как пройденную проверку, только если:

- подпись сделана ключом, который вы указали;
- в результате стоит код запуска, выданный этим сервером для его текущих настроек;
- стенд работает на той же версии дистрибутива;
- все выбранные платёжные системы прошли все этапы;
- результату не больше 24 часов, и он не из будущего.

Принятый результат виден в «Последняя проверка». Открытие и закрытие платежей от него не зависит.

## 1. Стенд

Стенд — отдельная установка того же дистрибутива **той же версии**, что и рабочий сервер.

- Свои домены, база, Redis и **отдельная панель Remnawave**. Общих ключей, адресов уведомлений и данных с рабочим сервером быть не должно.
- В `.env` стенда:

```dotenv
APP_ENV=staging
COOKIE_SECURE=true
# Ключи ПЕСОЧНИЦЫ провайдеров, не боевые
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=test_...
YOOKASSA_WEBHOOK_IP_ALLOWLIST=185.71.76.0/27,185.71.77.0/27,77.75.153.0/25,77.75.156.11,77.75.156.35,77.75.154.128/25,2a02:5180::/32
PLATEGA_MERCHANT_ID=...
PLATEGA_SECRET=...
ROLLYPAY_API_KEY=...
ROLLYPAY_SIGNING_SECRET=...
# Remnawave стенда
REMNAWAVE_URL=https://panel.staging.example.com
REMNAWAVE_TOKEN=...
```

  Список адресов YooKassa сверьте с актуальной документацией YooKassa.

- В кабинетах провайдеров для **тестового** магазина укажите уведомления на стенд: `https://api.staging.example.com/api/webhooks/yookassa` (`platega`, `rollypay`).
- Создайте на стенде включённый тариф с положительной ценой и профилем Remnawave.
- Платёжные системы без ключей в `.env` стенда в проверку выбрать нельзя.

## 2. Ключ стенда на рабочем сервере (один раз)

1. На **стенде**: **Тарифы и оплата → Проверка платежей** → скопируйте «Открытый ключ стенда».
2. На **рабочем сервере**: тот же раздел → «Добровольная проверка на стенде (E2E v2)» → вставьте ключ, отметьте платёжные системы → «Сохранить».

Сохранение начинает новую ревизию: прежний результат перестаёт считаться актуальным. Приём платежей при этом не меняется.

## 3. Проверка

1. **Рабочий сервер** → «Получить код запуска» → скопируйте код `e2e2n.…`. Новый код отменяет предыдущий.
2. **Стенд** → «Проверка E2E v2 на стенде»:
   - вставьте код запуска;
   - выберите тариф и платёжные системы;
   - укажите время на оплату (по умолчанию 30 минут);
   - нажмите «Запустить проверку».
3. Для каждой платёжной системы появится ссылка **«Открыть страницу оплаты»**. Оплатите заказ тестовой картой песочницы провайдера. Дальше всё идёт само: webhook, выдача, повторы, подделки, возврат, отзыв доступа. Обычно это несколько минут на систему.
4. Когда все платёжные системы «пройдено», скопируйте «Подписанный результат».
5. **Рабочий сервер** → вставьте результат → «Принять результат».

Покупатель проверки — служебный аккаунт стенда `e2e-buyer@staging.invalid`, магазин создаёт его сам. Тело и заголовки webhook, нужные для повтора, хранятся зашифрованными только до конца проверки.

Запускать проверку может только администратор: она выполняет возврат. Одновременно идёт одна проверка; вторая получает `409`.

## 4. Разбор ошибок

| Сообщение | Что делать |
| --- | --- |
| «Нет подписанного webhook провайдера для этого заказа» | Проверьте адрес уведомлений в тестовом кабинете провайдера, DNS и HTTPS стенда, для YooKassa — `YOOKASSA_WEBHOOK_IP_ALLOWLIST` |
| «Оплата не завершена за отведённое время» | Оплатите заказ по ссылке или увеличьте время на оплату |
| «Провайдер не подтвердил оплату…» | Сумма, валюта или номер заказа у провайдера не совпали: проверьте ключи песочницы |
| «Выдача VPN не завершилась за 5 минут» | **Состояние системы** и **Очередь задач** стенда: Remnawave стенда, профиль тарифа |
| «Пользователь Remnawave не найден или не активен», «Срок в Remnawave не совпадает» | Проверьте панель Remnawave стенда |
| «Поддельный webhook … не отклонён» | Ошибка конфигурации: например, пустой `YOOKASSA_WEBHOOK_IP_ALLOWLIST` или общий доверенный прокси. Исправьте её и на рабочем сервере |
| «Возврат не подтверждён провайдером за 15 минут» | Проверьте возврат в тестовом кабинете провайдера; запустите проверку снова |
| «Подпись RollyPay действует 5 минут…» | Возврат подтвердился позже окна подписи: запустите проверку снова |
| «Проверка прервана: процесс сервера перезапущен» | Запустите заново |
| На рабочем сервере: «Код запуска не совпадает» | Результат получен со старым кодом: возьмите новый код и повторите |
| «Стенд работает на …, а этот сервер — на …» | Обновите стенд до версии рабочего сервера |
| «Результату больше 24 часов» | Повторите проверку |

## 5. Границы

- Оплату в песочнице провайдера выполняет человек: это требование провайдеров, автоматизировать его нельзя.
- Отдельно не проверяются пополнение кошелька и автопродление: они проходят через тот же шлюз платежей, но своих сквозных сценариев у них пока нет.
- Недоступность Remnawave и очередь повторов выдачи проверяются автотестами, а не на стенде.
- Старая «Проверка ключей песочницы (v1)» в том же разделе проверяет только ключи и возврат у провайдера. Платежи она не открывает.

## API

Стенд: `GET /api/admin/e2e-v2/overview`, `POST /api/admin/e2e-v2/runs` (`nonce`, `plan_id`, `providers`, `payment_timeout_seconds`), `POST /api/admin/e2e-v2/runs/{id}/cancel`.

Рабочий сервер: `PUT /api/admin/e2e-v2/admission/config` (`public_key`, `providers`, `staging_url`), `POST /api/admin/e2e-v2/admission/nonce`, `POST /api/admin/e2e-v2/admission/attestation` (`attestation`), `POST /api/admin/payments/production-gate` (`enabled`) — аварийная остановка и открытие приёма платежей, от результата проверки не зависит.

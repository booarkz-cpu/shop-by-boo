# Выпуск v28.87.0 — свои правила и фрагментация TLS в приложении магазина; учения по восстановлению в CI

Дистрибутив: `v28.87.0`. Runtime/API: `21.5.1`. Head магазина: `0093_ssh_key_rotation` (миграций нет). Support Pro: `0008` / 3.8.

## Этап 19, C3: приложение магазина для Android

В приложение покупателя (`mobile/android-user`) перенесено лучшее из «Корги Люси: клиента»:

- **Свои правила.** «Что работает без VPN → Свои правила»: сайт или адрес (`example.com`, `full:api.example.com`, `keyword:ads`, `regexp:…`, `10.0.0.0/8`) отправляется через VPN, напрямую или блокируется. Правила действуют раньше правил подписки, но после встроенных (частные сети, российские сайты). «Через VPN» идёт туда же, куда остальной трафик: на выбранный сервер или на автоматический выбор. Списки `geosite:`/`geoip:` не принимаются: файлов geo в приложении нет, и Xray отказался бы запускать весь конфиг.
- **Фрагментация TLS.** Делит начало TLS-соединения (ClientHello, пакеты 1–3 или 1–5) — помогает, когда провайдер мешает подключению. Только для серверов с TLS; REALITY не затрагивается.
- Работает для подписок ссылками и для подписок Remnawave в формате Xray JSON. Изменения применяются при следующем подключении (окно переподключает VPN при закрытии). Тексты на русском, английском и украинском.

Версия приложения осталась 3.4.0: номера версий приложений семейства (Android и iOS, клиент и администратор) меняются вместе.

## Этап 19, C2: учения по восстановлению в CI

Каждый PR проходит учения `scripts/ci/restore-drill.sh` в задании «Containers»: данные в работающем магазине → зашифрованная копия `scripts/backup.sh` → потеря всех томов и обоих `.env` → восстановление только из копии → совпадение числа строк каждой из 191 таблицы обеих баз, клиента, подписки, платежа, администратора и файла → магазин стартует, администратор входит. Описание — `docs/ru/BACKUP_CURRENT.md`.

## Этап 19, C1: проверки денег и доступа поведением

Тесты, которые искали строки в исходниках, заменены тестами, вызывающими код: уведомления ЮKassa (чужой заказ, привязка только после подтверждения, список адресов), повтор выдачи и сверка, списание промокода один раз, CSRF и адрес клиента за прокси, адреса, к которым ходит сервер (staging-кассы, мониторинг, DNS rebinding), возвраты под блокировками выдачи, порядок блокировок «клиент → платёж», выбор кассы без ключей, лимит входа администратора, удаление аккаунта. Файлы — `tests/test_behaviour_*.py`.

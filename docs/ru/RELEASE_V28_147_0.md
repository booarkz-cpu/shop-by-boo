# Релиз v28.147.0 — метрики сервера, проверка часов, документ полного восстановления

Дистрибутив: `v28.147.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-14. Раздел реестра «Инфраструктура», продолжение.

## Метрики сервера (REQ-INFRA-0025)

В `/metrics` (по `X-Metrics-Token`) добавлены: задержка запросов p50/p95/p99 по последним 5000 запросам, свободное
место и размер диска (корень и папка media), память сервера, нагрузка процессора за минуту, число процессоров, память
процесса бэкенда, размер пула соединений с базой и занятые соединения. Ничего личного — только числа.

## Часы сервера (REQ-INFRA-0028)

Подписи платёжных уведомлений с окном по времени, коды входа TOTP, сертификаты и расписания полагаются на верные часы.
Раз в 6 часов магазин сверяет свои часы с заголовком `Date` HTTPS-сервера; расхождение больше минуты — оповещение
(больше 5 минут — срочное) с командой `timedatectl set-ntp true`. На тестовых стендах проверка не идёт.

## Полное восстановление (REQ-INFRA-0029, 0035, 0036)

`docs/ru/DISASTER_RECOVERY.md`: какие данные критичны, важны или восстановимы, где лежат и сколько их можно потерять
(база магазина — не больше часа, по решению владельца); почему снимок сервера у хостинга не заменяет копии; порядок
восстановления в 11 шагов — сервер, магазин, копия, секреты, базы, файлы, проверка, DNS, панель Remnawave, ноды,
расписание копий.

## Чем проверено

`tests/test_host_metrics.py`, `tests/test_ops_alerts.py` (часы), тесты наблюдаемости. Восстановление магазина из копии
проверяет `scripts/ci/restore-drill.sh` в каждом PR; восстановление панели и нод по документу вживую не проверено.

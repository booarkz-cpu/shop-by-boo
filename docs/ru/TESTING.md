# Проверка магазина без платёжных систем

Этот контур поднимает API, админку, кабинет и Mini App на вашем компьютере. YooKassa, Platega, RollyPay, Stripe, PayPal, крипто-шлюз, Telegram и Remnawave не нужны.

Песочница не имитирует боевой VPN. Ссылка подписки будет `sandbox://local/...`. Клиент Happ её не импортирует. Так проверяются регистрация, витрина, оплата и запись подписки в базе.

`bash scripts/test-up.sh` передаёт `.env.test` в Docker Compose и привязывает тестовые порты к `127.0.0.1`. Для доступа с другого компьютера используйте SSH-туннель: `ssh -L 18081:127.0.0.1:18081 user@server`. `COOKIE_SECURE=false` годится только для локальной проверки. Боевая установка описана в [DEPLOYMENT.md](DEPLOYMENT.md).

## Что нужно

- Docker Engine и плагин Compose.
- Свободные порты 18080, 18081, 18082, 18083.
- Каталог с этим репозиторием.

## 1. Запустить

Из корня репозитория:

```bash
bash scripts/test-up.sh
```

Скрипт делает пять вещей:

1. Если файла `.env.test` нет, копирует `.env.test.example` и подставляет случайные `APP_SECRET`, пароль базы и пароль администратора.
2. Передаёт `.env.test` в Compose и запускает `docker-compose.test.yml`.
3. Ждёт `http://127.0.0.1:18080/health`.
4. Прогоняет `scripts/sandbox-e2e.sh`: регистрация, покупка тарифа «Тестовый месяц» через провайдер `sandbox`, завершение выдачи.

В конце скрипт печатает `ADMIN_EMAIL` и, при первой генерации, `ADMIN_PASSWORD`. Пароль также лежит в `.env.test`. Файл не коммитьте.

Адреса:

| Поверхность | Адрес |
| --- | --- |
| API | http://127.0.0.1:18080 |
| Админка | http://127.0.0.1:18081 |
| Кабинет | http://127.0.0.1:18082 |
| Mini App | http://127.0.0.1:18083 |

Остановить:

```bash
docker compose --env-file .env.test -f docker-compose.test.yml down
```

Данные базы сохраняются в томах Compose. Чтобы начать с пустой базы, добавьте `-v`.

## 2. Проверить здоровье

```bash
curl -fsS http://127.0.0.1:18080/health
curl -fsS http://127.0.0.1:18080/api/public/config
```

Во втором ответе `payments_sandbox` равен `true`, а в `payment_providers` есть `sandbox`.

## 3. Войти в админку

1. Откройте http://127.0.0.1:18081
2. Введите `admin@example.test` и пароль из `.env.test`.
3. Откройте список тарифов. На пустой базе уже есть «Тестовый месяц»: 100 в валюте по умолчанию, 30 дней, 100 ГБ, 3 устройства.
4. Создайте второй тариф и выключите его. Выключенный тариф не должен появиться в кабинете.

## 4. Купить тариф в кабинете

1. Откройте http://127.0.0.1:18082
2. Зарегистрируйте новый email и пароль.
3. Откройте тарифы и оплатите «Тестовый месяц». Если кнопка не передаёт провайдера, запрос без имени провайдера всё равно уходит в песочницу: других касс в `.env.test` нет.
4. Кабинет возвращается с параметром `sandbox_payment`. Завершение вызывает `POST /api/payments/sandbox/complete`.
5. В разделе подключения ссылка начинается с `sandbox://local/`.

Тот же путь уже выполнил `scripts/sandbox-e2e.sh`. Повторная покупка другим email проверяет, что витрина живая.

## 5. Пополнить баланс

В кабинете, если есть пополнение кошелька, сумма от 50 до 100000. Песочница помечает платёж оплаченным и зачисляет сумму на `wallet_balance`. Повтор с тем же `Idempotency-Key` не зачисляет сумму второй раз.

## 6. Чего ждать не стоит

- Контейнер бота в тестовом файле не запускается. Пустой `BOT_TOKEN` в production по-прежнему останавливает бота, а вне production процесс бота просто ждёт, если его всё же запустили.
- Узлы в `/api/public/servers` могут быть пустыми. Это нормально без агента и без Remnawave.
- Живой провайдер в этом контуре отвечает ошибкой: ключей касс нет.
- Запрос `provider=yookassa` не переписывается в песочницу. Песочница выбирается сама только когда провайдер не указан и ни одна живая каса не настроена, либо когда явно передан `sandbox`.

## 7. Починить запуск

```bash
docker compose --env-file .env.test -f docker-compose.test.yml logs --tail 80 backend
```

Если API не становится готовым, почти всегда виден текст Alembic или `APP_SECRET must be at least 32 characters`. Не ставьте в `.env.test` значение `APP_ENV=production`.

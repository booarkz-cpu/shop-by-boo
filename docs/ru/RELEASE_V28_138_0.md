# Релиз v28.138.0 — MASQUE: страница обслуживания, когда сайт SelfSteal не отвечает

Дистрибутив: `v28.138.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-14. Пункт плана MASQUE: «своя страница, когда сайт не работает».

## Что было

Порт MASQUE отдаёт всё, кроме туннеля, сайту SelfSteal на ноде. Когда сам сайт не отвечал (контейнер Caddy
перезапускается после обновления или остановлен), HAProxy закрывал соединение пустым ответом 503. Обычный веб-сервер
так не отвечает — по этому можно было догадаться, что на порту прокси.

## Что стало

- Пока сайт не отвечает, порт показывает обычную страницу «сайт на обслуживании»: HTML, код 503, `Retry-After: 300`,
  `Cache-Control: no-store`. В ней нет имени прокси, Xray, MASQUE или бренда.
- Как только сайт снова работает, порт сразу показывает его.
- Туннель это не затрагивает: его ответы по-прежнему закрываются без страницы.
- Ноды, где MASQUE уже стоит, воркер переустанавливает сам один раз (стек версии 3); туннели переподключатся.

## Чем проверено

Настоящий HAProxy в CI (`scripts/ci/masque-check.sh`): сайт остановлен — порт отвечает страницей обслуживания с
`Retry-After` и без имени прокси; сайт запущен — снова его главная страница. `tests/test_masque_panel.py`: страница
подключена к 502/503/504 только у сайта, без лишних слов, помещается в буфер HAProxy. На живой ноде не проверено.

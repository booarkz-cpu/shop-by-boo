# Промогруппы и персональные предложения

Раздел «Маркетинг → Группы и предложения» доступен admin/operator с `manage_marketing`. Правило аудитории дополняет существующий промокод: цена, сроки, тарифы, минимальная сумма, общая квота и лимит клиента остаются частью общего checkout. Новые предложения не создают второй финансовый механизм.

## Новый персональный оффер

Включите «Создать новый персональный промокод». Укажите код из 2–64 заглавных латинских букв, цифр, `_` или `-`, вид скидки (процент/фиксированная сумма), размер, название и описание. Процент не превышает 100; фиксированная сумма относится к валюте магазина. Выберите персональные ID клиентов магазина (не Telegram ID) либо промогруппу. Нажмите «Сохранить предложение».

Промокод и ограничение аудитории создаются **в одной транзакции**: код не бывает временно общедоступным. По умолчанию новый код можно использовать один раз на клиента. API позволяет задать `max_uses_per_user` от 1 до 1000. Нулевой итог заказа существующее ядро не принимает: оффер со скидкой 100% не заменяет бесплатный триал или конкурсный бонус.

Можно назначить аудиторию существующему промокоду. До сохранения правила он сохраняет прежнюю доступность; уже оплаченные заказы и зафиксированные снимки цены не изменяются задним числом. Для нового приватного предложения используйте атомарное создание, а не создание публичного кода с последующим ограничением.

## Промогруппы

Группа содержит название, состояние и один способ определения участников:

- **Ручной список** — до 1000 разных положительных Shop ID. Все клиенты должны существовать и не быть удалёнными. Пустая группа никого не допускает.
- **Без покупок** — нет платежей в `paid`, `fulfilled`, `refunded`.
- **Активная подписка** — есть подписка со статусом `active` и сроком в будущем.
- **Истёкшая подписка** — есть истёкшая подписка и нет действующей `active`.
- **Приглашённые** — установлен `referred_by_id`.

Динамические группы вычисляются на сервере при чтении предложения и оформлении заказа. Ручные ID у динамической группы не задаются. Существующую группу можно изменить или выключить; изменение использует её номер версии. После ответа 409 обновите раздел и сравните настройки. Отключённая группа никого не допускает; она не превращается в публичную аудиторию.

## Кабинет и Mini App

На странице тарифов клиент видит «Ваши предложения». Показываются только предложения, разрешённые для его аккаунта, действующие по сроку и доступные по квоте. Нажатие «Применить CODE» заполняет промокод; итоговая цена и ограничения выбранного тарифа проверяются сервером при оформлении. Список не раскрывает ID остальных получателей или состав групп.

Покупка с кошелька и внешняя покупка проверяют аудиторию при расчёте и повторно при резервировании промокода. Правило, отключённое после расчёта, не позволяет списать деньги по новому заказу. Квота кошелька резервируется до записи списания и выдачи VPN, поэтому задержка выдачи не даёт использовать одноразовый код дважды. Повтор с прежним `Idempotency-Key` возвращает прежний заказ. Оплаченная незавершённая выдача сохраняет резерв; не удаляйте её вручную ради освобождения квоты.

Выключение оффера блокирует промокод для новых заказов; это не снимает ограничение аудитории. Удаление промокода, связанного с оффером, запрещено: отключите код/оффер, сохранив историю. Подарки и автопродление не получают новые скидки автоматически. Полная цена будущего автопродления сохраняется существующим ядром.

## API, backup и проверки

- `GET/POST /api/admin/promo-groups`, `PUT /api/admin/promo-groups/{id}` — группы; при обновлении нужен `version`.
- `POST /api/admin/personal-offers` — атомарные код и аудитория, `version=0`.
- `GET /api/admin/promo-audiences`, `PUT /api/admin/promo-audiences/{promo_id}` — существующие ограничения; первый `version=0`, далее текущий номер.
- Списки админки принимают `offset`/`limit` до 100; при работе через API учитывайте все страницы.
- `GET /api/me/offers` — приватный список. `next_offset` — курсор следующей страницы; даже пустая страница может содержать следующий курсор, если остальные предложения предназначены другим клиентам.

Миграция 0060 создаёт группы, участников и аудитории. При наличии правил downgrade запрещён: удаление ограничения при откате могло бы сделать приватный код публичным. Таблицы входят в backup магазина. При восстановлении проверяйте оффер чужим аккаунтом и выполните тестовую покупку по процедуре staging.

Автотесты проверяют личную/групповую доступность, динамические сегменты, отключение после расчёта, запрет устаревшей правки, квоты и повтор покупки с кошелька до выдачи VPN, отсутствие утечки получателей, права и PostgreSQL-конкуренцию создания одного кода. Chromium проверяет создание через админку и чтение своим клиентом.

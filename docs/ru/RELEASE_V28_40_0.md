# Выпуск v28.40.0 — кассы WATA и Antilopay

Дистрибутив: `v28.40.0`. Runtime/API: `21.5.1`. Head магазина: `0081_subscription_proxy` (новых миграций нет). Support Pro: `0008` / 3.8. Мобильные приложения: 3.4.0. Дата и commit фиксируются тегом выпуска.

## Что изменилось

**Кассы WATA и Antilopay** — «Платёжные агенты»

- Карта и СБП через WATA и Antilopay. Каждая касса встаёт в очередь касс и в выбор способа оплаты, как только заданы её ключи: «Система → Настройки без перезапуска» (секреты хранятся зашифрованно) или `.env`.
- Уведомления подписаны RSA:
  - WATA — `X-Signature`, SHA-512; открытый ключ магазин берёт у WATA сам и хранит час;
  - Antilopay — `X-Apay-Callback`, SHA-256; открытый ключ — из кабинета Antilopay.
- Запросы к Antilopay подписаны закрытым ключом магазина.
- Подписка выдаётся только после повторной проверки платежа в API кассы: WATA — транзакции по заказу, Antilopay — `payment/check` с исходной суммой.
- RSA-ключи принимаются как base64 или PEM (в `.env` можно писать `\n`).
- Реестр настроек: 213 полей, из них 121 live (+6 ключей касс).

Подробно — [billing_and_taxes.md](../modules/billing_and_taxes.md#wata-и-antilopay-v2840), что сделать владельцу — [OWNER_ACTIONS.md](OWNER_ACTIONS.md).

## Проверки

- `tests/test_payments_wata_antilopay.py`. На моках API касс с настоящими RSA-подписями проверяется:
  - страница оплаты;
  - подпись запросов Antilopay;
  - подписи уведомлений и кэш открытого ключа WATA;
  - повторная проверка платежа;
  - отказ при чужой подписи.
- Боевая проверка — на договоре и ключах владельца.

## Не вошло

- Aurapay, Cashera, Tribute, Anore — следующими выпусками.
- Векторная карта стран: среда сборки не получает внешние геоданные.

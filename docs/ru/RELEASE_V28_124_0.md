# Релиз v28.124.0 — сверка настроек магазина с панелью Remnawave

Дистрибутив: `v28.124.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-12. Задача владельца: все требования реестра — в статус PASS (этап 23). Раздел Remnawave, требование `REQ-RW-0007`.

## Что изменилось

- В разделе «Расширения Remnawave» появился блок **«Сверка с панелью»**.
  - Магазин помнит, что он настроил на панели: пул автовыбора и временный бан за торренты.
  - Блок показывает, где панель перестала с этим совпадать: удалённая плитка или сервер пула, выключенный бан, другой срок бана.
  - У каждого расхождения есть ссылка на раздел, где его исправить.
- Проверка запускается по кнопке и каждые шесть часов. О новом расхождении администраторам приходит сообщение.
- Сверка ничего не меняет: исправление — повторное применение настройки в её разделе.

Подробно: [RW_DRIFT.md](../RW_DRIFT.md).

## Реестр требований: раздел Remnawave

Раздел сверен целиком (16 требований): 1 PASS, 13 PARTIAL, 2 NOT_IMPLEMENTED.
`REQ-RW-0007` переведено из NOT_IMPLEMENTED в PARTIAL: расхождения выявляются для пула автовыбора и бана за торренты, но не для подписок.

Не реализовано: раздельное хранение желаемого и наблюдаемого состояния для всех объектов (`REQ-RW-0005`) и цикл согласования
с повторами и очередью неудавшихся операций (`REQ-RW-0006`).

## Чем проверено

- `tests/test_rw_drift.py` — поиск расхождений, последний результат, сбой панели, расписание, одно сообщение на расхождение.
- `tests/test_rw_torrent_ban.py` — магазин запоминает включённый бан и забывает выключенный.
- `admin/e2e/rw-drift.spec.ts` — блок в браузере.

## Чего пока нет

- Сверки подписок, профилей конфигурации и хостов вне пула.
- Автоматического исправления расхождений.
- Проверки на настоящей панели: нужен VPS.
- Бан за торренты, включённый до этого выпуска, магазин не помнит: чтобы он попал в сверку, включите его ещё раз.

## Что нужно от владельца

Ничего для установки.

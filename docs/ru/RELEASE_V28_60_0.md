# Выпуск v28.60.0 — Админ-центр

Дистрибутив: `v28.60.0`. Runtime/API: `21.5.1`. Head магазина: `0089_index_cleanup` (миграций нет). Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

Этап 6 мастер-задания: единая административная панель. Таблица управляемости — [ADMIN_CONTROL_MATRIX](new/ADMIN_CONTROL_MATRIX.md).

## Что изменилось

**«Система → Админ-центр»**

- В таблице 30 модулей из задания. По каждому видно:
  - какие разделы панели им управляют (каждый открывается кнопкой);
  - какие операции доступны: чтение, создание, изменение, удаление, поиск и фильтр, настройки, проверка, запись в журнал;
  - какие права нужны.
- Операции не отмечены вручную, а вычисляются из маршрутов API (`backend/app/admin_center.py`):
  - метод запроса даёт операцию;
  - параметры запроса — поиск и фильтры;
  - зависимости маршрута — права;
  - код обработчика показывает, пишет ли изменение в журнал.

  Поэтому таблица не расходится с кодом. Те же данные записаны в `docs/ru/new/ADMIN_CONTROL_MATRIX.md`, тест следит, чтобы документ был актуальным.
- **Модули без раздела:** установка Remnawave, домены, сертификаты, Reverse Proxy, расширения нод. Они отмечены `NOT_STARTED` с номером этапа, который их добавит, и не показывают кнопок, которые ничего не делают.
- **Итог:** 25 из 30 модулей управляются из панели.

**Права ролей**

- В «Безопасность → Роли и администраторы» появилась таблица: роли `viewer`, `operator`, `admin` и права каждой из них, у каждого права — описание. Наборы прав заданы в коде и одинаковы на всех установках; роль администратора меняется в списке администраторов.

**Журнал действий**

- Поиск по администратору, действию (по началу, например `payment.`), цели и периоду, постраничный просмотр. Введённый текст ищется буквально: `%` и `_` не служат подстановкой.
- Теперь в журнал попадают изменения, которые раньше в него не писались:
  - настройки прослойки подписок;
  - блокировка и разблокировка устройств;
  - каталог клиентских приложений.

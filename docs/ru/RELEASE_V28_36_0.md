# Выпуск v28.36.0 — очередь касс, монитор блокировок, возврат брошенных оплат, юнит-экономика, горячий резерв, автомасштабирование, приложения 3.2.0

Дистрибутив: `v28.36.0`. Runtime/API: `21.5.1`. Head магазина: `0079_acquisition`. Support Pro: `0008` / 3.8. Мобильные приложения: 3.2.0. Дата и commit фиксируются тегом выпуска.

Установка с нуля до продакшена: [docs/INSTALLATION.md](../INSTALLATION.md). Архитектура: [docs/modules](../modules/README.md).

## Что изменилось

**Резервные кассы** — [оплата](../modules/billing_and_taxes.md#резервный-шлюз-и-автоплатежи)

- «Платёжные агенты → Очередь касс» в веб-админке и вкладка «Платежи» в мобильных админках: порядок касс, включение каждой, состояние «принимает / остывает / нет ключей», «Вернуть в работу».
- Исправлено: в админке можно было менять только ЮKassa, Platega и RollyPay — теперь все пять касс.
- Проверка «Резервная касса» в «Запуск и оповещения», если готова только одна касса.
- Сквозной тест всей цепочки ЮKassa → RollyPay → Platega → CryptoBot → Freekassa.

**Монитор блокировок** — [защита от блокировок](../modules/anti_blocking.md#монитор-блокировок)

- Пробы (`scripts/block-probe.py`) на серверах в регионах клиентов каждые 5 минут проверяют домены API и ноды.
- Блокировка в регионе — сообщение в Telegram; заблокированный домен API уходит в конец подписанного списка зеркал; по желанию всем клиентам добавляется резервный Internal Squad, пока блокировка длится.

**Деньги** — [модуль 25](modules/25-automation-jobs.md#готовые-сценарии-и-личные-промокоды), [юнит-экономика](../modules/unit_economics.md)

- События автоматизации «Начал оплату и не заплатил» и «Автопродление не прошло» с готовыми сценариями; сценарий «Трафик закончился».
- «Кассы за период»: заказы, оплаты, конверсия, выручка и время до оплаты по каждой кассе.
- Юнит-экономика: источник клиента (`start=src_…`, `startapp=src_…`, `?utm_source=…`), расходы на рекламу по месяцам, CAC и ROMI. Миграция `0079_acquisition` добавляет `users.acquisition_source`.

**Инфраструктура** — [горячий резерв](../modules/hot_standby.md), [автомасштабирование](../modules/node_autoscale.md)

- Горячий резерв базы: `scripts/hot-standby.sh` (потоковая репликация PostgreSQL по TLS, роль только для репликации, порт открыт лишь для IP резерва, `promote` / `demote`), агент `scripts/standby-agent.py` на резерве (отставание, сообщение в Telegram, если основной молчит по всем путям; по желанию — автоповышение и переключение DNS в Cloudflare). «Резервные копии → Горячий резерв»: реплики, отставание, слоты, агент; оповещения и пункт готовности. Автоповышение выключено по умолчанию; на двух настоящих серверах сценарий ещё не проверялся — проведите учебное переключение.
- Автомасштабирование нод по числу пользователей онлайн на ноду: рекомендации в Telegram или (режим «Авто») создание и удаление серверов Hetzner Cloud с Remnawave Node; удаляются только ноды, созданные автоматически. Ключи — `HETZNER_API_TOKEN`, `REMNANODE_SECRET_KEY` в `.env`. Вызовы создания ноды в Remnawave на живой панели не проверялись.

**Приложения и надёжность** — [диагностика](../modules/in_app_diagnostics.md)

- Приложения 3.2.0 (номер сборки 3200).
- «Не работает VPN» в приложениях: проверки с телефона (DNS, API, подписка, TCP до каждого сервера) → `POST /api/me/diagnostics` → клиент сразу видит причину и подсказку, поддержка получает тикет с отчётом.
- `/api/me/sync` будится каждым сохранением подписки, платежа или баланса клиента (Redis pub/sub) вместо опроса базы раз в 3 секунды.
- Проверки готовности: копия базы в Telegram, резервный адрес API, база знаний ИИ.
- CI: Maestro закреплён на 2.12.0, приложение перед сценариями компилируется заранее; XCUITest повторяется один раз только при сбое запуска симулятора.

## Обновление

Автообновление поставит выпуск само ночью; вручную — «Выпуски → Автообновление → Проверить и обновить сейчас» или

```bash
bash /opt/vpn-shop/scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.36.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

Документация на английском и украинском: [docs/en/NEW_IN_V28_36.md](../en/NEW_IN_V28_36.md), [docs/uk/NEW_IN_V28_36.md](../uk/NEW_IN_V28_36.md).

Миграция `0079_acquisition` только добавляет колонку и совместима с прежней версией — обновление без простоя работает.

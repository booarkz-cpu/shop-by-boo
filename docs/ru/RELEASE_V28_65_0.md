## Найдено и исправлено

`POST /api/admin/provision-node` принимал из запроса текст compose-файла и разворачивал его на сервере от root. Проверялось только, что в тексте есть строка `remnawave/node`. Значит, можно было запустить любой контейнер с любыми правами.

Теперь:
- тело запроса — типизированная модель `NodeProvisionIn`, лишние поля дают ответ 422;
- отпечаток ключа SSH обязателен;
- compose строит магазин по официальному образцу (`provisioner.node_compose`), ключ ноды берётся у панели;
- SSH выполняется вне цикла событий API.

Раздела в админке у маршрута не было; он вызывался только через API.

## Обновление

Миграций нет.

```bash
cd /opt/vpn-shop && bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.65.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

Если вы вызывали `POST /api/admin/provision-node` из своих скриптов, вместо `compose_yaml` передавайте `ssh_host_key` в формате `SHA256:…`; остальные поля прежние.

# Ключи доступа клиента — v21.5.1

WebAuthn реализован в HTTPS браузере кабинета. Сервер проверяет challenge, origin/RP ID, подпись, UV, opaque user handle и счётчик. Одноразовые challenges хранятся в БД, привязаны к браузеру и действуют пять минут. Клиентские и административные credentials/challenges разделены.

## Настройка оператора

В `.env` задайте `CUSTOMER_WEBAUTHN_ORIGIN=https://cabinet.YOUR_DOMAIN` без пути и завершающего `/`. Пересоздайте backend/worker/bot. В админке включите feature flag `passkeys`. Миграция `0055_customer_passkeys` должна быть применена. Новая VDS установка записывает origin автоматически.

Не меняйте hostname после регистрации без плана переноса: credential связан с RP ID. Mini App на другом hostname и native платформы требуют своих отдельных интеграций; здесь они не объявляются завершёнными. HTTP допустим только на localhost в test/development.

## Регистрация и вход

1. Войдите в кабинет обычным способом. Откройте «Безопасность → Ключи доступа».
2. Введите название. Для email/password аккаунта укажите текущий пароль. Для Telegram/OAuth-only аккаунта войдите заново не более чем за пять минут до действия; пароль ему автоматически не назначается.
3. Нажмите «Добавить ключ доступа» и подтвердите биометрией/PIN в браузере.
4. Убедитесь, что ключ появился в списке. Максимум десять ключей на аккаунт.
5. Выйдите. На странице входа выберите «Войти с ключом доступа» и подтвердите устройство.

Успешный вход создаёт штатную серверную сессию; её можно отозвать через обычные механизмы безопасности. Реальный ключ остаётся у аутентификатора; сервер хранит только открытый ключ и metadata. Ответ inventory не содержит public key/credential ID.

## Удаление и восстановление

В разделе ключей подтвердите текущий пароль либо свежий OAuth/Telegram вход, затем удалите выбранный ключ. Чужой ключ удалить нельзя. Удалённая credential больше не проходит проверку новых assertions. Уже выданные сессии отзывайте отдельно, если устройство потеряно.

При анонимизации аккаунта сервер удаляет все его клиентские credentials и незавершённые registration challenges, очищает opaque handle и отзывает доступ.

Passkey не заменяет сохранение способа восстановления аккаунта. Сброс пароля, email и обычные сессии описаны в [руководстве](WORKSPACE_ACCOUNT_SECURITY.md). При удалённом/ограниченном аккаунте вход по ключу отклоняется. Downgrade 0055 запрещён при зарегистрированных клиентских ключах.

## Проверка

CI проверяет реальные COSE signatures и UV/origin/handle/replay/counter attacks, разделение владельцев и отсутствие сессии при отказе. Chromium с virtual authenticator выполняет регистрацию, discoverable login и удаление через настоящий WebAuthn браузера. Физические устройства и синхронизацию ключей проверьте на своём HTTPS стенде.

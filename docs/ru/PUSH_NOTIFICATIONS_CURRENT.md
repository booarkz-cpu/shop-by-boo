# Push-уведомления в приложениях Android и iOS

Приложения Corgi для Android и iOS получают системные push-уведомления о событиях из центра уведомлений клиента: оплата подтверждена, подписка активирована, ответ поддержки, призы, массовые рассылки из админки. Центр уведомлений в приложении остаётся основным источником: push — это сигнал «откройте приложение», без гарантии доставки.

- Android — Firebase Cloud Messaging (FCM HTTP v1).
- iOS — Apple Push Notification service (APNs, авторизация ключом `.p8`, HTTP/2).
- Без ключей провайдеров магазин работает как раньше: устройства можно зарегистрировать, но ничего не отправляется, а приложение и админка показывают «не настроено».

## Как это работает

1. Клиент включает push на вкладке **Уведомления** приложения. Android 13+ и iOS запрашивают системное разрешение.
2. Приложение передаёт токен провайдера в `POST /api/me/push/devices`. Сервер хранит только SHA-256 токена для поиска и сам токен в зашифрованном виде (AES-GCM, ключ из `APP_SECRET`). Токен привязывается к **текущей сессии входа**.
3. Worker раз в несколько секунд создаёт доставку для каждого нового уведомления и каждого активного устройства клиента и отправляет её провайдеру.
4. Перед каждой отправкой проверяется, что устройство не отключено, сессия не завершена и не истекла, а аккаунт не удалён и не объединён с другим. Иначе устройство отключается без обращения к провайдеру.

### Когда устройство отключается

| Причина в админке | Что произошло |
| --- | --- |
| выход из аккаунта | Сессия завершена: «Выйти», «Завершить все сессии», смена устройства, истечение. Приложение также само отзывает токен до выхода. |
| токен недействителен | FCM ответил `UNREGISTERED`/`INVALID_ARGUMENT`, APNs — `410`/`BadDeviceToken`/`DeviceTokenNotForTopic` (приложение удалено, токен сменился). |
| выключено/удалено клиентом | Клиент выключил push в приложении. |
| токен обновлён | Провайдер выдал новый токен, приложение заменило старый. |
| вход в другой аккаунт | На том же устройстве вошли в другой аккаунт — прежний владелец перестаёт получать push. |
| аккаунт закрыт | Аккаунт удалён или объединён. |
| лимит устройств | У клиента больше 10 активных устройств — отключаются самые давние. |

При повторном входе и при каждом обновлении данных приложение заново привязывает токен к новой сессии — включать push повторно не нужно, если клиент не выходил из аккаунта. После выхода push выключается: следующий владелец телефона должен включить его сам.

### Повторы и ограничения

- Временные ошибки (`429`, `5xx`, сеть) повторяются с паузой 30 с, 1, 2, 4 минуты; после 5 попыток доставка помечается ошибкой.
- Ошибки ключей (`401`/`403`, неверный JSON сервисного аккаунта, неверный `.p8`) не отключают устройства клиентов — они повторяются и видны в админке как «Ошибка» с кодом.
- В push попадают только уведомления не старше часа на момент обработки; неотправленные за 24 часа истекают. Прочитанные в приложении уведомления не отправляются.
- Заголовок обрезается до 80, текст — до 180 символов. Текст ответа поддержки на экран блокировки не выводится: показывается «Откройте приложение, чтобы прочитать ответ поддержки».
- Повторная отправка той же доставки схлопывается на устройстве (`apns-collapse-id`, тег FCM).
- Журнал доставок хранится 30 дней, отключённые устройства удаляются через 30 дней.

## Настройка сервера

Ключи провайдеров — секреты сервера. Задайте их в `.env` и перезапустите `backend` и `worker` (`docker compose up -d backend worker`). Через «Настройки без перезапуска» они не меняются.

### Android (FCM)

1. В [Firebase console](https://console.firebase.google.com/) создайте проект и добавьте Android-приложение с пакетом `shop.remnawave.user`. Для отладочных сборок из CI (`assembleDebug`) добавьте также `shop.remnawave.user.preview`.
2. **Project settings → Service accounts → Generate new private key** — скачайте JSON сервисного аккаунта (роль Firebase Cloud Messaging API Admin или выше). Включите **Firebase Cloud Messaging API (V1)** в Google Cloud.
3. В `.env` магазина:

```dotenv
FCM_PROJECT_ID=your-firebase-project-id
# JSON целиком одной строкой или base64 от файла: base64 -w0 service-account.json
FCM_SERVICE_ACCOUNT_JSON=eyJ0eXBlIjoic2VydmljZV9hY2NvdW50Ii...
```

Магазин подписывает JWT ключом сервисного аккаунта (RS256), получает OAuth-токен Google и кэширует его на время жизни.

### iOS (APNs)

1. В Apple Developer: **Certificates, IDs & Profiles → Keys → +**, включите Apple Push Notifications service, скачайте `.p8` (скачивается один раз), запишите Key ID и Team ID.
2. В App ID `shop.remnawave.user` включите capability Push Notifications. В проекте Xcode entitlement `aps-environment` уже добавлен (`VpnShopUser/VpnShopUser.entitlements`).
3. В `.env` магазина:

```dotenv
APNS_KEY_ID=ABC123DEFG
APNS_TEAM_ID=TEAM123456
APNS_BUNDLE_ID=shop.remnawave.user
# Содержимое .p8; переводы строк можно записать как \n
APNS_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIGT...\n-----END PRIVATE KEY-----
# sandbox для сборок, установленных из Xcode; production для TestFlight/App Store
APNS_ENVIRONMENT=production
```

Провайдерский JWT (ES256) перевыпускается каждые 45 минут.

## Сборка приложений

### Android

Push включается в сборку, если заданы публичные идентификаторы Firebase (они не секретны — это те же значения, что в `google-services.json`; плагин google-services не используется). Задайте переменные окружения или Gradle-свойства перед сборкой:

| Переменная | Gradle-свойство | Где взять |
| --- | --- | --- |
| `CORGI_FIREBASE_APP_ID` | `corgi.firebase.app_id` | Project settings → Your apps → App ID (`1:…:android:…`) |
| `CORGI_FIREBASE_API_KEY` | `corgi.firebase.api_key` | Web API key проекта |
| `CORGI_FIREBASE_PROJECT_ID` | `corgi.firebase.project_id` | Project ID |
| `CORGI_FIREBASE_SENDER_ID` | `corgi.firebase.sender_id` | Cloud Messaging → Sender ID |

```bash
export CORGI_FIREBASE_APP_ID=1:1234567890:android:abcdef
export CORGI_FIREBASE_API_KEY=AIza...
export CORGI_FIREBASE_PROJECT_ID=your-firebase-project-id
export CORGI_FIREBASE_SENDER_ID=1234567890
bash scripts/build-android-apk.sh "$PWD/dist/mobile"
```

Без этих значений приложение собирается и работает, а на вкладке «Уведомления» пишет «Эта сборка приложения не поддерживает push». Автоматическая инициализация Firebase, сбор аналитики и выдача токена до согласия клиента отключены в манифесте.

### iOS

Отдельной настройки сборки нет: подпишите приложение профилем с Push Notifications. В CI проверяется сборка для симулятора без подписи; реальные токены выдаются только подписанной сборке на устройстве.

## Проверка

1. В админке откройте **Уведомления**. Карточка «Push-уведомления» показывает, настроены ли FCM и APNs (проект, bundle ID и окружение), число активных устройств Android/iOS, итоги доставки за 24 часа, причины отключений за 7 дней и частые ошибки. Токены не показываются. Нужна роль с правом `ops.diagnostics`.
2. В приложении на устройстве: **Уведомления → Включить push**, разрешите уведомления. Сообщение «Магазин ещё не настроил отправку push» значит, что на сервере нет ключей для этой платформы.
3. Нажмите **Отправить тестовое уведомление** — не чаще раза в минуту. Уведомление появится и в центре уведомлений приложения.
4. Выйдите из аккаунта и отправьте клиенту уведомление из админки: push не должен прийти, а устройство — отключиться с причиной «выход из аккаунта».

Если тестовое уведомление не пришло, проверьте карточку в админке: `FCM SENDER_ID_MISMATCH`/`THIRD_PARTY_AUTH_ERROR` — проект Firebase в сборке и на сервере разный; `APNs BadCertificateEnvironment` — неверный `APNS_ENVIRONMENT`; `APNs BadTopic` — `APNS_BUNDLE_ID` не совпадает с приложением.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/me/push/devices` | регистрация токена текущей сессии (`platform`, `token`, `app_version`, `locale`, `replaces`) |
| `GET` | `/api/me/push/devices` | активные устройства клиента и готовность провайдеров |
| `POST` | `/api/me/push/devices/unregister` | отзыв токена (`token`) |
| `DELETE` | `/api/me/push/devices/{id}` | отключение устройства клиента |
| `POST` | `/api/me/push/test` | тестовое уведомление на текущее устройство |
| `GET` | `/api/admin/push/status` | состояние провайдеров, устройств и доставки |

Миграция `0066_push_notifications` добавляет таблицы `push_devices`, `push_deliveries` и колонку `notifications.push_fanout_at`. Уже существующие уведомления помечаются обработанными — после обновления старые события не рассылаются.

## Границы

Автотесты (`tests/test_push.py` на SQLite и PostgreSQL) проверяют регистрацию, привязку к сессии, подписи запросов FCM и APNs по ключам, ответы провайдеров, повторы, отключение устройств и отсутствие токенов в ответах. Они не проверяют реальную доставку через серверы Google и Apple: это делается на стенде с ключами оператора и подписанными сборками. Виджет Android и административный мультипрофиль пока не реализованы.

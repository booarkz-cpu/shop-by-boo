# v28.1.0 — админ-панель и проверяемый дистрибутив

Дистрибутив `v28.1.0` содержит runtime/API `21.5.1`, магазин `0062_support_delivery_identity` и Support Pro `0007` / 3.7. Миграции не меняются. Дата выпуска и точный коммит фиксируются GitHub Release.

## Изменения

- Списки редактирования переведены на shadcn/Radix Select. Сохраняются значения и обработчики форм; доступны клавиатура, иконки, hover, focus и disabled.
- Тема и язык выбираются через Radix DropdownMenu. Тема сервера используется по умолчанию, выбор браузера сохраняется.
- Каждое видимое редактируемое поле получает RU/EN-подсказку: доступное описание, кнопку помощи, фокус и нажатие на мобильном экране. Portal предотвращает обрезание контейнерами; Escape закрывает подсказку.
- Успешная авторизация сбрасывает только свой счётчик попыток входа в Redis и локальном fallback. Общие лимиты запросов и лимиты неверных паролей сохраняются.
- Тег дистрибутива отделён от API-версии: обновление UI при прежнем API определяется корректно. Новый загрузчик проверяет архив, SHA-256, манифест и коммит GitHub-тега.
- Упаковка исходников детерминирована. Публикация ждёт успешных CI и Docker на актуальном `main`, проверяет загрузку всех файлов и сохраняет черновик при ошибке. Существующие теги и несовпадающие файлы не заменяются.
- Обновлены действующие инструкции и полная [карта файлов](../PROJECT_FILE_MAP.md). Исторические release notes остаются историческими.

Точные результаты проверок доступны в CI на коммите релиза. Проверяются типы и сборки интерфейсов, браузерные сценарии, Python-тесты, миграции, контейнеры, зависимости и мобильные сборки. Отдельные тесты проверяют отказ при несовпадении манифеста, повреждённой загрузке и изменении `main` во время публикации. Docker на релизном теге запускается явно, поскольку тег, созданный `GITHUB_TOKEN`, не запускает push workflow автоматически.

## Границы выпуска

`production_ready`, `full_function_transfer` и `production_e2e_verified` остаются `false`. Реальные платежи требуют завершения application E2E и проверки собственного стенда. Неперенесённые продуктовые подсистемы остаются открытыми в [матрице](WORKSPACE_COVERAGE.md); этот выпуск закрывает описанные изменения интерфейса и публикации. Новая реализация Freekassa не входит в выпуск: разрешённые кассы новых покупок — YooKassa, RollyPay и Platega. Подписанные APK/IPA требуют ключей владельца. Архив и манифест не подписаны криптографически; SHA-256 подтверждает целостность и соответствие опубликованных файлов.

# Выпуск v28.66.0 — мастер установки Remnawave

Дистрибутив: `v28.66.0`. Runtime/API: `21.5.1`. Head магазина: `0090_remnawave_installer` (одна новая миграция). Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

Этап 10 мастер-задания.

## Что сделано

**Раздел «Серверы → Установка Remnawave»** ([руководство](new/REMNAWAVE_INSTALLATION_WIZARD.md)):
- **Реестр серверов.** Адрес, порт и пользователь SSH, ключ или пароль, назначение. Секрет хранится зашифрованным и не возвращается. Отпечаток ключа сервера обязателен: кнопка «Получить отпечаток» читает его без входа, администратор сверяет его с хостингом.
- **Проверка сервера** ([preflight](new/REMNAWAVE_PREFLIGHT.md)): ОС, архитектура, CPU, память, диск, Docker, занятые порты, веб-серверы, ufw, DNS. Ошибка останавливает установку до любых изменений.
- **Семь режимов** ([режимы](new/REMNAWAVE_INSTALLATION_MODES.md)): панель + нода, только панель, только нода, панель + страница подписки, только страница подписки, распределённая установка, добавить ноду.
- **План.** Что изменится на каждом сервере, все шаги, образы с SHA-256. Запуск — только этого плана: хэш сверяется, план строится заново из текущих серверов.
- **Установка по шагам** с журналом, откатом и отменой. Docker из подписанного репозитория; файлы по официальным compose и `.env.sample`; закреплённые образы (панель 3.4.8, нода 3.4.4, страница подписки 8.0.1, PostgreSQL 18.4, Valkey 9.1.3, Caddy 2.11); первый администратор и токен API панели; регистрация нод; Caddy с Let's Encrypt или внутренним сертификатом; проверка HTTPS и связи нод.
- **Обслуживание.** Обновление (с копией базы панели), диагностика, восстановление базы, переустановка, удаление — каждое через план и подтверждение.
- **Подключение магазина к новой панели** — через двухшаговые настройки без перезапуска.

**Исполнитель** ([Deployment Agent](new/DEPLOYMENT_AGENT.md)): свой цикл в worker, отдельно от очереди платежей. Задачу берёт один worker; на сервере — одна задача за раз. Задача без «пульса» 5 минут становится `failed`.

**Безопасность.** Браузер выбирает только серверы, режим и типизированные значения; на сервере выполняются фиксированные скрипты закрытого списка, значения передаются экранированными аргументами или через stdin. Ключ сервера сверяется по отпечатку. Секреты (SSH, пароли базы и администратора, токен API) зашифрованы, в журналах шагов заменены на `***`. Порты панели — только `127.0.0.1`. Общий Caddy магазина и `sub_proxy` не меняются; рядом с чужим веб-сервером мастер не ставит второй прокси.

## Чего нет

- Агента на сервере установки: управление после установки идёт по SSH из worker. Агент и автообновление — этап 15.
- Передачи копии базы панели в хранилище магазина: копии остаются на сервере панели (5 последних) — этап 15.

## Обновление

Миграция `0090_remnawave_installer` добавляет три таблицы и применяется обычным обновлением.

```bash
cd /opt/vpn-shop && bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.66.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

Worker перезапускается обновлением и начинает выполнять задачи мастера.

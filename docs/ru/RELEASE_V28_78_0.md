**Вход в панель Remnawave через магазин — своя реализация** ([мастер установки](new/REMNAWAVE_INSTALLATION_WIZARD.md#доступ-к-страницам-панели))
- В мастере: «Доступ к панели → Вход через магазин». Страницы панели открываются только администраторам магазина с правом управлять серверами — их паролем, 2FA и passkey. Отдельных паролей и сторонних контейнеров нет.
- Кнопка «Открыть панель» в мастере даёт одноразовую ссылку (60 секунд, в Redis только SHA-256). Панель меняет её на свою cookie (12 часов): общий родительский домен с магазином не нужен.
- Caddy сервера панели спрашивает магазин о каждом запросе (`forward_auth` → `/api/panel-gate/verify`). «Завершить все сеансы», отключение администратора или роль без права сразу закрывают панель. Каждый вход — в журнале действий.
- Запросы магазина к API с токеном и подписки `/api/sub/` проходят без входа. Нужен публичный адрес API магазина (`API_DOMAIN`).

**Вход через TinyAuth перед панелью Remnawave** (вариант для тех, кому нужен отдельный портал входа) ([мастер установки](new/REMNAWAVE_INSTALLATION_WIZARD.md#доступ-к-страницам-панели))
- В мастере: «Доступ к панели → Вход через TinyAuth» и домен входа рядом с доменом панели (`auth.example.com` для `panel.example.com`).
- На сервере панели — отдельный контейнер TinyAuth v5.2.0 (GPL-3.0, образ закреплён по SHA-256) и `forward_auth` в Caddy. Браузер без входа попадает на страницу входа, другие клиенты получают 401. Запросы магазина к API с токеном и подписки `/api/sub/` проходят без входа.
- Логин `corgi` и пароль создаёт мастер. В `.env` на сервере только bcrypt-хеш; пароль показывается в «Показать вход в панель», просмотр пишется в журнал действий. Сменить вариант доступа можно действием «Обновить».
- Идея — модуль `tinyauth.sh` из eGamesAPI/remnawave-reverse-proxy (MIT); конфигурация Caddy написана для магазина.

**Исправлено**
- Разделы без пункта меню («Командный центр», «Карточка клиента», «Интеграции», «События», «Центр безопасности», «Статус сервиса») не открывались: защита вкладок отправляла их на «Все разделы». Английские подписи в них переведены.
- Изменения платформы (ключи API, вебхуки, почта, DKIM, агенты, модули, чёрный список устройств, порог торрентов) и сброс подключений клиента теперь пишутся в журнал аудита.
- Последнего активного администратора нельзя понизить, отключить или удалить (409).
- Скидка акции и промокода проверяется и при изменении, не только при создании.
- Подарочная карта создаётся только в валюте магазина и пишется в журнал.
- Имя домена с переводом строки в конце больше не проходит проверку мастера (`\Z` вместо `$`).

**Что из eGames осознанно не перенесено**
- Интерактивное меню CLI внутри контейнера панели: надёжно автоматизировать его нельзя. Нужные действия (администратор, токен API, ноды, профили) мастер выполняет через API панели.

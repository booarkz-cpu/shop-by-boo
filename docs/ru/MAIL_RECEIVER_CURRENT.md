# Собственный приём почты (MX)

Магазин может сам принимать почту своего домена, без почтового ящика у провайдера. Это не почтовый сервер для сотрудников: принимаются письма только на заданные служебные адреса, и у каждого адреса свой получатель.

| Адрес (пример) | Куда попадает письмо |
| --- | --- |
| `dmarc@shop.example` | отчёты DMARC разбираются в разделе **Система → Почтовый домен** ([как читать отчёты](MAIL_DOMAIN_CURRENT.md)) |
| `support@shop.example` | обращение в Support Pro через email-канал ([email-канал](SUPPORT_EMAIL_CHANNEL_CURRENT.md)) |

Отправка писем остаётся за SMTP-провайдером (`SMTP_*`): приёмник сам ничего не отправляет.

## Как работает приём

Сервис `mail_receiver` — SMTP-сервер в образе backend. Он слушает порт 25 (в контейнере 2525) и для каждого письма проходит такие шаги:

1. **Адрес получателя.** Если адреса нет в `MAIL_RECEIVER_ROUTES`, ответ 550 «No such recipient (relay denied)». Сервер не может стать открытым релеем: чужие адреса отклоняются ещё до приёма письма. На одно письмо — до 10 получателей.
2. **Грейлистинг.** Первое письмо от незнакомой тройки «сеть отправителя (/24 или /64) — отправитель — получатель» получает временный отказ 451. Через минуту настоящий почтовый сервер повторит отправку, и письмо примется. Сеть и домен, прошедшие проверку, помнятся 30 дней. Отключается `MAIL_RECEIVER_GREYLIST=false`.
3. **Лимиты:**
   - размер письма до `MAIL_RECEIVER_MAX_MB` (по умолчанию 10 МБ, объявляется в `SIZE`);
   - 30 писем за 10 минут с одной сети;
   - 5 одновременных соединений с одного адреса и 100 всего;
   - строки до 4096 байт;
   - тайм-ауты: 60 секунд на команду и 5 минут на передачу письма.
4. **SPF** отправителя из `MAIL FROM` (для пустого отправителя — по имени из HELO). Результат `fail` — отказ 550.
5. **DKIM** — проверка подписей `rsa-sha256` и `ed25519-sha256`, канонизация `simple` и `relaxed`, не больше трёх подписей на письмо. Отозванные и истёкшие ключи дают `fail`.
6. **DMARC** домена из `From` с выравниванием по SPF или DKIM (мягким по умолчанию, строгим при `aspf=s`/`adkim=s`):
   - `fail` при политике `p=reject` — отказ 550;
   - при `quarantine` и `none` письмо принимается с пометкой `dmarc=fail`. Email-канал Support Pro покажет её в обращении.
7. **Антивирус.** При заданном `MAIL_RECEIVER_CLAMAV` (адрес clamd `хост:порт`, доступный из контейнера) письмо проверяется целиком:
   - вирус — отказ 554;
   - ClamAV недоступен — временный отказ 451: письмо не теряется, отправитель повторит позже.
8. **Заголовки.** Сверху добавляется `Authentication-Results` с результатами SPF, DKIM и DMARC, затем `Received`. Входящие заголовки `Authentication-Results` с именем нашего сервера удаляются, чтобы их нельзя было подделать.
9. **Доставка:**
   - **dmarc** — вложения-отчёты разбираются с теми же ограничениями, что и при чтении из ящика (размер, архивы-бомбы, XXE, только свой домен, без дублей). Отправитель считается подтверждённым, если письмо прошло DMARC;
   - **support** — письмо передаётся в Support Pro, `POST /email/inbound`, с подписью HMAC-SHA256 по `MAIL_INBOUND_SECRET` и меткой времени (старше 5 минут отклоняется). Дальше работает обычный email-канал: обращение, повтор по Message-ID, автоответы, рассылки, петли, отказы доставки. Если Support Pro недоступен, отправителю уходит временный отказ 451.

Приёмник никогда не отправляет уведомления о недоставке: все отказы звучат внутри SMTP-сеанса, поэтому петля писем невозможна.

**STARTTLS** включается, если заданы `MAIL_RECEIVER_TLS_CERT` и `MAIL_RECEIVER_TLS_KEY`; минимальная версия — TLS 1.2.

## Настройка

### 1. DNS

```text
mx.shop.example.   A     IP_СЕРВЕРА
shop.example.      MX    10 mx.shop.example.
```

На хостинге должен быть открыт входящий порт 25: у некоторых провайдеров он закрыт по умолчанию. Раздел «Почтовый домен» предупредит, если MX указывает не на приёмник.

### 2. `.env` магазина

```dotenv
MAIL_RECEIVER_ROUTES=dmarc@shop.example=dmarc,support@shop.example=support
MAIL_RECEIVER_HOSTNAME=mx.shop.example
MAIL_RECEIVER_MAX_MB=10
MAIL_RECEIVER_GREYLIST=true
# STARTTLS (сертификат для mx.shop.example)
MAIL_RECEIVER_TLS_CERT=/tls/fullchain.pem
MAIL_RECEIVER_TLS_KEY=/tls/privkey.pem
# антивирус (необязательно)
MAIL_RECEIVER_CLAMAV=clamd.internal:3310
# передача обращений в Support Pro
MAIL_SUPPORT_INBOUND_URL=http://support_pro:8000/email/inbound
MAIL_INBOUND_SECRET=длинная-случайная-строка
```

Сертификат положите в `deploy/mail-tls/`: каталог монтируется в контейнер как `/tls` только для чтения.

### 3. `support-pro/.env`

Укажите тот же секрет: `MAIL_INBOUND_SECRET=длинная-случайная-строка`. Без него `/email/inbound` отвечает 404. Отвечать клиентам по email Support Pro будет через `EMAIL_SMTP_*`; IMAP (`EMAIL_IMAP_*`) для писем, пришедших через приёмник, не нужен.

### 4. Запуск

```bash
docker compose --profile mail up -d mail_receiver
```

В записи DMARC укажите `rua=mailto:dmarc@shop.example`. В разделе **Почтовый домен** появятся блок «Приём почты (MX)» с адресами, настройками и журналом последних писем, а также предупреждение, если MX указывает на другой сервер.

Все переменные — настройки развёртывания. Реестр настроек — 180 полей: 96 live, 82 deployment, 2 workflow.

## Чего здесь нет

- Почтовых ящиков для людей, IMAP/POP3 и пересылки на внешние адреса: приёмник служебный.
- Контентного антиспама (оценки текста): письма проверяются по подлинности отправителя (SPF, DKIM, DMARC), грейлистингу, лимитам и антивирусу. На адреса поддержки пишут люди, а email-канал Support Pro уже отсеивает рассылки и автоответы.

## Проверка

`tests/test_mail_receiver.py` прогоняет настоящий SMTP-сеанс через `smtplib` против запущенного приёмника:

- канонизация на примерах из RFC 6376 (3.4.5);
- отказ в релее;
- письмо с подписью DKIM (RSA и Ed25519) проходит SPF, DKIM и DMARC и доходит до Support Pro с верной подписью и заголовками;
- поддельный `Authentication-Results` удаляется;
- отказ при SPF `fail` и при DMARC `p=reject` с испорченной подписью;
- причины ошибок DKIM (подпись, хэш тела, отозванный ключ), два заголовка `From`;
- лимиты размера (`SIZE` и `DATA`), слишком длинная строка, порядок команд;
- грейлистинг с повтором и белым списком, лимит частоты, лимит соединений;
- ClamAV: вирус, чистое письмо, недоступен;
- временный отказ при недоступном Support Pro;
- отчёт DMARC по SMTP;
- STARTTLS с сертификатом;
- разбор адресов и реестр настроек.

`support-pro/tests/test_email_inbound.py` (SQLite и PostgreSQL) проверяет вход Support Pro: обращение создаётся один раз, вердикт приёмника принимается, подделанная подпись, устаревшая метка, изменённое тело, слишком большое письмо и выключенный вход отклоняются.

Приём на вашем домене (открытый порт 25, MX, сертификат, реальные отправители) проверяет оператор.

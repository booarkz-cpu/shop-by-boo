# 04. Импорт и массовые операции

## Для чего

- **Перенос клиентов** из другого бота: Telegram-профили и остатки кошельков из SQLite-выгрузки.
- **Перенос истории** подписок (по UUID Remnawave) и платежей прежнего сервиса для отображения клиенту и сверки.
- **Массовые операции** над 1–200 клиентами сразу:
  - отозвать сессии входа;
  - отключить автопродление;
  - отправить уведомление в кабинет;
  - ограничить или восстановить доступ к магазину.

Импорт не переносит пароли, email, OAuth-входы, токены касс и реферальные сети. Перенос истории не создаёт пользователей Remnawave и не продлевает сроки, платежи сохраняются только как история и не попадают в выручку.

## Где и кто

**Пользователи → Импорт и массовые операции**, только роль «Администратор» (права `users.import`, `users.bulk`). Все шаги пишутся в журнал действий.

## Перенос клиентов

1. Сделайте резервную копию магазина: `bash scripts/backup.sh`. Остановите продажи в старом боте на время перехода.
2. На сервере старого бота снимите согласованный snapshot SQLite (простое копирование работающего файла может потерять данные):

   ```bash
   python3 - <<'PY'
   import sqlite3
   from pathlib import Path
   source = Path('/путь/к/users.db'); snapshot = Path('/путь/к/users-snapshot.db')
   with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as src, sqlite3.connect(snapshot) as dst:
       src.backup(dst)
   snapshot.chmod(0o600)
   PY
   ```

3. В разделе загрузите snapshot, укажите таблицу (обычно `users`) → «Прочитать поля».
4. Задайте **постоянное имя источника**, например `old-bot`. Используйте одно и то же имя для всех повторных выгрузок этого бота, иначе остатки зачислятся повторно.
5. Сопоставьте поля:
   - постоянный ID строки — первичный ключ источника;
   - Telegram ID — положительное целое;
   - имя — необязательно;
   - остаток — необязательно.
6. Укажите единицы остатка (рубли или копейки) и валюту (должна совпадать с валютой магазина). Флажок зачисления начисляет остаток **только новым** клиентам.
7. «Проверить перенос». Просмотрите категории:
   - `new` — новые клиенты;
   - `existing` — уже есть в магазине;
   - `already_imported` — перенесены раньше;
   - `blocked` — заблокированы.

   Конфликт хотя бы одной строки блокирует весь перенос.
8. Подтвердите и примените. Предпросмотр действует 30 минут. Ограничения:
   - до 1000 строк и 5 МБ на файл;
   - остаток клиента до 1 000 000;
   - общая сумма до 10 000 000.

   Большой источник переносите частями с тем же именем источника.
9. Проверьте историю переносов и операцию «Перенос начального баланса» в кошельке нового клиента.

## Перенос истории подписок и платежей

1. Сначала перенесите клиентов (выше) с тем же именем источника.
2. Подготовьте тарифы с теми же названиями или выберите «тариф по умолчанию».
3. Возьмите в старой системе контрольные итоги: число успешных и возвращённых платежей, сумму успешных, число подписок.
4. Вкладка «Перенос подписок и платежей»:
   1. выберите файл и таблицы → «Загрузить колонки…» → проверьте сопоставление;
   2. введите контрольные итоги → «Сверить историю».
5. Применить можно только при совпадении всех итогов и без конфликтов. Повтор того же файла дублей не создаёт.
6. Ошибочный перенос можно откатить: «Журнал переносов истории» → «Откатить» с причиной.

Формат таблиц, допустимые статусы и даты: [перенос истории](../HISTORY_IMPORT_CURRENT.md).

## Массовые операции

1. Введите внутренние ID клиентов (не Telegram ID), до 200, выберите действие и причину.
2. «Проверить операцию» — сверьте список, число клиентов, подписок и сессий.
3. Подтвердите и примените. Если данные изменились после предпросмотра, сервер вернёт `409` — сделайте новый предпросмотр.

| Действие | Что произойдёт |
| --- | --- |
| Отозвать сессии | Клиенты выйдут на всех устройствах; способы входа и VPN сохраняются |
| Отключить автопродление | Флаг снят для аккаунта и всех подписок; уже созданные платежи не отменяются |
| Уведомление в кабинет | Одно личное уведомление каждому; в Telegram и на почту не отправляется |
| Ограничить доступ к магазину | Флаг ограничения, отзыв сессий, отключение автопродления; покупки и пробный период недоступны |
| Восстановить доступ | Снимает ограничение; автопродление само не включается |

## Проверка

На тестовом стенде перенесите выгрузку из 2–3 строк. Затем повторите перенос с тем же именем источника: строки должны получить статус `already_imported`, остатки не должны удвоиться.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Весь перенос заблокирован | Конфликт идентичности в одной строке | Исправьте строку в выгрузке или исключите её |
| «Расхождение» в сверке истории | Итоги не совпадают с файлом | Проверьте выгрузку и статусы; не подгоняйте итоги |
| Предпросмотр устарел | Прошло больше 30 минут или изменились данные | Сделайте новый |
| Остатки зачислились дважды | Разные имена источника | Используйте одно постоянное имя; ошибку исправляйте корректирующей операцией с журналом |

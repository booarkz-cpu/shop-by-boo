# 29. Антифрод

## Для чего

Защищает от подозрительных оплат:

- **оценка риска** перед созданием каждого счёта (покупка, продление, операции с подпиской). Платёж с высокой оценкой не создаётся;
- **сканирование** последних 24 часов: много платежей от одного клиента, много неудачных выдач подряд;
- **сигналы** — список для ручного разбора.

Антифрод платежей и антиабуз подписок ([модуль 19](19-node-agent-antiabuse.md)) — разные механизмы. Антифрод смотрит на оплаты, антиабуз — на подключения к VPN.

## Где и кто

**Безопасность → Антифрод**, только администратор (`security.manage`):

- кнопка «Сканировать»;
- фильтр «Показать»: открытые, решённые, мошенничество, все;
- таблица сигналов: ID, клиент, тип, оценка, статус, время, кнопка «Решение»;
- панель «Решение по сигналу» с заметкой и кнопками «Ложная тревога», «Мошенничество», «Открыть снова».

Те же сигналы видны в **Центре безопасности**.

## Как считается риск платежа

| Признак | Баллы |
| --- | --- |
| 8 и больше платежей клиента за 24 часа (включая текущий) | +35 |
| Сумма больше 1000 | +20 |
| 10 и больше сигналов антифрода с того же IP за 24 часа | +40 |
| Аккаунт удалён | 100 |

| Порог | Переменная | По умолчанию | Что происходит |
| --- | --- | --- | --- |
| Ручная проверка | `PAYMENT_RISK_REVIEW_SCORE` | 60 | Платёж создаётся, оценка `review` сохраняется вместе с ним |
| Блокировка | `PAYMENT_RISK_BLOCK_SCORE` | 90 | Платёж не создаётся, клиент видит «Платёж отклонён системой защиты от мошенничества» |

Пороги меняются в **Система → Настройки без перезапуска**, группа «Платежи и риск». Порог проверки должен быть ниже порога блокировки.

Важно понимать ограничения текущей версии:

- оценка `review` только записывается. Платёж не останавливается и в очередь на ручную проверку не попадает;
- сканирование не записывает IP в сигналы, поэтому признак «IP» срабатывает только на сигналах, созданных с IP (например, через API);
- с настройками по умолчанию максимум без удалённого аккаунта — 35 + 20 = 55 при обычных сигналах, то есть ни проверки, ни блокировки. Блокировка реально срабатывает для удалённых аккаунтов и при всплеске сигналов с одного IP. Если вам нужна более строгая защита, снизьте пороги: например `review` 30 и `block` 55 блокирует крупные платежи клиента, который сделал 8+ попыток за сутки.

## Работа

1. Раз в день или после всплеска оплат нажмите «Сканировать». Новые сигналы появятся в таблице:
   - `payment_velocity` — 10 и больше платежей клиента за сутки, оценка = количество × 5;
   - `fulfillment_failure_velocity` — 3 и больше неудачных выдач за сутки, оценка = количество × 15.
2. Повторное сканирование не создаёт дубль, пока у клиента есть открытый сигнал того же типа. После решения по сигналу следующее сканирование снова отметит клиента, если картина повторяется.
3. Откройте клиента в **Клиенты** ([модуль 03](03-customers.md)): платежи, устройства, обращения.
4. Решите, что делать:
   - ложная тревога (например, клиент покупал подписки для семьи) — «Ложная тревога»;
   - много неудачных выдач — обычно это проблема Remnawave, а не мошенничество: смотрите **Очередь задач** ([модуль 25](25-automation-jobs.md));
   - подтверждённое мошенничество — «Мошенничество», затем оформите возврат или отмену ([модуль 07](07-payments.md)) и ограничьте клиента массовой операцией ([модуль 04](04-customer-import.md)). Отметка сама клиента не ограничивает.
5. В сигнале нажмите «Решение», впишите заметку (почему принято решение) и выберите кнопку. Решение и заметка пишутся в журнал действий. Ошиблись — «Открыть снова».

Пересчитать риск конкретного платежа с текущими порогами можно через API `POST /api/admin/payments/{id}/risk/recheck` (право `payments.reconcile`).

## Проверка

На тестовом стенде с песочницей платежей сделайте 10 тестовых оплат одним клиентом и нажмите «Сканировать»: появится сигнал `payment_velocity` с оценкой 50.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Честный клиент получает «Платёж отклонён системой защиты» | Пороги слишком низкие или аккаунт помечен удалённым | Поднимите пороги в «Настройках без перезапуска»; проверьте аккаунт |
| Сигналы не появляются | Сканирование запускается только вручную | Нажимайте «Сканировать» по расписанию |
| Открытых сигналов много | Решения не приняты | Разберите их кнопкой «Решение» |

## API

`GET /api/admin/fraud` (последние 500), `POST /api/admin/fraud/scan`, `POST /api/admin/fraud/{id}` (`{"status":"open|resolved|blocked","note":"…"}`), `POST /api/admin/payments/{id}/risk/recheck`, `GET /api/admin/security/risk-summary`.

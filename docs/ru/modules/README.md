# Инструкции по модулям

Здесь описан каждый модуль магазина отдельно: для чего он, где находится в админ-панели, кто может с ним работать, как его включить и настроить, что делать каждый день, как проверить работу и что делать при типичных проблемах. Порядок первого запуска всего магазина — в [инструкции «Запуск в работу»](../LAUNCH_GUIDE.md).

Каждая инструкция построена одинаково:

1. **Для чего** — что делает модуль и чего он не делает.
2. **Где и кто** — разделы панели и права ролей «Наблюдатель», «Оператор», «Администратор».
3. **Настройка** — переменные `.env` и действия в панели по шагам.
4. **Работа** — типичные ежедневные сценарии.
5. **Проверка** — как убедиться, что всё работает.
6. **Проблемы** — симптом, причина, что делать.
7. **API** — основные маршруты (полный каталог — [API_ENDPOINTS.md](../../API_ENDPOINTS.md)).

Переменные `.env` меняются в `/opt/vpn-shop/.env`, после чего нужен перезапуск сервиса: `docker compose up -d --force-recreate backend worker bot`. Многие параметры можно поменять и без перезапуска — в разделе **Система → Настройки без перезапуска** ([модуль 23](23-settings-features.md)).

## Роли и права коротко

| Роль | Что может |
| --- | --- |
| Наблюдатель (`viewer`) | Смотреть разделы, клиентов, платежи, аналитику, обращения; включить свою 2FA |
| Оператор (`operator`) | Всё из «Наблюдателя», а также тарифы, клиенты, платежи и повтор выдачи, маркетинг и рассылки, контент, ответы в поддержке, диагностика, инциденты, флаги функций, просмотр настроек |
| Администратор (`admin`) | Всё, включая администраторов, безопасность, возвраты, резервные копии и восстановление, импорт и массовые операции, изменение настроек, production gate, терминал узлов |

Права проверяются сервером: видимый пункт меню ещё не означает права на действие. Ответ `403` — не хватает прав, `401` — нужно войти заново.

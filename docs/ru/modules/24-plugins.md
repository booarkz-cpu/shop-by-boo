# 24. Плагины

## Для чего

Плагин подключает к магазину внешний сервис: CRM, аналитику, программу лояльности, собственную автоматизацию. Плагин — это отдельный сервис издателя. В магазин загружается только подписанный пакет-описание, кода в нём нет. Плагин:

- получает подписанные HMAC события о новом клиенте, успешном платеже, активированной подписке;
- читает данные и отправляет уведомления через `/api/plugin/v1` — только в рамках подтверждённых прав;
- включается, обновляется, откатывается и выключается без перезапуска магазина.

## Где и кто

**Система → Плагины**:

- просмотр — с правом диагностики;
- управление — администратор.

## Подключение

1. **Ключ издателя.** Получите у издателя открытый ключ Ed25519 (base64, 44 символа) по проверенному каналу и добавьте его. Отзыв ключа сразу выключает все плагины, подписанные им.
2. **Пакет.** «Проверить и загрузить» — `.zip` до 256 КБ. Магазин отклонит пакет, если:
   - подпись не сходится;
   - ключ неизвестен;
   - в пакете есть что-то кроме `manifest.json`, `signature.json`, `README.md`;
   - запрошены неизвестные права;
   - адрес событий не HTTPS или ведёт во внутреннюю сеть.
3. **Настройки.** Заполните поля из манифеста, например ключ CRM. Секреты хранятся зашифрованными.
4. **Права.** Проверьте права и события и отметьте «Разрешаю плагину эти права и события» → «Включить версию». API-ключ плагина показывается один раз — передайте его издателю.

| Право | Что даёт |
| --- | --- |
| `users.read` | ID, имя, дата регистрации; событие «Новый клиент» |
| `payments.read` | Сумма, валюта, статус, тариф; событие «Успешный платёж» |
| `subscriptions.read` | Тариф, статус и срок подписок; событие «Подписка активирована» |
| `notifications.send` | Уведомления клиенту в приложении (до 60 в минуту) |

Email, телефоны, балансы, ссылки подписок и платёжные реквизиты плагину недоступны ни при каких правах.

## Каталог плагинов

Вместо ручной загрузки zip можно подключить **подписанный каталог** — JSON по HTTPS со списком пакетов.

1. Издатель подписывает каталог своим ключом: `python3 scripts/sign-plugin.py catalog publisher.key catalog.json catalog.signed.json`. В каталоге у каждого пакета `id`, `version`, `package_url` (HTTPS) и `sha256`.
2. Ключ издателя добавлен в доверенные (раздел выше).
3. **Система → Плагины → Каталог плагинов:** вставьте адрес каталога (до пяти) и «Сохранить каталоги».
4. Магазин скачивает каталог (до 512 КБ, только публичные адреса), проверяет подпись Ed25519, показывает пакеты и отмечает доступные обновления.
5. «Установить» скачивает пакет, сверяет SHA-256 с каталогом, затем делает те же проверки, что ручная загрузка. Включение и подтверждение прав — вручную, как обычно.

Подменённый пакет (другой хеш) или каталог с чужой подписью отклоняются с понятной ошибкой.

## Обновление, откат, выключение

- Новая версия загружается тем же способом. Если она просит новые права, до подтверждения работает прежняя версия.
- «Вернуть эту версию» — откат на любую загруженную версию без новых прав.
- «Выключить» сразу закрывает плагину API и останавливает события. «Удалить» стирает плагин, версии, настройки и журнал.

## Проверка

После включения создайте событие, например зарегистрируйте тестового клиента. В журнале доставок плагина появилась запись со статусом успеха.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Пакет отклонён | Подпись, неизвестный ключ, лишние файлы, внутренний адрес | Текст ошибки показывает причину; обратитесь к издателю |
| Событие «в повторе» | Сервис плагина недоступен или отвечает 5xx/429 | Повторы через 30 с, 1, 2, 4, 8 минут (до 6 попыток) |
| Плагин выключился сам | Отозван ключ издателя | Добавьте новый ключ и новую версию |

Издателям: формат манифеста, подпись `scripts/sign-plugin.py` и API — в [подробной инструкции](../PLUGINS_CURRENT.md).

## API

`/api/admin/plugins/...` (админка), `/api/plugin/v1/...` (плагин).

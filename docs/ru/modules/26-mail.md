# 26. Почта

## Для чего

Почта магазина состоит из трёх независимых частей. Включайте их по мере необходимости.

| Часть | Что делает | Нужна ли |
| --- | --- | --- |
| **Отправка (SMTP)** | Подтверждение email, восстановление пароля, письма-алерты | Да, для входа по email, конкурсов и опросов |
| **Почтовый домен** | Проверка MX, SPF, DKIM, DMARC и разбор отчётов DMARC: доходят ли письма и кто отправляет почту от имени домена | Рекомендуется |
| **Приём почты (MX)** | Собственный SMTP-приёмник только для служебных адресов: отчёты DMARC и письма в поддержку | По желанию, вместо ящика у провайдера |

Письма поддержки отправляет Support Pro со своими настройками `EMAIL_SMTP_*` ([модуль 05](05-support.md)).

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Система → Почтовый домен: SPF, DKIM, DMARC** | Проверка домена, отчёты DMARC (загрузка, чтение из ящика), блок «Приём почты (MX)» с журналом | просмотр — диагностика; загрузка и проверка — оператор; удаление отчётов — администратор |
| **Система → Настройки без перезапуска** | `SMTP_*` без перезапуска | администратор |
| **Серверы → Антиабуз и агенты** | Генерация DKIM-ключа магазина, если провайдер принимает собственный ключ | администратор |

## Отправка (SMTP)

```dotenv
SMTP_HOST=smtp.provider.example
SMTP_PORT=587             # 587 — STARTTLS, 465 — SSL
SMTP_USER=noreply@ДОМЕН
SMTP_PASSWORD=...
SMTP_FROM=noreply@ДОМЕН   # адрес, разрешённый провайдером
CABINET_URL=https://cabinet.ДОМЕН
```

Задайте в `.env` и выполните `docker compose up -d --force-recreate backend worker`. Те же поля можно изменить в **Настройках без перезапуска**. Проверьте: зарегистрируйте тестового клиента по email — письмо должно прийти во «Входящие».

## Почтовый домен

1. Опубликуйте записи SPF, DKIM и DMARC по инструкции своего SMTP-провайдера. Пример DMARC для начала: `v=DMARC1; p=none; rua=mailto:dmarc@ДОМЕН`. Перейдите к `quarantine` и `reject`, когда отчёты станут чистыми.
2. **Почтовый домен** → «Проверить домен». Магазин проверяет записи через DNS-over-HTTPS (`MAIL_DNS_DOH_URL`) и показывает ошибки:
   - `+all`;
   - две записи SPF;
   - больше 10 DNS-запросов в SPF;
   - отозванный ключ DKIM;
   - DMARC без `rua`.
3. Домен по умолчанию берётся из `SMTP_FROM`, другой задаётся `MAIL_DOMAIN`.

**Отчёты DMARC** показывают, сколько писем от имени домена прошли проверку и с каких адресов они пришли. Три способа получать их:

- загрузить XML, gzip или zip вручную в разделе;
- читать из ящика по IMAP (только чтение): `DMARC_IMAP_HOST`, `DMARC_IMAP_PORT`, `DMARC_IMAP_USER`, `DMARC_IMAP_PASSWORD`, `DMARC_IMAP_FOLDER`;
- принимать собственным приёмником (ниже).

Отчёты хранятся `DMARC_REPORT_RETENTION_DAYS` дней (по умолчанию 180).

## Приём почты (MX)

Магазин сам принимает письма на заданные адреса. Остальные адреса отклоняются ещё в SMTP-диалоге, поэтому сервер не может стать открытым релеем. Ничего не отправляет и писем о недоставке не создаёт.

1. **DNS:** `mx.ДОМЕН A IP_СЕРВЕРА` и `ДОМЕН MX 10 mx.ДОМЕН`. У хостера откройте входящий порт 25 (часто закрыт по умолчанию). Если установщик включил firewall, откройте порт и на сервере: `ufw allow 25/tcp`.
2. **Сертификат** для `mx.ДОМЕН` положите в `deploy/mail-tls/` (`fullchain.pem`, `privkey.pem`).
3. **`.env` магазина:**

```dotenv
MAIL_RECEIVER_ROUTES=dmarc@ДОМЕН=dmarc,support@ДОМЕН=support
MAIL_RECEIVER_HOSTNAME=mx.ДОМЕН
MAIL_RECEIVER_TLS_CERT=/tls/fullchain.pem
MAIL_RECEIVER_TLS_KEY=/tls/privkey.pem
MAIL_RECEIVER_MAX_MB=10
MAIL_RECEIVER_GREYLIST=true
MAIL_RECEIVER_CLAMAV=           # clamd хост:порт, необязательно
MAIL_SUPPORT_INBOUND_URL=http://support_pro:8000/email/inbound
MAIL_INBOUND_SECRET=длинная-случайная-строка   # тот же в support-pro/.env
```

4. **Запуск:** `docker compose --profile mail up -d mail_receiver`, затем `docker compose up -d --force-recreate support_pro support_worker`.

Как приёмник обрабатывает письмо:

- проверяет SPF, DKIM (RSA и Ed25519) и DMARC отправителя: SPF `fail` и DMARC `fail` при `p=reject` отклоняются;
- грейлистинг: первое письмо от незнакомого отправителя откладывается на минуту;
- лимиты: размер, 30 писем за 10 минут с сети, 5 соединений с адреса;
- ClamAV, если задан;
- STARTTLS;
- журнал последних писем — в разделе «Почтовый домен».

## Проверка

- SMTP: письмо подтверждения приходит во «Входящие».
- Домен: «Проверить домен» без красных пунктов.
- MX: письмо с внешнего ящика на `support@ДОМЕН` через 1–2 минуты (грейлистинг) становится обращением в Support Pro; в журнале приёмника — «принято».

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Письма в «Спаме» | Нет SPF, DKIM или DMARC, или провайдер не подписывает | «Проверить домен», настройки провайдера |
| SMTP «не принял письмо» | Неверный порт, TLS или пароль | 587 + STARTTLS или 465 + SSL; адрес From разрешён провайдером |
| Почта на MX не приходит | Порт 25 закрыт у хостера, нет MX-записи | `telnet mx.ДОМЕН 25` извне; MX-запись |
| «MX не указывает на приёмник» | MX-запись ведёт на другой сервер | Исправьте MX или выключите приёмник |
| Отправитель получает 451 | Грейлистинг, временная ошибка DNS или ClamAV | Нормально: сервер отправителя повторит |
| Обращение не создаётся | Разные `MAIL_INBOUND_SECRET` или не пересоздан Support Pro | Сверьте секреты, пересоздайте сервисы |

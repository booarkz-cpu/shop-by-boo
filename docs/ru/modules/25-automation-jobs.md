# 25. Автоматизация и фоновые задачи

## Для чего

Магазин выполняет много работы в фоне. Процесс `worker` отвечает за:

- выдачу и продление VPN-доступа после оплаты, пробного периода, подарка;
- повторы при сбоях Remnawave;
- истечение подписок, напоминания, автопродление;
- возвраты, рассылки, уведомления и push;
- резервные копии по расписанию, очистку старых данных;
- торренты, сеть узлов, терминал, почтовый домен.

Здесь видно, жив ли worker и что происходит с очередью.

## Где и кто

| Раздел | Что показывает | Права |
| --- | --- | --- |
| **Система → Фоновые процессы** | Рабочие процессы: ID, роль, статус, текущая задача, последняя активность | `read` |
| **Система → Очередь задач** | Задачи: тип, статус, попытки, процесс, ошибка; «Повторить» | просмотр `read`, повтор `payments.retry` (оператор, администратор) |
| **Система → Автоматизация** | Правила «событие → условие → действие» и кампании | просмотр `read`, переключение `manage_users` |
| **Система → Корпоративный контур** | Внешние HTTP-проверки доступности, кампании, правила | просмотр `read`, проверки `ops.diagnostics`, правила `feature_flags.manage` |

## Что работает автоматически

| Сценарий | Как настроить |
| --- | --- |
| Выдача после оплаты, пробного периода, подарка; до `FULFILLMENT_MAX_ATTEMPTS` попыток | Без настройки |
| Напоминание об окончании подписки | `NOTIFICATION_EXPIRY_DAYS` |
| Автопродление | `AUTO_RENEW_*` ([модуль 06](06-plans.md)); требует открытого production gate |
| Истечение и отключение подписок в Remnawave | Без настройки |
| Рассылки по очереди с продолжением после сбоя | [Модуль 09](09-promotions-broadcasts.md) |
| Резервные копии по расписанию | [Модуль 30](30-backups-recovery.md) |
| Внешние HTTP-проверки | «Корпоративный контур» → «Проверки»: название, URL (только публичный HTTPS/HTTP), метод GET или HEAD, интервал от 15 секунд, тайм-аут |

**Правила автоматизации и кампании** в разделах «Автоматизация» и «Корпоративный контур» сейчас только хранятся как план: движка, который выполнял бы их, в этой версии нет. Не рассчитывайте на них в работе. Для сценариев используйте встроенные механизмы из таблицы выше и [плагины](24-plugins.md).

Результаты внешних HTTP-проверок (ok / degraded / down, задержка, ошибка) видны в разделе. При 1-й, 3-й и 5-й ошибке подряд пишется запись в журнал действий. Оповещения в Telegram для этих проверок не отправляются, поэтому подключите [Prometheus](02-health-incidents-monitoring.md).

## Работа

**Каждый день:**

1. **Фоновые процессы** — worker «online», последняя активность меньше 90 секунд назад.
2. **Очередь задач** — нет задач в `failed` за последние сутки и нет давно `queued`.

**Задача упала:**

1. Прочитайте ошибку, например «Remnawave недоступен» или «нет профиля».
2. Устраните причину.
3. «Повторить». Повтор не создаёт второй выдачи: операции идемпотентны.

**Worker не работает:**

```bash
cd /opt/vpn-shop
docker compose ps worker
docker compose logs --tail=200 worker
docker compose restart worker
```

Не запускайте два разных по версии worker против одной базы, например при неполном обновлении.

## Проверка

Получите пробный период тестовым клиентом. В **Очереди задач** появилась задача `trial` со статусом «завершена».

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Worker «stale» | Процесс упал или завис | Перезапустите, смотрите логи |
| Задачи копятся в `queued` | Worker не запущен или Redis недоступен | **Состояние системы** |
| Задача `failed` с ошибкой Remnawave | Панель недоступна, circuit breaker | Исправьте связь, «Повторить» |
| Prometheus: «oldest queued job» > 15 минут | Очередь стоит | См. выше |

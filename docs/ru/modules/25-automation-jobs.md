# 25. Автоматизация и фоновые задачи

## Для чего

Магазин выполняет много работы в фоне. Процесс `worker` отвечает за:

- выдачу и продление VPN-доступа после оплаты, пробного периода, подарка;
- повторы при сбоях Remnawave;
- истечение подписок, напоминания, автопродление;
- возвраты, рассылки, уведомления и push;
- резервные копии по расписанию, очистку старых данных;
- торренты, сеть узлов, терминал, почтовый домен.

Здесь видно, жив ли worker и что происходит с очередью.

## Где и кто

| Раздел | Что показывает | Права |
| --- | --- | --- |
| **Система → Фоновые процессы** | Рабочие процессы: ID, роль, статус, текущая задача, последняя активность | `read` |
| **Система → Очередь задач** | Задачи: тип, статус, попытки, процесс, ошибка; «Повторить» | просмотр `read`, повтор `payments.retry` (оператор, администратор) |
| **Система → Автоматизация** | Создание, проверка и включение правил «событие → условие → действие»; создание и запуск кампаний | просмотр `read`, правила `feature_flags.manage` (бонус на баланс — только администратор), включение `manage_users`, кампании `manage_marketing` |
| **Система → Корпоративный контур** | Внешние HTTP-проверки доступности и сводка правил и кампаний; правила и кампании настраиваются в «Автоматизации» | просмотр `read`, проверки `ops.diagnostics` |

## Что работает автоматически

| Сценарий | Как настроить |
| --- | --- |
| Выдача после оплаты, пробного периода, подарка; до `FULFILLMENT_MAX_ATTEMPTS` попыток | Без настройки |
| Напоминание об окончании подписки | `NOTIFICATION_EXPIRY_DAYS` |
| Автопродление | `AUTO_RENEW_*` ([модуль 06](06-plans.md)); не работает, пока приём платежей остановлен |
| Истечение и отключение подписок в Remnawave | Без настройки |
| Рассылки по очереди с продолжением после сбоя | [Модуль 09](09-promotions-broadcasts.md) |
| Резервные копии по расписанию | [Модуль 30](30-backups-recovery.md) |
| Внешние HTTP-проверки | «Корпоративный контур» → «Проверки»: название, URL (только публичный HTTPS/HTTP), метод GET или HEAD, интервал от 15 секунд, тайм-аут |

**Правила автоматизации и кампании** выполняет фоновый процесс `worker` каждые 5 минут. Создаются и включаются они в разделе **Система → Автоматизация**.

### Правила «событие → условие → действие»

| Событие | Когда срабатывает |
| --- | --- |
| Подписка скоро закончится | За N дней до конца (1–30, по умолчанию 3), один раз на каждый срок |
| Подписка закончилась и не продлена | Через N дней после окончания (0–30), если у клиента нет другой активной подписки |
| Оплата прошла и доступ выдан | Каждая оплата после создания правила |
| Новый клиент | Каждый клиент, зарегистрированный после создания правила |
| Клиент не купил за N дней | Через N дней после регистрации (1–60), если не было ни одной оплаты |

Условия:

- только определённые тарифы (ID через запятую);
- для оплаты — сумма от и до;
- не больше N выполнений в сутки (по умолчанию 500).

Действия:

- **уведомление** — в кабинете, Mini App и push; по желанию ещё и сообщением в Telegram. В тексте работают `{name}`, `{expires_at}`, `{amount}`;
- **бонус на баланс** — до 1000 за раз, запись `automation_bonus` в финансовом журнале. Правила с бонусом создаёт, меняет и включает только администратор.

Каждое действие выполняется **один раз** для клиента и события: повторный запуск, перезапуск worker или второй worker его не повторят. Клиенты, которые подходили под правило до его создания, не затрагиваются: правило не устроит массовую рассылку по старой базе. Правило создаётся выключенным. «Проверить» показывает, сколько клиентов оно затронет при включении.

### Кампании

Кампания — разовое сообщение в Telegram выбранной аудитории: все, с активной подпиской или без неё. Текст до 4096 символов, кнопка по желанию. «Запланировать» передаёт кампанию в очередь рассылок в указанное время, без времени — при ближайшем запуске worker. Счётчики «отправлено» и «ошибки» берутся из рассылки. Отправка соблюдает лимиты Telegram (до 25 сообщений в секунду, ожидание `retry_after` при ответе 429).

Правила, сохранённые до v28.21.0, при обновлении выключаются: проверьте их и включите заново.


Результаты внешних HTTP-проверок (ok / degraded / down, задержка, ошибка) видны в разделе. При 1-й, 3-й и 5-й ошибке подряд пишется запись в журнал действий. Оповещения в Telegram для этих проверок не отправляются, поэтому подключите [Prometheus](02-health-incidents-monitoring.md).

## Работа

**Каждый день:**

1. **Фоновые процессы** — worker «online», последняя активность меньше 90 секунд назад.
2. **Очередь задач** — нет задач в `failed` за последние сутки и нет давно `queued`.

**Задача упала:**

1. Прочитайте ошибку, например «Remnawave недоступен» или «нет профиля».
2. Устраните причину.
3. «Повторить». Повтор не создаёт второй выдачи: операции идемпотентны.

**Worker не работает:**

```bash
cd /opt/vpn-shop
docker compose ps worker
docker compose logs --tail=200 worker
docker compose restart worker
```

Не запускайте два разных по версии worker против одной базы, например при неполном обновлении.

### Готовые сценарии и личные промокоды

В **Автоматизации** блок «Готовые сценарии» создаёт правило одной кнопкой (выключенным — проверьте текст и включите):

| Сценарий | Событие | Что получает клиент |
| --- | --- | --- |
| Вернуть ушедших | `subscription.expired`, через 3 дня | Промокод −20% на 48 часов |
| Пробный без покупки | `trial.ended`, через 1 день | Промокод −15% на 3 дня |
| Напоминание о продлении | `subscription.expiring`, за 3 дня | Напоминание |
| Неделя без покупки | `user.no_purchase`, через 7 дней | Промокод −10% на 3 дня |
| Трафик на исходе | `remnawave.traffic_threshold` | Предложение докупить трафик |

Действие **«Личный промокод»** (5–90%, 1–30 дней) создаёт одноразовый код `BACK…` для конкретного клиента; вставьте `{promo}` в текст уведомления. Без уведомления правило с промокодом не сохраняется.

Новые события: `trial.ended` (пробный период закончился, оплат не было) и `remnawave.traffic_threshold`, `remnawave.limited`, `remnawave.expired`, `remnawave.first_connected`, `remnawave.not_connected`, `remnawave.expiration` — из вебхуков Remnawave ([модуль 18](18-nodes-routing.md#вебхуки-remnawave)). События учитываются только за последние 7 дней и после создания правила.

## Проверка

Получите пробный период тестовым клиентом. В **Очереди задач** появилась задача `trial` со статусом «завершена».

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Worker «stale» | Процесс упал или завис | Перезапустите, смотрите логи |
| Задачи копятся в `queued` | Worker не запущен или Redis недоступен | **Состояние системы** |
| Задача `failed` с ошибкой Remnawave | Панель недоступна, circuit breaker | Исправьте связь, «Повторить» |
| Prometheus: «oldest queued job» > 15 минут | Очередь стоит | См. выше |

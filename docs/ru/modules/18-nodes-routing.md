# 18. Узлы, маршрутизация и мощность

## Для чего

Связь магазина с панелью Remnawave и наблюдение за VPN-узлами:

- состояние панели и узлов;
- рекомендация клиенту наименее загруженного узла;
- прогноз нагрузки по данным агентов;
- оркестратор: предлагает вывести недоступный узел.

Магазин **не устанавливает** Remnawave и узлы, **не создаёт** облачные серверы и не меняет маршрутизацию внутри Xray. Он управляет пользователями Remnawave и наблюдает за узлами.

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Серверы → Серверы** | Мониторинг Remnawave: панель отвечает или нет, задержка, узлы онлайн и офлайн, имя, страна, статус | `read` |
| **Серверы → Маршрутизация** | Включено, стратегия, максимальная нагрузка %, предпочтительные страны, резервный узел | просмотр `read`, изменение `manage_users` |
| **Серверы → Планирование мощности** | Нагрузка каждого узла по агенту (наибольшее из CPU, памяти, диска), состояние, прогноз до порога, сколько узлов добавить | `read` |
| **Серверы → Оркестратор** | Автовосстановление, ручное подтверждение вывода и возврата узлов, через сколько секунд узел считается потерянным; «Оценить инфраструктуру» | просмотр `read`, оценка `provision_nodes`, изменение `security.manage` (администратор) |

Адреса узлов, токены и сырой ответ панели в интерфейсе не показываются.

## Интеграция с Remnawave

| Переменная | Значение |
| --- | --- |
| `REMNAWAVE_URL` | HTTPS-адрес панели, например `https://panel.example.com` |
| `REMNAWAVE_TOKEN` | API-токен: **Settings → API Tokens → Create** |
| `REMNAWAVE_CB_FAILURES`, `REMNAWAVE_CB_COOLDOWN` | Circuit breaker: после 5 ошибок подряд запросы к панели приостанавливаются на 30 секунд, чтобы не создавать лавину повторов |

Как магазин работает с панелью:

- **Выдача.** Пользователь `user_<ID клиента>` создаётся с конечным сроком, лимитом трафика (0 — без ограничения) и Internal Squad тарифа. При продлении срок увеличивается идемпотентно: повтор не добавляет дни дважды.
- **Лимит устройств.** Лимит устройств тарифа передаётся в панель как `hwidDeviceLimit` при создании и при каждом продлении.
- **Отзыв.** После возврата пользователь отключается.
- **Совместимость.** Клиент рассчитан на API Remnawave 3.x: ответы панели приходят в обёртке `{"response": …}`, магазин её разворачивает. Подписки, у которых из-за старой ошибки сохранился идентификатор `None`, при следующей выдаче пересоздаются автоматически.
- **Источник истины по сроку — магазин.** Более поздний срок в панели не продлевает неоплаченную подписку.

### Internal Squads

Squad — набор инбаундов, к которым получает доступ пользователь. Создайте их в Remnawave под свои тарифы, например:

| Squad | Содержимое | Тарифы |
| --- | --- | --- |
| Standard | Все обычные узлы, основные протоколы | 1, 3, 6, 12 месяцев |
| Premium | Плюс быстрые или выделенные узлы | Премиум-тариф |
| Trial | Ограниченный набор узлов | Пробный период |

В **Тарифах** выберите squad для каждого тарифа ([модуль 06](06-plans.md)). Проверка покрытия: `POST /api/admin/remnawave/shop/plan-mapping/validate` показывает тарифы без профиля.

## Вебхуки Remnawave

Панель сама сообщает магазину о событиях пользователей: трафик на исходе, лимит, окончание, первое подключение, новое устройство. Магазин проверяет подпись, записывает событие один раз и:

- отправляет клиенту уведомление ([модуль 14](14-bot-miniapp.md#уведомления-из-remnawave));
- запускает правила автоматизации `remnawave.*` ([модуль 25](25-automation-jobs.md));
- проверяет новое устройство на повторный пробный период ([модуль 06](06-plans.md#защита-пробного-периода)).

**Настройка:**

1. Придумайте секрет: `openssl rand -hex 32`.
2. В `.env` магазина: `REMNAWAVE_WEBHOOK_SECRET=<секрет>` и перезапустите `backend` (`./manage.sh restart backend`).
3. В `.env` панели Remnawave:
   ```
   WEBHOOK_ENABLED=true
   WEBHOOK_URL=https://api.<ваш-домен>/api/webhooks/remnawave
   WEBHOOK_SECRET_HEADER=<тот же секрет>
   ```
   и перезапустите панель.
4. Проверка: подключитесь к VPN тестовым пользователем — в **Журнале действий** нет ошибок, а у клиента появится уведомление «VPN подключён».

Без секрета магазин отвечает `503` и ничего не принимает; неверная подпись — `403`. Повтор того же события — `duplicate: true`. Пользователь сопоставляется по UUID Remnawave подписки или по имени `user_<ID>`.

## Автоматический мониторинг и перезапуск нод

«Серверы» → карточка «Мониторинг и автовосстановление нод» (веб-админка) и вкладка «Операции» в мобильной админке. Раз в минуту магазин
проверяет ноды Remnawave и агентов на серверах:

* нода не в сети 3 проверки подряд → перезапуск через Remnawave (не чаще раза в 15 минут на ноду);
* нода недоступна дольше 10 минут или агент молчит дольше 10 минут → сообщение в Telegram;
* плановый перезапуск всех нод (по умолчанию 04:30 МСК) и обновление нод агентом (05:00, нужен
  `AGENT_ALLOW_NODE_UPDATE=1` на сервере ноды) — включаются в настройках мониторинга;
* кнопки «Перезапустить» у каждой ноды и «Обновить ноды» — для ручных действий.

Состояние нод кешируется в Redis на 30 секунд (`nodes:status:v1`), поэтому кабинет и приложения не нагружают
панель Remnawave. Права: смотреть — `ops.diagnostics`, настраивать — `settings.runtime.write`, действия с
нодами — `provision_nodes`.

## Маршрутизация (рекомендация узла)

1. **Маршрутизация** → «Включено».
2. Стратегия:
   - «Задержка и нагрузка»;
   - «Сначала страна, затем нагрузка».
3. «Максимальная нагрузка %» — узлы выше порога не рекомендуются.
4. «Предпочтительные страны» и «Резервный узел, если основной недоступен».
5. «Сохранить».

Кабинет показывает клиенту рекомендуемый узел, чтобы он выбрал его в своём VPN-клиенте. Реальное распределение трафика по-прежнему определяет Remnawave и выбор клиента.

## Мощность и оркестратор

- **Планирование мощности** использует телеметрию агентов узлов ([модуль 19](19-node-agent-antiabuse.md)). Пороги по умолчанию: предупреждение 75%, критично 90%, горизонт прогноза 14 дней. Без агентов раздел пуст.
- **Оркестратор** → «Оценить инфраструктуру»: для узлов без heartbeat дольше заданного времени (по умолчанию 180 секунд) или с упавшим Xray создаёт действие «вывести узел». По умолчанию действие ждёт ручного подтверждения. Облачные серверы оркестратор не создаёт и не удаляет: без учётных данных провайдера он формирует только проверяемые намерения.

## Проверка

- **Серверы**: «Панель отвечает», узлы в статусе онлайн.
- **Маршрутизация** включена — в кабинете клиента виден рекомендуемый узел.
- С агентами — **Планирование мощности** показывает нагрузку каждого узла.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «Remnawave недоступен» | Неверный URL или токен, панель недоступна с сервера магазина, открыт circuit breaker | `curl -I https://panel...` с сервера; проверьте токен |
| Узлы есть, а «Планирование мощности» пусто | Нет агентов на узлах | Установите агенты |
| Подписка создана без серверов | У тарифа нет squad | [Модуль 06](06-plans.md) |
| Пользователь в панели «disabled» после оплаты | Отзыв после возврата или ручное отключение в панели | При повторной выдаче магазин включает пользователя сам |

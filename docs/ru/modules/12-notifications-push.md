# 12. Уведомления и push

## Для чего

Центр уведомлений клиента: оплата подтверждена, подписка заканчивается, ответ поддержки, бонус начислен, замечен торрент и т. д. Уведомления видны в кабинете и Mini App. В приложениях Android и iOS они дополнительно приходят системными push через Firebase (FCM) и Apple (APNs).

Без ключей FCM/APNs центр уведомлений работает как обычно, просто push не отправляются.

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Маркетинг → Уведомления** | Карточка «Push-уведомления»: настроены ли FCM и APNs, сколько устройств получают push, доставки за 24 часа, причины отключения устройств за 7 дней, частые ошибки; список последних 200 уведомлений: клиент, канал, тип, статус | `read` |
| Создание уведомления клиенту | Через API: одному клиенту по ID; массово — [массовые операции](04-customer-import.md) | `manage_content` |

Токены устройств в панели не показываются.

## Настройка push

### Android (FCM)

1. В Firebase Console создайте проект и добавьте Android-приложение с пакетом `shop.remnawave.user` (или своим, если пересобираете).
2. **Project settings → Service accounts → Generate new private key** — скачайте JSON. Включите Firebase Cloud Messaging API.
3. В `.env`:

```dotenv
FCM_PROJECT_ID=your-firebase-project-id
FCM_SERVICE_ACCOUNT_JSON=<JSON одной строкой или base64 -w0 файла>
```

### iOS (APNs)

1. Apple Developer → **Keys → +** → Apple Push Notifications service. Скачайте `.p8` (скачивается один раз), запишите Key ID и Team ID.
2. В App ID приложения включите Push Notifications.
3. В `.env`:

```dotenv
APNS_KEY_ID=ABC123DEFG
APNS_TEAM_ID=TEAM123456
APNS_BUNDLE_ID=shop.remnawave.user
APNS_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----
APNS_ENVIRONMENT=production    # sandbox — для сборок из Xcode
```

После изменения: `docker compose up -d --force-recreate backend worker`. Ключи храните только на сервере.

## Стиль push-уведомлений и кампании

**Бот и кабинет → Приложения: стиль push-уведомлений.**
- Для каждого типа уведомлений (подписка заканчивается, оплата и выдача, push-кампании, ответ поддержки, розыгрыши, остальные) задаются:
  - включено или нет, эмодзи;
  - заголовок и текст по шаблону (`{title}`, `{body}`, `{brand}`);
  - картинка — баннер `app-*` или ссылка https;
  - раздел, который откроется по нажатию;
  - до двух кнопок с разделами, группа Android и звук.
- Общие настройки: цвет, название, логотип, картинки, группировка.
- Предпросмотр рядом с формой. Изменения действуют со следующего push.
- Ответ поддержки на экране блокировки всегда скрыт.

**Бот и кабинет → Приложения: push-кампании.**
- Сообщение уходит сегменту:
  - подписка заканчивается в ближайшие N дней;
  - подписка закончилась за N дней;
  - ещё не покупали;
  - давно не заходили (N дней);
  - установили приложение;
  - все.
- До отправки видно, сколько получателей и у скольких включён push. Сообщение появляется в «Уведомлениях» и приходит push на все телефоны клиента.
- Ту же рассылку тому же сегменту повторно можно отправить только через 10 минут: случайный второй клик не дублирует сообщения.
- **Отправить позже.** Отметьте «Отправить позже» и укажите дату и время по Москве (не дальше 60 дней). Кампания ждёт со статусом «запланирована»; воркер отправит её в течение минуты после этого времени, ровно один раз. До отправки её можно «Отменить». Сегмент считается в момент отправки.
- **A/B-тест.** Отметьте «A/B-тест», напишите заголовок и текст B и долю получателей варианта B (1–90 %). Один клиент всегда видит один и тот же вариант.
- **Итог.** «Считать оплаты в течение, дней» (1–30, по умолчанию 7) задаёт окно. В списке кампаний у A/B-кампании видно для каждого варианта: сколько получателей оплатили за окно, конверсию и выручку. «Лучше» появляется, когда разница значима (p < 0,05 и не меньше 30 получателей в каждом варианте); пока окно идёт, итог меняется.

Напоминание «Подписка заканчивается» с v28.32.0 приходит в приложение и push всем клиентам, а не только через Telegram.

## Как доставляются push

1. Клиент включает push на вкладке «Уведомления» приложения и даёт системное разрешение.
2. Worker отправляет каждое новое уведомление на все активные устройства клиента.
3. Временные ошибки (429, 5xx, сеть) повторяются через 30 секунд, 1, 2 и 4 минуты. После 5 попыток доставка считается неудачной.
4. В push уходят только уведомления не старше часа. Заголовок обрезается до 80 символов, текст — до 180. Текст ответа поддержки на экран блокировки не выводится.
5. Устройство отключается, если:
   - клиент вышел из аккаунта;
   - токен стал недействительным;
   - на устройстве вошли в другой аккаунт;
   - у клиента больше 10 устройств — отключаются самые давние.

## Проверка

1. Соберите приложение, войдите тестовым клиентом, включите push.
2. В **Уведомлениях** число устройств выросло.
3. Отправьте тестовое уведомление на текущее устройство (`POST /api/me/push/test` из приложения) или создайте событие — например, ответьте в поддержке. Push приходит на телефон, в карточке растёт число доставок.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «FCM не настроен» | Пустые `FCM_*` | Задайте ключи, перезапустите backend и worker |
| Ошибки `401/403` в карточке | Неверный JSON сервисного аккаунта или `.p8` | Перевыпустите ключ; устройства клиентов при этом не отключаются |
| На iOS не приходит, ошибка `BadDeviceToken` | Сборка из Xcode, а `APNS_ENVIRONMENT=production` | Для Xcode-сборок используйте `sandbox` |
| Устройство «вход в другой аккаунт» | На телефоне сменили аккаунт | Ожидаемо |

## API

`GET /api/admin/notifications`, `POST /api/admin/notifications`, `GET /api/admin/push/status`. Клиент: `GET /api/me/notifications`, `POST /api/me/push/devices`, `POST /api/me/push/test`.

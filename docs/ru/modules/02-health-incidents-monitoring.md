# 02. Состояние, инциденты и мониторинг

## Для чего

Отвечает на вопросы «всё ли работает» и «что сломалось»:

- проверки зависимостей (PostgreSQL, Redis, Remnawave, worker);
- журнал инцидентов;
- публичная страница статуса;
- оповещения в Telegram и на почту;
- метрики для Prometheus и Grafana.

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Аналитика → Запуск и оповещения** | Готовность к приёму оплат (бот, Mini App по HTTPS, Remnawave и его вебхук, кассы, тарифы, резервная копия за сутки, получатель оповещений); получатели оповещений, тестовое оповещение, текущие проблемы | `read` |
| **Аналитика → Состояние системы** | PostgreSQL, Redis (с задержкой), Remnawave, worker; признак приостановленных платежей | `ops.diagnostics` (оператор, администратор) |
| **Аналитика → Инциденты** | Открыть инцидент (уровень, категория, название), закрыть; провайдеры оплаты: включён, приоритет, успешные, ошибки, задержка, состояние circuit breaker | `ops.incidents` |
| **Серверы → Мониторинг** | Версия, свободный диск, число запросов и ошибок, рабочие процессы и их последняя активность | `read` |
| Статус сервиса (из «Все разделы») | Компоненты публичной страницы статуса и их состояние | `ops.diagnostics` (оператор, администратор) |

Публичный статус без входа: `GET https://api.ДОМЕН/api/public/v6/status`.

## Настройка

### Оповещения

| Переменная | Значение |
| --- | --- |
| `ALERT_TELEGRAM_CHAT_ID` | ID чата или канала для алертов. Бот магазина должен быть в нём участником (в канале — администратором) |
| `ALERT_EMAIL` | Адрес для алертов; нужен рабочий SMTP (`SMTP_*`) |

Алерты приходят, когда:

- за час 5 и больше неудачных выдач;
- нет успешной резервной копии 25 часов;
- резервная копия завершилась ошибкой;
- сбой планировщика возвратов.

После изменения выполните `docker compose up -d --force-recreate backend worker`.

### Prometheus и Grafana

1. Установщик уже задал `METRICS_ENABLED=true` и случайный `METRICS_TOKEN`. Без токена `/metrics` отвечает `503`, с неверным токеном — `401`.
2. На сервере мониторинга возьмите `deploy/prometheus/prometheus.example.yml`, замените адрес на свой API-домен, токен положите в файл `/etc/prometheus/secrets/vpnshop-metrics-token` (только для процесса Prometheus).
3. Добавьте правила `deploy/prometheus/vpnshop-alerts.yml`. Проверьте их:
   - `promtool check config /etc/prometheus/prometheus.yml`;
   - `promtool check rules /etc/prometheus/vpnshop-alerts.yml`.
4. Подключите Alertmanager к своему каналу уведомлений. Сами правила никуда не отправляют сообщений.
5. В Grafana импортируйте `deploy/grafana/vpnshop-operations.json` (14 панелей: API, БД, worker, RPS, доля 5xx, очередь, платежи, возвраты, обращения, подписки, нарушения, агенты, вебхуки).

Правила алертов:

- API недоступен 2 минуты;
- метрики БД недоступны 2 минуты;
- нет worker 3 минуты;
- задача ждёт в очереди дольше 15 минут;
- доля ошибок 5xx выше 5% в течение 5 минут.

### Страница статуса

В разделе «Статус сервиса» добавьте компоненты, которые видят клиенты: «Оплата», «VPN-серверы», «Поддержка». Пустой список показывается как неизвестное состояние, а не «всё работает».

## Работа

- **Каждый день:** «Состояние системы» — все проверки «ok»; «Мониторинг» — worker с последней активностью меньше 90 секунд назад, диск не заполнен.
- **При сбое:**
  1. «Инциденты» → «Создать инцидент»: уровень, категория, понятное название.
  2. Обновите компонент страницы статуса.
  3. Устраните причину ([диагностика](27-releases-updates.md)).
  4. «Закрыть».
- **Серьёзный сбой оплаты или выдачи:** **Безопасность → Восстановление → Аварийный режим → Включить**. Магазин переходит в технический режим: оплаты, покупки из кошелька, подарки и конкурсы недоступны. После устранения — «Выключить». Технический режим снимается вместе с аварийным, если нет незавершённого или неудачного восстановления ([модуль 30](30-backups-recovery.md)).

## Проверка

```bash
curl -fsS https://api.ДОМЕН/health/live
curl -fsS https://api.ДОМЕН/health/ready
curl -fsS -H "X-Metrics-Token: $(grep ^METRICS_TOKEN= /opt/vpn-shop/.env | cut -d= -f2)" https://api.ДОМЕН/metrics | head
```

`live` — процесс жив; `ready` — доступны БД и Redis. Это не проверяет оплату, почту и VPN-туннель.

Проверьте алерт: на тестовом стенде остановите worker (`docker compose stop worker`) — через 3 минуты Prometheus должен показать `firing`, после `docker compose start worker` — восстановление.

## Проблемы

## Оповещения о сбоях

Каждые 5 минут магазин ищет проблемы, которые требуют действий оператора, и присылает их в Telegram (`ALERT_TELEGRAM_CHAT_ID`, без него — владельцу `ADMIN_TELEGRAM_ID`) и на почту (`ALERT_EMAIL` с SMTP):

| Проблема | Когда |
| --- | --- |
| Оплата без доступа | Выдача доступа после оплаты завершилась ошибкой |
| Оплата ждёт выдачи | Оплачено, но доступ не выдан дольше 15 минут |
| Касса временно отключена | Сработал circuit breaker провайдера оплаты |
| Фоновый процесс не отвечает | Worker не отмечался дольше 3 минут |
| Проверка мониторинга не проходит | Три неудачи подряд у проверки из «Серверы → Мониторинг» |
| Резервная копия не создана | Последняя копия за сутки завершилась ошибкой |
| Remnawave недоступен | Панель не ответила |
| Отрицательный баланс клиента | Возвращённое пополнение кошелька уже было потрачено: купленное на него остаётся активным, оператор решает, ограничить доступ или договориться о погашении |

Каждая проблема приходит один раз и повторяется не чаще, чем раз в 6 часов. Когда она исчезает, приходит «✅ Решено». Если отправить сообщение не удалось, магазин повторит попытку на следующей проверке. Кнопка **Отправить тестовое оповещение** проверяет доставку.

API: `GET /api/admin/ops/readiness`, `GET /api/admin/ops/alerts`, `POST /api/admin/ops/alerts/test`.

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Redis «error» | Контейнер `redis` упал или неверный пароль | `docker compose ps redis`, `docker compose logs redis` |
| Worker «stale» | Процесс `worker` остановлен или завис | `docker compose restart worker`, затем логи |
| Remnawave «недоступен» | Панель недоступна или открыт circuit breaker после 5 ошибок | Проверьте панель; breaker закрывается через `REMNAWAVE_CB_COOLDOWN` секунд |
| Алерты в Telegram не приходят | Бот не в чате или неверный ID | Добавьте бота, для канала ID начинается с `-100` |
| `/metrics` — 503 | Пустой `METRICS_TOKEN` | Задайте токен и перезапустите backend |

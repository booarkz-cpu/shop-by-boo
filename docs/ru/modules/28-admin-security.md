# 28. Безопасность панели

## Для чего

Кто и как входит в админку:

- двухфакторный вход (TOTP) и коды восстановления;
- ключи доступа (passkeys);
- учётные записи и роли команды;
- активные сессии;
- журнал всех действий администраторов.

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Безопасность → Защита и 2FA** | Включить или выключить 2FA, состояние защиты (авторизация, права, ограничение запросов), аварийная остановка и открытие реальных платежей | своя 2FA — все роли; платежи — `security.manage` |
| **Безопасность → Ключи доступа** | Зарегистрировать или удалить passkey | `security.passkeys` (оператор, администратор) |
| **Безопасность → Роли и администраторы** | Email, пароль (от 12 символов), Telegram ID, роль; отключить или удалить | `manage_admins` (администратор) |
| **Безопасность → Сессии** | Активные входы: администратор, браузер, последняя активность, срок; завершить одну или все свои | своё — `sessions.self`; все — `sessions.manage` |
| **Безопасность → Журнал действий** | Кто, когда и что изменил | `read` |
| Центр безопасности (из «Все разделы») | Инциденты безопасности и сигналы антифрода | `read` |

## Первичная настройка

1. **Защита и 2FA** → «Включить 2FA» → отсканируйте QR в приложении-аутентификаторе (Google Authenticator, Aegis, 1Password) → введите код → «Подтвердить».
2. Сохраните **коды восстановления** офлайн. Каждый код действует один раз и заменяет код из приложения, если телефон потерян.
3. **Роли и администраторы** → для каждого сотрудника своя учётная запись:

| Роль | Кому |
| --- | --- |
| Наблюдатель | Аналитику, бухгалтеру: только чтение |
| Оператор | Поддержке и маркетингу: клиенты, тарифы, контент, рассылки, ответы, повтор выдачи |
| Администратор | Владельцу и техническому специалисту: всё, включая безопасность, возвраты, копии, импорт, терминал |

4. Попросите каждого включить 2FA. Терминал узлов без 2FA недоступен.

### Ключи доступа (passkeys)

1. `WEBAUTHN_ORIGIN=https://admin.ДОМЕН` — установщик задаёт его сам. Значение должно точно совпадать с адресом админки, без пути и `/` в конце.
2. **Система → Функции и модули** → включите `passkeys`.
3. **Ключи доступа** → зарегистрируйте ключ: подтвердите паролем и кодом 2FA, затем биометрией или PIN устройства.

### Вход через Telegram

Если у администратора указан Telegram ID, он может войти в мобильное приложение администратора по данным Telegram. **Для администратора с включённой 2FA такой вход запрещён:** только email, пароль и код.

## Работа

- **Сотрудник уходит:** **Роли и администраторы** → отключите или удалите учётную запись; **Сессии** → завершите его входы.
- **Подозрение на компрометацию:**
  1. **Сессии** → «Завершить все».
  2. Смените пароль и перевыпустите 2FA.
  3. Проверьте **Журнал действий** за последние дни.
  4. При необходимости включите аварийный режим ([модуль 30](30-backups-recovery.md)).
- **Журнал действий** неизменяемый. Каждое изменение тарифа, настройки, возврата, флага, терминала пишется с email администратора и временем.

## Защита по умолчанию

- Сессии в cookie `HttpOnly` и `Secure`, проверка CSRF и точного `Origin`.
- Ограничение частоты запросов через Redis: вход, API админки.
- Секреты в базе зашифрованы `APP_SECRET`.
- Firewall сервера открывает только SSH и 80/443.

## Проверка

- Выйдите и войдите: требуется код 2FA.
- Войдите вторым аккаунтом-наблюдателем: изменение тарифа отвечает `403`.
- В **Журнале действий** видны оба входа.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Потерян телефон с 2FA | — | Войдите кодом восстановления, затем перевыпустите 2FA |
| Потеряны и телефон, и коды | Сбросить чужую 2FA из панели нельзя | Другой администратор удаляет вашу учётную запись и создаёт её заново. Если администратор один: на сервере задайте в `.env` новый `ADMIN_EMAIL` (которого ещё нет среди администраторов) и `ADMIN_PASSWORD`, выполните `docker compose up -d --force-recreate backend` — при запуске будет создан новый администратор. Войдите им и пересоздайте старую учётную запись |
| Passkey: ошибка origin | `WEBAUTHN_ORIGIN` не совпадает с адресом | Исправьте `.env`, перезапустите backend |
| `401` постоянно | Истекла сессия или неверное время сервера | Войдите снова; проверьте `timedatectl` |
| `429` при входе | Слишком много попыток | Подождите |

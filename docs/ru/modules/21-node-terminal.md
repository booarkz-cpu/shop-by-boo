# 21. Терминал узлов

## Для чего

Полная командная оболочка на VPN-сервере прямо в админке: посмотреть журнал Xray, перезапустить службу, открыть `top`, поправить конфигурацию. SSH-ключи в магазине не хранятся, порты на узле не открываются: агент сам забирает ввод и отправляет вывод по HTTPS.

Это полная оболочка. Пользователь терминала может сделать на узле всё, что разрешают его права. Поэтому включение двухступенчатое, каждая сессия подтверждается и записывается.

## Где и кто

**Серверы → Терминал узлов**:

- только «Администратор» (право `nodes.terminal`) с включённым двухфакторным входом;
- журнал сессий виден администратору с правом управления безопасностью.

## Настройка

### 1. Сервер магазина

```dotenv
TERMINAL_ENABLED=true
TERMINAL_MAX_MINUTES=30        # до 120
TERMINAL_IDLE_MINUTES=10
TERMINAL_TRANSCRIPT_DAYS=90
```

`docker compose up -d --force-recreate backend worker`. Из панели терминал не включается.

### 2. Узел

Заведите отдельного пользователя с ограниченными правами и укажите его агенту:

```bash
useradd --create-home --shell /bin/bash corgi-term
echo 'corgi-term ALL=(root) /usr/bin/systemctl restart xray, /usr/bin/journalctl' > /etc/sudoers.d/corgi-term
```

В `/etc/corgi-agent.env` агента ([модуль 19](19-node-agent-antiabuse.md)):

```dotenv
AGENT_TERMINAL=1
AGENT_TERMINAL_USER=corgi-term
# AGENT_TERMINAL_SHELL=/bin/bash
```

`systemctl restart corgi-agent`. Агент сообщает магазину, что терминал на узле разрешён.

### 3. Администратор

**Безопасность → Защита и 2FA** → включите 2FA, затем выйдите и войдите заново с кодом.

## Работа

1. **Терминал узлов** → у узла «Открыть терминал» (кнопка активна, если агент на связи и терминал на нём разрешён).
2. Причина доступа (попадёт в журнал), пароль и код 2FA → «Подтвердить и открыть». Один код открывает одну сессию; после 5 ошибок — пауза 15 минут.
3. Узел подключается за несколько секунд. Щёлкните по экрану и вводите команды. Работают:
   - Ctrl+C на любой раскладке, стрелки, F1–F12, вставка;
   - полноэкранные программы `top`, `htop`, `less`, `vim`.
4. **Сниппеты** — сохранённые команды. Они вставляются без Enter, чтобы их можно было проверить.
5. «Закрыть сессию» завершает оболочку и все её процессы. Сессия также закрывается сама:
   - через `TERMINAL_MAX_MINUTES`;
   - после `TERMINAL_IDLE_MINUTES` без ввода;
   - при выходе из оболочки или отключении агента.

Ограничения: одна сессия на узел, две у администратора, пять всего.

## Журнал

«Журнал сессий» → «Журнал» показывает зашифрованную запись: ввод выделен, вывод очищен от управляющих последовательностей. Ввод при запросе пароля (`sudo`, `passwd`, `read -s`) записывается только длиной. Начало, закрытие и просмотр журнала попадают в журнал действий. Записи хранятся `TERMINAL_TRANSCRIPT_DAYS` дней.

## Проверка

Откройте сессию, выполните `uname -a` и `sudo journalctl -u xray -n 5`, закройте. В журнале видна команда, а введённый пароль `sudo` не записан.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «Терминал выключен» | `TERMINAL_ENABLED` не `true` | Задайте и перезапустите backend |
| «Нужен 2FA» | У администратора выключена 2FA | Включите и перезайдите |
| «На узле терминал не включён» | Агент без `AGENT_TERMINAL=1` | Задайте и перезапустите агент |
| «Агент узла не на связи» | Нет heartbeat 3 минуты | `journalctl -u corgi-agent` |
| Сессия не открывается от root-агента | `AGENT_TERMINAL_USER` указан, но агент не root и не этот пользователь | Запускайте агент от root или от пользователя терминала |

## API

`GET /api/admin/terminal`, `POST /api/admin/terminal/sessions`, `GET .../sessions/{id}/output`, `POST .../sessions/{id}/input`, `POST .../sessions/{id}/close`, `GET .../sessions/{id}/transcript`, `/api/admin/terminal/snippets`; агент — `/api/agent/terminal/...`.

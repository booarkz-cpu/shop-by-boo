# 07. Платежи

## Для чего

Приём оплаты через три платёжных агента (YooKassa, RollyPay, Platega), внутренний кошелёк клиента, возвраты, повтор выдачи после оплаты, сверка с провайдерами и проверка платёжного контура перед запуском.

## Главное ограничение сейчас

Создание реальных платежей закрыто **production gate**. Под запретом:

- оплата тарифа через провайдера;
- пополнение кошелька;
- автопродление.

Ворота открываются только после полного staging E2E v2: оплата → подписанный webhook → выдача VPN → повтор webhook → возврат, не старше 24 часов. Проверяющая часть этого теста пока не реализована, поэтому ворота открыть нельзя.

**Что работает без ворот:**

- покупка с уже имеющегося баланса кошелька (бонусы, перенос, возвраты);
- пробный период;
- подарочные коды;
- настройка и sandbox-проверка провайдеров.

Не открывайте ворота правкой базы: сервер перепроверяет результат при каждом платеже, а обход создаёт риск списаний без выдачи.

## Где и кто

| Раздел | Что делает | Права |
| --- | --- | --- |
| **Тарифы и оплата → Платежи** | Поиск по клиенту, номеру, статусу, сумме; статус оплаты отдельно от выдачи; «Повторить» выдачу; «Сверить платежи» с провайдерами | просмотр `payments.read`, повтор `payments.retry` (оператор), сверка `payments.reconcile` (администратор) |
| **Тарифы и оплата → Платёжные агенты** | Включён ли агент, приоритет, успешные и ошибочные оплаты, задержка, автоматический circuit breaker | `ops.providers` |
| **Тарифы и оплата → Возвраты** | Заявки на возврат: предпросмотр (dry-run), одобрение, выполнение через провайдера, сверка | `payments.refund` (администратор) |
| **Тарифы и оплата → Проверка платежей** | Тестовые реквизиты sandbox и запуск проверки платёжного контура | `staging_e2e.manage` (администратор) |
| **Безопасность → Защита и 2FA** | Состояние и переключатель «Разрешить реальные платежи» (production gate) | `security.manage` (администратор) |

## Настройка агентов

| Агент | Переменные `.env` | Адрес уведомлений в кабинете провайдера |
| --- | --- | --- |
| YooKassa | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_WEBHOOK_IP_ALLOWLIST` (IP-адреса YooKassa из её документации) | `https://api.ДОМЕН/api/webhooks/yookassa` |
| RollyPay | `ROLLYPAY_API_KEY`, `ROLLYPAY_SIGNING_SECRET`, `ROLLYPAY_TEST_MODE`; для возвратов `ROLLYPAY_REFUND_URL`, `ROLLYPAY_REFUND_STATUS_URL` | `https://api.ДОМЕН/api/webhooks/rollypay` |
| Platega | `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET`; для возвратов `PLATEGA_REFUND_URL`, `PLATEGA_REFUND_STATUS_URL` | `https://api.ДОМЕН/api/webhooks/platega` |

1. Впишите ключи в `.env` или в **Система → Настройки без перезапуска** (секреты хранятся зашифрованными и в браузер не возвращаются).
2. Перезапустите при правке `.env`: `docker compose up -d --force-recreate backend worker`.
3. **Платёжные агенты**: проверьте, что агент «Включён», задайте приоритет. Порядок на новой базе — YooKassa, RollyPay, Platega. Отключённые, ненастроенные и находящиеся в cooldown агенты в выбор не попадают.
4. YooKassa: в кабинете YooKassa включите HTTP-уведомления о платежах и возвратах. Автопродление работает только с сохранённым способом оплаты YooKassa.

Валюта магазина — `DEFAULT_CURRENCY`. Сумма и валюта уведомления сверяются с заказом. Оплата считается подтверждённой только после проверки у провайдера, возврат браузера на страницу «успех» ничего не подтверждает.

Старые адаптеры (CryptoBot, Stripe, PayPal) остаются только для завершения ранее созданных операций. Новые счета через них не создаются. Мобильная оплата через Apple/Google (`/api/payments/mobile/verify`) отключена (ответ 410).

## Проверка платёжного контура (sandbox)

1. Получите у провайдера тестовые ключи. Они должны отличаться от боевых.
2. **Проверка платежей**: публичный HTTPS URL, токен Remnawave для staging, bearer-токен тестового пользователя, ID тестового тарифа, ключи каждого выбранного провайдера → «Подтверждаю sandbox-ключи» → «Сохранить безопасную конфигурацию» → «Запустить staging E2E».
3. Проверка создаёт платёж через отдельный тестовый контур и проверяет ответы API провайдера и возврат. Webhook и выдачу VPN она пока не подтверждает, поэтому статус будет «ожидание checkout», а не «пройдено». Это ожидаемо.

## Работа

**Клиент оплатил, а подписки нет:**

1. **Платежи** → найдите платёж. «Оплата» = оплачен, «Выдача» = ошибка или ожидание.
2. Проверьте Remnawave (**Состояние системы**) и профиль тарифа.
3. «Повторить» выдачу. Новый счёт не создавайте: это двойное списание.

**Неопределённое создание платежа** (провайдер не ответил): нажмите «Сверить платежи». Не создавайте новый платёж вместо старого неопределённого.

**Возврат:**

1. **Возвраты** → заявка → проверьте сумму и последствия для доступа (предпросмотр).
2. «Одобрить», затем «Выполнить». Возврат уходит провайдеру, доступ к подписке отзывается.
3. Дождитесь подтверждения провайдера; при неясном статусе — «Сверить».

Ручная отметка «возвращено» отключена: факт возврата подтверждает только провайдер.

**Кошелёк** — внутренний баланс клиента, не отдельный агент. Пополнение идёт через агентов (под воротами), покупка с баланса записывается в финансовый журнал.

## Проверка

- **Платёжные агенты** показывают настроенных агентов включёнными.
- **Проверка платежей** завершается без ошибок провайдера.
- `curl -s -o /dev/null -w '%{http_code}' -X POST https://api.ДОМЕН/api/webhooks/yookassa` возвращает 4xx (подпись или IP не прошли), а не 5xx и не таймаут. Значит, адрес достижим.

## Проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Клиент видит «оплата недоступна», `503` | Закрыт production gate или включён технический режим | Ожидаемо до реализации E2E v2; технический режим — [модуль 30](30-backups-recovery.md) |
| Агент не выбирается | Нет ключей, выключен или в cooldown после ошибок | **Платёжные агенты**, ключи в `.env` |
| Webhook отклоняется | Неверная подпись, IP не в allowlist, другая сумма или валюта | Логи backend; обновите `YOOKASSA_WEBHOOK_IP_ALLOWLIST` |
| Оплачен, выдача «ошибка» | Remnawave недоступен, нет профиля | Исправьте причину, «Повторить» |
| Возврат Platega/RollyPay не выполняется | Не заданы URL возврата и статуса | Согласуйте их с провайдером и задайте |

## API

`POST /api/payments/create`, `POST /api/me/wallet/topup`, `POST /api/me/wallet/spend`, вебхуки `POST /api/webhooks/yookassa|platega|rollypay`. Админка: `GET /api/admin/payments`, `GET /api/admin/payments/{id}`, `POST /api/admin/payments/{id}/retry`, `POST /api/admin/payments/reconcile`, `GET|PUT /api/admin/v41/providers`, `/api/admin/refunds/...`, `/api/admin/staging-e2e/config|run|status`, `POST /api/admin/payments/production-gate`.

# Выпуск v28.58.0 — исправления по техническому аудиту

Дистрибутив: `v28.58.0`. Runtime/API: `21.5.1`. Head магазина: `0089_index_cleanup` (одна новая миграция). Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

Выпуск закрывает находки этапа 3 мастер-задания ([аудит](new/FULL_TECHNICAL_AUDIT.md), [безопасность](new/SECURITY_AUDIT.md), [производительность](new/PERFORMANCE_AUDIT.md)). Журнал исправлений — [BUGFIX_LOG](new/BUGFIX_LOG.md), список тестов — [REGRESSION_TESTS](new/REGRESSION_TESTS.md).

## Что изменилось

**Админ-панель, кабинет и Mini App: ответ, который не JSON, — это ошибка (BUG-H1, BUG-H2)**

- Раньше клиент API превращал успешный ответ, который не разобрался как JSON, в `{}`. Чаще всего это `index.html`, который nginx отдаёт, когда `/api` не доходит до backend. Экран падал далеко от причины: `(s || []).map is not a function` и `Cannot read properties of undefined (reading 'trim')`.
- Теперь оба клиента читают ответ через `cabinet/src/http-json.ts`, и на экране видно, какой запрос вернул HTML и что проверить. Пустой ответ (204) и ответ с ошибкой обрабатываются как раньше.
- В «Документах» убрана вторая копия функции баннера (BUG-H3).

**База данных: миграция `0089_index_cleanup` (BUG-A1, BUG-A2)**

- Удалены 26 индексов, которые повторяли ограничение уникальности на тех же колонках. На `payments.order_id` их было три. Индекс удаляется, только если ограничение на тех же колонках есть в базе.
- Добавлены 12 индексов: шесть на внешние ключи без индекса и шесть, которые объявлены в моделях, но миграции их не создавали (`payments.idempotency_key`, `users.referred_by_id`, `promo_redemptions.user_id`, `referral_rewards.referred_user_id`, `payment_chargebacks.status`, `payout_transactions.status`).
- `gift_redemptions.operation_key` теперь `NOT NULL`, как в модели. Строкам без ключа выставлен `legacy:<id>`.
- Модели и миграции описывают одну схему: `alembic` autogenerate больше не находит различий (было 110). Это проверяет новый тест.

**Безопасность**

- Получатели пересылки вебхуков и рекламные постбэки принимают только публичные адреса `https://`. Соединение закрепляется на публичном IP из DNS, поэтому имя не может увести запрос во внутреннюю сеть сервера (SEC-01).
- Установка ноды больше не выполняет `curl https://get.docker.com | sh` от root. Docker ставится из подписанного apt-репозитория Docker, а скачанный ключ сверяется с опубликованным отпечатком `9DC8 5822 9FC7 DD38 854A E2D8 8D81 803C 0EBF CD88`. На системах, кроме Debian и Ubuntu, установщик останавливается и просит поставить Docker заранее (SEC-02).
- Ограничение частоты (10 в минуту с адреса) для погашения подарков и подарочных карт, реферальных и корпоративных кодов и гостевого входа (SEC-03).

**Remnawave 3.x и импорт истории (BUG-A7)**

- Remnawave 3.4 обращается к пользователю по числовому `id` и не умеет искать его по UUID. Импорт истории теперь принимает короткие числовые id (раньше требовалось не меньше 8 символов). Строки с UUID показываются как заблокированные с объяснением, а не ломают продление после переноса.

**Docker**

- У `worker`, `bot`, `mail_receiver` и `support_worker` появился healthcheck. Сервис обновляет файл `/tmp/<имя>.alive`; worker — только после успешного обращения к PostgreSQL и Redis. Docker помечает зависший сервис как `unhealthy`: это видно в `docker compose ps` и `docker inspect`. Сам Docker такой контейнер не перезапускает (BUG-A6).

**Тесты**

- Новые: схема против миграций, повторяющиеся индексы, проверка вызывающего у всех изменяющих маршрутов, ограничения частоты, установка ноды (сценарий установщика запускается с поддельными системными утилитами), healthchecks, публичные адреса вебхуков, чтение ответов API (vitest).
- `test_payment_provider_health_bootstraps_without_admin_page` больше не зависит от `PAYMENTS_SANDBOX` в окружении (BUG-T1).

## Обновление

Одна миграция; она меняет только индексы и одну колонку и проходит за секунды.

```bash
cd /opt/vpn-shop && bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.58.0 bash /opt/vpn-shop/scripts/update-from-github.sh
docker compose exec -T backend alembic current   # ожидается 0089_index_cleanup (head)
```

Если в журнале пересылки вебхуков или постбэков был адрес во внутренней сети, после обновления такой получатель перестанет получать запросы. Сохранить его заново тоже не выйдет: при сохранении появится ошибка с объяснением.

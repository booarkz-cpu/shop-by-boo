# Релиз v28.136.0 — клиент 1.9.6: обновление приходит в тот же день

Дистрибутив: `v28.136.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Дата: 2026-11-13. Сообщение владельца: «Обновление приложения 1.9.5 не вышло на GitHub, проверь всё и исправь».

## Что проверено

На GitHub версия 1.9.5 опубликована:

- выпуск `v28.134.0` (отмечен как последний): `corgi-lusi-client.apk`, `.sha256`, `corgi-lusi-client.json` с versionCode 195;
- собственный выпуск клиента `client-v1.9.5` с тем же APK (SHA-256 `0f720fae…6fb755` совпадает).

Ссылка, по которой клиент ищет обновление (`releases/latest/download/corgi-lusi-client.json`), отдавала 1.9.5.
Значит, ошибка была в самом клиенте.

## Что было

- Ответ «обновлений нет» клиент запоминал на сутки. Телефон, проверивший выпуски до выхода 1.9.5, не видел её до следующего дня.
- Фоновая проверка шла раз в сутки и только по Wi‑Fi. В мобильной сети обновление не приходило совсем.
- «Настройки» → «Проверить обновления» только скачивала файл, а установку надо было искать отдельно.

## Что стало

- Магазин спрашивается не реже раза в 3 часа. Уже установленная версия больше не считается «доступной».
- Фоновая проверка — раз в 6 часов по любой сети. Задача, поставленная прежней версией, заменяется.
- В мобильной сети APK (около 150 МБ) сам не скачивается: приходит уведомление «Доступна версия» (один раз на версию),
  нажатие скачивает и ставит. По Wi‑Fi всё как раньше: скачивается само и ставится без вопросов на Android 12+, если VPN выключен.
- «Проверить обновления» сразу передаёт найденную версию установщику.

## Чем проверено

Unit-тесты `UpdatesTest` (интервал проверки, забывание установленной версии, поведение в мобильной сети), сборка клиента в CI.
На телефоне не проверено.

## Как обновиться

Чтобы получить новую версию сразу: «Настройки» → «Проверить обновления»; в 1.9.4 и 1.9.5 после проверки появится строка «Установить 1.9.6».
Или файл `corgi-lusi-client.apk` из этого выпуска.

# Настройки без перезапуска

> Актуально для дистрибутива `v28.23.0`, runtime/API `21.5.1`, head магазина `0075_app_config`.

Раздел **Система → Настройки без перезапуска** управляет операционными параметрами API и worker-процессов. Реестр покрывает все 179 полей `Settings`: 96 значений допускают live-применение, 81 требуют deployment или специальной процедуры, ещё 2 управляются существующими workflow резервного копирования и восстановления.

## Модель безопасности

- Чтение доступно `operator` и `admin` по праву `settings.runtime.read`; изменение — только `admin` по `settings.runtime.write`.
- Секретные значения шифруются AES-GCM через ключ приложения. API сообщает только факт настройки; исходный секрет, его длина и фрагменты не возвращаются.
- Staged-набор целиком хранится зашифрованным. Его fingerprint — HMAC-SHA256, поэтому он не создаёт offline-oracle для подбора секрета.
- Каждая подготовка, публикация, отмена и удаление набора записывается в audit log без значений секретов.
- Изменение сначала проверяется, затем применяется отдельным подтверждением. Версия и fingerprint защищают от устаревшей вкладки и повторной публикации.
- Подготовленный набор и откат привязаны HMAC к исходным live-параметрам `.env`. Если deployment изменил окружение, API вернёт 409 до записи; обновите страницу и подготовьте явный набор заново.
- Полная конфигурация повторно проверяется под блокировкой версии перед применением и откатом. При отказе значения, история и номер версии сохраняются.
- Процессы перечитывают подтверждённую версию не позднее чем через 5 секунд. API-процесс, worker и bot используют один и тот же реестр.

Отдельный worker загружает опубликованную конфигурацию до проверки безопасности и запуска заданий, затем перечитывает версии вместе с API и ботом.

## Как изменить параметр

1. Откройте раздел и найдите поле по названию, техническому ключу или назначению.
2. Прочитайте подсказку у поля. Значок источника показывает `.env` либо переопределение в БД.
3. Измените одно или несколько значений. Для возврата к окружению нажмите **Вернуть .env**.
4. Введите причину без секретных данных и нажмите **Проверить и подготовить**.
5. Проверьте preview, предупреждения и короткий fingerprint.
6. Нажмите **Применить версию N**. При конфликте обновите раздел и подготовьте новый набор.
7. Убедитесь, что новая версия появилась в истории, а health всех процессов остаётся зелёным.

Секретное поле оставьте пустым, если его менять не нужно. После сохранения значение снова будет пустым; метка «секрет задан» подтверждает наличие, но не раскрывает его.

Пароли и непрозрачные ключи сохраняются точно, включая значимые пробелы. Причина операции после удаления крайних пробелов должна содержать от 3 до 500 символов.

## Откат

Откатить можно только последнюю применённую версию. Это исключает восстановление старого снимка поверх более новых решений. Укажите причину, подтвердите операцию и дождитесь появления новой версии: откат не уменьшает счётчик, а создаёт отдельную аудируемую ревизию. Для более старого состояния подготовьте новый явный набор либо восстановите согласованный backup.

## Что нельзя менять live

Внизу страницы находится закрываемый список deployment-параметров с причиной для каждого. К ним относятся корневые ключи, подключение БД/Redis, bot token, origin/cookie middleware, домены/порты, volume paths и образы. `DEFAULT_CURRENCY` требует миграции финансовых снимков, а не простой перезагрузки. `backup_s3_enabled` и `maintenance_mode` меняются в специализированных workflow, потому что связаны с другими атомарными действиями.

## Проверка после обновления

```bash
cd /opt/vpn-shop
docker compose exec -T backend alembic current
docker compose ps
curl -fsS https://API_DOMAIN/health/live
curl -fsS https://API_DOMAIN/health/ready
docker compose logs --since=10m backend worker bot | grep -E "Runtime settings|ERROR|CRITICAL" || true
```

Ожидаемый migration head — `0075_app_config`. В интерфейсе счётчики должны показывать 96 live, 81 deployment и 2 workflow. Затем безопасно измените неопасное значение на стенде, например уровень логирования, примените его, проверьте сходимость и выполните откат.

## Миграция и downgrade

`0064_runtime_settings` создаёт глобальную версию и неизменяемую историю staged/apply/rollback. Пока история пуста, downgrade технически возможен. После первой записи миграция блокирует downgrade, чтобы не потерять audit trail и снимки отката. Для production используйте исправление вперёд или согласованное восстановление базы.

Live-config не подтверждает доступность внешних касс, SMTP, Telegram или Remnawave. После изменения их ключей выполните профильные проверки из [инфраструктурного регламента](INFRASTRUCTURE_CHECKS_CURRENT.md) и не открывайте production gate без полного application E2E.

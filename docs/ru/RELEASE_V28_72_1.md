# Выпуск v28.72.1 — исправление модуля IPv6

Дистрибутив: `v28.72.1`. Runtime/API: `21.5.1`. Head магазина: `0092_telegram_bot` (миграций нет). Support Pro: `0008` / 3.8.

## Что исправлено

Модуль IPv6 мастера установки («Модули серверов → IPv6», v28.70.0):

- **Ошибки.**
  - После «выключить → включить» сервер с глобальным IPv6-адресом мог остаться без него: Linux сбрасывает адреса интерфейса при `disable_ipv6 = 1`, а при включении статические и DHCPv6-адреса сами не возвращаются (так же устроен модуль `ipv6` eGames).
  - Живой тест CI трижды падал на шаге сразу после переключения: запрос к GitHub (файлы ядра Xray) обрывался на TLS. У машины CI глобального IPv6 нет; диагностика показала, что через несколько секунд сеть отвечает нормально. Причина — сеть, которая ещё переинициализируется после переключения; доказать её точнее в CI не удалось.
- **Исправление.**
  - Шаг переключает `disable_ipv6` и у интерфейса маршрута по умолчанию, и у `lo`, а не только у `all` и `default`.
  - При включении шаг перечитывает сеть так, как её настраивает дистрибутив: `netplan apply`, `ifdown`/`ifup` или `systemd-networkd`.
  - Затем ждёт адрес. Если адрес не вернулся, шаг сообщает об этом, и мастер откатывает изменение.
  - После включения шаг ждёт, пока адреса интерфейса пройдут проверку дубликатов (статус «tentative»).
  - Поиск файлов релиза на GitHub делает 4 попытки с паузами 2, 5 и 10 секунд.

Сделано по образцу модуля `ipv6` из `eGamesAPI/remnawave-reverse-proxy` (MIT).

# Выпуск v28.59.0 — единая бизнес-логика backend

Дистрибутив: `v28.59.0`. Runtime/API: `21.5.1`. Head магазина: `0089_index_cleanup` (миграций нет). Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

Этап 5 мастер-задания. Подробно — [устройство backend](new/BACKEND_ARCHITECTURE.md), [правила API](new/API.md), [схема базы](new/DATABASE_SCHEMA.md).

## Что изменилось

**Одна выдача доступа**

- Семейная подписка (`growth.py`) и корпоративные места (`corporate.py`) содержали один и тот же код обращения к Remnawave: создать пользователя, включить, перенести срок, обновить трафик, устройства и сквад, а при потере места — выключить. Теперь он один — `backend/app/seat_access.py`. Исправление в одном месте действует для обоих.
- Тест `tests/test_single_business_logic.py` закрепляет:
  - пользователей панели создают и продлевают только `payments_api` (покупка и продление), `gift_orders` (подарочный код), `admin_api` и `bonus_days` (ручная выдача) и `seat_access` (места);
  - каждая оплата любого провайдера подтверждается одной функцией `_confirm_and_fulfill_payment`.

**Ошибки**

- Непредвиденная ошибка сервера отвечает JSON `{"detail": "Внутренняя ошибка сервера…", "request_id": "…"}` вместо текста «Internal Server Error». Причина и стек пишутся в журнал с тем же `request_id`, клиенту они не отдаются.

**Списки и отчёты**

- Общая реализация страниц (`backend/app/pagination.py`): `?limit=` (по умолчанию 500, до 1000), `?offset=`, общее число строк в заголовке `X-Total-Count`. Её используют «Корпоративные клиенты» и «Кампании».
- Аналитика оплат (`/api/admin/payments/analytics`) считает итоги в базе, принимает `?days=` и отдаёт не больше 1000 дневных строк.
- Новый отчёт «Целостность данных» (раздел «Аналитика → Запуск и оповещения», `GET /api/admin/integrity`, право `ops.diagnostics`). Он показывает записи, которые ссылаются на удалённого клиента, подписку, платёж или тариф: 16 связей денег и доступа. Отчёт ничего не меняет. Пустой результат — условие для внешних ключей в базе.

**Прочее**

- Отчёты DMARC разбираются через `defusedxml` (новая зависимость `defusedxml==0.7.1`).
- `Subscription.remnawave_user_id` — синоним колонки `remnawave_uuid`. В ней хранится числовой id пользователя Remnawave 3.x; колонка не переименована ради совместимости установок и резервных копий.
- Перечень API (`docs/API_ENDPOINTS.md`) получил колонку «Доступ»: право роли для админки или вид вызывающего для остальных маршрутов. Она берётся из зависимостей маршрутов.
- Схема базы `docs/ru/new/DATABASE_SCHEMA.md` генерируется из моделей (`scripts/generate-db-schema.py`), тест следит, чтобы она не устарела.

## Обновление

Миграций нет. Docker-образ backend ставит новую зависимость `defusedxml` при сборке.

```bash
cd /opt/vpn-shop && bash scripts/backup.sh
sudo env APP_DIR=/opt/vpn-shop RELEASE_TAG=v28.59.0 bash /opt/vpn-shop/scripts/update-from-github.sh
```

После обновления откройте «Аналитика → Запуск и оповещения → Целостность данных» и нажмите «Проверить». Если найдены записи без связи, пришлите отчёт: по нему решается, можно ли включать внешние ключи.

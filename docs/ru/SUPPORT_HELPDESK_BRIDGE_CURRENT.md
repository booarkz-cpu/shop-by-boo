# Мост Zendesk и Freshdesk (Support Pro 3.8)

Если команда уже принимает обращения в Zendesk или Freshdesk, Support Pro забирает их в общую очередь вместе с историей. Операторы отвечают из Support Pro, ответ появляется во внешнем обращении как обычный ответ агента и уходит клиенту оттуда. SLA, назначения, правила, отчёты и карточка клиента работают для этих обращений так же, как для Telegram и email.

Одновременно подключается одна внешняя система: `HELPDESK_PROVIDER=zendesk` или `freshdesk`. Без этой переменной мост выключен и ничего не запрашивает.

## Как это работает

**Клиент.** Автор внешнего обращения становится клиентом Support Pro (идентичность канала `zendesk`/`freshdesk` по ID пользователя во внешней системе). Если его email уже есть у клиента — например, из [email-канала](SUPPORT_EMAIL_CHANNEL_CURRENT.md), — обращения присоединяются к этому клиенту, а не создают дубль.

**Импорт истории и новые сообщения.** Worker раз в `HELPDESK_SYNC_SECONDS` читает изменённые обращения:

- Zendesk — инкрементальный экспорт с курсором (`/api/v2/incremental/tickets/cursor.json`);
- Freshdesk — список обращений по `updated_since` с постраничным обходом.

Первый запуск начинает с `HELPDESK_IMPORT_SINCE` (по умолчанию — последние 30 дней). Каждое внешнее обращение и каждый комментарий записываются в таблицу связей под уникальным ключом, а страница обращений сохраняется в одной транзакции с курсором. Повтор страницы, перезапуск worker или сбой посреди страницы не создают дублей.

| Во внешней системе | В Support Pro |
| --- | --- |
| публичный комментарий клиента | сообщение клиента, обращение ждёт ответа; закрытое обращение открывается снова |
| публичный ответ агента в самой системе | ответ оператора (видно в истории) |
| внутренняя заметка | приватная заметка |
| статус solved/closed (Zendesk), «Решено»/«Закрыто» (Freshdesk) | обращение закрывается |
| вложение | файл в обращении после проверки антивирусом; файл больше `HELPDESK_MAX_MB` помечается ошибкой со ссылкой на внешнюю систему |

**Ответы операторов.** Ответ ставится в общую очередь доставки и публикуется как публичный комментарий (Zendesk) или ответ (Freshdesk), вложение — вместе с ним. ID созданного комментария связывается с сообщением, поэтому следующий импорт его не повторяет. Если подтверждение потерялось по сети, сообщение получает состояние «результат неизвестен», а не отправляется ещё раз: следующая синхронизация найдёт этот текст во внешнем обращении и отметит сообщение отправленным.

**Ошибки внешней системы.**

| Ответ | Что происходит |
| --- | --- |
| HTTP 429 | синхронизация и отправка ставятся на паузу по `Retry-After` (от 5 секунд до часа), сообщения остаются в очереди |
| 5xx, сеть | курсор не сдвигается, импорт повторяется; ответ повторяется до 5 раз с растущим интервалом |
| 401/403 | ответ не отправлен: «проверьте учётную запись и ключ API»; ошибка видна на странице моста |
| 404/422 | ответ не отправлен с причиной — обращение удалено или отклонено внешней системой |

Вложения скачиваются только по HTTPS. Учётные данные передаются лишь самой системе; при перенаправлении на хранилище файлов (Zendesk) ключ API туда не уходит.

## Настройка

1. Создайте учётную запись для интеграции:
   - **Zendesk:** Admin Center → Apps and integrations → APIs → Zendesk API → включите доступ по токену и создайте токен. Нужен email агента, от имени которого будут публиковаться ответы.
   - **Freshdesk:** профиль агента → «Ключ API».
2. Добавьте в `support-pro/.env`:

   ```dotenv
   HELPDESK_PROVIDER=zendesk          # или freshdesk
   # Zendesk
   ZENDESK_SUBDOMAIN=acme             # acme.zendesk.com
   ZENDESK_EMAIL=support-bot@acme.example
   ZENDESK_API_TOKEN=...
   # Freshdesk
   FRESHDESK_DOMAIN=acme              # или acme.freshdesk.com
   FRESHDESK_API_KEY=...
   # Общие
   HELPDESK_IMPORT_SINCE=2026-09-01T00:00:00Z
   HELPDESK_SYNC_SECONDS=60
   HELPDESK_MAX_MB=10
   ```

3. Выполните миграцию и пересоздайте app и worker:

   ```bash
   docker compose run --rm support_migrate
   docker compose up -d support_pro support_worker
   ```

   В самостоятельном развёртывании Support Pro (каталог `support-pro/`): `docker compose run --rm migrate`, затем `docker compose up -d app worker`.
4. Откройте **Внешний helpdesk** в меню Support Pro (только администратор): там видны система и домен, время последней успешной синхронизации, число импортированных обращений и комментариев, пауза по 429 и последняя ошибка. Кнопка «Синхронизировать сейчас» запускает цикл без ожидания.

В обращении из внешней системы есть ссылка «Открыть во внешней системе».

Ответы операторов во внешней системе публикуются от имени учётной записи из шага 1. Не отвечайте на одно обращение одновременно в обеих системах: оба ответа уйдут клиенту.

## Данные клиента

В карточке клиента с идентичностью Zendesk/Freshdesk администратор может удалить данные моста. Удаление:

- очищает текст и файлы обращений этой системы в Support Pro и закрывает их;
- отменяет неотправленные ответы;
- удаляет идентичность канала, а если других каналов у клиента нет — имя и заметки;
- оставляет метку на внешнем обращении, чтобы следующие обновления этого обращения не импортировались снова.

Данные внутри Zendesk/Freshdesk удаляет администратор этой системы её средствами — Support Pro их не изменяет.

## Обновление и откат

Сделайте согласованный backup базы и uploads Support Pro, затем миграцию `0008` — она создаёт таблицы `helpdesk_state` и `helpdesk_links` и не меняет существующие данные. Откат ниже `0008` запрещён, если уже импортированы обращения Zendesk/Freshdesk: без таблицы связей повторный импорт создал бы дубли. Чтобы отключить мост, очистите `HELPDESK_PROVIDER` и пересоздайте worker — связи сохранятся, и после повторного включения импорт продолжится с сохранённого курсора.

## Проверка

`support-pro/tests/test_helpdesk_bridge.py` (SQLite и PostgreSQL) на имитации API Zendesk и Freshdesk проверяет:

- импорт истории с клиентом, комментариями, заметками и статусом; повтор страницы без дублей;
- присоединение к существующему клиенту по email;
- новое сообщение клиента: обращение открывается снова, вложение скачивается через перенаправление без передачи ключа хранилищу;
- однократную публикацию ответа оператора и отсутствие его повторного импорта;
- потерю подтверждения: «результат неизвестен», затем сверка при импорте;
- классификацию ошибок 401/403/404/422/5xx и паузу по 429;
- сохранение курсора при сбое импорта;
- удаление данных и запрет повторного импорта;
- импорт и ответ Freshdesk (HTML экранируется);
- страницу моста и выключенный мост без настроек.

`support-pro/tests/test_migrations.py` проверяет roundtrip миграции `0008` и защиту отката.

Работу с реальной учётной записью Zendesk или Freshdesk (права агента, лимиты тарифа, вложения больших размеров) проверяет оператор на своём стенде.

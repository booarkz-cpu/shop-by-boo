# Матрица функций и критерии завершения — дистрибутив v28.54.0

Этот документ завершает **описание** функциональной матрицы: у каждой открытой области есть владелец проверки, обязательный сценарий и условие, после которого статус можно повысить. Он не подменяет отсутствующую реализацию и не объявляет внешнюю production-проверку выполненной.

Актуальные версии: API `21.5.1`, база магазина `0088_filter_and_regions`, Support Pro `0008` / 3.8. Полный перечень реализованных функций и границ находится в [карте покрытия](WORKSPACE_COVERAGE.md), инструкции по функциям — в [общем указателе](../../FUNCTIONS.md).

## Значения статусов

| Статус | Что подтверждено | Что запрещено утверждать |
| --- | --- | --- |
| Есть | Реализация и автоматические проверки присутствуют в исходниках | Что внешняя касса, SMTP, VPN или мобильная подпись проверены в production |
| Есть, внешний E2E нужен | Внутренний контракт и regression-тесты готовы | Что интеграция допущена к реальным пользователям |
| Частично | Работает явно указанная часть сценария | Что покрыта вся функция сравниваемого проекта |
| Нет | Пользовательского production-сценария нет | Что функцию можно включить настройкой |

## Порядок закрытия матрицы

1. Создать отдельный issue/ветку на одну строку таблицы; не смешивать внешний E2E и новую подсистему.
2. До кода зафиксировать угрозы, миграцию, rollback и доказательство приёмки.
3. Добавить unit/integration/regression тесты и негативные конкурентные сценарии.
4. Обновить профильную инструкцию, API, карту покрытия, changelog и release manifest.
5. Провести проверку на отдельном стенде. Секреты, персональные данные и полный callback payload не прикладывать к issue или release.
6. Повышать статус только по фактическому evidence; недоступную внешнюю систему оставлять открытой.

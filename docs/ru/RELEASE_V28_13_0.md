# Выпуск v28.13.0 — почтовый домен: SPF, DKIM, DMARC и отчёты DMARC

Дистрибутив: `v28.13.0`. Runtime/API: `21.5.1`. Head магазина: `0069_mail_domain`. Support Pro: `0008` / 3.8 (без изменений). Дата и commit фиксируются тегом выпуска.

## Что завершено

Из строки матрицы «MX/SPF/DMARC» закрыты DNS-проверки, отчёты и их хранение. Новый раздел **Система → Почтовый домен: SPF, DKIM, DMARC**. [Инструкция](MAIL_DOMAIN_CURRENT.md).

- **Проверка DNS** через DNS-over-HTTPS — вручную и раз в сутки:
  - MX: записи есть и резолвятся; null MX;
  - SPF: одна запись, не больше 10 DNS-запросов с учётом всех `include`/`redirect` (как считает получатель), завершающий `all`, входит ли адрес `SMTP_HOST` в разрешённые; предупреждения о `ptr` и макросах;
  - DKIM: ключ селектора панели совпадает с опубликованным; отозванный ключ; `t=y`; селекторы провайдера можно указать при проверке;
  - DMARC: политика `p=`, `pct=`, адреса `rua=`, подтверждение внешнего получателя отчётов (RFC 7489, 7.1), наследование для поддомена, выравнивание `SMTP_FROM`.
- **Отчёты DMARC.**
  - Приходят из ящика IMAP (папка открывается только на чтение, курсор UID с UIDVALIDITY, магазин ничего не отправляет) или загружаются вручную.
  - Защита: файл до 5 МБ, XML до 50 МБ, ограничение степени сжатия, в zip — один файл, отказ от `DOCTYPE`/`ENTITY`, только отчёты о своём домене.
  - Один отчёт хранится один раз; отчёт, отправитель письма которого не совпадает с организацией, помечается «не подтверждён».
- **Сводка.** Писем и доля прошедших DMARC, источники писем (сначала не прошедшие), решения получателей, записи отчёта, журнал приёма.
- **Хранение.** Отчёты старше `DMARC_REPORT_RETENTION_DAYS` удаляются; администратор может удалить все отчёты с подтверждением, действие попадает в журнал.
- **Скриншоты** пересняты целиком: 62 снимка админ-панели (59 разделов) и 20 снимков кабинета.

## Обновление

Используйте [проверяемый регламент обновления](DISTRIBUTION_UPGRADE_CURRENT.md):

1. Сделайте согласованный backup базы магазина.
2. Примените миграцию `0069_mail_domain`: она создаёт `dmarc_reports`, `dmarc_records` и `dmarc_intake_state` и не меняет существующие данные.
3. Задайте переменные почтового домена (необязательно) и перезапустите backend и worker.
4. Проверьте:

   ```bash
   docker compose exec -T backend alembic current
   ```

   В разделе «Почтовый домен» нажмите «Проверить сейчас».

Откат ниже `0069` запрещён, пока сохранены отчёты: сначала удалите их в разделе. Ожидаемые head: магазин `0069_mail_domain`, Support Pro `0008`.

## Границы выпуска

Магазин не запускает собственный MX-сервер: входящую почту принимает провайдер, магазин читает из ящика только отчёты DMARC. Чтение настоящего ящика и отчёты реальных почтовых служб проверяет оператор на своём домене.

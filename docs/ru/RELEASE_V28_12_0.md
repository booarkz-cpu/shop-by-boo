# Выпуск v28.12.0 — мост Zendesk и Freshdesk в Support Pro

Дистрибутив: `v28.12.0`. Runtime/API: `21.5.1`. Head магазина: `0068_network_intel` (без новых миграций). Support Pro: `0008` / 3.8. Дата и commit фиксируются тегом выпуска.

## Что завершено

Закрыта строка матрицы «Внешние helpdesk-системы»: Support Pro 3.8 подключает Zendesk или Freshdesk. [Регламент](SUPPORT_HELPDESK_BRIDGE_CURRENT.md).

- **Клиент.** Автор внешнего обращения становится клиентом Support Pro; если его email уже известен (например, из email-канала), обращения присоединяются к существующему клиенту.
- **Импорт истории.** Worker читает изменённые обращения по курсору (Zendesk incremental export, Freshdesk `updated_since`) начиная с `HELPDESK_IMPORT_SINCE`. Каждое обращение и комментарий записываются под уникальным ключом, страница сохраняется в одной транзакции с курсором — повтор или сбой не создают дублей.
- **Входящие.** Комментарии клиента, ответы агентов и внутренние заметки попадают в историю; новое сообщение клиента открывает закрытое обращение; закрытие во внешней системе закрывает обращение; вложения проверяются антивирусом.
- **Ответы операторов.** Ответ из общей очереди доставки публикуется во внешнем обращении один раз, созданный комментарий связывается с сообщением. Потерянное подтверждение даёт состояние «результат неизвестен», а следующий импорт сверяет текст и отмечает сообщение отправленным без повтора.
- **Ошибки.** HTTP 429 ставит синхронизацию и отправку на паузу по `Retry-After`; 5xx и сбои сети повторяются без сдвига курсора; 401/403/404/422 показывают причину.
- **Вложения.** Скачиваются только по HTTPS, перенаправления обрабатываются явно; ключ API не передаётся хранилищу файлов.
- **Данные клиента.** Удаление в карточке клиента очищает текст и файлы обращений моста и оставляет метку против повторного импорта.
- **Интерфейс.** Страница «Внешний helpdesk» (состояние, пауза, ошибка, ручная синхронизация) и ссылка «Открыть во внешней системе» в обращении.

### Настройки Support Pro

Новые переменные `support-pro/.env`: `HELPDESK_PROVIDER` (`zendesk` или `freshdesk`), `ZENDESK_SUBDOMAIN`, `ZENDESK_EMAIL`, `ZENDESK_API_TOKEN`, `FRESHDESK_DOMAIN`, `FRESHDESK_API_KEY`, `HELPDESK_IMPORT_SINCE`, `HELPDESK_SYNC_SECONDS`, `HELPDESK_MAX_MB`. Без `HELPDESK_PROVIDER` мост выключен.

## Обновление

Магазин без миграций. Используйте [проверяемый регламент обновления](DISTRIBUTION_UPGRADE_CURRENT.md), затем:

1. Сделайте согласованный backup базы и uploads Support Pro.
2. Примените миграцию `0008` (`docker compose run --rm support_migrate`); она создаёт `helpdesk_state` и `helpdesk_links` и не меняет данные.
3. Чтобы подключить внешнюю систему, заполните переменные и пересоздайте `support_pro` и `support_worker`.

Откат ниже `0008` запрещён, если уже импортированы обращения Zendesk/Freshdesk. Ожидаемые head: магазин `0068_network_intel`, Support Pro `0008`.

## Проверка

- Support Pro: полный набор на SQLite и PostgreSQL, включая `support-pro/tests/test_helpdesk_bridge.py` на имитации API Zendesk и Freshdesk и roundtrip миграции `0008`.
- Магазин, сборки и браузерные сценарии — в CI.

## Границы выпуска

Работу с реальной учётной записью Zendesk или Freshdesk (права агента, лимиты тарифа, большие вложения) проверяет оператор на своём стенде. Подключается одна внешняя система одновременно.

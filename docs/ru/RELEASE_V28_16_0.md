# Выпуск v28.16.0 — глубокий анализ трафика на узлах

Дистрибутив: `v28.16.0`. Runtime/API: `21.5.1`. Head магазина: `0072_traffic_analysis`. Support Pro: `0008` / 3.8 (без изменений). Дата и commit фиксируются тегом выпуска.

## Что завершено

Закрыта строка матрицы «Глубокий анализ трафика (nDPI)». [Инструкция](TRAFFIC_ANALYSIS_CURRENT.md).

Решения владельца:

- два режима: nDPI, если установлен, иначе свой классификатор;
- клиент определяется по журналу Xray.

Что сделано:

- **Режим nDPI.** Агент запускает `ndpiReader` окнами по 30 секунд и разбирает его CSV.
- **Встроенный классификатор.** Работает через `AF_PACKET` (нужен root) по первым пакетам каждого потока. Распознаёт рукопожатие BitTorrent, DHT (KRPC), uTP SYN, HTTP- и UDP-трекеры. Даёт одно срабатывание на поток и держит до 100 000 потоков; разбирает около 200 000 пакетов/с на ядро.
- **Шифрованный BitTorrent** — эвристика обмена ключами MSE/PE. Показывается как «вероятно», не влияет на антиабуз и не уведомляет клиента.
- **Определение клиента.** Индекс «адрес назначения → клиент» строится из журнала Xray и хранится только в памяти узла 15 минут. С узла уходят только счётчики «клиент — вид — число».
- **Магазин.** Миграция `0072_traffic_analysis` добавляет к счётчикам вид срабатывания. Раздел «Торренты на узлах» показывает, как замечено каждое срабатывание.

## Обновление

1. Сделайте backup базы магазина и примените миграцию `0072_traffic_analysis`.
2. На узлах, где нужен анализ, обновите `scripts/node-agent.py` и задайте:
   - `AGENT_DPI=1`, `AGENT_DPI_IFACE`, запуск от root;
   - `AGENT_XRAY_ACCESS_LOG` для определения клиента;
   - при желании установите nDPI.

Ожидаемые head: магазин `0072_traffic_analysis`, Support Pro `0008`.

- Полный набор на SQLite и PostgreSQL, roundtrip миграции `0072`.

## Границы выпуска

- Эвристика шифрованного BitTorrent может срабатывать на другие зашифрованные протоколы, поэтому она только информирует.
- Распознавание на ваших узлах (интерфейс, права, версия nDPI) проверяет оператор.

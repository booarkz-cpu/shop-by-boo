# Выпуск v28.94.0 — MTProto-прокси для Telegram на нодах

Дистрибутив: `v28.94.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Задача владельца N7 этапа 20, продолжение. Всё — в **«Серверы → Установка» → «MTProto-прокси для Telegram»**.

## Что нового

- **MTProto-прокси на ноде** — Telegram работает и там, где его блокируют: прокси [9seconds/mtg](https://github.com/9seconds/mtg) (MIT) v2.3.0 с маскировкой FakeTLS — для цензора трафик выглядит как TLS к выбранному сайту (по умолчанию `www.cloudflare.com`).
  - Порт выбирается в карточке (по умолчанию TCP 9443); порты ноды (80, 443, 2053, 4443, 8443 и порт ноды для панели) заняты — план откажет. Порт ниже 1024 нельзя: контейнер работает без привилегий.
  - Образ закреплён по digest (`nineseconds/mtg:2@sha256:9553495b…`), контейнер — `--read-only`, `--cap-drop ALL`, `no-new-privileges`, `--restart unless-stopped`.
  - Секрет создаётся один раз на сервере (`/etc/corgi/mtproto.secret`, права 0600) и сохраняется при повторном включении; в журнал шагов он не попадает.
  - После установки в карточке — ссылка для клиентов `https://t.me/proxy?…` и кнопка «Скопировать tg://». «Выключить» удаляет контейнер, секрет и правило ufw.
  - Ссылки — `GET /api/admin/install/mtproto` (право `provision_nodes`).

## Что пока не сделано из N7 и почему

| Операция | Причина |
| --- | --- |
| geo-файлы и списки zapret на нодах | Нужно проверить путь ресурсов Xray в образе remnanode на живой ноде, иначе можно подменить встроенные файлы неверно |
| Psiphon | Сторонний клиент с закрытыми частями — нужен аудит лицензии и бинарников |
| CDN (Cloudflare) | Нужен аккаунт и токен Cloudflare владельца |
| Смена домена панели | Меняет ссылки подписок всех клиентов — нужна согласованная миграция со страницей подписки |

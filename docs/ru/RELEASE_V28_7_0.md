# Выпуск v28.7.0 — email-канал поддержки

Дистрибутив: `v28.7.0`. Runtime/API: `21.5.1`. Head магазина: `0066_push_notifications` (без изменений). Support Pro: `0007` / 3.7. Дата и commit фиксируются тегом выпуска.

## Что завершено

Email-часть строки матрицы «Внешние helpdesk/email каналы» закрыта. Адаптеры внешних helpdesk-систем остаются в [реестре завершения](MATRIX_COMPLETION_21_5_1.md). [Регламент](SUPPORT_EMAIL_CHANNEL_CURRENT.md).

### Приём писем

- Support Pro читает ящик поддержки по IMAP (только чтение) и превращает письма в обращения; клиент получает email-идентичность с уникальным адресом.
- Повтор письма и смена UIDVALIDITY не создают дублей: учитывается Message-ID, курсор сдвигается в одной транзакции с сохранением.
- Ответ присоединяется к обращению только через Message-ID наших писем или метку `[#номер]` в теме и только от того же адреса; закрытое обращение открывается снова; цитата отрезается.
- Автоответы, рассылки и собственный адрес пропускаются; возвраты отмечают ответ как недоставленный.
- Проверка DMARC принимающего сервера показывается в карточке обращения как предупреждение о возможной подделке отправителя.
- Отказ ящика не сдвигает курсор; письмо, которое трижды не удалось обработать, пропускается с записью и остаётся в ящике.

### Ответы

- Ответ оператора уходит письмом по SMTP с `In-Reply-To`/`References`, меткой обращения в теме и подписью; Message-ID сохраняется до отправки.
- Временный отказ повторяется до 5 раз, постоянный отказ и возврат показываются с причиной, оборванная отправка получает статус «Результат неизвестен».
- Вложения ответа отправляются вместе с письмом.

### Данные

- Администратор переносит историю email-клиента к существующему клиенту и удаляет email-данные клиента (тексты, вложения, адрес) с подтверждением и записью в журнал.
- `EMAIL_RETENTION_DAYS` очищает закрытые email-обращения по сроку; `EMAIL_PRIVACY_NOTICE` добавляет уведомление о приватности в ответы.
- Раздел «Email-канал» показывает состояние приёма и отправки, счётчики и последние ошибки без паролей.

### Миграция

Support Pro `0007`: `email_channel_state`, `email_links`, уникальный email-адрес клиента. Откат блокируется при наличии email-обращений. Миграций магазина нет.

## Обновление

Сделайте согласованный backup базы магазина и Support Pro. Используйте [проверяемый регламент обновления](DISTRIBUTION_UPGRADE_CURRENT.md). Чтобы включить канал, добавьте переменные `EMAIL_*` в `support-pro/.env` по [регламенту](SUPPORT_EMAIL_CHANNEL_CURRENT.md) и перезапустите `support_pro` и `support_worker`. После запуска проверьте:

```bash
docker compose exec -T backend alembic current
docker compose run --rm support_migrate
docker compose ps
curl -fsS https://API_DOMAIN/health/ready
```

Ожидаемые head: магазин `0066_push_notifications`, Support Pro `0007`.

## Проверка

- Support Pro: полный набор тестов на SQLite и PostgreSQL, включая `tests/test_email_channel.py` и roundtrip миграции `0007`.
- Магазин: полный набор Python-тестов на SQLite и PostgreSQL; браузерные сценарии админки и кабинета; сборки Android и iOS в CI.

## Границы выпуска

Автотесты используют имитацию IMAP и SMTP и не проверяют конкретный почтовый сервис, доставляемость и фильтры спама. Проверка на реальном ящике, а также внешние payment/SMTP/Remnawave E2E и production gate остаются за оператором. Полный статус — [матрица покрытия](WORKSPACE_COVERAGE.md) и [реестр завершения](MATRIX_COMPLETION_21_5_1.md).

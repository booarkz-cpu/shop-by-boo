# Новости, лендинги и юридические страницы

Раздел админки «Настройка магазина → Новости и страницы» доступен admin и operator с правом `manage_content`. Viewer не получает черновики, историю или возможность публикации. Публичные страницы доступны без входа в кабинете и Mini App; это общая реализация.

## Создание страницы

1. Нажмите «Новая страница». Выберите тип: новость, лендинг или юридическая страница.
2. Укажите slug из латинских строчных букв, цифр и дефисов (до 80 символов), язык RU/EN и заголовок. Одинаковый slug допускается для разных языков. Slug, язык и тип после создания неизменяемы: новая адресация требует новой страницы.
3. Добавьте краткое описание и блоки. Есть заглавный блок, текст, кнопка, преимущества и вопросы/ответы. В каждом блоке преимущества/FAQ можно создать до 20 элементов; страница содержит 1–30 блоков. Кнопки принимают HTTPS, относительный путь внутри магазина или `#plans`.
4. При необходимости задайте начало и конец публикации **в UTC**. Например, 12:00 Москвы — 09:00 UTC. API требует часовой пояс (`Z` или смещение). Конец должен быть позже начала.
5. Откройте «Предпросмотр». Сохраните черновик. Пока есть несохранённые изменения, публикация недоступна.
6. Нажмите «Опубликовать». Это создаёт неизменяемый снимок и отдельную запись аудита. До начала расписания страница скрыта; после конца скрывается автоматически при чтении API, без отдельного worker.

HTML и JavaScript не исполняются: редактор использует структурированные текстовые блоки и React text nodes. Вставленный `<script>` будет показан как текст. Запрещены `javascript:`, `data:`, ссылки с логином/паролем и пути `//host`. Страница ограничена 128 КиБ текстового содержимого; заголовок — 200 символов, описание — 1000, текст блока — 10000. Это редактор контента, а не загрузчик произвольных скриптов или шаблонов.

## Чтение и ссылки

В кабинете откройте «Новости и документы». Каталог содержит только действующие опубликованные версии; доступны фильтры по типу, переключение RU/EN и загрузка следующих страниц. Прямая ссылка: `https://CABINET_DOMAIN/#page/slug`; каталог — `#pages`. При переключении языка читается версия того же slug в другом языке; отсутствующая публикация возвращает 404, без подмены языка.

`CABINET_URL` должен содержать HTTPS-адрес кабинета. Тогда админка показывает кнопку «Публичная страница». Mini App использует тот же каталог и renderer. Проверяйте страницу в нужном языке и в Telegram перед рассылкой ссылки.

Публичный ответ содержит только опубликованный снимок, номер версии и время публикации. ID редактора, email автора, черновики и прежние ревизии не выдаются. Ответы API имеют `private, no-store`: изменение расписания/архива не должно задерживаться общим кэшем.

## Изменение, история и снятие

Изменение и сохранение черновика не меняет опубликованный снимок. Для вывода новых условий нужна новая публикация. «История публикаций» сохраняет снимки, время и автора; «Восстановить в черновик» копирует выбранную публикацию для редактирования и также не меняет действующую страницу. Для применения восстановленного текста опубликуйте его отдельно.

«Снять с публикации» скрывает страницу, сохраняя черновик и историю. Повторная публикация снимает архивный статус. Опубликовать уже завершившееся расписание нельзя; сначала исправьте даты. При параллельном редактировании сервер отвечает 409 на устаревшую версию. Нажмите «Загрузить актуальную версию», сравните текст и повторите изменение. Сервер не перезаписывает чужую правку молча.

Юридические условия заполняет владелец магазина под свою деятельность. Редактор хранит версии документов; он не создаёт фиктивные реквизиты и не подтверждает юридическую достаточность текста.

## Эксплуатация и API

Миграция 0059 создаёт `content_pages` и `content_revisions`. Они входят в backup магазина. При наличии любого черновика/публикации downgrade блокируется, чтобы не уничтожить документы. Восстановление выполняйте из согласованной резервной копии.

- `GET/POST /api/admin/pages` — список/создание; список имеет `offset`, `limit` до 100.
- `GET/PUT /api/admin/pages/{id}` — чтение и сохранение с текущим `version`.
- `POST /api/admin/pages/{id}/publish`, `/archive` — версия обязательна.
- `GET /api/admin/pages/{id}/revisions` — история с пагинацией.
- `POST /api/admin/pages/{id}/restore` — текущая `version` и номер `revision`.
- `GET /api/public/pages` — язык, тип и пагинация; `/api/public/pages/{slug}?locale=ru` — опубликованный снимок.

Проверки: права viewer/operator, непубличность черновика/автора, расписание, неизменность публикации, восстановление, stale version и PostgreSQL-конкуренция. Chromium проверяет создание/предпросмотр/публикацию, чтение без входа, отсутствие исполнения HTML, сохранение старого текста при изменении и снятие страницы.

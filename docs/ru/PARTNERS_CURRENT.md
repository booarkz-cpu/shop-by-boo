# Партнёры, комиссии и выплаты — v21.5.1

Миграция `0057_partner_commissions` добавляет владельца кабинета, валюту/баланс, снимки ставки заказа, фактические комиссии и резервируемые заявки. Историческая «оценочная комиссия» не превращается в выплату автоматически: старые платежи без снимков не начисляются задним числом.

## Создание и настройки

В «Безопасность → Восстановление → Партнёры и выплаты» укажите название, уникальный lowercase slug, ID существующего активного клиента и ставку 0–100% с точностью до двух знаков. Создайте партнёра. API key отображается один раз: сохраните его в защищённом месте или скройте, если не нужен.

В клиентском меню владельца откройте «Партнёрский кабинет». Здесь показаны ссылка, текущая ставка, доступный баланс, последние 100 комиссий и заявок. Партнёр не видит email/Telegram ID покупателей или их подписочные ссылки.

Оператор может менять текущую ставку, список разрешённых `plan_ids`, branding и enabled через `PATCH /api/admin/marketplace/resellers/{id}`. Пустой список планов означает все enabled fixed/linked plans. `owner_user_id` можно назначить прежнему API-only партнёру без финансовой истории; заменять существующего владельца или владельца с финансовой историей нельзя. Новый аккаунт партнёра не создаётся этим API.

## Заказы и начисления

Ссылка ведёт в кабинет с `?partner=slug`. Checkout внешнего провайдера и покупка с кошелька сохраняют `reseller_id`, slug и процент. Проверяются enabled партнёр, allowlist тарифа и запрет собственной покупки партнёром по его ссылке.

Ставка фиксируется при создании нового заказа. Последующее изменение/отключение партнёра не меняет сохранённый intent; повтор того же idempotency key восстанавливает его без новой покупки. Подмена партнёра при повторе отклоняется.

Комиссия начисляется после `fulfillment_status=completed` для подтверждённой подписки, по реально оплаченному amount, округление half-up до 0.01. Повтор не создаёт вторую строку. При подтверждённом возврате строка становится `reversed`, баланс уменьшается ровно один раз. Повтор success не восстанавливает отменённую комиссию.

Если деньги уже зарезервированы/выплачены, возврат может сделать баланс отрицательным. Это задолженность clawback, а не новая выплата. Разные валюты в одном партнёрском балансе смешивать нельзя. Подарки, пополнения, автопродление и отдельная смена тарифа не получают новой партнёрской атрибуции в этом выпуске.

## Выплата

1. Владелец указывает сумму и реквизиты, отправляет заявку. Доступный баланс уменьшается на резерв. Повтор запроса не резервирует его второй раз.
2. Оператор проверяет заявку и одобряет её.
3. Оператор выполняет внешний перевод согласованным способом.
4. В админке указывает номер фактического перевода и отмечает «Выплачено».

Автоматического банковского перевода нет. «Выплачено» без предварительного одобрения/номера операции отклоняется. Отклонение requested/approved возвращает резерв ровно один раз. Выплаченную/отклонённую заявку нельзя переписать новым решением.

Отключённый партнёр видит историю, но не создаёт новые заявки; свяжитесь с оператором. Доступны API catalog/stats/branding по Bearer reseller key, ротация ключа в административном API и customer portal через обычную сессию владельца. API `commission_credited` показывает фактические строки, `available_balance` — баланс после резервов/возвратов, а не оценку по сегодняшней ставке.

## Проверки и обновление

Удаление аккаунта владельца блокируется при ненулевом балансе (включая задолженность), pending/approved выплатах и незавершённых партнёрских покупках. Сначала завершите расчёты. При допустимом удалении партнёр отключается, API key отзывается; финансовые записи сохраняются для аудита.

CI проверяет неизменность ставки, однократное начисление/возврат, reserve/retry/reject, отрицательный clawback, изоляцию кабинета, allowlist, paid workflow и PostgreSQL races. Реальные кассы/выдача проверяются на внешнем стенде. Новая миграция не изменяет старые балансы клиента и не начисляет исторический партнёрский доход. Downgrade при комиссиях/выплатах запрещён.

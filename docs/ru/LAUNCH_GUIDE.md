# Запуск магазина в работу: полный порядок

Этот документ ведёт от пустого сервера до работающего магазина: бот, Mini App, кабинет, админка, поддержка, узлы, почта, копии и мониторинг. Шаги идут в том порядке, в котором их удобно выполнять: каждый следующий опирается на предыдущий. Подробности по каждой функции — в [инструкциях по модулям](modules/README.md).

## Сначала главное: всё запускается сразу

После установки работают все части магазина: бот, Mini App, кабинет, админка, Support Pro, тарифы, пробный период, подарки, кошелёк, выдача VPN, узлы, почта, копии и мониторинг. **Реальные платежи открыты с момента установки** — как только вы впишете боевые ключи YooKassa, Platega или RollyPay и укажете у провайдера адрес уведомлений (шаг 12). По таймеру они не закрываются.

На случай сбоя кассы или выдачи есть аварийная кнопка «Остановить приём платежей» (**Безопасность → Защита и 2FA** или **Тарифы и оплата → Проверка платежей**). По желанию платёжный контур можно полностью проверить на отдельном стенде ([staging E2E v2](STAGING_E2E_V2_IMPLEMENTATION.md)) — на приём платежей это не влияет.

## Что подготовить заранее

| Что | Зачем | Где взять |
| --- | --- | --- |
| Сервер Ubuntu 24.04 или Debian 12, от 4 vCPU / 8 ГБ RAM / 40 ГБ диска | Магазин, базы, Support Pro | Любой хостинг VDS |
| Домен и доступ к его DNS | Пять поддоменов магазина | Регистратор домена |
| Работающая панель Remnawave и хотя бы один узел | Выдача VPN-доступа | Устанавливается отдельно от магазина (документация Remnawave) |
| Telegram-бот | Бот и Mini App | @BotFather |
| Ваш Telegram ID | Команда `/ops`, привязка администратора | @userinfobot |
| SMTP-ящик для отправки | Подтверждение email, восстановление пароля, ответы поддержки | Почтовый провайдер |
| Аккаунт платёжной системы: YooKassa, Platega или RollyPay | Приём оплаты | Личный кабинет провайдера |
| S3-совместимое хранилище (необязательно) | Копии вне сервера | Любой S3 / R2 / B2 |
| Firebase и Apple Developer (необязательно) | Push и мобильные приложения | Firebase Console, Apple Developer |

Держите staging и production раздельно: разные серверы, базы, токены Remnawave и ключи касс.

## Шаг 1. Remnawave и узлы

Магазин не устанавливает Remnawave и не создаёт VPN-узлы — он управляет пользователями уже работающей панели.

1. Установите панель Remnawave и подключите узлы по документации Remnawave. Проверьте, что тестовый пользователь, созданный в панели вручную, подключается.
2. В панели создайте **Internal Squads** — группы инбаундов, к которым получает доступ подписка. Например: «Стандарт» (все обычные узлы) и «Премиум» (плюс быстрые узлы). Каждый тариф магазина будет ссылаться на один squad.
3. Создайте API-токен: **Settings → API Tokens → Create**. Сохраните URL панели и токен — они понадобятся установщику.
4. Убедитесь, что панель доступна с будущего сервера магазина по HTTPS.

## Шаг 2. DNS

Создайте A-записи на IP сервера магазина (пример для домена `vpn.example.com`):

| Запись | Назначение |
| --- | --- |
| `api.vpn.example.com` | API, вебхуки платёжных систем, OAuth |
| `admin.vpn.example.com` | Админ-панель |
| `cabinet.vpn.example.com` | Личный кабинет |
| `app.vpn.example.com` | Telegram Mini App |
| `support.vpn.example.com` | Support Pro |

AAAA добавляйте, только если IPv6 на сервере действительно работает. Если планируете собственный приём почты, позже добавите ещё `mx.vpn.example.com` и MX-запись (шаг 11). Проверка: `dig +short api.vpn.example.com` с вашего компьютера показывает IP сервера.

## Шаг 3. Установка

Подключитесь к серверу по SSH (в Termius — новый Host с IP, пользователем root и SSH-ключом):

```bash
ssh -t root@SERVER_IP
```

Выполните одну команду установки:

```bash
curl -fsSL https://raw.githubusercontent.com/booarkz-cpu/shop-by-boo/v28.36.0/install.sh -o /root/shop-install.sh && BRANCH=v28.36.0 bash /root/shop-install.sh
```

Установщик ставит Docker, клонирует точный тег, задаёт вопросы, создаёт `.env`, собирает и запускает все сервисы, включает firewall (открыты только SSH, 80/443 TCP и 443 UDP). Рабочий каталог — `/opt/vpn-shop`.

Что отвечать на вопросы:

| Вопрос | Что ввести |
| --- | --- |
| Основной домен | `vpn.example.com`; поддомены предлагаются автоматически, Enter — принять |
| Email и пароль администратора | Ваш вход в админку; Enter на пароле — сгенерировать и показать в конце |
| `BOT_TOKEN` | Токен от @BotFather (ввод скрыт) |
| Remnawave URL и token | Из шага 1 |
| Провайдер оплаты | `none`, если ключей пока нет; подключите позже (шаг 12) |
| Имя бота без @, ваш Telegram ID | Из @BotFather и @userinfobot |
| Язык, валюта, часовой пояс | `ru`, `RUB`, `Europe/Moscow` — или свои |
| Email для TLS-сертификата | Любой рабочий адрес |
| SMTP host / port / user / password / From | Данные почтового провайдера; Enter — пропустить и настроить позже (шаг 11) |
| Цены 1/3/6/12 месяцев | Справочные значения; тарифы создаются в админке (шаг 7) |
| Автопродление, обязательный канал, процент рефералов, срок предупреждения | Можно оставить по умолчанию и поменять позже |
| Yandex / VK OAuth | Enter — пропустить; подключение — шаг 9 |
| Песочница платежей | `false`. На production `true` запрещено, сервер не стартует |
| S3 | Enter — пропустить; настроить можно позже в админке |

В конце установщик печатает адреса, пароль администратора магазина, логин `admin` и пароль Support Pro. **Сохраните их в менеджере паролей.** Все секреты лежат в `/opt/vpn-shop/.env` и `/opt/vpn-shop/support-pro/.env` (права 600). Скопируйте эти файлы в надёжное место вне сервера: без `APP_SECRET` не расшифровать сохранённые секреты.

## Шаг 4. Проверка после установки

```bash
cd /opt/vpn-shop
docker compose ps
bash scripts/doctor.sh
docker compose exec -T backend alembic current
curl -fsS https://api.vpn.example.com/health/ready
```

Ожидается:

- все постоянные сервисы в состоянии `running`. Одноразовые `volume_init` и `support_migrate` завершаются с кодом 0;
- head миграций `0079_acquisition`;
- `health/ready` отвечает `200`.

Откройте все пять адресов в браузере: везде должен быть HTTPS без предупреждений. Если сертификат не выдан — проверьте A-записи и открытость портов 80/443 у хостера, затем `docker compose logs --tail=100 caddy`.

## Шаг 5. Первый вход и защита админки

1. Откройте `https://admin.vpn.example.com`, войдите email и паролем из установки.
2. **Безопасность → Защита и 2FA**: включите двухфакторный вход, отсканируйте QR, сохраните коды восстановления офлайн.
3. **Безопасность → Ключи доступа** (необязательно): зарегистрируйте passkey. Перед этим включите функцию `passkeys` в **Система → Функции и модули**.
4. **Безопасность → Роли и администраторы**: заведите отдельные учётные записи. Права ролей:
   - «Наблюдатель» — только просмотр;
   - «Оператор» — тарифы, клиенты, поддержка, маркетинг;
   - «Администратор» — всё, включая безопасность, копии, импорт и терминал.
   Не работайте всей командой под одним входом: журнал действий записывает, кто что сделал.
5. **Система → Диагностика**: нажмите «Проверить снова» и исправьте всё, что отмечено красным.

[Модуль «Безопасность панели»](modules/28-admin-security.md).

## Шаг 6. Оформление и тексты

1. **Бот и кабинет → Оформление**: название магазина, логотип, favicon, тема по умолчанию.
2. **Бот и кабинет → Меню бота и Mini App**:
   - название бота, картинка для `/start`;
   - кнопки главного меню;
   - экран Mini App: заголовок, фон, инструкция.
3. **Бот и кабинет → Дерево кнопок**: вложенные меню бота, если они нужны.
4. **Маркетинг → Новости и страницы**: опубликуйте правила сервиса, оферту, политику конфиденциальности и инструкцию по подключению. Правила понадобятся для пункта о торрентах и для платёжных систем.
5. **Бот и кабинет → Личный кабинет**: порядок вкладок и тексты подключения для Android, iOS, ПК и TV.

[Бот и Mini App](modules/14-bot-miniapp.md) · [Кабинет](modules/15-cabinet.md) · [Оформление](modules/17-branding.md) · [Страницы](modules/13-content-pages.md).

## Шаг 7. Тарифы

1. **Тарифы и оплата → Тарифы**. Для каждого тарифа задайте:
   - название и цену;
   - срок: 1, 3, 6, 12 месяцев или свой;
   - трафик: 0 — без ограничения;
   - число устройств;
   - **профиль Remnawave (Internal Squad)** из шага 1. Список подтягивается из панели. Без профиля клиент получит подписку без серверов — раздел подсвечивает такие тарифы.
2. При желании настройте **Конструктор тарифов** (клиент сам выбирает устройства, трафик и срок) и **Пакеты трафика** (докупка гигабайт).
3. Пробный период: клиент выбирает тариф и получает его на `TRIAL_MAX_DAYS` дней (по умолчанию 3, не больше 30), один раз на аккаунт.
4. Проверьте тарифы в кабинете и Mini App: цены, сроки и описания должны совпадать.

[Модуль «Тарифы и подписки»](modules/06-plans.md).

## Шаг 8. Бот и Mini App в Telegram

В @BotFather:

1. `/mybots` → ваш бот → **Bot Settings → Menu Button** → URL `https://app.vpn.example.com`, текст кнопки, например «Открыть магазин».
2. **Bot Settings → Configure Mini App** → тот же URL (чтобы Mini App открывался и по ссылке `t.me/имя_бота/app`).
3. `/setcommands` — список команд:

```text
start - Главное меню
buy - Тарифы
subscription - Моя подписка
account - Мой кабинет
balance - Кошелёк
payments - Платежи
gifts - Подарки
referral - Реферальная программа
devices - Устройства
support - Поддержка
promo - Промокод
surveys - Опросы
```

4. Напишите боту `/start` со своего аккаунта: должно прийти приветствие с кнопкой Mini App. Откройте Mini App: вход проходит автоматически по данным Telegram.
5. Команда `/ops` отвечает только владельцу из `ADMIN_TELEGRAM_ID` и показывает сводку нарушений и агентов.

Бот работает через long polling: вебхук Telegram не нужен, бот сам снимает старый вебхук при запуске.

## Шаг 9. Личный кабинет и входы

Кабинет `https://cabinet.vpn.example.com` поддерживает несколько способов входа:

- **email и пароль** — нужен SMTP для подтверждения и восстановления (шаг 11);
- **Telegram** — через Mini App;
- **Yandex ID и VK ID** — по желанию:
  - зарегистрируйте приложение у провайдера с redirect URI `https://api.vpn.example.com/api/auth/yandex/callback` или `https://api.vpn.example.com/api/auth/vk/callback`;
  - впишите `YANDEX_*` / `VK_*` в `.env`;
  - выполните `docker compose up -d --force-recreate backend`;
- **ключ доступа (passkey)** — `CUSTOMER_WEBAUTHN_ORIGIN` уже задан установщиком, остаётся включить функцию `passkeys`.

Зарегистрируйте тестового клиента, получите пробный период и подключитесь к VPN по ссылке подписки из кабинета. Убедитесь, что пользователь появился в Remnawave с правильным сроком, лимитами и squad.

[Модуль «Личный кабинет»](modules/15-cabinet.md) · [Клиенты](modules/03-customers.md).

## Шаг 10. Поддержка

Support Pro установлен вместе с магазином и связан с ним мостом (секреты `SUPPORT_BRIDGE_TOKEN` и SSO созданы установщиком).

1. Откройте **Пользователи → Support Pro** → «Открыть Support Pro» (вход по SSO) или войдите напрямую на `https://support.vpn.example.com` логином `admin`.
2. Создайте операторов и команды, настройте рабочие часы и SLA.
3. Создайте обращение из кабинета тестового клиента и ответьте из Support Pro: ответ должен прийти в кабинет.
4. По желанию подключите email-канал (IMAP или собственный приём почты) и Zendesk/Freshdesk.

[Модуль «Поддержка»](modules/05-support.md).

## Шаг 11. Почта

1. **Отправка.** Если SMTP не задан при установке, впишите в `.env` `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` и выполните `docker compose up -d --force-recreate backend worker`. Проверьте подтверждение email тестового клиента.
2. **Домен.** Опубликуйте записи SPF, DKIM и DMARC по инструкции своего SMTP-провайдера. Проверьте их в **Система → Почтовый домен: SPF, DKIM, DMARC** → «Проверить домен».
3. **Отчёты DMARC.** Укажите в записи DMARC `rua=mailto:...`. Отчёты можно читать из ящика по IMAP (`DMARC_IMAP_*`) или загружать вручную.
4. **Собственный приём почты** (необязательно): магазин сам принимает письма на служебные адреса, например `dmarc@` и `support@`, без ящика у провайдера. Для этого нужны:
   - открытый входящий порт 25;
   - A- и MX-записи;
   - сертификат;
   - запуск `docker compose --profile mail up -d mail_receiver`.

[Модуль «Почта»](modules/26-mail.md).

## Шаг 12. Платежи

1. Впишите боевые ключи провайдера в `.env` (`YOOKASSA_*`, `PLATEGA_*`, `ROLLYPAY_*`) или в **Система → Настройки без перезапуска**. Для YooKassa обязателен `YOOKASSA_WEBHOOK_IP_ALLOWLIST` (адреса уведомлений YooKassa из её документации).
2. В личном кабинете провайдера укажите адрес уведомлений:
   - `https://api.vpn.example.com/api/webhooks/yookassa`;
   - `https://api.vpn.example.com/api/webhooks/platega`;
   - `https://api.vpn.example.com/api/webhooks/rollypay`.
   Для YooKassa включите события `payment.succeeded`, `payment.canceled` и `refund.succeeded` — последнее нужно, чтобы магазин узнавал о возвратах, сделанных в кабинете YooKassa.
3. При правке `.env`: `docker compose up -d --force-recreate backend worker`.
4. **Тарифы и оплата → Платёжные агенты**: агент «Включён», порядок провайдеров.
5. По желанию: **Тарифы и оплата → Проверка платежей → Проверка ключей песочницы (v1)** — быстрая проверка тестовых ключей, создания платежа и возврата у провайдера.

**Реальные платежи открыты сразу.** Как только заданы боевые ключи и адрес уведомлений, клиенты могут платить. Перед объявлением запуска сделайте одну покупку своей картой и верните её через **Тарифы и оплата → Возвраты**: так вы проверите оплату, уведомление, выдачу VPN и возврат на своих кассах.

Если касса или выдача сбоит, нажмите **«Остановить приём платежей»** (**Безопасность → Защита и 2FA** или **Проверка платежей**). Клиенты увидят «Приём платежей временно остановлен», уже оплаченные подписки продолжат работать. После исправления — «Открыть реальные платежи».

По желанию: полная автоматическая проверка на отдельном стенде — [staging E2E v2](STAGING_E2E_V2_IMPLEMENTATION.md).

[Модуль «Платежи»](modules/07-payments.md).

## Шаг 13. Узлы и защита от злоупотреблений

1. **Серверы → Серверы**: узлы Remnawave видны со статусом и нагрузкой.
2. **Серверы → Антиабуз и агенты** → «Создать агента»: имя узла, токен показывается один раз. На каждом узле запустите `scripts/node-agent.py` с `SHOP_API_BASE` и `AGENT_TOKEN`. Агент отправляет метрики узла и наблюдения подключений.
3. Настройте политику антиабуза (пороги, анализаторы, чёрный список HWID). Сначала только наблюдайте: CGNAT и мобильные сети дают ложные сигналы.
4. По желанию:
   - [торренты](modules/20-torrents-traffic-analysis.md) — `AGENT_XRAY_ACCESS_LOG`, `AGENT_DPI`;
   - [терминал узлов](modules/21-node-terminal.md) — `TERMINAL_ENABLED`, `AGENT_TERMINAL`;
   - [сетевая аналитика](modules/22-network-intel.md).

[Узлы и маршрутизация](modules/18-nodes-routing.md) · [Агенты и антиабуз](modules/19-node-agent-antiabuse.md).

## Шаг 14. Резервные копии

1. **Безопасность → Резервные копии**: расписание (6, 12 или 24 часа), сколько копий хранить, пароль шифрования, S3 для внешнего хранения → «Сохранить» → «Создать сейчас» → «Проверить».
2. Согласованная копия обеих баз (магазин и Support Pro) с файлами и окружением делается командой `bash scripts/backup.sh`. Обязательно выполняйте её перед каждым обновлением.
3. Один раз проведите **пробное восстановление** на отдельном сервере. Копия, которую ни разу не восстанавливали, не считается проверенной.

[Модуль «Резервные копии и восстановление»](modules/30-backups-recovery.md).

## Шаг 15. Мониторинг и оповещения

1. **Оповещения в Telegram:** `ALERT_TELEGRAM_CHAT_ID` — ID чата, куда бот присылает алерты (бот должен быть в этом чате).
2. **Prometheus и Grafana:** `METRICS_TOKEN` создан установщиком. Подключите `/metrics` к своему Prometheus по примеру `deploy/prometheus/`, импортируйте дашборд `deploy/grafana/vpnshop-operations.json`.
3. Ежедневно смотрите **Аналитика → Состояние системы** и **Система → Фоновые процессы**: worker должен быть онлайн, очередь не должна стоять.

[Модуль «Состояние, инциденты и мониторинг»](modules/02-health-incidents-monitoring.md).

## Шаг 16. Мобильные приложения и push (необязательно)

Исходники Android и iOS в репозитории. Для публикации нужны:

- сборка с URL вашего API;
- подпись своими ключами;
- загрузка в **Бот и кабинет → Android и iOS** или в сторы.

Push-уведомлениям нужны ключи FCM и APNs в `.env`. Ключи доступа в приложениях требуют `ANDROID_USER_CERT_SHA256` и `IOS_USER_APP_ID`.

## Шаг 17. Приёмка перед открытием

Пройдите чек-лист на тестовом аккаунте:

- [ ] Все пять доменов открываются по HTTPS, `/health/ready` — 200, `doctor.sh` без ошибок.
- [ ] 2FA администратора включена, учётные записи команды созданы, коды восстановления сохранены офлайн.
- [ ] `/start` в боте, открытие Mini App, вход в кабинет по email, Telegram (и OAuth, если включали).
- [ ] Письмо подтверждения email и восстановления пароля приходит во «Входящие», не в «Спам».
- [ ] Пробный период выдаётся, пользователь появляется в Remnawave с нужным squad, VPN подключается.
- [ ] Подарочный код активируется и продлевает подписку; бонус кошелька начисляется и списывается.
- [ ] Обращение из кабинета видно в Support Pro, ответ приходит клиенту.
- [ ] Агент узла в сети (heartbeat не старше 5 минут).
- [ ] Резервная копия создана и проверена; пробное восстановление выполнено на отдельном сервере.
- [ ] Prometheus видит `up{job="vpnshop"}=1`, тестовый алерт доходит.
- [ ] Правила, оферта и политика конфиденциальности опубликованы.
- [ ] Одна настоящая покупка своей картой прошла: оплата, уведомление, выдача VPN; возврат через **Возвраты** выполнен.

## Если что-то пошло не так

| Симптом | Где смотреть |
| --- | --- |
| Сайт не открывается или ошибка сертификата | A-записи, порты 80/443 у хостера, `docker compose logs caddy` |
| `health/ready` не 200 | `docker compose ps`, `docker compose logs --tail=200 backend`, `bash scripts/doctor.sh` |
| Бот молчит | `BOT_TOKEN`, `docker compose logs --tail=100 bot`; бот не должен работать ещё где-то с тем же токеном |
| Mini App пишет об ошибке входа | Menu Button ведёт на `MINI_APP_URL`; открывайте из Telegram, а не из браузера |
| Подписка выдана, но VPN не подключается | Профиль Remnawave у тарифа, squad содержит инбаунды, узел онлайн |
| Письма не приходят | SMTP в `.env`, **Система → Почтовый домен**, журнал очереди |
| «Оплата недоступна» / «Приём платежей временно остановлен» | Не заданы ключи провайдера, агент выключен, включён технический режим или приём остановлен кнопкой (шаг 12) |

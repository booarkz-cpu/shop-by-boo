# Защита приложений: привязка сертификата, Play Integrity и DeviceCheck

Актуально для клиентских приложений 3.2.0 (дистрибутив v28.37.0). Обе защиты по умолчанию выключены и включаются ключами владельца.

## Привязка сертификата (certificate pinning)

Приложение соединяется с вашим магазином, только если сервер предъявил заранее известный ключ. Подмена сертификата (прокси, перехват трафика) тогда не сработает. Пины проверяются только для адреса, вшитого в сборку (`corgi.shop_url` / `CORGI_SHOP_URL`), до отправки тела запроса и токена сессии.

1. Получите пин ключа сервера и ключа удостоверяющего центра:
   ```bash
   openssl s_client -connect api.example.com:443 -servername api.example.com </dev/null 2>/dev/null \
     | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64
   ```
   Для удостоверяющего центра (например, ISRG Root X1 у Let's Encrypt) сделайте то же для его сертификата.
2. Соберите приложения с пинами (через запятую). Указывайте минимум два: ключ сервера и ключ удостоверяющего центра, иначе после продления сертификата приложение перестанет входить.
   - Android: `-Pcorgi.pins=PIN1,PIN2` или `CORGI_PINS=PIN1,PIN2` (нужен и `corgi.shop_url`).
   - iOS: настройка сборки `CORGI_PINS=PIN1,PIN2` (нужен и `CORGI_SHOP_URL`).
3. Let's Encrypt меняет ключ сервера при каждом продлении, если certbot запущен без `--reuse-key`. Пиньте корневой ключ удостоверяющего центра или продлевайте сертификат с `--reuse-key`.

## Проверка подлинности приложения при входе

Переменная `MOBILE_INTEGRITY_MODE` в `.env`:

| Значение | Что происходит |
| --- | --- |
| `off` (по умолчанию) | Проверки нет. |
| `report` | Приложение присылает подтверждение. Ответ проверяется, отказы только пишутся в журнал сервера. Начните с этого режима. |
| `enforce` | Вход в клиентские приложения без успешной проверки отклоняется (HTTP 403). Админские приложения не проверяются: у них пароль и MFA. |

Проверка выполняется при обмене кода на сессию (`POST /api/auth/mobile/token`). Через этот обмен проходят все способы входа: пароль, ключ доступа, ссылка из бота, Telegram, Яндекс, VK и Google.

**Android — Play Integrity.** Приложение получает от Google Play токен, привязанный к одноразовому значению сервера (`POST /api/mobile/integrity/challenge`). Магазин расшифровывает токен через Google и проверяет:
- имя пакета (`ANDROID_USER_PACKAGE`) и одноразовое значение;
- что приложение установлено из Google Play и подписано вашим сертификатом (`ANDROID_USER_CERT_SHA256`, SHA-256 из Play Console → App integrity);
- что устройство проходит проверку целостности.

Нужны:
- `GOOGLE_SERVICE_ACCOUNT_JSON` — тот же сервисный аккаунт, что для покупок, с доступом к Play Integrity API;
- Play Integrity API, включённый в Play Console для приложения.

**iOS — DeviceCheck.** Приложение отправляет токен `DCDevice`, магазин проверяет его у Apple. Нужны ключ с возможностью DeviceCheck из Apple Developer (`DEVICECHECK_KEY_ID`, `DEVICECHECK_PRIVATE_KEY` — содержимое .p8) и `APNS_TEAM_ID`. Для разработки `APNS_ENVIRONMENT=sandbox` переключает проверку на тестовый сервер Apple.

Сборки не из стора (APK с сайта, RuStore) Play Integrity не проходят. Если вы раздаёте APK вне Google Play, оставьте `report` или `off`.

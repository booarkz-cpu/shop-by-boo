# Проверка выпуска и готовность к production

Текущий выпуск **v21.5.1 stable** фиксирует проверенное ядро. Полная готовность магазина к production не подтверждена; отдельный внешний стенд с сервисами владельца не проверен. CI и локальные тесты проверяют исходники, PostgreSQL, сборки и регрессии; они не подтверждают реальные платежи, SMTP, VPN-подключение или подписанные APK/IPA.

## Что ещё нужно завершить

Точный список находится в [матрице покрытия](WORKSPACE_COVERAGE.md), а проверяемые условия закрытия — в [реестре v21.5.1](MATRIX_COMPLETION_21_5_1.md). Многоуровневые рефералы, партнёрский кабинет/комиссии, клиентские browser passkeys, редакторы публикаций, персональные предложения и магазинный merge/split реализованы ранее; в v21.4.0 добавлено дерево кнопок, в v21.5.0 — пересопоставление магазинной истории Support Pro. Среди незавершённых областей: merge аккаунтов и native passkeys, самостоятельные email-каналы поддержки и mapping произвольных внешних helpdesk, полный исторический VPN/платёжный импорт, операторские инструменты, plugin runtime, native push/виджеты. Перевод версии из alpha в stable эти функции не добавит.

Платёжный application E2E v2 также не реализован полностью: прямой вызов адаптера не доказывает сквозной заказ, callback, выдачу, возврат и последующее восстановление. Production gate сохраняется закрытым; не редактируйте его evidence вручную и не подменяйте результаты внешней проверки unit-тестами.

## Локальный изолированный магазин

Нужны Git, Python 3, Docker Engine и Compose. На Windows используйте WSL2/Docker Desktop; на VDS — Linux с установленным Docker. Скрипт не арендует сервер и не подключает реальные кассы.

```bash
git clone --branch v27 https://github.com/booarkz-cpu/shop-by-boo.git
cd shop-by-boo
bash scripts/test-up.sh
```

Скрипт создаёт отдельный `.env.test` с уникальными паролями и запускает `docker-compose.test.yml`. Контейнеры и volumes тестового контура отделены от обычного Compose. Не переиспользуйте production `.env` или дамп с персональными данными. Порты тестового контура привязаны к loopback: 18080 — API, 18081 — админка, 18082 — кабинет, 18083 — Mini App. Проверяйте фактические адреса в выводе скрипта; не открывайте эти порты в интернет.

Управление:

```bash
docker compose --env-file .env.test -f docker-compose.test.yml ps
docker compose --env-file .env.test -f docker-compose.test.yml logs --tail=80 backend worker
docker compose --env-file .env.test -f docker-compose.test.yml down
```

`down` сохраняет volumes. Не добавляйте `-v`, если нужна тестовая история.

## SSH и Termius

Подключитесь к отдельному VDS и выполните те же команды. Для просмотра loopback-портов настройте в Termius Local Port Forwarding: локальный порт 18082 → `127.0.0.1:18082` сервера и 18081 → `127.0.0.1:18081`. Затем открывайте `http://127.0.0.1:18082` и `http://127.0.0.1:18081` на своём устройстве.

При командной строке вместо Termius:

```bash
ssh -L 18080:127.0.0.1:18080 -L 18081:127.0.0.1:18081 -L 18082:127.0.0.1:18082 -L 18083:127.0.0.1:18083 root@SERVER_IP
```

Пока SSH открыт, браузер обращается к серверу через туннель. Замените `SERVER_IP`; секреты в команду не вставляйте. Сам тестовый стек не поддерживает публичные callbacks касс — он проверяет sandbox/local VPN, а не реальные сервисы.

## Проверка новых сценариев

1. Создайте email-аккаунт и войдите; настройка SMTP проверяется отдельно через публичный HTTPS кабинет на стенде.
2. Проверьте фиксированный тариф и конструктор, кошелёк, несколько подписок, выбор профиля и неизменность привязки заказа.
3. Прервите ответ при покупке и повторите тот же idempotency key; сравните баланс/журнал.
4. Проверьте смену тарифа/трафика и задержанную выдачу другого оплаченного заказа: ожидание не должно расходовать попытки provisioning.
5. Проверьте выбранные условия конструктора в автопродлении. Неизвестные исторические условия не должны становиться ценой/сроком текущего плана.
6. Проверьте поддержку, приватность файлов, повтор отправки, устаревшее закрытие и импорт истории по [инструкции моста](WORKSPACE_SUPPORT_BRIDGE.md).
7. Проверьте восстановление/смену пароля и email по [руководству](WORKSPACE_ACCOUNT_SECURITY.md).
8. Проверьте конкурсы и колесо: условия/бюджет до публикации, один результат при повторе, лимит, розыгрыш после окончания и приватность чужих участий.
9. Проверьте удаление доступного к удалению тестового аккаунта: сессии и ссылки недействительны, персональные поля очищены.

## Условия допуска полного магазина к production

Завершить все обязательные функции в матрице, проверить миграции и backup/restore, провести визуальную проверку кабинета/админки и native-интерфейсов. Поднять отдельный HTTPS стенд с тестовыми доступами YooKassa/RollyPay/Platega, Remnawave и SMTP. Выполнить настоящий application E2E v2 и подтвердить evidence штатным механизмом. Для мобильного распространения собрать, подписать и проверить APK/IPA с собственными ключами владельца.

Релиз публикуется из точного проверенного commit; архив, SHA256 и манифест сверяются после загрузки. В v21.5.1 stable `production_ready=false`, `full_function_transfer=false`, `production_e2e_verified=false`, `signed=false`. Это фактические ограничения текущего выпуска, а не настройки, которые следует просто переключить.

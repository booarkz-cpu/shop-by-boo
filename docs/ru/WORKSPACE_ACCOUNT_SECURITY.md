> Актуальный дистрибутив: `v28.17.0`; runtime/API: `21.5.1`. Точные границы готовности указаны в текущей матрице покрытия.

# Пароль и подтверждение email

Инструкция для **v21.5.1**, текущая миграция магазина `0072_traffic_analysis`. Формы общие для кабинета и Mini App. Вход Telegram/Яндекс/VK сохраняется; восстановление через письмо относится только к аккаунтам, которым уже назначен email-пароль. Оно не создаёт пароль у OAuth-only аккаунта и не выполняет объединение без отдельного подтверждённого workflow.

## Настройка администратором

В серверном `.env` задайте `CABINET_URL=https://cabinet.example.com`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`; при необходимости `SMTP_USER` и `SMTP_PASSWORD`. `CABINET_URL` должен быть HTTPS адресом кабинета без credentials, query или fragment. Если он пуст, используется `MINI_APP_URL`. Отправитель должен быть разрешён вашим SMTP-сервисом. Порт 465 использует SMTP SSL; остальные порты — STARTTLS с проверкой сертификата. Соединения без TLS не поддерживаются.

После резервного копирования примените миграции и пересоздайте backend/worker:

```bash
cd /opt/vpn-shop
docker compose stop backend worker
docker compose build backend worker cabinet miniapp
docker compose run --rm backend alembic upgrade head
docker compose up -d backend worker cabinet miniapp
```

Для v28.17.0 в head должно быть `0072_traffic_analysis` (включает `0050_account_actions`); Support Pro обновляется до `0008` (email-канал). Не добавляйте `.env` в репозиторий. Секреты вводите в файл с правами 0600, а не в команды, сохраняемые в history. Письма отправляет worker, либо scheduler совмещённого backend при соответствующей роли. Запущенный API без worker не гарантирует отправку очереди.

## Восстановить забытый пароль

1. На странице входа выберите «Забыли пароль?».
2. Введите email регистрации и нажмите «Отправить письмо».
3. Ответ одинаковый для неизвестной почты и аккаунта с паролем: он не раскрывает наличие пользователя. Повтор одного назначения за две минуты не создаёт ещё одно письмо.
4. Откройте письмо, проверьте домен кабинета, введите новый пароль и повторите его.
5. Нажмите «Изменить пароль». Ссылка действует 30 минут и используется один раз.
6. Войдите с новым паролем. Старые веб/native-сессии и неиспользованные auth exchange codes отозваны; подписки, баланс и история покупок сохраняются.

Токен передаётся во fragment ссылки, сохраняется в памяти формы и удаляется из адресной строки при открытии интерфейса. Подтверждение выполняется только после нажатия кнопки. Не пересылайте письмо и не публикуйте полный URL. Потеря ответа после успешной смены не делает ссылку повторно действующей: попробуйте вход с новым паролем либо запросите новое письмо.

## Сменить известный пароль

Откройте «Безопасность» → «Почта и пароль». Введите текущий пароль, новый пароль и подтверждение. После успешной смены войдите заново на всех устройствах. OAuth-only аккаунтам эта форма не показывается. Новый пароль содержит от 8 до 128 символов.

## Подтвердить email

Откройте «Безопасность», проверьте адрес и нажмите «Подтвердить email». Откройте ссылку и подтвердите действие кнопкой. Ссылка действует 24 часа и используется один раз. Подтверждение не меняет пароль и не создаёт сессию. Смена адреса, обезличивание аккаунта или истечение срока делают прежнюю ссылку недействительной.

Для совместимости существующий email-вход не блокируется только из-за отсутствия отметки подтверждения. Отметка не является механизмом объединения аккаунтов. Для merge используется отдельный двухсторонний workflow с preview и повторной проверкой каждого владельца: [полная инструкция](ACCOUNT_MERGE_CURRENT.md). После объединения все сохранённые email принимают пароль основного аккаунта; смена или восстановление этого пароля синхронно обновляет email aliases.

## Как обрабатываются ошибки

- «SMTP недоступен»: проверьте настройки отправителя, HTTPS URL кабинета и наличие worker. При отсутствии настроек запрос завершается 503, сообщение не ставится в очередь.
- Письма нет: проверьте «Спам», права отправителя у SMTP-провайдера, его журналы, DNS отправки и доступность порта. Наличие очереди не подтверждает получение письма человеком.
- Ошибка SMTP: до восьми попыток, задержка увеличивается до часа. В error сохраняется только тип исключения, без пароля, текста письма или токена. При повторе отправляется тот же одноразовый URL. Сбой после принятия SMTP может привести к повтору одинакового письма, но не к второму использованию ссылки.
- «Ссылка недействительна»: запросите новую. Параллельное подтверждение одной ссылки на PostgreSQL успешно только один раз. Проверяются email, состояние аккаунта и отпечаток прежнего пароля.
- HTTP 429: выдержите паузу. Публичные операции имеют отдельные лимиты на IP; обход лимита сменой устройства не предусмотрен.

В базе хранится SHA256 токена; секрет для отправки временно зашифрован APP_SECRET в `account_mail`. После отправки/отмены/окончательной ошибки ciphertext очищается. Истёкшие действия и соответствующие письма удаляются scheduler спустя семь дней. Backup базы и APP_SECRET даёт возможность расшифровки ещё не отправленных ссылок: храните резервные копии приватно.

При обезличивании аккаунта email, пароль, VK ID, отметка подтверждения и одноразовые действия удаляются, сессии отзываются. Связанные финансовые записи сохраняются по существующему регламенту. Удаление уже отправленного письма из внешнего ящика этим процессом не выполняется.

## Проверка на стенде

Проверьте реальный SMTP с собственной тестовой почтой: запрос восстановления → письмо → смена → вход; повтор ссылки; подтверждение email; отзыв старой сессии. Автоматические тесты проверяют маршруты/хранилище, повторы и конкурентность. Они используют тестовый отправитель и не являются подтверждением доставляемости вашего SMTP.

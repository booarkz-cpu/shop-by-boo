# Выпуск v28.39.0 — кассы Pal24 и Mulen Pay

Дистрибутив: `v28.39.0`. Runtime/API: `21.5.1`. Head магазина: `0081_subscription_proxy` (новых миграций нет). Support Pro: `0008` / 3.8. Мобильные приложения: 3.4.0. Дата и commit фиксируются тегом выпуска.

## Что изменилось

**Кассы Pal24 (PayPalych) и Mulen Pay** — «Платёжные агенты»

- Карта и СБП через Pal24 и Mulen Pay. Кассы встают в очередь касс и в выбор способа оплаты, как только заданы ключи: «Система → Настройки без перезапуска» (секреты хранятся зашифрованно) или `.env`.
- Уведомления проверяются по подписи: Pal24 — `SignatureValue` (MD5), Mulen Pay — `sign` (SHA-1). Подписка выдаётся только после повторной проверки платежа в API кассы: статус, номер заказа и сумма.
- Повторное уведомление не выдаёт подписку второй раз; сверка платежей и восстановление зависших оплат знают обе кассы.
- В кабинете, Mini App, веб- и мобильных админках кассы показываются по имени. В сверке платежей можно задать их комиссию.
- Реестр настроек: 207 полей, 115 live (+6 ключей касс).

Подробно — [billing_and_taxes.md](../modules/billing_and_taxes.md#pal24-и-mulen-pay-v2839), что сделать владельцу — [OWNER_ACTIONS.md](OWNER_ACTIONS.md).

## Проверки

- `tests/test_payments_pal24_mulenpay.py`: страница оплаты, подписи запросов и уведомлений, повторная проверка платежа, отказ при неверной подписи, пропуск неоплаченных статусов — на моках API касс.
- Боевая проверка — на договоре и ключах владельца: пробная оплата на минимальную сумму и возврат в кабинете кассы.

## Не вошло

- Векторная карта стран для «Географии клиентов»: среда сборки не получает внешние геоданные, раздел остаётся таблицей.
- Antilopay, Aurapay, Cashera, Tribute, WATA, Anore — следующими выпусками.

# Виджет Android и профили админ-приложений

## Виджет подписки на рабочем столе Android

Покупательское Android-приложение Corgi добавляет виджет «VPN Shop» (3×2 ячейки, размер меняется). На нём:

- название тарифа;
- состояние подписки: «Активна · N дн.», «Скоро истечёт» (3 дня и меньше), «Отмена запланирована», «Истекла», «Нет подписки»;
- дата окончания;
- остаток трафика с полосой («Осталось 70 GB из 100 GB») или «Безлимитный трафик»;
- число непрочитанных уведомлений и время последнего обновления.

Нажатие открывает приложение — после разблокировки отпечатком или кодом устройства.

### Включение и приватность

Виджет виден без разблокировки приложения, поэтому данные на нём появляются только по согласию:

1. Добавьте виджет на рабочий стол (долгое нажатие → Виджеты → VPN Shop). Без согласия он показывает «Откройте приложение».
2. В приложении откройте вкладку **Безопасность** и нажмите **«Показывать подписку на виджете»**.
3. Чтобы убрать данные, нажмите **«Скрыть данные с виджета»**.

На виджет никогда не попадают ссылка подписки, QR, балансы, email и данные платежей. Выход из аккаунта стирает сохранённую сводку и согласие: следующий владелец телефона увидит только «Откройте приложение». Если обновить сводку не удаётся больше суток (например, сессию отозвали из кабинета), виджет тоже скрывает данные.

### Обновление

- Android обновляет виджет раз в 30 минут — это минимальный интервал системы; приложение дополнительно обновляет его при каждом обновлении данных.
- Сводку отдаёт `GET /api/me/widget`. Трафик из Remnawave кэшируется на сервере на 10 минут на подписку (в Redis), поэтому частые обновления не нагружают панель. Если панель недоступна, виджет пишет «Трафик пока недоступен», а неудачный ответ не кэшируется.
- При ошибке сети остаётся последняя сводка с временем её получения.

Ответ API:

```json
{
  "subscription": {
    "name": "VPN",
    "plan": "Базовый",
    "state": "active",
    "expires_at": "2026-11-05T12:00:00Z",
    "days_left": 15,
    "traffic_available": true,
    "traffic_used_bytes": 32212254720,
    "traffic_limit_bytes": 107374182400,
    "traffic_left_bytes": 75161927680
  },
  "unread_notifications": 1,
  "generated_at": "2026-10-21T12:00:00Z",
  "refresh_after_seconds": 1800
}
```

`state`: `active`, `expiring`, `cancel_scheduled`, `expired`, `none`. `subscription` равно `null`, если основной подписки нет.

## Несколько профилей в админ-приложениях Android и iOS

Админ-приложения хранят до 8 профилей: разные магазины или разные учётные записи в одном магазине. У каждого профиля своя сессия в защищённом хранилище устройства (Android Keystore, iOS Keychain «только это устройство»).

### Работа с профилями

1. Над разделами — название текущего профиля и кнопка **«Профили (N)»**. Список показывает название, адрес сервера, email и состояние: «вход выполнен» или «нужно войти».
2. **Добавить профиль** открывает форму входа: название (необязательно, по умолчанию — адрес сервера), адрес API, email, пароль, код 2FA.
3. **Переключиться** сменяет профиль: данные предыдущего магазина сразу очищаются с экрана, а поздний ответ его сервера не попадает в новый профиль.
4. **Выйти** завершает сессию текущего профиля на сервере, профиль остаётся в списке.
5. **Удалить** завершает сессию на сервере (если связь есть) и стирает профиль и его токен с устройства.

Повторно добавить тот же email на тот же сервер нельзя — приложение предложит переключиться на существующий профиль. Профили видны только до входа или после разблокировки приложения.

### Ошибки

- **Сессия истекла или отозвана** (ответ 401): приложение пишет «Сессия профиля «…» истекла или отозвана — войдите снова», удаляет только сессию этого профиля и показывает форму входа. Остальные профили не затрагиваются.
- **Нет прав** (403): показывается сообщение сервера или «У роли нет доступа к этому разделу»; сессия сохраняется.
- **Нет связи**: «Нет связи с сервером профиля «…»» с кодом ошибки; повторите «Обновить».

### Обновление с прежней версии

Сессия, сохранённая прежней версией приложения, становится первым профилем без повторного входа. Его название — адрес сервера; задать название можно при следующем входе.

## Сборка и проверка

Изменения не требуют новых переменных сервера и миграций. Соберите приложения как обычно (`bash scripts/build-android-apk.sh`, Xcode для iOS) и проверьте на устройстве:

1. Виджет: добавьте на рабочий стол → «Откройте приложение»; включите в «Безопасности» → появилась сводка; выйдите из аккаунта → снова «Откройте приложение».
2. Профили: добавьте второй магазин, переключитесь туда и обратно, убедитесь, что данные не смешиваются; отзовите сессию в веб-панели («Сессии») и нажмите «Обновить» → сообщение об истёкшей сессии только для этого профиля.

Автотесты: `tests/test_widget.py` (SQLite и PostgreSQL) — состав ответа без ссылки, балансов и UUID Remnawave, состояния подписки, кэш трафика, отказ панели и кэша. Сборки Android и iOS проверяются CI. Проверка на реальных устройствах и подписанные пакеты остаются за оператором.

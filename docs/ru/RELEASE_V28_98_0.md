# Выпуск v28.98.0 — Cloudflare CDN для нод и подписки

Дистрибутив: `v28.98.0`. Runtime/API: `21.5.1`. Head магазина: `0094_store_subscriptions` (без новых миграций). Support Pro: `0008` / 3.8.

Решение владельца (N7): за CDN выносятся трафик нод через XHTTP и домен подписки; функция включается и выключается в панели управления. Всё — в **«Серверы → Установка» → «Cloudflare CDN»**.

## Что нового

- **Токен API Cloudflare** вводится в карточке (права: Zone · DNS · Edit, Zone · Zone Settings · Read, Zone · Config Rules · Edit) и хранится зашифрованным у установки; при включении он проверяется в Cloudflare.
- **Трафик ноды через CDN** (установка с SelfSteal на одной ноде):
  - на ноде появляется inbound **VLESS + XHTTP + TLS на TCP 2083** (порт, который Cloudflare проксирует) с сертификатом домена SelfSteal; в панели — хост с адресом, SNI и Host домена CDN, путь `/cdn`, `securityLayer: TLS`;
  - в Cloudflare: A-запись домена CDN → адрес ноды с оранжевым облаком и правило конфигурации «SSL: Full» **только для этого домена** (остальная зона и правила владельца не меняются);
  - включение: сначала транспорт на ноде, потом DNS; выключение — наоборот.
- **Домен подписки за CDN**: отдельная страница подписки — её домен, иначе домен панели; существующая A-запись переключается на «оранжевое облако» (выключение — обратно на «серое»). Если режим SSL зоны не «Full (strict)», в журнале шага — предупреждение.
- Ошибки Cloudflare (неверный токен, зона не найдена) показываются в шаге; при сбое следующего шага записи и правило возвращаются как были.
- Транспорт `cdn` меняет только модуль «Cloudflare CDN»: «Протоколы и маскировка» его не трогают.

# Выпуск v28.5.0 — push-уведомления в приложениях Android и iOS

Дистрибутив: `v28.5.0`. Runtime/API: `21.5.1`. Head магазина: `0066_push_notifications`. Support Pro: `0006` / 3.6. Дата и commit фиксируются тегом выпуска.

## Что завершено

### Push-уведомления

- События центра уведомлений клиента (оплата, активация подписки, ответ поддержки, призы, рассылки из админки) отправляются системными push-уведомлениями в приложения Corgi: Android через FCM HTTP v1, iOS через APNs. [Регламент](PUSH_NOTIFICATIONS_CURRENT.md).
- Push включается по согласию клиента на вкладке «Уведомления» и запрашивает системное разрешение. Есть тестовая отправка.
- Токен привязан к сессии входа. Выход, завершение всех сессий, истечение сессии, вход в другой аккаунт, удаление или объединение аккаунта прекращают доставку. Приложения отзывают токен перед выходом.
- Потерянный токен (`UNREGISTERED`, `410`, `BadDeviceToken`) отключает устройство. Временные ошибки повторяются с паузой до 5 попыток; ошибки ключей не отключают устройства клиентов.
- Сервер хранит только SHA-256 токена и зашифрованный токен. Текст ответа поддержки на экран блокировки не выводится.
- Админка: карточка «Push-уведомления» в разделе «Уведомления» — настройка FCM/APNs, активные устройства, итоги доставки за 24 часа, причины отключений и частые ошибки.
- Android: FCM без плагина google-services (идентификаторы Firebase задаются при сборке), разрешение `POST_NOTIFICATIONS`, канал уведомлений, показ уведомлений при открытом приложении, переход в центр уведомлений по нажатию. Без идентификаторов приложение собирается без push.
- iOS: регистрация в APNs через app delegate, entitlement `aps-environment`, показ баннера при открытом приложении, переход в центр уведомлений по нажатию.

### Миграция и настройки

- Миграция `0066_push_notifications`: `push_devices`, `push_deliveries`, `notifications.push_fanout_at`. Существующие уведомления помечаются обработанными. Откат миграции удаляет только реестр токенов (устройства зарегистрируются снова).
- Новые переменные `.env` (необязательные): `FCM_PROJECT_ID`, `FCM_SERVICE_ACCOUNT_JSON`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID`, `APNS_PRIVATE_KEY`, `APNS_ENVIRONMENT`. Они классифицированы как deployment-параметры: реестр настроек — 151 поле (96 live, 53 deployment, 2 workflow).
- Зависимость `h2` 4.4.1 для HTTP/2-соединения с APNs.

### Матрица

Строка «Native push/widget/multiprofile» переведена в «частично»: push реализован, виджет Android и административный мультипрофиль остаются в [реестре завершения](MATRIX_COMPLETION_21_5_1.md).

## Обновление

Перед обновлением создайте согласованный backup базы и файлов. Используйте [проверяемый регламент обновления](DISTRIBUTION_UPGRADE_CURRENT.md). Чтобы включить push, добавьте ключи провайдеров в `.env` по [регламенту](PUSH_NOTIFICATIONS_CURRENT.md) и пересоберите мобильные приложения с идентификаторами Firebase. После запуска проверьте:

```bash
docker compose exec -T backend alembic current
docker compose ps
curl -fsS https://API_DOMAIN/health/live
curl -fsS https://API_DOMAIN/health/ready
```

Ожидаемый head — `0066_push_notifications`.

## Проверка

- Python: полный набор тестов на SQLite и PostgreSQL, включая `tests/test_push.py` (подписи FCM/APNs проверяются сгенерированными ключами, ответы провайдеров имитируются) и roundtrip миграций.
- Браузер (Chromium, под production CSP): карточка состояния push в админке и прежние сценарии.
- CI: сборка Android (`assembleDebug`) и iOS (симулятор) с push-кодом.

## Границы выпуска

Автотесты не подтверждают реальную доставку через серверы Google и Apple, реальные платежи, SMTP/Telegram, доступ к конкретному Remnawave и restore drill инфраструктуры владельца. Production gate остаётся закрытым до внешней приёмки; APK/IPA не подписаны без owner signing secrets. Полный статус — [матрица покрытия](WORKSPACE_COVERAGE.md) и [реестр завершения](MATRIX_COMPLETION_21_5_1.md).

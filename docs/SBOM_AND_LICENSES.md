# Состав (SBOM) и лицензии (REQ-DOC-0036)

Что входит в магазин и под какими лицензиями — и где это проверяется автоматически. Всё ниже сверено с
`.github/workflows/ci.yml` и `scripts/ci/check-licenses.py`.

## Лицензия проекта

Авторский код — по собственной лицензии из [LICENSE](../LICENSE). Лицензии зависимостей она не заменяет: состав и
обязательные уведомления — в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Чужой код из проектов под AGPL,
Commons Clause или без лицензии не копируется — только идеи (решение владельца № 13, `docs/OWNER_DECISIONS.md`;
источники — [REFERENCE_REPOSITORIES.md](REFERENCE_REPOSITORIES.md)).

## Что проверяется в каждом PR

| Проверка | Где | Что блокирует слияние |
|---|---|---|
| SBOM | Trivy строит перечень компонентов репозитория. Задание `release-sbom` добавляет три графа Android и встроенный движок. `scripts/ci/check-sbom.py` проверяет итог по строгой схеме CycloneDX | ошибка схемы, неполный граф или 100 и менее компонентов репозитория. CI сохраняет файл `sbom.cdx.json` в артефакте `sbom` |
| Секреты и уязвимости репозитория | тот же шаг, Trivy `fs --scanners vuln,secret` | секрет в репозитории или уязвимость HIGH/CRITICAL в lock-файле |
| Уязвимости образов | `ci.yml`, «Container scan»: Trivy по каждому образу, который собирает магазин | HIGH/CRITICAL с готовым исправлением; исключения — `.trivyignore`, каждое с причиной и сроком |
| Лицензии зависимостей | `ci.yml`, «Dependency licences»: `pip-licenses` для backend, `license-checker` для admin, miniapp, cabinet → `scripts/ci/check-licenses.py` | сильный копилефт или source-available среди поставляемых зависимостей; слабый копилефт (LGPL, MPL) для библиотеки «как есть» допустим; исключение — строка в `ALLOWED` с причиной |
| Аудит npm | `ci.yml`, «JavaScript dependencies»: `npm audit --audit-level=high` для admin, miniapp, cabinet | уязвимость high и выше |

## Где взять SBOM конкретной версии

Для опубликованного `v28.161.0` доступен артефакт `sbom` в соответствующем прогоне «Corgi Lusi CI».
Для следующего выпуска `publish-release.yml` берёт проверенный файл из CI текущего коммита `main`.
Рядом с ZIP дистрибутива публикуется файл с тем же базовым именем и расширением `.cdx.json`.
Его имя, размер в байтах и SHA-256 записаны в поле `sbom` отдельного манифеста выпуска.
Скачанный файл можно сверить командой `sha256sum <имя-файла>.cdx.json` и сопоставить с `sbom.sha256`.
Порядок публикации описан в [RELEASE_PROCESS.md](RELEASE_PROCESS.md).

## Android

Для VPN Shop, Corgi Lucy Client и Lucy Admin задание `release-sbom` использует закреплённую версию 3.6.1
плагина CycloneDX. Gradle разрешает `releaseRuntimeClasspath` каждого приложения и записывает выбранные версии,
прямые и транзитивные связи и локальные файлы. Проверка сверяет с этим графом каждую Maven-координату
и каждую связь в SBOM продукта. При пропущенной зависимости, неизвестной лицензии или лицензии,
запрещённой политикой проекта, задание завершается с ошибкой.

Два VPN-приложения используют общий `libv2ray.aar` из задания сборки движка. В SBOM входят SHA-256 архива
и четырёх библиотек JNI, ревизия обвязки и версии Go-модулей из каждой библиотеки. Для модуля с опубликованной
контрольной суммой сохраняется исходная сумма Go `h1`. Граф Lucy Admin содержит только его собственные компоненты.
Проверка лицензий Maven использует декларации POM. Для нативного графа явно указаны лицензии обвязки
и Xray-core. Для каждого встроенного модуля CI загружает исходный архив через публичный Go proxy, повторно
вычисляет Go h1 по всем его файлам и проверяет его по метаданным ELF. Для локальной обвязки
проверяется upstream-коммит. В CycloneDX сохраняются исходные тексты лицензий, включая
вложенные файлы и исключения, SHA-256 файлов лицензий и уведомлений и ссылка на архив
с SHA-256. Проверка завершится ошибкой при несовпадении исходников или отсутствии текста
лицензии. Сохранённые тексты доступны для проверки условий распространения. Для приёмки
REQ-DOC-0036 также нужны полный release-граф Gradle, проверка составных условий и SBOM,
прикреплённый к опубликованному релизу.


Точный граф конфигурируется через Android Components после создания варианта release. Для повторения
в каждом из трёх Android-проектов выполните `:app:verifyReleaseSbomInputs` с параметром
`--init-script <корень>/scripts/ci/android-sbom.gradle`. В каталоге `app/build/reports/cyclonedx-direct`
будут `bom.json` и независимо полученный `resolution.json`. Оба VPN-приложения должны видеть один AAR.

Перед упаковкой отдельного файла релиза дополнительно проверяются привязка всех трёх приложений
к корню, Maven-зависимости каждого приложения и связь обоих VPN-клиентов с общим AAR и четырьмя ABI.
В корневом компоненте CycloneDX указаны имя «VPN Shop by Corgi Lucy» и полный Git SHA проверенной
сборки в поле `version`. Упаковщик сверяет SHA с коммитом исходников дистрибутива.
Он обходит Maven-зависимости от корня каждого приложения. Каждый объявленный компонент
должен быть достижим и содержать лицензионную декларацию. Ссылка на отсутствующий
компонент или на зависимость другого Android-приложения останавливает упаковку.
Упаковщик также проверяет наличие SHA-256 у AAR и каждой JNI-библиотеки. Для каждой ABI нужны
ссылки на обвязку AndroidLibXrayLite и Xray-core. Для каждого связанного Go-модуля в SBOM
должны присутствовать текст лицензии и SHA-256 архива исходников. Набор дополнительных
модулей может различаться между ABI.
Сохранённый файл проверяется командой `python scripts/ci/check-sbom.py --release <файл>` в окружении
с зависимостями валидатора из workflow. Для проверки исходного Trivy SBOM используется режим без `--release`.

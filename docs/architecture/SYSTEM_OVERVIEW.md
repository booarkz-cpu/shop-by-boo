# Обзор системы

## Что это

Магазин VPN «Корги Люси» поверх панели Remnawave: продажа и продление подписок, выдача доступа,
управление серверами и поддержка клиентов. Всё, кроме самой панели и нод, устанавливается одним набором
Docker Compose на один сервер.

## Три продукта

| Продукт | Для кого | Из чего состоит |
| --- | --- | --- |
| Магазин | Клиент | Telegram-бот, Mini App, личный кабинет, приложения для Android и iOS |
| Панель администратора | Владелец и операторы | Веб-панель, приложения администратора для Android и iOS |
| «Корги Люси: клиент» | Клиент | Отдельное приложение VPN для Android с собственной версией |

Все три работают с одним API (`backend`). Клиент VPN получает подписку по ссылке и к API магазина не привязан:
он работает с любой подпиской формата Xray.

## Из чего состоит

| Часть | Где в репозитории | Назначение |
| --- | --- | --- |
| API магазина | `backend/app/` | Клиенты, платежи, подписки, панель администратора, установка нод |
| Фоновые задачи | `backend/worker.py` | Выдача доступа, расписания, проверки |
| Бот | `backend/app/bot.py` и соседние модули | Вход, покупка, уведомления |
| Веб-панель | `admin/` | Интерфейс администратора |
| Кабинет и Mini App | `cabinet/`, `miniapp/` | Интерфейс клиента |
| Support Pro | `support-pro/` | Обращения в поддержку; своя база и свои фоновые задачи |
| Мобильные приложения | `mobile/` | Три приложения для Android, два для iOS |
| Установка и обновление | `install.sh`, `scripts/`, `deploy/` | Установщик, агент обновления, Caddy |

Службы, сети и тома перечислены в [CONTAINER_DIAGRAM.md](CONTAINER_DIAGRAM.md).

## Внешние системы

| Система | Зачем | Как связана |
| --- | --- | --- |
| Панель Remnawave | Пользователи VPN, ноды, подписки | REST API панели; webhook панели в магазин |
| Ноды | Передача трафика | Панель управляет нодой; магазин ставит ноду и модули по SSH |
| Платёжные провайдеры | Приём денег | Создание платежа по API; webhook с подписью |
| Telegram | Бот, Mini App, уведомления | Bot API |
| GitHub | Выпуски и обновления | Агент обновления и приложения читают выпуски |
| Почта, push (FCM, APNs), OAuth | Уведомления и вход | По ключам владельца |

## Главные свойства

- **Один API на все клиенты.** Права проверяются на сервере на каждом маршруте.
- **Доступ выдаётся только после сверки платежа с провайдером**, а не по сообщению клиента.
- **Секреты** лежат в `.env` и в базе в зашифрованном виде.
- **Обновление** — агент на сервере: проверка выпуска, копия, обновление, откат при сбое.

## Чего в системе нет

- Отдельных служб на каждую предметную область: магазин — один процесс API с модулями.
  См. [DOMAIN_BOUNDARIES.md](DOMAIN_BOUNDARIES.md).
- Шины событий между службами. См. [EVENT_CATALOG.md](EVENT_CATALOG.md).
- Окружения staging и запуска на нескольких серверах с балансировкой: есть только запасной экземпляр API.

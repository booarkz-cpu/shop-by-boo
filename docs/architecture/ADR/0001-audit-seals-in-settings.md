# 0001. Печати журнала действий хранятся в настройках, без изменения схемы

- Дата: 2026-11-12
- Статус: принято
- Выпуск: v28.125.0. Требование: `REQ-ADMIN-0012`.

## Контекст

Журнал действий администраторов лежал в базе без защиты: запись можно было изменить или удалить напрямую, и это осталось бы незамеченным.

## Варианты

1. **Подпись в каждой записи** (новый столбец, цепочка от записи к записи). Точность до записи. Нужна миграция; при записи журнала
   нужно знать подпись предыдущей записи, а записи пишутся параллельно из многих запросов.
2. **Печати по диапазонам**, которые ставит фоновый процесс. Точность до диапазона. Запись журнала не меняется и не замедляется; схема не меняется.
3. **Выгрузка журнала во внешнее хранилище.** Самая сильная защита. Нужен внешний сервис, которого у владельца нет.

## Решение

Вариант 2. Фоновый процесс каждые десять минут считает HMAC-SHA256 по новым записям и предыдущей печати.
Ключ — `APP_SECRET`, которого нет в базе. Печати хранятся в таблице настроек (`audit.seals`).

## Последствия

- Запись в журнал осталась такой же быстрой; миграция не понадобилась.
- Проверка называет диапазон записей, а не запись.
- Записи моложе последней печати не защищены.
- Старые печати объединяются, чтобы список не рос бесконечно.

## Риски

- Тот, у кого есть секрет сервера, может поставить печати заново. Заметить это можно только по внешней копии.
- Удалённый конец журнала вместе с последними печатями не обнаруживается.

## Обратимость

Полная: достаточно удалить настройку `audit.seals` и модуль `backend/app/audit_seal.py`. Данные журнала не затрагиваются.

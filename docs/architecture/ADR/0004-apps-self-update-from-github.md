# 0004. Приложения для Android обновляют себя из выпусков на GitHub

- Дата: 2026-11-11
- Статус: принято
- Выпуски: v28.119.0, v28.120.0. Задача владельца: автообновление приложений без участия пользователя.

## Контекст

Приложения распространяются как APK из выпусков на GitHub, не через магазин приложений. Новую версию клиенты ставили вручную.

## Варианты

1. **Публикация в Google Play.** Обновляет сам магазин приложений. Нужен аккаунт разработчика; приложения VPN проходят отдельную проверку.
2. **Проверка обновлений в приложении** с открытием загрузки в браузере. Просто, но каждый раз нужны действия человека.
3. **Фоновая загрузка и установка системным установщиком.** На Android 12 и новее без вопросов со второго обновления.

## Решение

Вариант 3. В каждом выпуске лежит файл с номером версии, SHA-256 и адресом APK. Приложение раз в сутки сверяет версию,
скачивает APK, проверяет SHA-256 и передаёт системному установщику. Приложение, установленное из магазина приложений, GitHub не спрашивает.

## Последствия

- Нужны разрешения `REQUEST_INSTALL_PACKAGES` и `UPDATE_PACKAGES_WITHOUT_USER_ACTION`.
- Первое обновление и Android 11 и старше требуют подтверждения.
- Пока работает VPN, приложение себя не обновляет.
- Файл версии и APK должны публиковаться одной сборкой, иначе SHA-256 не сойдётся.

## Риски

- Google Play ограничивает разрешение на установку приложений: перед публикацией там сборку нужно менять.
- На iOS решение неприменимо: система не даёт приложению обновить себя.

## Обратимость

Частичная: уже установленные версии продолжат искать файл версии в выпусках. Если его перестать публиковать, они просто не найдут обновлений.

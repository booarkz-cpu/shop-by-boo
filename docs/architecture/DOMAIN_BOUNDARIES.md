# Границы областей: что есть и чего нет

Документ отвечает на требования `REQ-ARCH-0002` – `0008` по состоянию кода.

## Что разделено на деле

| Граница | Чем обеспечена |
| --- | --- |
| Магазин и Support Pro | Разные службы, разные базы и Redis; связь только по HTTP |
| Магазин и панель Remnawave | Панель на другом сервере; связь только через её API и webhook |
| Магазин и ноды | Только SSH по закрытому списку скриптов и API панели |
| Клиент VPN и магазин | Отдельное приложение, отдельная версия и выпуск; общих данных нет |
| Клиент и администратор | Разные сессии и права; право проверяется на каждом административном маршруте (`tests/test_admin_route_permissions.py`) |
| Интерфейсы и данные | Интерфейсы не обращаются к базе: только API |

## Что не разделено

| Требование промпта | Состояние |
| --- | --- |
| Отдельные bounded contexts с публичными контрактами | Области — группы модулей одного процесса `backend`. Модуль одной области может вызвать функцию другой напрямую |
| Запрет прямого доступа к таблицам чужой области | Не обеспечен: все модули `backend` работают с одной базой через общие модели `backend/app/models.py` |
| Отсутствие циклических зависимостей | Автоматически не проверяется. Многие модули импортируют `main` внутри функций, чтобы обойти цикл |
| Владелец каждой области | Не назначен: проект ведёт один владелец |
| События между областями | Шины событий нет; см. [EVENT_CATALOG.md](EVENT_CATALOG.md) |

## Общее для всех областей

Соответствует `REQ-ARCH-0003`: общими остаются вспомогательные части, а не бизнес-правила.

| Что | Где |
| --- | --- |
| Проверка прав, шифрование секретов, токены | `backend/app/security.py` |
| Настройки | `backend/app/config.py`, `runtime_settings.py` |
| Клиент панели | `backend/app/remnawave.py` |
| Тексты интерфейсов | `packages/localization/`, словари веб-интерфейсов |
| Дизайн-токены и компоненты веб-панели | `apps/lucy-admin/web/src/theme.css`, `apps/lucy-admin/web/src/components/ui/` |

## Описание служб

`REQ-ARCH-0008` требует для каждой службы назначение, входы и выходы, зависимости, проверки готовности, настройки,
секреты, миграции, журналы, метрики, копии, развёртывание и откат. Где это описано:

| Что | Документ |
| --- | --- |
| Назначение, зависимости, проверки готовности, тома | [CONTAINER_DIAGRAM.md](CONTAINER_DIAGRAM.md) |
| Настройки и секреты | `.env.example`, [SECURITY_MODEL_RU.md](../../SECURITY_MODEL_RU.md) |
| Миграции | `backend/alembic/`, `support-pro/alembic/` |
| Копии и восстановление | `scripts/backup.sh`, `scripts/ci/restore-drill.sh`, [OPERATIONS_RUNBOOK_RU.md](../../OPERATIONS_RUNBOOK_RU.md) |
| Обновление и откат | [AUTO_UPDATE.md](../AUTO_UPDATE.md) |
| Журналы и метрики | [OPERATIONS_RUNBOOK_RU.md](../../OPERATIONS_RUNBOOK_RU.md) |

Единой карточки на каждую службу со всеми двенадцатью пунктами нет.

## Что нужно, чтобы выполнить требования

1. Правило импортов между группами модулей и тест, который его проверяет.
2. Запрет на запросы к таблицам чужой области вне её модулей — тем же тестом, по именам моделей.
3. Карточка службы по единому образцу для каждой из служб Compose.

Это изменения структуры кода; до них статусы `REQ-ARCH-0002`, `0004` – `0006` остаются частичными или невыполненными.

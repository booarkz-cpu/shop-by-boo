# Дорожная карта: визуальное качество, скриншоты и бренд

Эта дорожная карта дополняет продуктовый план Shop by Boo. Работы по интерфейсу выполняются отдельным этапом и не считаются завершёнными только на основании изменения CSS или документации.

## Приоритет 1 — полный визуальный аудит админ-панели

- [ ] Проверить все разделы админ-панели на актуальном тестовом стенде, а не только главную страницу.
- [ ] Исправить отступы и выравнивание заголовков, описаний, текста карточек, подписей полей, подсказок, ошибок валидации, кнопок и таблиц.
- [ ] Привести вертикальный ритм к единой шкале отступов; устранить двойные отступы, слипшийся текст, переполнение и случайные разрывы строк.
- [ ] Проверить тултипы и подсказки: ширина, перенос длинных слов/URL, расстояние до поля, границы экрана, контраст и клавиатурная доступность.
- [ ] Проверить формы с длинными и короткими подписями, необязательными полями, ошибками, загрузкой и пустыми состояниями.
- [ ] Проверить таблицы, фильтры, панели действий, диалоги, выпадающие меню и уведомления.
- [ ] Проверить тёмную и светлую темы, ширины 320/360/390/768/1024/1440 px, масштаб браузера и клавиатурную навигацию.
- [ ] Сохранить фирменный стиль «Корги Люси»: спокойный тёмно-синий интерфейс, чистая типографика, сдержанный акцентный цвет, понятные статусы и дружелюбные тексты без визуального шума.
- [ ] Добавить автоматические проверки на горизонтальную прокрутку, обрезанные элементы, переполнение подсказок и ошибки консоли.
- [ ] Переснять скриншоты админки после исправлений и проверить их визуально перед публикацией.

## Приоритет 2 — обновить все скриншоты README

Обновить иллюстрации после сборки актуальных приложений и веб-интерфейсов. Все снимки должны быть получены из текущего кода на изолированном стенде с демонстрационными данными; нельзя выдавать макеты или старые снимки за актуальные.

- [ ] Админ-панель: обзор, все группы разделов, формы, подсказки, таблицы, светлая/тёмная темы и мобильный вид.
- [ ] Личный кабинет: главная, тарифы, подписка, устройства, оплата/кошелёк, рефералы, поддержка и документы.
- [ ] Telegram Mini App: основные экраны на типичном мобильном размере и в контейнере Telegram.
- [ ] Telegram-бот: актуальные сценарии /start, тарифы, покупка, кошелёк, подписка, поддержка и уведомления.
- [ ] Android-клиент: подключение, состояние VPN, подписка, локации, устройства, поддержка и настройки.
- [ ] iOS-клиент: те же ключевые сценарии с настоящими скриншотами приложения под iOS.
- [ ] Android- и iOS-приложения администратора: обзор, мониторинг, платежи, поддержка, запуск и полный доступ к панели.
- [ ] Проверить каждую ссылку на изображение в README, читаемость на GitHub Mobile, единый масштаб и отсутствие персональных данных/секретов.
- [ ] Указать в README команду генерации скриншотов и дату/версию, из которой они получены.

## Приоритет 3 — закрепить визуальное качество в CI

- [ ] Разделить скриншоты по поверхностям и платформам; сохранять стабильные имена файлов.
- [ ] Генерировать снимки после сборки frontend и запуска тестового стенда с фикстурами.
- [ ] Добавить smoke-тесты ключевых экранов и проверку отсутствия ошибок браузерной консоли.
- [ ] Сравнивать скриншоты с эталонами с допустимым порогом визуальных отличий; динамические данные стабилизировать фикстурами.
- [ ] Запретить обновление README-скриншотов без проверки, что файлы существуют и соответствуют текущему выпуску.

## Критерии приёмки

1. Все разделы панели открываются без ошибок и имеют корректные состояния загрузки, пустых данных и отказов API.
2. Нет обрезанных подсказок, некорректных отступов, наложений и горизонтальной прокрутки на поддерживаемых ширинах.
3. Тёмная и светлая темы сохраняют контраст и читаемость.
4. Скриншоты README обновлены для веба, Mini App, Telegram, Android и iOS, включая клиентские и административные приложения.
5. Typecheck, сборка и соответствующие UI/E2E-тесты проходят. Внешняя проверка на реальных устройствах отмечается отдельно и не подменяется автоматическим тестом.

## Порядок выполнения

1. Сначала собрать baseline и полный список страниц.
2. Исправить общие компоненты, токены отступов и подсказок, затем индивидуальные страницы.
3. Повторно прогнать тесты на всех контрольных размерах.
4. Переснять снимки из чистого тестового окружения и обновить README.
5. Провести ручную визуальную приёмку, затем объединять изменения в main.

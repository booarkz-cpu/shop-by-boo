Дистрибутив `v28.147.0`. Инвентаризация 399 изображений (`png`, `jpg`, `webp`) в репозитории,
без `node_modules` и `.git`.

Документ фиксирует, что реально лежит в репозитории, где используется и что требует обновления.
Ничего не удалено: ссылки на изображения проверялись перед выводами.

## 1. Design system

Реализовано в `admin/src/style.css` и переиспользуемых компонентах. Проверено по коду и тестам
(`tests/test_critical_startup_and_i18n.py` утверждает наличие этих признаков):

| Требование | Состояние |
| --- | --- |
| Фон `#090D16` | Реализовано через переменные темы |
| Карточки `#0F172A` | Реализовано (`--surface`) |
| Тонкие границы slate | Реализовано |
| Синий акцент | `--accent` |
| Шрифт Inter | `@fontsource-variable/inter`, присутствует в `style.css` |
| JetBrains Mono для технических данных | `@fontsource-variable/jetbrains-mono` |
| Светлая тема | `html[data-theme="light"]` |
| Адаптивная боковая панель | Реализовано, скриншоты `admin-mobile-drawer-v28-10-0.png` |
| Поиск по командам | Реализовано, `admin-command-search`, `admin-panel-search` |

| Подтверждение опасных операций | `confirm()` в опасных действиях, например «Обновить сейчас» |

Кабинет использует собственную тему (`cabinet/src/style.css`), согласованную по палитре.

## 3. Проверка полноты

`tests/test_screenshots.py` в CI:
- у каждого раздела бокового меню (`SECTION_GROUPS` в `admin/src/sections.ts`) есть снимок `NN_<раздел>.png`, номера не повторяются;
- README ссылается только на существующие изображения.

Новый раздел без снимка не пройдёт CI: перед выпуском запустите скрипт съёмки.

## 4. Как переснять

Инструкция — [руководство по админ-панели](ru/ADMIN_PANEL_CURRENT.md). Кратко:
1. сборка админки и кабинета;
2. тестовый стенд `tests/passkey_browser_server.py` с PostgreSQL и Redis (`BROWSER_DATABASE_URL`, `BROWSER_REDIS_URL`, `PAYMENTS_SANDBOX=true`);
3. `node admin/scripts/screenshots-catalog.mjs <корень>`;
4. `python3 scripts/screenshots/readme_admin.py` — блок «Админ-панель» в README.

После этапа, который менял интерфейс, снимки обновляются тем же скриптом. Полная пересъёмка — на этапах 17 и 18.

## 5. Требования к новым изображениям

При пересъёмке соблюдать:

- разрешение 1440×900 для десктопа админки, 390×844 для мобильных;
- тёмная тема по умолчанию, светлая — отдельным кадром, где это важно;
- PNG без прозрачности для скриншотов интерфейса;
- имена в формате `NN_section.png` для админки (нумерация сохраняется — на неё опираются ссылки);
- для документации — `admin-<section>-v<X-Y-Z>.png`;
- в кадре не должно быть реальных данных клиентов: email, телефоны, токены, ссылки подписок.

Последний пункт критичен: скриншоты коммитятся в публичный репозиторий.

Баннеры бота и изображения контента хранятся в медиа-каталоге и управляются через админку —
в git они не попадают, что правильно: это пользовательские данные.

## 7. Изображения Mini App и кабинета

Кабинет: `cabinet/public/` содержит статические ассеты, собираются в `dist`. Mini App
(`miniapp/`) использует те же статические ресурсы через общий кабинет (`npm ci --prefix ../cabinet`
в CI).

Фон и изображения Mini App задаются настройками (`miniapp_background_image`, `miniapp_image`) и
подставляются из `/api/public/config` — это runtime-контент, а не файлы репозитория.

## 8. Чего в репозитории нет

- Исходников desktop-приложений: `desktop/{linux,macos,windows}` содержат только `README.md`.
- Опубликованных ссылок на Google Play / App Store / RuStore.
- Подписанных мобильных артефактов: в релизе `v28.147.0` — `*_unsigned.apk` / `*_unsigned.aab`.

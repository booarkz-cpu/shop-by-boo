# Целевые показатели и замеры API

Порог сборки определяется сценариями k6 в репозитории. В изолированном стеке на `aa90c899148b3131167f42e1754932d408a4f4fa` три сценария выполнили 12 045 HTTP-запросов за один прогон, в среднем 170,1 запроса в секунду. Выполнены все 12 044 проверки ответов. [Журнал CI от 25 ноября 2026 года](https://github.com/booarkz-cpu/shop-by-boo/actions/runs/45658460522/job/139361452061)

| Сценарий | Порог k6 | Результат этого прогона |
| --- | ---: | ---: |
| Каталог, p95 | < 800 мс | 21 мс |
| Синхронизация, p95 | < 1000 мс | 54 мс |
| Создание заказа, p95 | < 2500 мс | 283 мс |
| Доля запросов за пределами ожидаемых HTTP-статусов | < 1 % | 0 из 12 045 |
| Успешные проверки бизнес-ответов | > 98 % | 12 044 из 12 044 |

k6 считает HTTP 409 и 429 ожидаемыми для этого набора. Границы нагрузки, проверки содержимого и профиль виртуальных пользователей описаны в [сценарии магазина](../tests/load/shop.js). При сравнении прогонов сверяйте SHA, состав данных, длительность и аппаратное окружение. [Предыдущий замер и методика](PERFORMANCE_BASELINE.md)

Отдельный сценарий ступенчатого чтения публичных API задаёт p95 < 1500 мс и долю HTTP-ошибок < 2 %. Результаты такого испытания нужно связывать с конкретной установкой и её конфигурацией. Для эксплуатационного SLO доступности и бюджета ошибок нужны выбранное окно наблюдения и данные мониторинга установки. Единственный тестовый прогон измеряет задержку и ошибки лишь во время испытания.

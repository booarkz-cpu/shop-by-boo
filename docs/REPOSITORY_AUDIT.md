## 1. `booarkz-cpu/remnawave-manager`

**Назначение:** production-установщик Remnawave на Debian/Ubuntu — интерактивное меню с описанием
каждой функции, интерфейс на английском и русском.

**Стек:** shell. Версия 1.5.6.

**Лицензия:** MIT — позволяет использовать, копировать, изменять и распространять при сохранении
уведомления об авторстве. Загружаемые меню файлы остаются под условиями своих авторов
(`CREDITS.md`).

**Отношение к проекту:** тот же владелец (`booarkz-cpu`). Это установщик **панели Remnawave**, а не
магазина; магазин работает поверх уже установленной панели.

**Что можно взять:** ничего переносить не требуется — установка Remnawave не входит в задачу
магазина. Полезно как ссылка в инструкции «сначала поставьте панель».

**Риск:** нет.

## 2. `eGamesAPI/remnawave-reverse-proxy`

**Назначение:** скрипт установки nginx как reverse proxy для панели Remnawave. 1046 звёзд — самый
популярный из списка.

**Стек:** shell + nginx-конфигурации; есть `src/`, `docs/`, `install_remnawave.sh`.

**Лицензия:** MIT.

**Важно:** в README стоит явное предупреждение автора:

> THIS REPOSITORY IS AN EDUCATIONAL EXAMPLE … NOT FOR PRODUCTION AND NOT FOR PRODUCTION USE!
> USE AT YOUR OWN RISK!

То есть автор сам не позиционирует это как production-решение.

**Отношение к проекту:** магазин **не использует** его. У проекта собственный reverse proxy — Caddy
(`deploy/Caddyfile`, сервис `caddy` в compose), который сам выпускает TLS и маршрутизирует домены на
`admin`, `cabinet`, `miniapp`, `backend`, `support_pro`.

**Что можно взять:** идеи маршрутизации и подсказки по заголовкам — как справку, не как код.
Замена Caddy на nginx не оправдана: пришлось бы заново решать автоматический TLS, HTTP/3 и
маршрутизацию, которые Caddy даёт из коробки.

**Риск:** прямой перенос противоречит предупреждению автора и концепции проекта.

## 3. `Case211/remnawave-admin`

**Назначение:** «панель управления и Telegram-бот поверх вашей панели Remnawave» — пользователи,
ноды, анти-абьюз, почта, мониторинг.

**Стек:** Python, веб-панель, бот.

**Лицензия:** GitHub определяет как NOASSERTION, в README заявлена **AGPL v3**. Для целей переноса
надо считать AGPL: копирование кода в проект под собственной лицензией потребовало бы открыть весь
проект по AGPL. Это несовместимо с Corgi Lusi Source License 2.8.

**Важно:** в README прямо сказано, что проект **стал платным** — в репозитории осталась последняя
бесплатная версия 5.2.0, она больше не обновляется.

**Отношение к проекту:** это конкурирующий продукт с пересекающейся функциональностью (админка,
бот, анти-абьюз). Своего в проекте уже больше: 458 административных маршрутов, анти-абьюз
(`abuse_suspension.py`, `anti_sharing.py`), мониторинг, почтовый домен.

**Что можно взять:** ничего — только идеи и сравнение сценариев.

**Риск:** AGPL. Перенос кода недопустим.

## 4. `BEDOLAGA-DEV/remnawave-bedolaga-telegram-bot`

**Назначение:** Telegram-бот-магазин подписок под Remnawave. 1184 ★ — самый заметный проект в списке.

**Стек:** Python.

**Лицензия:** «Commons Clause» License Condition v1.0 поверх **MIT** (Licensor: Fr1ngg). Это уточнено
после фактического чтения `LICENSE` в клоне — GitHub показывает «Other», но файл содержит полный текст.

Commons Clause **отзывает право продажи**: нельзя предоставлять третьим лицам за плату продукт или услугу,
ценность которой целиком или в существенной части происходит от функциональности софта. Магазин —
коммерческий продукт, поэтому перенос кода запрещён. Это строже, чем «лицензия не определена».

**Отношение к проекту:** прямое пересечение — продажа подписок через Telegram. В проекте это уже
реализовано (`bot.py`, 860 строк, плюс `bot_api_rules.py`, `bot_banners.py`).

**Что можно взять:** ничего. Ни одна строка не переносилась.

**Риск:** неопределённая лицензия — перенос запрещён.

## 5. `BEDOLAGA-DEV/bedolaga-cabinet`

**Назначение:** веб-кабинет для того же бота.

**Стек:** TypeScript.

**Лицензия:** **AGPL-3.0** — явно указана GitHub. Любое распространение производной работы требует
открыть исходники под AGPL, включая сетевой доступ (пункт про network use).

**Отношение к проекту:** пересекается с `cabinet/` (52 компонента) и Mini App.

**Что можно взять:** ничего.

**Риск:** AGPL несовместима с закрытым коммерческим распространением магазина.

## 6. `STEP-CORP/StepBot`

**Назначение:** «конструктор Telegram-ботов для продажи VPN на базе Remnawave» — бот собирается и
настраивается через веб-кабинет, без правки кода и перезапусков.

**Стек:** Python 3.12+, PostgreSQL 15+, React 18.

**Лицензия:** MIT.

**Отношение к проекту:** та же ниша. Ключевая идея — **конструктор**: меню и кнопки собираются в
кабинете. В проекте это уже есть в другой форме: `admin/src/menu-tree.tsx`,
`backend/app/mobile_layout.py` (590 строк), `admin/src/botBanners.tsx`, `app_config.py`.

**Что можно взять:** ничего переносить не требуется. MIT разрешает перенос, но дублировать уже
работающий конструктор смысла нет.

**Риск:** нет.

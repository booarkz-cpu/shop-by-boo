## 20.0.29 — 2026-10-01

## 20.0.28 — 2026-10-01

Актуализирована документация: добавлена отдельная пошаговая инструкция обновления существующего VDS до v20.0.28, обновлены production-маршруты и инструкции по проверке после обновления. Исправлен обязательный CSS-токен админ-центра, чтобы enterprise-регрессионный тест проходил после визуального обновления в стиле Support Pro.


## 20.0.27 — 2026-10-01

Админ-центр визуально приведён к единой дизайн-системе Support Pro: навигационная rail-панель, glass top bar, светлая/тёмная тема, карточки, поля и кнопки используют тот же визуальный язык. Функциональность и существующие разделы админ-центра сохранены.

## 20.0.25 — 2026-10-01

Исправлена уязвимость CVE-2026-101918 в PyJWT: зависимость обновлена до 2.15.0 и регрессионная проверка закреплена на этой версии. Также исправлен production-установщик VDS: ввод из терминала нормализуется перед записью `.env`, чтобы перенос строки не мог повредить доменные переменные; определение SSH-порта стало устойчивее к временной ошибке `sshd -T`. Это выпуск исходников; проверки реального VDS и живых платежей остаются отдельными.

## 20.0.24 — 2026-09-30

Исправлена первая ротация `APP_SECRET`: прежний ключ добавляется в `APP_SECRET_PREVIOUS` даже если этой строки ещё не было; повторная ротация сохраняет только предыдущий ключ без дублей. Скрипт закрепления Docker образов теперь отклоняет отсутствие immutable digest до записи `.env.images` и изменения `.env`. PyJWT обновлён с 2.13.0 до 2.14.0 после обнаружения уязвимостей в CI. Добавлены проверки отказов и обновлена инструкция обслуживания. Это выпуск исходников; проверки реального VDS и живых касс остаются отдельными.

## Неизданные исправления — 2026-09-28

- **GitHub Actions:** workflow CI, Docker, мобильных пакетов, публикации и развёртывания переведены на версии официальных GitHub и Docker actions с Node.js 24; Linux runner закреплён на Ubuntu 24.04. Устранены предупреждения о Node.js 20 и предстоящей смене `ubuntu-latest`. Проверка итоговых заданий выполняется в GitHub Actions после публикации.
- **Mobile packages:** сборки для коммита, не совпадающего с тегом `v20.0.15` или текущей веткой `main`, остаются в артефактах workflow; шаг публикации выводит причину пропуска и завершается без ложной ошибки. Для нового production-выпуска требуются отдельный тег, успешный CI и постоянная подпись Android/iOS.
- **Восстановление:** ручной откат и аварийный откат обновления сохраняют все обычные вложенные `.env` и `.env.*` из установленного дерева, а не только `support-pro/.env`. Добавлена регрессия для `backend/.env.local`; восемь тестов восстановления проходят.
- **Откат:** перед остановкой сервисов архив проверяется на опасные пути, ссылки, специальные записи и попадание `.env`, `.git` или `.rollback`. Раньше проверялась только читаемость gzip/tar: подготовленный вручную архив мог перезаписать секреты либо содержать ссылки за пределы дерева приложения. При отказе установка остаётся работающей; архивы со ссылками нужно пересоздать без них.
- **Обновление:** копирование проверенного релиза исключает вложенные `.env*`, `.git` и `.rollback` на всех уровнях. Раньше фильтр покрывал только корень архива, из-за чего релиз мог заменить локальный `support-pro/.env`.
- **Проверки:** добавлены регрессии отката для защищённых файлов и символических ссылок, а также проверка сохранения вложенного файла окружения при обновлении. Локально проходят 8 тестов `test_v2018_recovery.py`, `compileall`, `bash -n` и `git diff --check`.

Ограничение проверки: полный CI, Docker-сценарии и сборки клиентов здесь не выполнены: `pytest` не установлен, npm offline не содержит все пакеты. Эти исправления не означают допуска реальных платежей; по-прежнему требуется полный staging E2E v2.
